## 研究问题
后训练量化和剪枝需要校准数据（少量无标注样本）。惯例是从网页文本（如 C4）随机抽样，但存在两个问题：(1) 校准样本不具代表性会损害性能；(2) 很多模型不公开训练数据。作者提出 self-calibration：让被压缩的模型自己生成合成校准数据，以更好地逼近其预训练分布（p.1–3）。

## 方法细节
- **数据生成（Sec 3.1，p.3）**：只以 BOS token 为条件做开放式生成，不加任何 prompt 或外部数据，直到 EOS 或达到最大长度；不够长就拼接多段生成。对 Gemma、Mistral、Llama 这些多语模型，第一步被限制在英文停用词表中，以保证生成英文（p.4）。
- **温度调度（Sec 3.2，p.3–4）**：P(w_i | w_{1:i−1}) = softmax(u/t_i)；t_i 在前 n 步从 t_initial 线性变到 t_final，之后固定为 t_final。主实验用 t_initial = t_final = 1（标准采样）。Figure 3 的扫描用 n=10。
- **样本量**：128 条×2048 token；每个数据源独立采样 5 套校准集，报告均值和标准差（p.4）。
- **基线**：真实数据 C4、WikiText；合成数据有随机词表 token（Vocabulary）和 Cosmopedia（由 Mixtral 8x7B Instruct 生成）（p.4）。
- **被压缩的模型（Sec 4.2，p.4）**：Gemma 2B、Phi-2 2.7B、OPT 6.7B、Mistral 7B v0.3、Llama 3.1 8B，均为预训练基座模型。
- **压缩方法（Sec 4.3，p.5）**：AWQ、GPTQ（4-bit 仅权重量化，group 128），SparseGPT、Wanda（2:4 半结构化 50% 稀疏）。超参见 Table 6（p.15）。**算法和超参由人类固定**，模型只负责提供校准文本。
- **评估（Sec 4.4，p.5）**：10 个零样本任务（ARC-e/c、BoolQ、HellaSwag、LAMBADA、OBQA、PIQA、RTE、StoryCloze、WinoGrande），使用 lm-eval-harness，单卡 A100 80GB（p.15）。
- **谁在压缩谁**：生成校准数据的模型与被压缩的模型是**同一个模型、同一个 checkpoint**，这正是 "self" 的含义。但"决策/写代码"不是模型做的：压缩算法（AWQ/GPTQ/SparseGPT/Wanda）、超参、流程全部由人类研究者选定并用现成库（AutoGPTQ、TensorRT Model Optimizer、Wanda 代码库）执行。模型对自身压缩的唯一贡献是被动的数据来源，没有 agent 行为，也没有"压缩后的模型接任下一轮"的实验或讨论。
- **效率测量**：**不测任何 latency/throughput/内存**。只说 4-bit 可实现高效推理、2:4 稀疏在 GPU 上可加速，并引用他人工作（p.5），没有实测。也不报告 PPL 作为压缩质量指标（Table 4 的 PPL 是校准文本本身的 PPL）。
- **多轮递归**：无。每次压缩都是一次性的后训练压缩。

## 关键实验与数字
1. **Table 2（p.5）总表**：self-calibration 在 20 个（模型×方法）组合中有 17 个达到或超过其他合成数据（Sec 5，p.5）。例：GPTQ 量化 Gemma 2B 时，self-calibration 平均准确率 59.9%，Cosmopedia 58.5%，Vocabulary 57.9%，C4 58.7%。
2. **剪枝收益最大（Table 2，p.5）**：SparseGPT 剪 Llama 3.1 8B 时，self-calibration 53.8%，Cosmopedia 50.9%（+2.9），C4 54.8%（真实数据仍更高）。SparseGPT 剪 Phi-2 时，self 56.4%，C4 54.3%。
3. **不总是赢**：Mistral 7B 和 Llama 3.1 8B 上 self-calibration 不如真实数据，例如 GPTQ Mistral 下 self 65.9%，C4 66.8%（Table 2，p.5；p.6 正文）。
4. **样本效率（Fig 2，p.6；Sec 6.1，p.7）**：SparseGPT 剪 Phi-2 时，C4 用 128 条样本达到 54.3%，self-calibration 只用 16 条就达到 54.5%。
5. **温度调度（Fig 3，p.7；Sec 6.2）**：标准采样（t=1/1）距最优不超过 0.5 个点；贪心（0/0）明显更差，例如 Gemma SparseGPT 下贪心 42.5%，最优 51.0%。
6. **数据特性（Table 4，p.8；Table 8，p.16）**：self-calibration 文本的 PPL 更低（Llama 下 6.29，C4 为 8.65），n-gram 多样性更低（0.58 对比 0.62–0.65），Zipf 系数更高（1.24 对比 1.12–1.16）。
7. **量化对校准数据不敏感**：Gemma 2B 上不同数据源之间的最大差距，AWQ 为 0.6、GPTQ 为 2.0，而 SparseGPT 为 7.5、Wanda 为 3.2（p.6）。

## 作者自己声明的局限与 future work
- Limitations（p.9）：只做了英文模型、英文任务和英文校准数据；希望未来扩展到多语模型。
- 伦理（p.9）：自生成数据可能含有有害内容，但这些内容必然已经编码在原始权重中，作者认为不会引入新的安全问题。
- 结论（p.8）：希望推动合成数据在 LLM 压缩中的应用。
- **没有提到** self-compression 意义上的"模型自主压缩自己"，也没有提到递归或多轮。

## 方法问题与替代解释
- 【推断】"更接近预训练分布"这一机制解释没有被直接验证（训练数据大多未知）。另一种解释是：自生成文本对模型来说 PPL 低、处于高置信区域，激活统计更"典型"，因此有利于 Hessian/激活范数估计，而不一定是因为它逼近了训练分布。
- 【推断】增益集中在 2:4 剪枝且幅度有限（多为 0–3 个点），量化上差异常在标准差范围内；对 Mistral 和 Llama 不如 C4，说明结论依赖于模型。
- 【推断】只看零样本多选和 LAMBADA，没有生成式任务，也没有压缩后的 PPL，难以判断生成质量是否保持。
- 【推断】完全没有效率实测，"enabling efficient inference" 只是引用文献得到的推论。
- 【猜测】多语模型首 token 被限制为英文停用词，引入了轻微的外部先验，与"无外部数据"的表述存在小张力。

## 与每个 core claim 的关系
- **C1（LLM 自主决定并执行对自身权重的压缩，目标是推理效率并保持能力）**：部分相关。"自身"这一点成立：同一模型为自己的压缩生成校准数据，确实是"模型参与压缩自己"的先例。但"自主决定并执行"不成立：算法、比特数、稀疏模式、超参都由人类固定，模型只被动采样文本，没有决策或代码执行；也没有测推理效率。结论：不覆盖 C1 的核心（自主决策与执行），但应作为"模型自生成数据用于自身压缩"的相关工作引用。
- **C2（LLM 自己产出 LoRA adapter 并应用于自身）**：未涉及。没有 LoRA、没有微调、没有下游任务适配。不过"模型自生成数据→用于自身权重修改"的思路与 C2 中"自生成训练数据"一支在形式上相似（类似 Self-Instruct 的谱系），但用途是校准而非训练。未覆盖。
- **C3（递归：编辑后的模型成为下一轮编辑者）**：未涉及。一次性压缩，没有多轮，也没有讨论压缩后的模型再生成校准数据进行二次压缩。未覆盖。【推断】一个自然的延伸是让压缩后的模型再生成校准数据做下一轮压缩，但本文没有做。
- **C4（自我改进作用于权重）**：动作作用于权重（量化/剪枝），且数据来自模型自身，但这不是"改进"闭环（目标是保持性能，不是自我提升），动作也不由模型选择。部分相关，不覆盖。
