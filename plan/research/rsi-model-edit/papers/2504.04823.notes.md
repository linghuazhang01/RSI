## 研究问题
推理模型（长 CoT）在量化后的表现缺少系统研究。作者担心量化误差会沿长推理链累积，于是问四个问题（p4）：
- RQ1：哪些量化配置对推理模型基本无损？
- RQ2：推理任务上该选哪种量化算法？
- RQ3：任务难度怎样影响量化损伤？
- RQ4：模型来源（蒸馏 vs RL、Qwen vs LLaMA）怎样影响量化敏感度？
讨论部分还看了：量化后输出会不会变长、校准数据的选择、模型大小/延迟的 scaling、test-time scaling。

## 方法细节
### 被压缩的模型（p4 §3.1）
- 蒸馏系：DeepSeek-R1-Distill-Qwen 1.5B / 7B / 14B / 32B；DeepSeek-R1-Distill-LLaMA 8B / 70B
- RL 系：QwQ-32B、Qwen3-8B
- **20B–35B 区间的模型：有两个，DeepSeek-R1-Distill-Qwen-32B 和 QwQ-32B**（两者同底座 Qwen2.5-32B，一个靠蒸馏得到，一个靠 RL 得到）。

### 压缩方法与配置（p3 §2.1；附录 A p15–16）
只做训练后量化（PTQ），**没有剪枝和蒸馏实验**，也**没有恢复训练**。统一采用均匀整数量化（MXFP4 除外）。
- **只量化权重**（W-A-KV = 4-16-16 / 3-16-16）：GPTQ、AWQ；非对称量化，group size 128；所有线性层都量化，其余参数保持 BF16。
  - GPTQ：开 act-order 和 static group（70B 例外）；校准集是让推理模型在 NuminaMath-1.5 上**自己生成的推理数据**，128 条，长度 2048。
  - AWQ：用 Pile 采 128 条、长度 512。
- **只量化 KV cache**（16-16-4 / 16-16-3）：
  - QuaRot：按 token 非对称量化，group 128。
  - KVQuant*（简化版）：K 用静态 per-channel 量化，V 用 per-token 量化，group 128，去掉了非均匀和混合精度部分；在 1.5B/7B 上额外做“加 bias 之前量化 K”（pre-bias）。校准用 Pile 128×512。
- **权重+激活量化**（8-8-8 / 4-4-4，KV 也一起量化）：SmoothQuant（叠加 GPTQ；校准用自生成推理数据 128×2048）、QuaRot（Hadamard 旋转）、FlatQuant（可学习的 Kronecker 仿射变换，校准用 WikiText2 128×2048；1.5B/7B 上把长度加到 4096）、MXFP4（E2M1，每 32 个元素共享一个 8-bit 指数 scale）。权重 per-channel 对称量化，激活 per-token 非对称量化，KV 按 group 128 非对称量化，query 保持全精度。
- 量化后的模型和代码都已开源。

## 评测设置
- 基准（p4 §3.1）：
  - AIME-120：AIME 2022–2025 共 120 题，竞赛数学，最难
  - MATH-500：500 题，难度混合，有 5 个难度等级
  - GSM8K：小学应用题，最容易
  - GPQA-Diamond：研究生水平的科学多选题（原文把它描述成证明题）
  - LiveCodeBench：代码生成
- 工具：Lighteval + vLLM；temperature 0.6，top-p 0.95，最多生成 32,768 token；3 个随机种子取均值±标准差。
- shot 数：**正文没写**【推断：应为 Lighteval 默认的 zero-shot】。指标是准确率（3 个 seed 的平均 pass@1）。GSM8K、MATH-500、LiveCodeBench 的题量正文没给。
- 损伤分档：无损 ≤1%，尚可 1–3%，有风险 ≥3%（p4）。
- **真实速度/显存**：模型大小（GB）是算出来的；延迟 = 生成 token 数 × TPOT，而 TPOT 取自 Qwen 官方速度报告（p10 脚注 1），**不是自己实测的端到端速度**。没有测显存峰值。

## 关键实验与数字
### (a) 断崖出现在哪个比特数
- **只量化权重：W4G128 接近无损，W3G128 出现断崖**（Table 1，p5）：
  - R1-Distill-Qwen-32B：AWQ-W4 −0.4，GPTQ-W4 −1.9；AWQ-W3 −3.9，GPTQ-W3 −5.1。
  - 1.5B：AWQ-W4 −2.1；AWQ-W3 −18.6（AIME 从 23.3 掉到 4.4）。
  - QwQ-32B（Table 3，p16）：AWQ-W4 −0.8，GPTQ-W4 −0.9；AWQ-W3 −6.9，GPTQ-W3 −4.4；LiveCodeBench 在 W3 下掉了 7 分以上（AWQ 从 60.2 到 50.3）。
  - Qwen3-8B（Table 5，p17）：W4 −1.3/−1.5；W3 −13.0/−14.5。
  - LLaMA-8B（Table 4，p17）：AWQ-W4 已经 −3.9（GPTQ −1.6）；W3 −12.8/−11.4。LLaMA-70B：W4 −0.8/−1.1，W3 −6.2/−3.9。
- **KV cache：KV4 无损，KV3 有风险**：32B 用 QuaRot 时 KV4 −0.3、KV3 −3.0；QwQ 在 KV3 下 −5.7/−5.8；Qwen3-8B 在 KV3 下 −7.4（Table 1/3/5）。
- **权重+激活：W8A8KV8 全部无损（最好的算法掉分 <1），W4A4KV4 有风险**：32B 上 FlatQuant −2.9、QuaRot −5.9、MXFP4 −11.8；1.5B/7B 上超过 10 分；LLaMA-70B 上 MXFP4 −31.4、QuaRot −30.0（Table 1/4）。
- 按规模：模型越小越怕量化（p5）。

### (b) 哪些能力/任务最容易受损
- **任务越难，掉分越多**：32B 在 W4A4KV4 下，AIME −3.9、MATH-500 −1.2、GSM8K 0.0（p7 §3.4）；引言称难任务的掉分最多可达简单任务的 4 倍（p2）。
- MATH-500 分难度看，Level 5 掉分最大：14B 的 FlatQuant-W4A4KV4 整体与 BF16 相当，但在 Level 5 上掉 2 分以上（Fig. 6，p18）。
- 输出很长的任务（AIME、LiveCodeBench）在低比特下掉得最狠（附录 B.1，p16–17）。GSM8K 几乎不受影响，**拿它当评测信号会严重低估损伤**。
- 输出长度：损伤小的配置（W4G128、W8A8KV8、KV4）输出长度与 BF16 接近；W3G128、W4A4KV4 会让输出变长，小模型更明显（Fig. 3，p8；Fig. 7，p18）。
- Test-time scaling：推理越长，量化模型越好，但提升斜率低于 BF16；推理过长两者都会下降（Fig. 5，p10）。
- 定性样例：量化模型的推理结构（理解→计算→检查→作答）和 BF16 一样，错误多是计算失误；MXFP4 版 32B 甚至把题目里的坐标看错，以为是笔误（Table 11，p25）。

### (c) 量化 vs 剪枝 vs 蒸馏
- 本文**只做了量化**，剪枝和蒸馏只在相关工作里提到。
- 能间接比较的一点：同显存下“大模型低比特”胜过“小模型 BF16”。3-bit 的 QwQ-32B / Qwen-32B 约 14.5GB，与 BF16 的 Qwen-7B 差不多大，LiveCodeBench 却高约 17 分（Fig. 4a，p9）。4-bit 模型的精度-延迟权衡优于 8-bit 和 BF16（Fig. 4b，p10）。
- 模型来源（Fig. 2，p7）：两个 32B 对不同量化的耐受度不同。小标题说 Qwen-32B 更耐 KV 量化、QwQ-32B 更耐权重和权重+激活量化。正文给的数字是：Qwen-32B 在 W3G128 下掉 6.4%，QwQ 掉 5.4%。但正文接着把“3.8% vs 2.5%”标成 KV3，又说 Qwen-32B 在 KV 上少损失 3.1%，**这几处自相矛盾**【推断：3.8/2.5 那组数可能其实是 W4A4KV4】。Qwen-7B 更耐权重量化，LLaMA-8B 更耐 KV 量化和权重+激活量化（例如 AIME 上 KV3 掉分 12.5 vs 4.7）。

### (d) 比特分配 / 哪些模块敏感
- 本文**没有做层级或模块级的比特分配实验**，所有层都用同样的比特数。
- 与模块有关的发现：Qwen-1.5B/7B 的 key 投影 bias 极大（绝对值最大到 402），使 K cache 出现极端离群通道，per-token 量化（QuaRot）因此崩溃（1.5B 在 KV4 下 −46.6）。“加 bias 之前量化 K”能把 7B 的 KV4 从 −55.8 救回到 −1.7（Table 6，p20）。
- 对 FlatQuant，校准长度越长越好：2K/4K/8K 对应 −16.3/−10.3/−5.7（Table 7，p21）。原因是 RoPE 让离群通道随位置旋转。
- 校准数据的领域：GPTQ-W3 的校准集从 WikiText2 换成 NuminaMath 推理数据后平均 +9.8；AWQ、KVQuant*、SmoothQuant、FlatQuant 对此不太敏感（≤1.8）（Table 2，p9）。原因是推理数据与预训练数据的激活分布不同（Fig. 9，p19），但通道幅值分布一致（Fig. 8）。

## 作者自己声明的局限
- 正文没有单独的 Limitations 章节。结论（p10）承认：已经找出影响量化推理模型的关键因素，但背后的机制没有完全弄清，因果关系留给后续工作。
- 正文多处说明：4-bit 权重+激活量化仍是未解决的问题（p6）；如何在更长推理长度上持续获益也没解决（p10）。

## 方法问题与替代解释
- 【推断】AWQ 的校准用 Pile，GPTQ 用自生成的推理数据，两者校准数据不同。所以“AWQ 与 GPTQ 相当，且更不依赖校准数据”这个结论混入了校准数据的差异。
- 【推断】延迟由 token 数 × 官方 TPOT 算出，没有反映真实的 W3 kernel 或 group-wise 反量化开销，也不包括 FlatQuant 的在线变换开销，所以 Fig. 4b 的结论偏理想。
- 【推断】AIME-120 只有 120 题，3 个 seed 的标准差常有 2–4 分（如 32B GPTQ-W3 是 ±4.4），1 分以内的“无损”判定在 AIME 上统计意义很弱。
- 【推断】“量化模型不会想得更久”的结论只在掉分小的配置上成立；它与“掉分小”本身是相关的，不能推广到任意配置。
- 【推断】Fig. 2 文字与数字不一致，模型来源的结论需要回到原图核对。
- 【猜测】QwQ-32B（RL）比 Distill-Qwen-32B 更耐权重量化，可能因为 RL 训练对权重的扰动更小，保留了底座的分布，但论文没有验证。

## 对“~27B 模型自我压缩、压缩后继续当 agent 做下一轮压缩”研究设计的启示
- **选量化还是剪枝/LoRA**：本文只给出量化方面的证据。在 32B 级别上，W4G128（AWQ/GPTQ）和 W8A8KV8 都基本无损（32B AWQ-W4 −0.4，QwQ −0.8），说明第一轮压缩选 4-bit 只量化权重是有证据支撑的安全起点。本文没有剪枝和 LoRA 的数据，那部分要看别的论文。
- **比特数安全区**（32B 级证据）：
  - 权重：4-bit 安全；3-bit 掉 4–7 分，是第一道断崖（Qwen3-8B 在 3-bit 下掉 13 分以上，提示不同家族差别很大）。
  - KV cache：4-bit 安全，3-bit 掉 3–6 分。
  - 权重+激活：8-bit 安全；4-bit 即使用最好的 FlatQuant 也掉 2–3 分，其他方法掉 6–30 分。
  - 【推断】自我压缩的多轮循环里，第 2 轮若从 W4 再降到 W3，按本文数据大概率跨过断崖，对 agent 能力的损伤（长输出、难任务）会被放大。
- **评测应包含**：AIME（或其他难数学题）和 LiveCodeBench 这类长输出、高难度任务，因为它们最先暴露损伤；GSM8K 几乎不敏感，不宜作主要信号。还应监控输出长度，因为低比特会导致输出变长，延迟收益随之打折。
- **校准数据**：如果 agent 自己选 GPTQ 这类依赖误差补偿的方法，必须用推理领域的数据校准，最好用模型自己生成的推理轨迹（+9.8 分）。【推断】在自我压缩的循环里，第 k 轮模型生成的校准数据质量会随压缩下降，可能形成正反馈式退化，需要固定一份由原始模型生成的校准集作为对照。
- **模型家族差异**：同底座、不同训练方式的两个 32B 敏感度就不一样；Qwen 小模型有 K-bias 离群值的特殊问题。【推断】要先确认 27B 目标模型的 KV/bias 离群情况，不要直接套用 32B 的数字。
