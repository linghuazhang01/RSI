## 研究问题
LLM 能否识别自己的计算基底被降级，也就是被量化？作者借用神经心理学中的"病感失认"（anosognosia）做类比，分两条通道：
- 内部觉察：只靠前向传播中的激活判断自己是否被量化；
- 外部觉察：给模型看它自己生成的文本，再让它判断。
进一步追问：如果答不出来，是因为没有信号（fingerprint），还是有信号但读不出来（readout）？训练能否补上这个缺口，并且能否泛化（p1–2）？

## 方法细节
- **模型**：Qwen3-8B、Llama-3.1-8B-Instruct、Gemma-3-27B-IT、Qwen3-32B，都是预训练加后训练的现成模型，全程关闭 reasoning/CoT（p3）。
- **量化（由研究者外部施加，不是模型自己决定）**：GPTQ（group size 64/128/256）、AWQ（gs128）、RTN（gs128），各做 8-bit 和 4-bit；GPTQ/AWQ 的校准集是 C4 的 128 条样本、长度 2048（Table 1 p18）。
- **实验 1：自发自报（2 节）**：三类问题（是否异常、是否量化、bit-width），每类 240 个模板变体（10 种先验 framing × 4 种指令 × 选项顺序），温度 1.0，生成 3 次取平均（p3；B.3 p20–22）。外部觉察版本先放一轮同一 checkpoint 对 benchmark 问题的回答作为上下文（Table 5 p20）。
- **实验 2：线性探针（3 节）**：用 Dolly/XSum/ELI5 共 3000 题，70/15/15 按 prompt 切分。
  - 外部指纹：把 16/8/4-bit 模型生成的回答喂给 16-bit 模型，取 response mean 做 3 分类；
  - 内部指纹：同一 prompt 分别送入 16/8/4-bit 模型，取每层残差流的 prompt mean 和 prompt last；
  - 另外分别探测 attention 和 MLP 输出，并设置 norm-only、direction-only、shuffled 标签对照（C.1 p24）。
- **实验 3：从文本检测量化的 SFT（4 节）**：用 LoRA（r16, α32）训练 16-bit 模型判断文本出自哪个精度，分 Pointwise、Pairwise、Setwise 三种格式。训练集 42,000 条，外部验证集取自 WritingPrompts/CodeAlpaca/GSM8K。评估用 forced-choice log-likelihood，并按格式做 chance 校正（式 1–2 p6；D.1–D.2 p28–29）。
- **实验 4：shared LoRA 读出（5 节）**：同一个 LoRA 同时挂在 16-bit 和 8/4-bit GPTQ-g128 三个冻结 backbone 上。输入完全相同（问"你的权重是几 bit"），标签是真实 bit-width，loss 取三个精度上 NLL 的平均（式 3 p7）。用 80 个模板（60 个训练、20 个 held-out），30,000 条域内 QA 上下文，6,000 条外部 QA 上下文。false control：三个 backbone 都用 16-bit（E.1 p31）。
- **谁改谁的权重**：研究者对模型做外部量化。模型自己不修改任何权重，也不决定压缩方式。唯一的"训练"是研究者用 SFT/LoRA 教模型报告自己的 bit-width（或判断文本来源精度），属于自我监测能力训练，不是自我编辑。
- **是否涉及压缩、量化或推理效率**：涉及量化，但量化只被当作"可控的基底损伤"，有明确的真值。论文不关心推理效率，只在附录 B.2 报告量化带来的能力损失（MMLU-Pro/BBH）。
- **是否多轮递归**：不涉及。

### 特别说明：模型能否感知或判断自己被量化后的退化？这对"模型自己决定如何压缩自己"意味着什么
- **自发情况下不能**：8-bit 与 16-bit 的自报分布没有实质差异；4-bit 的部分变化（如 Qwen3-8B）在不同方法间方差接近 20%，作者认为这是能力退化的副作用，不是真正的觉察（p3–4，Fig 2）。给模型看自己的输出也没有帮助（p4，Fig 2c/d）。
- **信号存在于内部，不在文本中**：线性探针在第一个被量化的层之后就几乎 100% 区分 16/8/4-bit，而且主要是方向编码而非范数（p5，Fig 3b）。生成文本中几乎没有可探测的指纹，准确率不到 40%，接近 chance（p4，Fig 3a）。
- **从文本只能做比较判断，不能做绝对判断**：Setwise 时 4-bit 识别率超过 85%，但 8-bit 和 16-bit 混淆；Pointwise 几乎是 chance（p6–7，Fig 5，Table 15）。
- **能训练出读出能力，但不能泛化**：shared LoRA 在 600 步内达到 90% 以上，训练后 80 个模板都是 100%（p8，Fig 22–23）。但换到没见过的 AWQ/RTN，甚至只是改变 GPTQ 的 group size，就完全失效：8-bit 一律答"16-bit"（p8，Fig 8）。作者的结论是 LoRA 学到的是把方法特有的指纹映射到标签，而不是识别"量化"这一现象。
- **对 C1 的含义**【推断】：如果"模型自己决定如何压缩自己"需要模型通过内省来判断某个压缩方案伤了多少能力，那么本文给出的是负面或警示性证据：(a) 现成 LLM 无法内省出自己的量化状态或退化程度；(b) 从自己的输出（单条）也看不出来，只有在多个候选并排比较、且退化严重（4-bit）时才能区分；(c) 即使训练出读出能力，也不能泛化到新的压缩方法。因此，一个让 LLM 自主压缩的系统，**评估信号恐怕必须来自外部**（benchmark、验证集、成对比较或 judge），不能依赖模型的自我感知。另一方面，Pairwise/Setwise 的结果说明"同时比较多个压缩候选的输出、挑出明显退化者"是可学习的，这与"生成多个候选后用比较式评估做选择"的设计相容。本文没有测试 2–3 bit、剪枝、层删除等其他压缩，作者把层删除和 LoRA 挂载列为 future work（A，p18）。

## 关键实验与数字
- **Fig 3（p5）与 3.1–3.2 节（p4–5）**：外部指纹的 3 分类准确率不到 40%（Gemma 最佳层：16-bit 36.7%、8-bit 29.8%、4-bit 47.6%，见 p4 与 Fig 19 p27）；内部 prompt last 在 embedding 层为 33.3%，第一个量化层后接近 100%，最后三分之一的层仍高于 80%；prompt mean 约 70–90%；norm-only 峰值约 60%。
- **Fig 5（p6）/ Table 15（p32）**：Qwen3-32B Setwise 下 4-bit 正确率 87.9%，16-bit 和 8-bit 约 47–49% 互相混淆；Pointwise balanced acc 从 0.348（Base）到 0.390（LoRA）；Setwise 从 0.364 到 0.627；Pairwise 从 0.502 到 0.601。
- **Fig 22（p32）/ 5.2 节（p8）**：shared LoRA 在 held-out 模板上 600 步内超过 90%；false control（三个都是 16-bit）始终不超过 33%（p31）。
- **Fig 7（p7）**：shared LoRA 训练后，外部觉察的 bit-width 自报正确率：Qwen3-8B 16/8/4-bit 分别提升 +30.9%、+36.8%、+64.9%；Gemma-3-27B-IT 分别提升 +7.6%、+32.4%、+73.6%。
- **Fig 8（p8）**：只用 GPTQ-g128 训练的 LoRA 在 GPTQ-g128 上 100%；在 AWQ、RTN 和 GPTQ-g64/g256 上明显失败（正文 p8 说，在未见过的 AWQ/RTN 上，8-bit 一律被判为"16-bit"；图中柱状数字经 pdftotext 提取后错位，单个条件的具体百分比请对照 PDF 图核实）。即使同时用 GPTQ 和 AWQ 训练，换到 RTN 等方法仍然失败。
- **Table 2/3（p19，量化造成的能力损失）**：Qwen3-32B 的 4-bit RTN 在 MMLU-Pro 上下降 43.3 个点；Gemma-3-27B-IT 的 AWQ 在 MMLU-Pro 上 8-bit 降 18.8、4-bit 降 25.5；GPTQ 的退化最小。

## 作者自己声明的局限与 future work（附录 A p18；6 节 p9）
- 没有使用 CoT/RLVR，让模型基于推理判断自己的基底可能会更好；
- "真正的觉察"难以严格评估，模型可能利用统计线索或评估觉察；
- 训练 bit-width 自报会带来简短化偏置，并使 benchmark 略有下降；
- 只测了 8B–32B 的稠密模型，没有测 70B 以上、MoE 或 SSM；
- 依赖固定模板，没有测多轮或 system prompt 的影响；
- 只研究了量化，层删除和 LoRA 挂载留作 future work；
- 没有尝试激活 steering 等非参数方法；
- 6 节的方向：让模型用 CoT 推理自己的指纹；记住未量化状态的"标准指纹"，把检测当作相对该参照的异常检测，而不是闭集分类，这样可能更易泛化；
- 安全含义：可用于检测利用量化绕过安全护栏的篡改，但读出不泛化，所以不实用；状态觉察也可能带来 sandbagging 风险。

## 方法问题与替代解释
- 【推断】内部探针接近 100% 可能部分来自"同一 prompt 在三个模型上的激活差异"这种模型身份信号，探针学到的是区分三个具体权重集合，而不是"退化程度"。作者在 5.3 节的泛化失败结果其实支持这种解释。
- 【推断】Setwise 的 4-bit 可分性可能来自 4-bit 输出更差（长度、重复、错误），即质量差异而非精度指纹；作者也把它解释为"严重退化提供了对比"。
- 【推断】shared LoRA 是在量化后的权重上额外挂一个 adapter，这个 adapter 本身也会和量化误差相互作用，"读出"可能部分是 adapter 与特定量化网格之间的交互，这也能解释为什么改变 group size 就会失效。
- 【猜测】自报实验在温度 1.0 下进行，并且明确给出 50% 先验，可能压低了模型给出非均匀回答的倾向。

## 与每个 core claim 的关系
- **C1（模型自主压缩自身权重以提升推理效率）**：**未覆盖，但提供了相关的约束性证据。** 本文由研究者外部量化，模型不做任何压缩决策，也不涉及效率目标。它对 C1 的意义是给出一个前提性的负面结果：LLM 自发地感知不到自己被量化及其退化，从单条输出也无法判断，训练出的读出能力也不能跨量化方法泛化。所以如果 C1 系统依赖"模型内省判断压缩伤害"，就会遇到困难；更可行的做法是依赖外部评测或比较式评估。可以作为 C1 的动机或风险文献引用。
- **C2（模型自己产出 LoRA 并应用到自己身上）**：**未覆盖。** LoRA 由研究者用标注数据训练，目的是自我监测（报告 bit-width），不是模型自己产出 adapter 来适配下游任务。
- **C3（递归闭环）**：**未覆盖。** 没有迭代或递归。
- **C4（动作空间在权重层面）**：**未覆盖。** 模型没有任何动作空间。量化和 LoRA 都是研究者施加的实验操作。只有"量化作为对权重的结构性修改"这个对象与 C4 中的压缩算子相同。
