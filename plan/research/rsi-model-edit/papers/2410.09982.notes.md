## 研究问题
一次性（one-shot）的深度结构化剪枝（删掉连续若干个 decoder 层）会明显损伤多步推理（GSM8k、ARC-C）。常规做法是剪完后用 SFT 恢复，但 SFT 数据分布与原模型分布不一致，会引入灾难性遗忘。作者问：如果用**未剪枝的原模型**把微调数据集的回答"改写成自己的话"，再用这份自生成数据去微调剪枝后的模型，能否比普通 SFT 恢复得更多、遗忘更少（p1–p2）？另外顺带研究了 model merging 和 speculative decoding 两个延伸用法。

## 方法细节
- **模型**：Llama3.1-8B Instruct（32 层，8.03B）为主；Mistral-7B-v0.3 Instruct 为第二个模型（§4，附录 A.1 p15）。都是已经指令微调过的模型，作者认为"从一个校准良好的 instruct 模型出发"是方法生效的前提之一（p8–p9）。
- **压缩方式**：深度结构化剪枝（Algorithm 1，p3）。
  - 对每个起始层 ℓ，计算第 ℓ 层与第 ℓ+n 层在最后一个 token 上激活的角距离（Gromov et al. 的 angular cosine，式 1，p3），选距离最小的连续 n 层删除，再把 ℓ 的输出直接接到 ℓ+n。
  - 块大小 n ∈ {2,4,6,8,10}，对应剩 30/28/26/24/22 层（附录 A.2 p15）。Llama 上参数分别为 7.59B/7.16B/6.72B/6.29B/5.85B，作者给出的"model savings"为 5.23%–27.16%（Table 1 p6；摘要中称 6 层剪枝减少 16.3% FLOPs）。
  - 校准集：RedPajama，128 条，最大长度 4096；C4、SlimPajama 选出的层几乎一样（Table 7 p15）。例如 n=6 时删的是第 22–27 层。
  - 与 BI score 对比：两种指标都显示中间层冗余，剪枝结果差不多；选角距离是因为只看最后一个 token，计算更省（§3.1，Fig. 3 p5）。
  - 不涉及量化。
- **自生成数据（self-data distillation）**（§2.2 p4–p5）：
  - 对微调集里每个样本 (上下文 c, 输入 x, 原回答 y)，让**未剪枝的原模型**在看到 c、x 和 y 的条件下重新生成回答 ỹ（即"用自己的口吻改写标准答案"）。
  - 条件筛选：如果从 ỹ 中抽出的最终答案与 y 一致就用 ỹ，否则退回原回答 y（沿用 Yang et al. 2024）。论文没有报告退回比例。
  - 然后用标准 NLL 在 (c, x, ỹ′) 上微调剪枝模型。所以"谁生成数据"是**原始大模型（剪枝前的自己）**，不是剪枝后的模型。
- **恢复训练**（附录 A.5 p16）：
  - **只用 LoRA**，不做全参（作者明确留作未来工作）。
  - 在 8k 条 OpenMathInstruct 上网格搜索：rank ∈ {4,8,16,32}，epochs ∈ {3,5,7,10}，lr 五档 2e-5 到 1e-4，batch ∈ {8,…,128}。最终选定 **rank=8，5 epochs，batch 64，lr 1e-4**，SFT 和自蒸馏两种方法共用这组超参。论文没有写 LoRA alpha、目标模块。
  - 框架 LLaMA-Factory v0.8.3；H100 训练和评测；大规模自蒸馏数据的生成用 Cerebras CS-3 推理（>1800 token/s），15k 条以内用 H100 即可（A.5.1 p16–p17）。没有报告 GPU 小时数或训练步数。
  - 数据量：消融中 GSM8k、Alpaca、OpenMathInstruct 各固定 8k 条，Dolly 用全量 15k；扩展实验用 Alpaca Cleaned 全量 50k 和 OpenMathInstruct 随机抽 50k（A.4.1 p16）。主结果（Table 1/2）用 OpenMathInstruct 50k。
- **Model merging**（§4.1 p7–p8，附录 D p17–p18）：分别在 OpenMathInstruct 和 Alpaca 上自蒸馏微调两个剪枝模型，用 SLERP（mergekit）合并；对照组是在两份数据混合后训练一个模型，总样本数相同。论文没有给出插值系数 t 的取值。
- **Speculative decoding**（§4.2 p9–p10）：剪枝+自蒸馏+合并后的 Llama 小模型给 Llama3.1-70B Instruct 当草稿模型，Mistral 小模型给 Mistral Large 2（123B）当草稿模型；K=6 个草稿 token，贪心验证。

## 关键实验与数字
### (a) 自生成数据 vs 普通 SFT 数据
- **Table 1（p6），Llama3.1-8B，OpenMathInstruct 50k**，6 项平均（未剪枝基线 69.40）：
  - n=2：No FT 66.22 / SFT 59.59 / 自蒸馏 65.51
  - n=4：64.06 / 58.66 / 64.75
  - n=6：51.82 / 56.68 / **63.33**（恢复率 74.67% / 81.66% / **91.24%**）
  - n=8：48.93 / 53.00 / 59.92
  - n=10：46.39 / 47.58 / 55.91（恢复率 66.83% / 68.56% / 80.56%）
  - n=6 时 GSM8k：No FT 1.29，SFT 43.82，自蒸馏 66.64（原模型 75.59）。
- **Table 2（p7），Mistral-7B-v0.3**：各块大小自蒸馏都高于 SFT，但差距比 Llama 小，例如 n=6 时 55.31 vs 53.87，n=10 时 48.84 vs 47.13。
- **Fig. 2（p4）+ Table 8（p19）**：四种微调数据上自蒸馏多数优于 SFT，数据越多恢复越好，OpenMathInstruct 50k 最好；n=6 时自蒸馏恢复 95.96%（三项平均口径），SFT 为 80.71%。也有反例：Table 8 中 n=4 的 Dolly，自蒸馏 57.69 低于 SFT 59.26；n=6 的 GSM8k 数据，自蒸馏的 GSM8k 分数 60.05 低于 SFT 62.09。
- 摘要中"比 SFT 平均高最多 8%"大致对应 n=8 的 59.92 vs 53.00（约 6.9 分）和 n=10 的 55.91 vs 47.58（约 8.3 分）（Table 1 p6）。
### (b) 恢复训练带来的遗忘
- 论文没有把遗忘单独做成一个"在训练集之外的任务上掉了多少"的实验，主要证据有两类：
  1. **Fig. 4（p6）**：在 GSM8k 上，自蒸馏模型的输出与原模型的句向量相似度均值更高，分布更窄。n=4 时 SFT 均值 0.85 vs 自蒸馏 0.89；n=6 时 0.84 vs 0.89；n=8 时 0.70 vs 0.84。这只是"输出更像原模型"，不是直接的遗忘测量。
  2. **Table 1（p6）分项**：可以从中读出非目标任务的变化。以 n=6 为例，与 No FT 比较，SFT 让 MMLU 从 67.42 掉到 59.98（−7.4），TruthfulQA 从 53.63 掉到 50.81；自蒸馏的 MMLU 为 64.96（−2.5），TruthfulQA 53.14（−0.5）。**普通 SFT 有明显遗忘，自蒸馏仍有遗忘，只是少很多。**
- 【推断】我按 Table 1（p6）把 GSM8k 去掉，算剩下 5 项（ARC-C、HellaSwag、TruthfulQA、MMLU、Winogrande）的平均：
  - n=2：No FT 65.98 / SFT 62.52 / 自蒸馏 64.60
  - n=4：65.28 / 61.52 / 63.81
  - n=6：61.93 / 59.25 / 62.67
  - n=8：58.72 / 57.67 / 60.37
  - n=10：55.66 / 54.02 / 58.17
  - 也就是说，轻度剪枝（n=2、4）时，自蒸馏 LoRA 在非数学任务上**比不微调还低约 1.4 分**；只有重度剪枝（n≥8）时才在非数学任务上有 1.6–2.5 分的净恢复。主表上的大幅提升主要来自 GSM8k，而 GSM8k 与训练数据 OpenMathInstruct 同分布。
### (c) 压缩 + LoRA 恢复 vs 单纯压缩
- 6 项平均的净增益（自蒸馏 − No FT，Table 1 p6）：n=2 为 −0.71，n=4 为 +0.69，n=6 为 +11.51，n=8 为 +10.99，n=10 为 +9.52。**轻度剪枝下 LoRA 恢复几乎没用甚至略有害，增益集中在中重度剪枝。**
- 普通 SFT 在 n=2、4 时比不微调还差得多（59.59 vs 66.22；58.66 vs 64.06），说明分布不匹配的数据本身就会伤模型。
- **Table 3/4（p7）model merging**：Llama n=6，混合数据训练 63.77（91.88%），SLERP 合并 64.75（93.30%）；n=8 时 59.37 vs 61.24。Mistral 上增益更小（n=6 为 56.26 vs 56.41）。
- **Table 5/6（p8）speculative decoding**：Llama n=10 剪枝模型给 70B 当草稿时，平均接受长度从 1.55（不微调）升到 3.25（+1.70），未剪枝 8B 草稿为 5.01；Mistral n=10 从 1.56 升到 3.18（+1.62），未剪枝为 4.04。论文没有报告端到端的 wall-clock 加速。

## 作者自己声明的局限
- 只做了 one-shot 剪枝，迭代剪枝可能在某些架构上更好，留作未来工作（p4）。
- 只用 LoRA，全参微调留作未来工作（附录 A.5 p16）。
- 自蒸馏不一定能完全恢复原模型质量，只是效率和精度之间的折中（p5）。
- 校准数据特性对剪枝决策的影响仍是开放问题（附录 A.3 p15）。
- 与标准 KD（logit 蒸馏）结合、与量化/稀疏结合、推广到更新的架构，都列为未来工作（p10–p11）。

## 方法问题与替代解释
- 【推断】**主表收益高度集中在 GSM8k**，而训练数据 OpenMathInstruct 就是基于 GSM8K/MATH 构造的。n=6 时 No FT 的 GSM8k 只有 1.29（Table 1 p6），这很可能是 5-shot 输出格式崩溃，而不是推理能力完全丧失。所以自蒸馏的大部分"恢复"可能是在恢复答题格式和数学领域能力，不能直接说明对通用能力的恢复。
- 【推断】**表格中有多处明显的复制或计算错误**，降低了数字的可信度：
  - Table 2（p7）Mistral n=2 的自蒸馏行（53.93/74.27/50.61/65.34/74.90/69.44，平均 64.75，恢复 93.29%）与 Table 1 中 Llama n=4 的自蒸馏行完全相同；而且这一行 GSM8k 69.44 远高于 Mistral 原模型的 48.75，不合理。
  - Table 8（p19）的未剪枝基线（ARC-C 58.70，GSM8k 63.15，MMLU 67.40）与 Table 1（60.92/75.59/68.15）不一致；Table 8 中 n=2 和 n=4 的 No FT 行完全相同，而且 GSM8k 与 MMLU 两列像是对调了。
  - Table 8 中 n=6 的 No FT 行（49.49, 0.00, 67.42）三项平均应为约 38.97，表中写的是 48.93。
  - Table 8 中 n=8 的 SFT-Dolly 行与 n=10 的 SFT-OpenMathInstruct 行数值相同（39.33/15.39/57.44）。
  - Mistral Table 2 中 n=2 不微调的 HellaSwag 62.31 低于 n=4 的 78.89，不太合理。
- 【推断】Table 8 中自蒸馏在 n=2、4 上的恢复率超过 100%（例如 101.76%），在 Table 1 的 6 项口径下并没有出现，说明结论对评测子集的选择敏感。
- 【推断】没有多 seed，没有置信区间；LoRA 超参在 OpenMathInstruct 8k 上调好后用于全部设置，可能对 SFT 基线不公平（SFT 用这组超参在 n=2 上反而掉了 6.6 分）。
- 【推断】"自生成数据"在这里是**改写人类或 Mixtral 写好的答案，并用标准答案过滤**，不是让模型自由生成题目和答案。它依赖带标准答案的数据集；没有标准答案的开放任务（如 Alpaca、Dolly）无法用这个过滤条件，论文也没说明这时怎么处理。
- 【猜测】自蒸馏优于 SFT 的另一种解释是：改写后的回答更符合 instruct 模型自己的格式和风格（例如 chat 模板、推理步骤写法），所以 LoRA 学的主要是"格式回到原样"，而这一点 5-shot 评测特别敏感。论文的 Fig. 4 相似度分析与这个解释也相容。
- 【推断】没有与 logit 级 KD（用原模型的输出分布作为软标签）对比，所以无法判断"自生成序列"本身是不是最优的恢复信号。

## 对"约 27B 模型自己压缩自己、并可能用自己生成的数据训练 LoRA 来恢复或提升能力"的启示
- **有证据支持的部分**：
  - 在 7–8B instruct 模型上，"剪枝前的自己生成数据 + LoRA 微调剪枝后的自己"在中重度深度剪枝（删 6–10 层，约 16–27% 参数）下，比不微调高约 10–11.5 分（6 项平均），比普通 SFT 数据高约 4–8 分（Table 1 p6）。这是本设计中"用自生成数据恢复"环节最直接的正面证据。
  - 用来生成数据的应该是**压缩前的模型**，被训练的是压缩后的模型。本文没有测试"让压缩后的模型自己生成数据"，这种做法的效果没有证据。
  - LoRA rank 8、5 epochs、50k 条数据就足够产生上述效果（附录 A.5 p16），成本相对低。
  - 合并在不同数据上恢复的两个 LoRA 版本（SLERP）比混合数据训练略好 1–2 分（Table 3 p7），可以作为"多个 adapter 合并"这一动作的弱证据。
- **需要警惕的部分**：
  - 轻度压缩（删 2–4 层，约 5–11%）时，LoRA 恢复在 6 项平均上几乎为零，非目标任务上反而略降（Table 1 p6 + 我的推算）。如果 27B 模型只做轻度压缩，"自生成数据 LoRA"可能帮不上忙，甚至需要专门证明它不伤通用能力。【推断】
  - 本文的"提升"基本限于与训练数据同领域的任务（GSM8k）。没有证据表明压缩后再加自生成数据 LoRA 能**超过**未压缩模型；所有设置下 6 项平均都低于原模型（Table 1 p6）。所以"恢复"有证据，"提升"没有。
  - 需要显式测量非目标任务上的遗忘：普通 SFT 让 MMLU 掉 7 分以上，自蒸馏也掉约 2.5 分（Table 1 p6，n=6）。
  - 本文只在 7–8B 上做，没有 27B 级别的证据；层冗余程度和恢复难度在更大模型上可能不同。【猜测】
  - 数据过滤依赖标准答案；若要做"模型自己出题自己答"，需要另找可靠的过滤信号。【推断】
