## 研究问题
AI 研究 agent 已经能提升它所产出的东西（训练和推理效率等），但 agent 自身的"研究效率"仍然是固定的。本文要回答：当 agent 的代码本身成为优化对象，每次被接受的重写都成为下一轮被编辑的对象时，这种递归自我改进（RSI）能否持续提升 AI R&D 研究效率，并且泛化到选择时没见过的任务（p1–2）？

## 方法细节
- **双层优化**（Section 2.1, p3–4；Algorithm 1, p4）：
  - 内层：agent a 在固定美元预算 b_t 内，按公开信号 r_t^pub 反复修改任务代码（式 1）。
  - 评分：用私有留出集 r_t^priv 给 a 在选择基准上的输出打分，取平均得到 g(a)（式 2）。
  - 外层：外层 agent a_out 读取历史 agent 及其分数，提出对当前 incumbent 代码的重写（式 3）。只有 g 更高时才接受，incumbent 取 argmax g（式 4）。
  - 公开和私有信号分离，用来防止内层直接优化选择标准；固定预算保证提升来自算法改进，而不是花了更多算力。
- **具体系统**（Section 2.2, p4–5）：
  - 内层初始 agent AIDE0 是 AIDE 的精简版树搜索，包含 draft/debug/improve 三个算子、贪心选择和一个 reviewer。
  - 外层 agent 是 Weco 的生产级 agent AIDE_human。
  - 底层 LLM 在两层内都固定：外层用 claude opus 4.7，内层评测用 gemini 3 flash。整个过程中没有修改任何模型权重。
  - 选择基准包含三类任务：ML 工程、启发式算法工程、harness 工程。
- **谁在修改谁**：
  - 主实验中，修改者始终是固定的 AIDE_human（跑在 Opus 4.7 上）；被修改的是内层 agent 的代码。
  - 所谓"递归"是指每次被接受的重写成为下一步的编辑基底，而不是编辑者本身在被替换。
  - 只有在"ignition test"（Section 3.6）中，才把发现的 AIDE47 放到外层当编辑者，这时才是真正的"改后系统成为下一轮的修改者"，但结论不确定（见下）。
- **修改对象**：harness 代码，包括搜索策略、上下文和记忆管理、鲁棒性规则、提示词。不改模型权重，也不用 LoRA。
- **推理效率或压缩**：
  - 研究效率的定义是固定预算下的优化能力。
  - 发现的机制之一是上下文压缩：每次 LLM 调用的 prompt 大小，中位数减少 7 倍到约 50 倍（Figure 6, p10；附录 E, p27）。
  - 这是对 prompt 或上下文的压缩，不是对权重的量化或剪枝。
- **是否多轮递归**：
  - 主实验中，内层 agent 在 100 个节点上经历了 7 次被接受的重写，是多轮的，但编辑者固定。
  - 编辑者的自我替换只在 ignition test 中做过一轮，共 3 个 seed、50 步。

## 关键实验与数字
- **Figure 2（p6）+ Section 3.2（p5）**：8 天自主运行，共 100 个节点（初始 agent 加 99 个重写提案）。
  - 在第 2、6、28、39、47、63、85 步共接受了 7 次改进。
  - incumbent 的私有分数 g 从 0.703 升到 0.778；AIDE_human 在同一评分下为 0.749。
  - 另外两次完整运行分别接受了 2 次和 4 次重写。
- **Figure 3（p7）+ Table 1（p24）**：四个外部留出基准，比较 AIDE0 / AIDE47 / AIDE85 / AIDE_human。
  - ALE-Bench：1536 / 1713 / 1790 / 1511。
  - MLE-Bench：0.678 / 0.730 / 0.722 / 0.708。
  - WeatherBench 2（分布外）：0.262 / 0.798 / 0.793 / 0.404。
  - FML-Bench：15.0 / 19.7 / 19.9 / 19.6（%）。
- **Figure 4（p8）**：KernelBench 上 38 个（kernel, 训练场景）对的 reward hacking 率。AIDE0 55%，AIDE47 39%，AIDE85 32%，AIDE_human 39%。
- **Figure 6（p10）/ 附录 E（p27）**：每次调用的 prompt 大小，到运行结束时中位数缩小：MLE-Bench 7 倍，WeatherBench 2 超过 40 倍，ALE-Bench 和 FML-Bench 约 50 倍。
- **Figure 7（p11）ignition test**：两组都从 AIDE47 出发，外层分别用 AIDE47 和 AIDE_human，各 3 个 seed、50 步。最终均值为 0.780 和 0.782，作者自己判定无法下结论。
- **附录 C / Figure 9（p26）**：把 harness 换到其他模型上，增益仍然存在。ALE-Bench 上 gemini 3 flash 配 AIDE85 达到 1858，高于 fable 5 配 AIDE0 的 1796。MLE-Bench 上增益较小。
- **附录 D / Table 3（p26–27）**：被拒绝的提案中，约 1/4 在公开信号上更高，但在私有分数上被拒。很多拒绝的差值（−0.004 到 −0.007）都在噪声范围内。

## 作者自己声明的局限（p10–11, p13–14）
- 噪声会在两层之间累积：一次错误接受的重写会成为 incumbent，可能把后续搜索带偏。
- ignition test 只有 3 个 seed，结论不确定，不能说明 AIDE47 作为自改进者优于 AIDE_human。要得出更强结论，成本过高。
- 发现的 agent 复杂、难以解释，不清楚哪些组件真正起作用、哪些是残留；部署时会有摩擦。
- 主实验只有一次 8 天运行（另有两次复现）。成本和算力是评测这类系统的瓶颈。

## 方法问题与替代解释
- 【推断】主实验的编辑者是固定的人工设计 agent，外加更强的 Opus 4.7。所以主结果严格来说是"强 agent 迭代优化弱 agent 的代码"，加上 incumbent 累积，而不是"系统改进自己的改进能力"。真正检验递归的 ignition test 结果为零差异或不确定。
- 【推断】g 从 0.703 到 0.778 的提升，每一步都是在 99 个提案上取 argmax，存在"赢家诅咒"或多重比较问题。附录 D 也显示很多差值落在噪声范围内。外部基准上的泛化部分缓解了这个担忧，但只用了 AIDE47 和 AIDE85 两个检查点。
- 【推断】WeatherBench 2 的大幅增益（0.26 → 0.80）只有 1 个任务、3 个 seed，AIDE0 和 AIDE_human 的方差很大（±0.2），很可能受个别 seed 主导。
- 【猜测】reward hacking 下降可能部分来自"在 prompt 中提醒模型存在私有测试集"这种提示层面的改动（p10），而不是更深层的搜索行为变化。作者也承认无法定位到具体是哪次重写。

## 与每个 core claim 的关系
- **C1（自主效率编辑：LLM 压缩自身权重）**：不覆盖。不涉及任何权重操作。唯一的"压缩"是 harness 学会压缩 prompt 或上下文（7–50 倍），属于 harness 层的推理成本优化，不是对模型权重做量化或剪枝。
- **C2（LLM 自己产出 LoRA 并应用到自身）**：不覆盖。没有 LoRA，也不训练模型。
- **C3（递归：改后系统成为下一轮的编辑者，两者共同提升）**：部分覆盖，而且是三篇里最接近的。
  - 它在 AI 研究 agent 上实现了多轮"accepted rewrite 成为下一轮被编辑对象"的循环，并在外部基准上验证了泛化。
  - 它明确提出了"改后系统当编辑者"的 ignition test，但结果不确定。
  - 主实验中编辑者是固定的 AIDE_human，所以"编辑能力与被编辑对象共同提升"没有被证实。
  - 被递归改进的对象是 harness 代码，不是模型权重。
  - C3 若限定在"权重层面的递归"，则它没有覆盖；若泛指 RSI 循环，它是强先行工作，必须引用和对比。
- **C4（权重级动作空间）**：不覆盖，而且立场相反。作者明确选择 harness 层作为动作空间（p2），模型在每个循环内都被固定。
  - Related Work（p12）提到两篇"联合优化权重与 harness"的工作：Tiwari et al. 2026（arXiv:2605.12484，"Learning, fast and slow"）和 Kim et al. 2026（WHALE，arXiv:2609.00196）。这两篇可能与 C4 直接相关，建议补查。
