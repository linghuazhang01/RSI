## 研究问题
4-bit PTQ 的损伤分布不均。作者问两件事：(1) 损伤在网络的哪里？(2) 有一小笔额外的比特预算时，应该补到哪里？
作者检验了三个直觉假设：损伤位于任务电路（H1）、位于模型做计算的位置（H2）、可以从权重统计看出来（H3）。每个假设都对应一个便宜的定位器，统一用一个因果“金标准”来检验：把某一层升到 8-bit、其余保持 4-bit，看能收回多少 4→8-bit 的精度差（即该位置精度的边际价值）。

## 方法细节
### 被压缩的模型（p2 §3）
- 9 个开源 base 模型，覆盖 4 个架构家族，规模相差 16 倍：LLaMA-3.2-1B/3B、LLaMA-3-8B；Qwen2.5-0.5B、Qwen3-0.6B/1.7B/8B；Mistral-7B；OpenLLaMA-3B。
- **20B–35B 区间：没有**。最大 8B，受单张 40GB A100（MIG 分区）限制（§6，p4）。也**没有推理模型或长 CoT 模型**。

### 压缩方法与配置
- 定位实验（§4）：per-row RTN 4-bit，作为“最大损伤”探针；逐层或成组升到 8-bit。
- 预算实验（§5）：
  - 全局方案：per-row 改成 group-128 的 RTN；
  - 局部方案：按 protect-one 恢复率排序，把排名靠前的整层升到 8-bit；
  - 两者在等效 bits/weight 相同（+0.146）的条件下比较；
  - 另加 GPTQ/AWQ（llm-compressor 0.6.0.1，W4A16，g128，3 个校准子集种子）和 8-bit 档（RTN8、g128-RTN8、GPTQ8、AWQ8）。
- 等效 bits/weight：per-row RTN 为 4.01，g128 为 4.156，fp16 为 16（附录 F）。
- OpenLLaMA 的中间维度是 8640，不能被 128 整除，所以不参与 g128 实验，预算部分只有 8 个模型。
- 校准集：只说三个定位器用“共同的校准集”，**具体内容未说明**。
- **没有剪枝、蒸馏或恢复训练**。

## 评测设置
- CORE 基准（来自 DCLM，nanochat 风格的评测循环），共 22 个任务，每个任务 200 条样本，固定 seed 1337，**用续写打分（continuation scoring）**，**不做生成，也不做 CoT**。正文提到 few-shot 自排除，但**没给 shot 数**。
- 附录 Table 2 列出的任务（按 5 个数据驱动的簇分组）：
  - 形式/结构类：dyck_languages、lsat_ar、cs_algorithms、operators、repeat_copy_logic
  - 短上下文补全：copa、openbook_qa、lambada、winograd、winogrande
  - 阅读理解：squad、boolq（coqa 在 9 个模型中有 7 个归到这里）
  - 事实检索：jeopardy、bigbench_qa_wikidata
  - 多选：arc_easy、arc_challenge、hellaswag、piqa
  - 另有 language_identification、commonsense_qa 等不稳定归属的任务。
- 指标：CORE 分数。“损伤”定义为 fp16→4-bit 的 CORE 差距；“恢复”定义为占 per-row RTN4→RTN8 差距的百分比。
- 统计检验：partial correlation、TOST 等价检验、混合效应模型、置换检验；对任务做 bootstrap（5000 次）。
- **没有测真实速度或显存**，比特开销只是一阶估计（权重部分，按层计）。

## 关键实验与数字
### (a) 断崖 / 比特数
- 本文没有扫描多个比特数，只比较 4-bit 和 8-bit 两档。
- **8-bit 基本无损**：per-row RTN8 相对 fp16 的平均差距为 −0.001，每个模型都在 ±0.005 以内（Table 7/8，p10–11）；bootstrap 后，8 个模型中有 6 个的残差 CI 包含 0（附录 G）。
- **4-bit per-row RTN 损伤很大**，平均差距 +0.151 CORE（Table 7）。例如 Qwen3-8B 从 0.411 掉到 0.171，g128 后回到 0.359（Table 6，p10）。
- 从 per-row 改成 g128 就能收回一大块损伤，粒度本身就是关键杠杆。

### (b) 哪些能力/任务最受损
- H1（任务电路漂移）：原始相关 r=+0.377（198 个任务-模型对），但它其实是任务类型造成的混杂；同时控制模型和任务类别后降到 +0.054（p=0.46），在 ±0.2 范围内 TOST 等价于 0（Table 3，p7；§4，p3）。也就是说，**电路漂移不能预测哪个任务掉分**；掉分的差异主要来自任务类型和模型本身。
- 本文没有逐任务的掉分排行。

### (c) 量化 vs 剪枝 vs 蒸馏
- 只研究量化。其中一个算法层面的发现：**4-bit 的收益主要来自粒度，而不是算法**。per-row→g128 平均 +0.095 CORE；在此基础上 GPTQ 只再加 +0.020，AWQ 只再加 +0.017（排除 Qwen3-8B 的异常值；Table 7，p10）。到 8-bit 时，各种手段的差别都归零。

### (d) 比特分配 / 哪些层敏感（本文核心）
- **三个便宜定位器都失败了**：
  - H2：激活修补把“计算位置”定在首尾两层 MLP，但把这两层升到 8-bit，在 9 个模型中有 6 个只能收回 ≤13% 的差距。只有 Mistral-7B 例外，收回 55.5%（附录 C，p8）。
  - H3：权重标准差只在 LLaMA 家族里能找到最可恢复的层（都是 L1），在 Mistral、Qwen 上失败（Table 4，p8）。重建误差在 Qwen3-8B 上与恢复率反相关：保护排名前 3 的层只把总重建误差降低约 7%，却几乎收回全部精度（附录 D）。
- **损伤是弥散的**：按 oracle 排序逐层恢复，要收回 50/75/90% 的差距，平均需要恢复 20/49/73% 的层（9/9 个模型；p3；附录 E，Fig. 3，p9）。没有任何单层能贡献超过约 44% 的损伤（附录 E，p8–9）。两层同时恢复的效果约等于两个单层效果之和（比值 0.91–1.10）。
- **Qwen3-8B 是唯一的集中型例外**：排名前 3 的层（L4、L2、L6）恢复 102±4%，单层最好只有 39.7±3%。
- 恢复峰值的位置在家族内相关：LLaMA-3.x 在所有规模上都是 L1，留一法可以预测被留出的规模（3/3）；Mistral 在最后一层；Qwen3 的峰值随规模移动。跨家族无法预测（§4，p3）。
- **全局细粒度胜过局部修复**（Table 1，p4）：在相同的 +0.146 bits/weight 下，g128 全局方案对 8 个模型都更好，领先 21–52 分。例如：
  - Llama-3-8B：78.8 vs 44.7
  - Qwen3-8B：76.6 vs 54.9
  - Mistral-7B：72.9 vs 51.7
  - Qwen3-0.6B：33.4 vs 4.8
  局部方案还是 oracle 挑选的，所以这是对局部方案偏乐观的上界。
- 稳健性：对 7 个弥散型模型，局部方案需要 5.16–6.33 bits/weight 才能追平全局方案，所以比特账要错 7–15 倍才会翻转结论。Qwen3-8B 在 4.206 bits/weight 时局部与全局持平。bootstrap 显示 8 个模型中 8 个满足 P(全局>局部)≥0.95，6 个的 CI 排除了局部方案更好的可能（附录 G，p10–11）。

## 作者自己声明的局限（§6，p4）
- 结论“没有少数几层就能修好”只限于贪心、按恢复率排序、整层粒度的干预；非贪心的层组合和权重级显著性保护没有测试；H3 没有测试 Hessian 敏感度。
- 定位实验用的是 per-row RTN 这种最大损伤探针，在 GPTQ/AWQ/g128 这类损伤更小的情形下结构是否相同，没有测试。
- 规模上限为 ≤8B，更大的模型没测。
- top-k 曲线在同一个评测集上排序和打分，属于 oracle 选择器，不能直接部署；只有 Qwen3-8B 跑了多个种子；小模型的恢复率接近噪声地板；Mistral 和 OpenLLaMA 各只有一个模型。
- 比特账是一阶、按层、只算权重的估计；精确字节数和多比特率失真曲线留待后续。

## 方法问题与替代解释
- 【推断】per-row RTN 4-bit 是很差的基线（比如 Qwen3-8B 掉了 58%），它的损伤可能主要来自少数离群通道使 per-row scale 失效，而 g128 恰好对这一点对症下药。所以“全局胜过局部”的幅度在已经用 g128+GPTQ 的现实起点上可能会小很多，作者也承认这一点未测。
- 【推断】CORE 是续写打分、每任务 200 条，测的是 base 模型的单步选择能力，**不涉及长 CoT 生成**。2504.04823 显示量化损伤会随推理长度和难度放大，所以本文对推理模型和 agent 的外推力有限。
- 【推断】局部方案用整层 8-bit，而全局方案只多 0.146 bit。两者比特账一致，但局部方案在 4→8 的跨度上浪费了比特（升到 5 或 6 bit 可能已经足够），因此比较对局部方案不利。论文用“需要多少 bits 才能追平”的分析部分回应了这一点。
- 【推断】与 2504.02010 的“最后一层 up_proj 关键”在表面上矛盾，但度量和模型不同（R1 蒸馏推理模型 + 3-bit + 单模块 vs base 模型 + 4-bit per-row + 整层），不能直接互相否定。
- 【猜测】Qwen3-8B 的集中性可能与 Qwen3 训练中某些早期层的离群激活有关，论文没有分析。

## 对“~27B 模型自我压缩、压缩后继续当 agent 做下一轮压缩”研究设计的启示
- **选量化还是剪枝/LoRA**：本文只覆盖量化，而且只到 8B。它对设计的直接启示是：如果 agent 要决定把额外的比特放在哪里，**默认应该先提升全局粒度（比如 per-row→g128，或 g128→g64），而不是挑几层升精度**。这在 8/8 个模型上成立，领先 21–52 分。
- **比特安全区**：8-bit（甚至 per-row RTN8）与 fp16 在统计上无法区分；4-bit 的关键是粒度（g128），GPTQ/AWQ 只带来小幅增益。本文没有 3-bit 数据，3-bit 断崖的证据要看 2504.04823 和 2504.02010。
- **定位类启发式不可靠**：用电路、激活修补、权重统计、重建误差来选“关键层”都无法预测保护收益。【推断】如果让 agent 自己设计“基于可解释性信号的混合精度”，它很可能被这些便宜信号误导；每个候选方案都需要用真实评测做因果验证（升精度 → 测精度）。这既增加每轮的评测开销，也意味着评测集必须独立于 agent 用来做选择的数据，否则就会出现论文所说的 oracle 偏差。
- **评测**：本文的 CORE 22 任务覆盖了知识、阅读、常识和形式推理，适合做“广谱回归测试”，但不能代替长 CoT 和 agent 任务。【推断】自我压缩研究里可以把 CORE 类续写打分作为便宜的第一道筛选，再用 AIME、LiveCodeBench、agent 基准做第二道筛选。
- **家族依赖**：最可恢复层的位置只在家族内部稳定，Qwen3 的峰值还随规模移动。【推断】对 27B 模型（尤其是 Qwen3 或 Gemma 系）不能套用别的规模的层敏感度结论，需要重新扫描。
