## 元信息

- 作者：Weizhong Huang, Yuxin Zhang, Xiawu Zheng, Fei Chao, Rongrong Ji（厦门大学）
- 日期/版本：arXiv v1，2025-02-20，Preprint

## 研究问题
后训练结构化剪枝（无需重训练）在 LLM 上精度掉得厉害，作者认为主因是逐层剪枝率设置不当（均匀剪枝或 OWL 这类手工启发式）。目标：自动搜索满足平均剪枝率约束的逐层剪枝率向量 p=(p1..pn)，使剪枝后模型精度最高（式 1，p.4）。

## 方法细节
- 框架：LLM 驱动的进化搜索（Algorithm 1，p.6；Figure 1，p.2）。
  1. 种群初始化：用 prompt（Figure 2，p.5）让 LLM 一次生成 K 个逐层剪枝率配置（每层 0–1 的小数，平均值等于目标剪枝率 β）。
  2. 适应度：按配置确定每层剪多少，层内用 Wanda-sp 指标决定剪哪些神经元；在 WikiText-2 上测困惑度作为 fitness（越低越好）（p.5）。
  3. 选择/交叉/变异：把当前种群和 fitness 写进 prompt（Figure 3，p.5），让 LLM 用高层自然语言指令自行完成父代选择、交叉、变异，产出新配置；Top-K 保留，迭代 N 次。
- 超参：K=30, M=10 变异, S=10 交叉, N=20 迭代（p.7）。
- **谁在剪谁**：做决策的 LLM 是 OpenAI GPT-4o（API，闭源，p.7）；被剪枝的是 LLaMA-1/2/3/3.1、Vicuna（7B–70B，均为预训练/指令模型，p.6）。两者**不是同一模型、不是同一 checkpoint**。论文的 "self" 指的是"LLM 这一类模型对自身冗余有先验知识，由 LLM 来剪 LLM"，属类别层面的 self，并非单个模型剪自己。消融里也只换了决策 LLM（GPT-3.5/GPT-4/GPT-4o，Table 4，p.9），从未让被剪模型（如 LLaMA）自己当决策者。
- 修改形式：LLM 只输出数值向量（逐层剪枝率）；具体剪哪些权重由固定的 Wanda-sp 规则执行，LLM 不写代码、不发明新指标。
- 是否多轮递归：只在搜索算法内多轮迭代（进化代数），决策者始终是固定的 GPT-4o；剪枝后的模型不会成为下一轮决策者。无递归自改进。
- 是否测真实加速：是。Table 7（p.9）用 vLLM 在 A100 80GB 上测 tokens/s、显存、参数量，属于真实推理吞吐测量（结构化剪枝带来稠密小矩阵）。
- 附带：Table 6（p.9）对剪枝后的 LLaMA-2-7B 做 LoRA（r=8，Alpaca-GPT4 10K 子集）恢复精度——LoRA 是人工设定的标准流程，不是模型自己写的。

## 作者自己声明的局限（p.9–10）
1. 尚未实现 LLM 压缩的完全自动化：只搜索了逐层剪枝率，离"LLM 自己完成压缩任务"还有距离。
2. 后训练结构化剪枝精度仍低于原模型，高剪枝率下差距明显；未来考虑高效微调恢复。

## 方法问题与替代解释
- 【推断】适应度用 WikiText-2 PPL，而 Table 1 汇报的也是 WikiText-2 PPL，存在在测试集上搜索的问题（search-on-test），PPL 优势可能部分来自过拟合评测集；零样本任务（Table 2）不受此影响，较可信。
- 【推断】"self" 名不副实：决策者 GPT-4o 与被剪模型完全不同，所谓"LLM 对自身冗余的先验"没有被检验——没有对照实验让被剪模型本身做决策，也没有对比非 LLM 的标准进化算法（同样评估预算下的随机/CMA-ES/普通 GA）。消融 "w/o mutation/crossover" 只是去掉算子，而非替换为传统算子，因此无法区分"LLM 的先验"与"任何搜索都有效"。
- 【推断】搜索成本（每次评估要剪+测 PPL，20 代×~50 个体的总 GPU 时、API 调用量）没有报告，"Efficient"缺乏量化。
- 【猜测】LLM 生成"平均值严格等于 β、5 位小数"的 32/80 维向量，实际很可能需要后处理归一化，论文未说明约束如何保证。
- 结果为单次运行，无方差/种子报告。

## 与每个 core claim 的关系
- C1（模型自己决定并执行对自身权重的压缩，面向推理效率）：**部分相关但未覆盖**。做了"LLM 决定压缩配置、面向推理加速且实测吞吐"，但决策者（GPT-4o）≠ 被压缩者（LLaMA 等），不是对**自身**权重的压缩；执行由固定的 Wanda-sp 代码完成，LLM 只输出逐层比例。标题里的 "Self-Pruning" 是类别层面的说法。
- C2（模型自己生成 LoRA 并装到自己身上）：**未覆盖**。仅有人工设定的 LoRA 微调恢复精度（Table 6），数据/超参均由人选定。
- C3（被编辑后的模型成为下一轮编辑者，递归共同提升）：**未覆盖**。多轮仅指进化代数，决策者固定，剪枝后模型从不参与决策。
- C4（作用于权重而非 prompt/代码）：**部分覆盖**。动作结果确实作用于权重（结构化剪枝），但 LLM 的动作空间仅是剪枝率向量这一低维超参；不涉及 adapter、合并、量化。
