## 研究问题
- 在不可验证的开放研究任务上做递归自我改进（RSI）时，最强的模型本身就是最好的执行者、优化者和评估者。但单个实例做自我批评会强化同一先验中的错误（p2）。
- 两个假设（p2）：(1) 优化多智能体之间的信息流（传什么、传给谁、什么时候传）可以产生更高质量的自监督数据；(2) 联合学习 orchestrator 和有界子任务执行的轨迹，比学习单智能体的长轨迹更高效。

## 方法细节
- **模型**：Qwen3.6-27B（预训练加指令/推理模型），推理时用 FP8 版本，通过 vLLM 和 qwen-code 0.20.0 作为编码 agent（p5, p16）。
- **同一模型承担三个角色**：L_agent = L_eval = L_opt = L(g)（p4，Algorithm 1）。
- **内环，Algorithm 2（p4–p5，p15）**：对每个训练任务，模型提出一个多智能体 workflow，即追加在任务 prompt 后的文本规范 w_t = {h_t, (role, instruction, output contract)_j}（h 表示子 agent 的调用顺序），然后执行并产生 workspace。模型自己把它与当前最优 workflow 的 workspace 做两两比较并给出反馈，优化器据此提出下一个 workflow（相当于 elite size 为 1 的进化）。优化 prompt 偏重 contract 和 hop。迭代 10–11 次。
- **外环，Algorithm 3（p5，p15）**：在最优 workflow 下对每个任务独立执行 M=18 次。模型自评两两锦标赛，用 Bradley–Terry 排序，取 top-15 进训练集、第 16 名进验证集。去掉 workflow prompt（只留裸任务），然后在 orchestrator、子 agent 和辅助对话窗口上做 assistant-only 的 SFT。
- **训练细节（p6，p16–p17）**：119 条轨迹，2,435 个窗口（282 个 orchestrator、2,054 个子 agent、99 个辅助），17.2M 监督 token。窗口最长 49,152，前文上下文最多 8,192 且被 mask。子 agent 与 orchestrator 的采样比例为 2:1。在 BF16 父模型上新建 **LoRA rank 64，α 128**，lr 3e-5，训练 1,624 步，按验证损失选 step 1200。用 6 张 H100 约 19 小时。**训好的 adapter 合并进父模型，再量化为 block-FP8 用于推理**（p17）。第二轮在合并后的 L(1) 上新建 LoRA，用相同配方训练（p17）。
- **谁修改谁的权重**：可以说是"同一模型通过自产数据修改自己"。数据（轨迹）由模型自己生成，筛选（BT 排序）也由模型自己完成。但 **SFT 的配方、超参、LoRA 配置和训练代码都由人类固定**，模型不决定是否训练、怎么训练，也不写训练代码。
- **修改形式**：自产数据，经过固定的 SFT 加 LoRA，再合并。没有 RL。
- **压缩/量化/剪枝/推理效率**：在方法层面不是目标。FP8 服务和合并后量化成 block-FP8 是人类定下的部署步骤，论文没有讨论它对能力的影响，也不由模型决定。论文报告的"每输出 token 得分"效率（Fig. 2）指的是 agent 输出 token 的效率，不是模型权重或推理计算的压缩。
- **是否多轮递归**：**是，做了 2 轮**，L(0) → L(1) → L(2)。L(1) 在下一轮同时担任执行者、workflow 优化者和评估者（p4，p17）。

## 关键实验与数字
- **Fig. 3b（p6）/ Table 7（p20）公开 benchmark**：ScienceAgentBench 28.8 → 30.4 → **31.7**；MLR-Bench 1.58 → 1.80 → **2.40**；AstaBench 0.053 → 0.055 → 0.067；DSBench 0.473 → 0.465 → 0.482；**Terminal-Bench 2.0 37.5 → 35.3 → 35.2（下降）；SWE-bench Verified 62.6 → 61.8 → 61.1（下降）**。
- Fig. 3b（p6）合成任务胜率：test 集上 L(1) 对 L(0) 为 **53.9%**，L(2) 对 L(0) 为 **69.9%**，L(2) 对 L(1) 为 60.8%；train 集上分别为 65.6% / 82.5% / 68.1%。
- **Fig. 3c（p6）**：自评估器与外部强模型判断的一致率，L(0) 0.73、L(1) 0.91、**L(2) 0.93**。
- Fig. 2（p3）：在 4 个研究 benchmark 上，L(2) 相对 L(0) 的每输出 token 得分为 1.2–1.6×（MLR 1.60×、DSBench 1.35×、AstaBench 1.28×、SAB 1.20×；Terminal-Bench 0.96×、SWE 0.94×）。
- Table 1（p7）：用 L(0) 执行时，L(1) 产出的 workflow 对比 L(0) 产出的 workflow 胜率为 0.64。
- **Fig. 6 / Table 8（p8，p22）**：M+（119 条多智能体轨迹，28.82M 处理 token）对基座胜率 **68.3%**；S++（290 条单智能体轨迹，42M token）为 64.0%。
- **Table 2a（p10）**：裸 prompt 下的委派率，L(0) 1/110、L(1) 48/110、L(2) 87/110；代码交接率 1/110 → 42/110 → 83/110。
- Fig. 7（p9）：把优化器换成 GPT-5.5 后能更早找到成功的 workflow；全用 L(0) 时最终 12 个任务中 11 个获得一致胜。作者据此认为瓶颈在优化器，而不在评估器。
- **p21 统计检验**：MLR-Bench 上 L(2) 对 L(0) 的 Welch p=0.0053，但按 12 个任务做配对符号检验 p=0.2266。交付论文数从 31/60 增加到 50/60，而**已交付论文的平均分从 3.07 降到 2.88**。180 次 MLR-Bench 执行**全都没有调用委派工具**。

## 作者自己声明的局限
- 正文没有单独的 Limitations 节。结论（p10）说每轮提升的速度有待加快。附录中有大量自我限定：
  - 公开 benchmark 上的提升主要伴随完成率提升，并非同一任务集上质量提高；符号检验不显著，不能说明跨任务一致提升（p21）。
  - MLR-Bench 上没有发生委派，所以无法证明委派是迁移的机制（p21）。
  - 对照实验的采样器、数据和 checkpoint 选择不同，只能有限地归因到 teacher 组成（p22）；8.3/6.3 个百分点是相对插值线的差，不是直接测得（p23）。
  - 同一 workflow 和种子的两次执行可能一次全胜、一次全败（Table 11，p25）；编辑幅度与效果的相关很弱（|ρ| ≤ 0.12，Table 10）。
  - 信息论统计只是描述性的文本统计，不是因果检验（p26）。
  - 基座本来就具备协调能力（generic directive 下委派 110/110），SFT 只是让模型在裸 prompt 下更常使用这种能力（p27–p28）。
  - 有一个 revision 修改了物理仿真的含义，却仍获得 5/6 好评（p29）。
  - 递归没有理论保证（p38）。

## 方法问题与替代解释
- 【推断】递归只做了 2 轮，训练任务只有 8 个，样本太少，无法判断能否持续自举。L(1) 在 test 上对 L(0) 的胜率只有 53.9%，接近随机。
- 【推断】Terminal-Bench 和 SWE-bench 两个通用编码 benchmark 都单调下降，说明可能存在领域窄化或遗忘，这正是递归改权重时的风险，论文没有处理。
- 【推断】评估器准确率从 0.73 升到 0.93，可能部分是因为训练后的模型更接近外部 judge（GPT-5.5 / Opus 4.8）的偏好风格，不一定代表评估能力本身提高。外部 judge 也是 LLM，存在偏好长输出、偏好"完成交付"的偏差。
- 【推断】"学习效率"的比较对象是插值线，数据量、任务覆盖和采样器都不匹配（作者自己承认，p22）。
- 【推断】自监督闭环中的选择信号（BT 排序）来自同一模型，筛选可能强化同一先验。论文用外部 judge 证明了总体提升，但没有分析被选中轨迹中的错误。p28 给出的一个例子就是：监督数据里包含错误的验证。
- 文中有小的不一致：p6 正文写 SAB 从 28.7% 到 31.8%，Table 7 中是 28.8 到 31.7。

## 与每个 core claim 的关系
- **C1（自主压缩自身权重以提升推理效率）**：**没有覆盖**。FP8 推理和合并后量化成 block-FP8 是人类固定的工程步骤，不由模型决定，也没有评估。"score per output token"指 agent 输出长度的效率，不是权重压缩。
- **C2（模型自产下游任务 LoRA 并装到自己身上）**：**部分覆盖**。同一模型生成训练数据（多智能体轨迹）并自评筛选，然后用 LoRA SFT 合并回自身。这接近"self-authored data → LoRA → apply to self"。但：(a) 训练配方、超参和训练代码是人类固定的，模型不决定也不写；(b) 目标是通用的研究型 agent 能力，不是针对某个具体下游任务的专用 adapter；(c) adapter 每轮合并进主干，没有保留为可插拔的任务 adapter；(d) 不直接生成权重。
- **C3（递归循环，编辑者和被编辑模型共同进步）**：**基本覆盖了这个结构**。L(g+1) 在下一轮担任执行者、workflow 优化者和评估者，做了 2 轮，并测量了三个角色都在提升（Fig. 3a/3c，Table 1）。但这里被改进的"编辑能力"是 **workflow（prompt）优化能力和评估能力**，不是"编辑权重"的能力。模型并不编辑自己的权重，权重更新是固定流水线。
- **C4（权重层面的动作空间）**：**没有覆盖**。模型的可选动作空间是 prompt 层面的多智能体 workflow；权重只通过固定的 SFT 被动更新，不存在由模型选择的压缩、adapter 或 merging 动作。作者在 p15 也明确写了：workflow 搜索改的是 prompt，SFT 改的是权重。
