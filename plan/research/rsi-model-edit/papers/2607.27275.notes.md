## 研究问题
- RQ1：4-bit 权重量化"几乎无损"的说法，在多轮工具调用 agent 上还成立吗？benchmark 的最终分数能否检测到损伤？
- RQ2：为什么每一步的失败成倍增加，最终分数却保持平稳？
- RQ3：为什么有些模型受损、有些不受损（是规模、架构，还是全精度下已有的失败倾向）？

## 方法细节
### 模型（**全部或大部分处于 20B–35B 区间，与 27B 设计高度相关**）
- Gemma-4-31B（dense）
- Gemma-4-26B-A4B（MoE，激活参数 4B）
- Qwen-3.6-27B（dense）
- Qwen-3.6-35B-A3B（MoE，激活参数 3B）
- 扩展：Qwen-3.5-27B（dense）、Qwen-3.5-9B（dense）
- 主网格为 2 个家族 × {dense, MoE} × 2 个领域 = 8 个单元格，另加 2 个 Qwen-3.5 telecom 单元格，共 10 个单元格（p1、p3）。

### 量化配置（p3；Table 6，p11）
- 三个精度：BF16（参考）、FP8、INT4。全部只量化权重；激活和 KV cache 在所有设置下都是 16-bit。
- FP8：A100 没有原生 FP8 计算，vLLM 实际以 Marlin kernel 运行 W8A16（只量化权重）。Gemma 使用 per-channel 对称量化；Qwen 使用 E4M3、128×128 block 级 scale。
- INT4：AWQ。Gemma 为 AWQ-style、**g=32**（31B 非对称、26B-A4B 对称，compressed-tensors 格式，MSE observer，视觉塔不量化）；Qwen 为带零点的标准 AWQ、**g=128**。Qwen-3.5-9B 使用社区发布的 checkpoint。
- 服务：vLLM，A100，KV cache 16-bit。

### Agent 协议
- 用户模拟器固定为 Qwen-3.6-27B BF16，只改变 agent 的精度。
- num_trials=4，每个领域 114 题，所以每个单元格 456 次模拟；max_errors=10，max_steps=300；agent 使用贪心解码（温度 0），用户模拟器温度 0.7。
- 修复组（repair arm）：遇到工具调用失败时，提示 agent 根据错误信息重新发出修正后的调用，最多 3 次；validator 在调用到达环境之前检查工具名和参数 schema（Fig. 8c，p13）。修复组的用户模拟器温度为 0.6，这是一个干扰变量。
- 反事实 error budget：把 max_errors 当作可调参数 K，S(K) 定义为"失败调用不超过 K 次且最终成功"的 episode 比例（p4）。这是基于已有轨迹的保守投影，没有真正重跑。

## 评测设置
- **τ²-bench**（Barres et al. 2026）的两个领域：
  - retail：单控制（只有 agent 操作环境），114 题，agent 轮数中位数约 11；主要失败通道为**实体/参数错误**（例如 User not found）。
  - telecom：双控制（用户也在自己设备上执行操作），114 题，轮数中位数约 16；主要失败通道为**工具名幻觉**（调用不在 agent 工具列表中的工具，报错 Tool 'X' not found）。
- 指标：
  - 最终分数：τ²-bench 二值任务奖励的均值（%）。
  - 过程指标：通道率（channel rate），即触发某个失败通道的 agent 工具调用占比；每 episode 失败调用数；预算耗尽次数；单次失败后的恢复率；轨迹长度；按工具名统计的幻觉分布及 BF16/INT4 相关性；"新事件"比例。
  - S(K) 曲线。
- 统计：按 114 个任务做 cluster bootstrap（5000 次重采样，同一任务的 4 个 trial 一起抽）；按任务配对比较；TOST 等价性检验（±7.5 分）；正文说做了多重比较校正，但没有写明具体方法。用一次 456-episode 重复运行估计运行间噪声底约 1.5 分；修复组的重复运行带为 ±2.0 分。

## 关键实验与数字
### (a) 工具调用 / agent 行为在哪个比特数出现断崖，什么类型的决策最脆弱
- **断崖在 8→4 bit 之间**：FP8 下没有任何单元格的分数显著下降，也没有任何通道率显著变化（Table 4，p10；Fig. 5，p9）。Gemma-4-31B telecom 的工具名幻觉率为 BF16 19.5%、FP8 17.0%、INT4 38.3%（Table 5a，p11）。唯一的例外趋势是 Gemma-4-26B-A4B retail，其实体错误在 FP8 时已经出现与 INT4 同等幅度的上升（+1.40，不显著），所以"安全精度边界与模型×通道组合有关"。
- **受损单元格**（Table 1，p4）：10 个单元格中只有 2 个通道率显著上升。
  - Gemma-4-31B telecom：19.51% → 38.26%（+18.75 分，CI [14.0, 23.6]）；
  - Qwen-3.5-27B telecom：0.26% → 1.21%（+0.95，CI [0.5, 1.5]）。
  - Qwen-3.6-27B / 35B-A3B 在所有单元格都没有被放大（telecom 0.38%→0.47%，9 个事件）。
- **最脆弱的决策类型是 agent/用户角色边界上的工具名选择**：24 个幻觉工具名中有 23 个是用户侧的真实设备工具（如 toggle_airplane_mode、can_send_mms），覆盖 99.8% 的 BF16 事件和 100% 的 INT4 事件（p5；Table 5，p11）。也就是说，agent 去调用只有用户才能执行的动作。
- **量化放大的是已有的失败集合，不会制造新失败**（Fig. 2，p5）：BF16 与 INT4 的按工具名频率分布相关系数为 0.97；1,646 个 INT4 幻觉事件中只有 3 个（0.18%）是 BF16 没出现过的工具；事件量 649 → 1,646（2.5×）。按任务看，增量是近似均匀的 +17.6 分，斜率 −0.06，与基线无关。
- 不同单元格的放大倍数从约 1× 到 4.6×；Gemma-4 MoE telecom 的基线失败率同样高（19.3%），但只放大了 1.05×。所以"有既存失败倾向"是受损的必要条件，不是充分条件（p2、p7）。
- **位置检验**：INT4/BF16 比值在每个轮次分箱内都保持在 1.3×–2.0×，在最长上下文四分位反而下降（Fig. 6，p9）。这否定了"量化会随上下文变长逐步侵蚀指令遵循"的解释。

### (b) 聚合分数为什么会掩盖损伤，推荐用什么指标
- **最终分数看不出变化**：10 个单元格的 95% 区间全部包含 0；7 个单元格在 ±7.5 分内 TOST 等价；最大的配对下降是 2.0 分（Qwen-3.6 MoE telecom，p=.049），既通不过多重比较校正，也没有超过噪声底。最高损伤单元格按任务配对：INT4 更差 33 题、更好 26 题、持平 55 题（p4）。
- **掩盖机制是 error budget**（Table 2，p6）：Gemma-4-31B telecom 每个 episode 的失败调用从 1.45 增加到 3.64（2.5×）；失败 ≥5 次的 episode 从 51 增加到 173（Fig. 4）；预算耗尽从 5 次增加到 46 次；每 episode 工具调用从 7.29 增加到 9.43；**单次失败后的恢复率在两个精度下都是 55%**。也就是说，量化并没有削弱恢复能力，只是制造了更多需要恢复的失败，而 10 次错误的预算把它们吸收了。
- **收紧预算会重新暴露差距**（Fig. 3，p6）：BF16−INT4 差距在 K=10 时为 1.3 分、K=5 时为 7.5 分、K=2 时为 16.7 分（约 13×）；同样的收紧让 BF16 损失 10 分、INT4 损失 25 分。Qwen-3.6-27B 作为负对照，在任何 K 下都没有差距。
- **可证伪的预测得到验证**：收紧预算后，只有新增了错误量的单元格差距变大（Gemma-4 dense telecom 扩大 15.4 分），其余单元格变化不超过 0.2 分（p6）。注意这一检验的正例组只有 1 个单元格。
- **推荐指标**：与任务奖励一起报告按通道划分的错误率，以及 S(K) 曲线（成功率随 error budget 的变化），两者都来自 benchmark 已经收集的日志（Discussion，p7）。量化前测一次全精度下的通道错误率，可以作为一个便宜的单向风险筛查。
- **修复实验**（Table 3，p10）：反思式修复只在受损单元格 Gemma-4-31B INT4 上显著，+5.9 分（CI [+1.1, +10.8]，p=.017），达到 71.3%，高于未修复的 BF16（66.7%）；工具名幻觉事件从 1,646 降到 82。其他单元格的区间都包含 0；精度×修复的交互效应本身不显著（+3.7，CI [−3.2, +10.7]）。

## 作者自己声明的局限（附录 B，p9）
1. 只有两个家族加两个 Qwen checkpoint，支持的是"开/关"式的门控结论，拟合不出连续曲线。
2. 预算掩盖是基于已有轨迹的投影（保守估计），没有在收紧的预算下实际重跑；logit-margin 解释是间接的，因为日志里没有 token log-prob。
3. 两个家族的 INT4 配方不同（g=32 vs g=128），checkpoint 与配方部分混淆；缺少同一配方重新量化的对照。
4. 只有一个 benchmark、两个领域、只量化权重、A100、16-bit KV cache、固定全精度用户模拟器，修复实验只在 telecom 上做。低比特 KV cache、激活 FP8、其他 benchmark、压缩后的用户模拟器都没有测试。

## 方法问题与替代解释
- 【推断】正例只有 1 个强受损单元格（Gemma-4-31B telecom），加上 1 个微弱的 Qwen-3.5-27B。"放大既有失败集合"和"预算掩盖"的主要证据都来自同一个单元格，外部有效性有限。
- 【推断】Qwen-3.6-27B dense 与用户模拟器是同一个基座（作者说 MoE 单元格行为相同，所以不影响结论）。但"同源用户"可能让对话更顺畅，从而降低 agent 的错误率，这会影响 Qwen 家族"不受损"的结论。
- 【推断】只做了一次重复运行就估计噪声底（1.5 分）；修复组的用户温度不同（0.6 vs 0.7），交互效应也不显著，所以修复"只在受损处起作用"属于跨组模式论证，不是严格的因果证据。
- 【猜测】Gemma 的 INT4 是 g=32、更细粒度、理论上更准的配方，却被放大，这说明损伤可能与模型本身的 margin 分布有关，而非配方。但这也可能来自 Gemma 的 compressed-tensors/MSE observer 实现细节，作者没有做同配方对照。
- 【推断】logit-margin 解释（零均值噪声翻转薄 margin）与 2608.06564 的发现有冲突：后者认为量化是乘法收缩加定向偏移，并非零均值加性噪声（2608.06564 A.11 明确说"we agree on where and correct how"）。本文对"为什么只放大已有失败"的解释，在机制层面可能不准确。
- 【推断】"恢复率 55% 不变"是在至少失败一次的 episode 中统计的，但 INT4 失败的 episode 更多，构成不同，可能存在选择效应。

## 对"约 27B 模型自己压缩自己（多轮递归）"研究设计的启示
1. **比特数安全区（直接证据来自 26B–35B 模型）**：
   - W8A16（FP8 只量化权重）在所有 10 个单元格中都是安全的，可以作为递归压缩的"保守档"。
   - INT4 AWQ（g=32/128）在最终分数上看似安全，但过程损伤取决于模型：Qwen-3.6-27B 不受损，Gemma-4-31B 的工具名幻觉翻倍，Qwen-3.5-27B 有小幅但显著的放大。所以**4-bit 对 27B 模型是"可能安全、必须逐模型验证"的区间**。
   - 作者建议：量化前先在目标领域测全精度下的按通道错误率。接近 0（如 Qwen-3.6 的 0.38%）提示 4-bit 可能安全；明显偏高则提示风险，但无法确定放大倍数。
2. **评测应包含的 agent/工具调用数据集与指标**：
   - τ²-bench retail（单控制，实体/参数错误通道）和 telecom（双控制，工具名幻觉通道），每个单元格 456 个 episode。
   - 必须报告：按通道的错误率、每 episode 失败调用数、预算耗尽次数、恢复率、S(K) 曲线（至少给出 K=2/5/10），不能只报告任务成功率。
   - 用 cluster bootstrap（按任务聚类）加 TOST，并估计运行间噪声底（vLLM 非确定性，约 1.5 分）。
3. **递归场景的特殊风险**：
   - 【推断】论文证据表明，量化放大的是模型在全精度下已经存在的失败通道。在递归自压缩中，如果第 k 轮的 agent（已压缩）在执行压缩工具链时有某个既存失败通道（例如调用不存在的工具、传错参数），这个通道可能逐轮被放大，而带重试的 agent 框架会把它掩盖掉。
   - 【推断】自压缩 agent 的执行环境如果允许多次重试（类似 max_errors=10），最终"压缩成功与否"的结果指标会掩盖 agent 能力的退化。建议在递归协议中把每轮 agent 的失败调用数和恢复率作为一等指标记录，并在严格的低预算（K=2）下复评。
   - 论文证据支持一种低成本缓解：在 validator 中检查工具名和 schema，失败时把工具清单重新注入上下文（反思式修复），能把工具名幻觉降低约 20 倍。约束解码（把工具名字段限制在工具清单内）是作者建议、但未测试的更强方案。
   - 【推断】本文的用户模拟器固定为全精度，相当于一个"外部锚点"。在自压缩设计中，评测器/环境模拟器不应随被压缩模型一起被压缩，否则测量本身会漂移（作者把"压缩后的用户模拟器"列为未测试的开放问题）。
