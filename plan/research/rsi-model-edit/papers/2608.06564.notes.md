## 研究问题
1. 低比特后训练量化（PTQ）改变模型的哪些"决策"（例如要不要调用工具、选哪个工具、拒答还是遵从）？不同类型的决策受损程度一样吗？
2. 量化前后的决策 margin（两个候选首 token 的 logit 差）之间是什么函数关系？是"加性噪声"还是"按比例收缩加偏移"？
3. 能否只用一半样本拟合参数，就预测另一半样本的翻转率（flip rate）？

## 方法细节
### 测量工具（decision margin）
- 每个样本 = 一个 prompt + 两个候选首 token t1、t2；margin m = logit(t1) − logit(t2)，量化后为 m′；m 与 m′ 符号相反即为一次 flip（p3，式 1）。
- 对大多数任务，t1 是正确答案的首 token，t2 是全精度下得分最高的其他选项；whether-to-call 比较"开启工具调用的 token"和文本开头 token "I"；拒答任务比较拒绝与遵从（p3）。
- 核心规律（作者称为 "the law"，式 2，p4）：m′ = c·m + b + ε，ε~N(0,σ²)。c 是"存活比例"（surviving fraction），b 是同一类决策共享的偏移，σ 是残差。
- 翻转预测（式 3，p8）：P(flip|m) = Φ(−(c·m+b)·sign(m)/σ)。

### 模型
- 16 个模型、8 个家族：Qwen3 0.6B/1.7B/32B 和 Qwen3-4B-Instruct-2507；Qwen3.5 2B/4B/9B；Qwen2.5-Instruct 1.5B/7B/14B；Granite-3.3-8B；Gemma-3-4B；Gemma-4-E4B；Llama-3.1-8B；Hermes-3-Llama-3.2-3B；Phi-4-mini（附录 A.6，p18）。
- 规模 0.6B–32B。**20B–35B 区间只有 Qwen3-32B 一个**，而且它主要出现在拒答结果里（3-bit RTN 拒答损失为 0，p20），工具调用的 32B 细粒度数据在正文中没有单独展开。主力示例模型是 Qwen3-4B。
- 另有 4 个 base 模型对照（Qwen3.5-4B-Base、Qwen3-1.7B-Base、Qwen2.5-7B-Base、Qwen2.5-1.5B-Base），以及只在激活轴上测的 Qwen3-8B；视觉部分使用 Qwen3-VL 2B/4B/8B（p18–19）。

### 量化配置（p3、p17–18）
- 只量化 decoder block 内的线性层；embedding 和输出头保持全精度（所以名义"4-bit"的有效比特数高于 4）。量化器覆盖参数比例：Qwen3-1.7B 81.9%、Qwen3-4B 90.3%、Granite-3.3-8B 97.5%（A.7，p19）。
- RTN（round-to-nearest）：group size 64，原地量化；16 个模型都做 4/3/2 bit；5 个模型额外做 8/6/5 bit。
- Activation-aware scaling：作者**自己实现的原型**，"not AWQ"（A.14，p25），4/3/2 bit，每个测试集用 48 个自身样本做校准，这些样本不参与打分。
- GPTQ：用 AutoRound 校准并导出，4/3/2 bit。校准集是自建的：约 60% 通用文本（bartowski calibration_datav3）+ 约 40% 工具对话（ToolACE、hermes-function-calling-v1，实际用了 61 条对话，其中只有 13–18 条达到 AutoRound 要求的 1024 token；Table 5，p23）。
- GGUF（llama.cpp）：q8_0、q4_k_m、iq3_xxs、iq2_m，使用 imatrix，margin 与同一模型的 f16 转换版对比。
- 激活量化：A16 到 A3，per-token min–max，有/无 block-diagonal Hadamard 旋转；KV cache 量化有对称和非对称两种 per-token 方案（p7、p24–25）。

## 关键实验与数字
### (a) 工具调用在哪个比特数出现断崖，哪类决策最脆弱
- **乘法律成立**：Qwen3-4B 的 whether-to-call（RTN）拟合 c 在 4/3/2 bit 分别是 0.83 / 0.13 / 0.00，160 个样本中翻转数分别为 10、93、88（Fig. 2，p4）。主矩阵中 c 的中位数为 4-bit 0.86、3-bit 0.29、2-bit 0.00（p4）。
- **3-bit 下各类决策的对比**（Table 1，p5，各列是 c 中位数 / flip 中位数 %）：
  - Whether to call：RTN 0.21/47，activation-aware 0.30/40，GPTQ 0.55/21，GGUF iq3_xxs 0.71/10
  - Which tool（BFCL）：0.25/11，0.51/4，0.59/2，0.70/0
  - Which tool（MetaTool）：0.24/16 … GGUF 0.76/5
  - Argument fill（作者自写题）：四个量化器下 flip 都是 0；BFCL 版 RTN 下为 4%
  - Forced-choice 拒答：0.27/31（RTN）；MMLU 0.19/36；BBQ 0.26/40
- **whether-to-call 先于 which-tool 崩塌**：在 16 个模型 × 4 个量化器 = 64 组 3-bit 运行中，作者自写的 which-tool 题一次都没有翻转，whether-to-call 的翻转率中位数为 32%（§4.1，p5；Fig. 8，p32）。到 2 bit 时，which-tool 在 RTN 和 activation-aware 下也会失效。
- **崩塌方向主要是"不再调用"**：在 97 个未饱和条件中，65 个偏向不调用（p6）；Qwen3-4B 3-bit RTN 下应调用样本翻转 96.3%，不应调用样本翻转 20.0%（Table 7，p29）。但按模型统计时方向性不显著：17 个模型中 10 个偏向不调用、6 个相反，p=0.63（A.18，p32）。
- **外部 BFCL 400 题、实际生成**（Table 11，p34）：3-bit RTN 下 Gemma-3-4B 调用丢失 0.87、名字丢失 0.32；Qwen2.5-7B 为 0.57 vs 0.12；Qwen3-4B 为 0.75 vs 0.55。五个模型等权平均 gap 为 +20.2 个百分点，95% 下界 +17.1（p6）。另有两个反例：Hermes-3 是名字先丢，Qwen3-1.7B 两者同时丢。**两个校准过的 GPTQ 运行都没有达到预先登记的标准**（Qwen2.5-7B 0.18 vs 0.02；Qwen3-4B 0.00 vs 0.01）。
- **崩塌机制是对调用 token 的定向惩罚**：3-bit 时调用 token 在全词表 logit 变化中处于第 0.0、0.3、0.5 百分位（A.15，p26）。
- **拒答比工具调用晚一个比特崩溃**：4-bit 时 4B 及以上的当代 instruct 模型保留拒答行为；3-bit forced choice 下有 4/16 个模型丢失大部分拒答（Qwen3-0.6B 100%、Gemma-3-4B 98%、Qwen3-1.7B 93%、Qwen3.5-2B 83%）；Qwen3-32B 和 Qwen2.5-14B 损失为 0（A.8，p20）。同一系列内，Qwen3 的 1.7B/4B/32B 在 3-bit 下损失分别为 0.93/0.13/0.00。
- **激活量化是第二条、更危险的轴**：A8 基本无代价；A4 不管权重精度如何都会毁掉 margin（Fig. 5，p15）。W8A4 下只量化 KV cache 时翻转 3–18%，量化线性层输入时翻转 44–84%（p7）。Hadamard 旋转能把崩溃点下移约 2.8–3 bit，但不能消除崩溃（A.13，p23–24）。
- **KV cache**：W4 + 全精度 cache 时 c 为 0.83–1.03；全精度权重 + 4-bit cache 时 c 为 0.57–0.81。低于 8 bit 的 cache 宽度没有一个对所有模型都安全；对称与非对称方案在 4/3 bit 时 c 最多相差 0.536（A.14，p24–25）。
- **修复手段**：不需要标签的修复方法都比不上"多给 1 bit"。多 1 bit 能把严重受损条件的翻转率降 0.330；带 oracle 标签的逐样本偏移校正能降 0.282（A.10，p21）。对所有 logit 做同一个仿射变换（温度缩放、全局 bias）在代数上不能改变任何翻转（p7）。
- **困惑度看不出该保护哪些层**：在 Qwen3-VL-4B 上逐段（4 个 block 一段）量化到 3 bit，blocks 16–19 让调用率从 .910 降到 .450，困惑度却只有 1.01×；blocks 0–3 的困惑度最高（1.21×），对调用的伤害反而最轻（Table 4，p21）。

### (b) 聚合分数为什么会掩盖损伤，推荐用什么指标
- Qwen3-4B 的 GGUF build（Table 3，p15）：q4_k_m 的 BFCL simple/irrelevance/live-simple 与 q8_0 持平甚至略高（95.8/89.2/81.4），iq3_xxs 降到 88.0/85.8/72.5，iq2_m 为 87.5/88.3/68.2；irrelevance 一项几乎不动。multi-turn 从 25.5 降到 7.5。flip 占比（全部 / 只看 call）从 .022/.047 增长到 .097/.208，增长约 4.4 倍。
- 作者的解释：对大量急剧翻转的决策取平均，曲线看起来是平滑的（A.9，p20）。
- 推荐做法：在实际要发布的那个模型和比特数上做一次配对测量（全精度一次、量化后一次），拟合 c、b、σ 并报告翻转率；c 无法估计时直接报告观测到的翻转率（§6，p8）。
- 预测精度：在 1,082 个条件上，held-out 预测误差中位数 1.0 pp（P90 为 7.8 pp），复用前一半的翻转率则为 1.3 pp；在中间区段（翻转率 0.2–0.8）分别是 4.3 和 6.0 pp（Fig. 3，p8；A.20）。**常数不能跨模型迁移**：借用其他模型的常数时，3-bit 误差中位数为 26.8 pp，4-bit 为 2.6 pp（Fig. 9，p36）。
- 预测的是 margin 符号的变化，不是实际输出。用 margin 预测"哪些调用会在生成中丢失"只在 Qwen3-4B 4-bit 上成立（Brier 改善 37%），其余条件（包括所有 3-bit）都失败了（A.19，p34–35）。

## 作者自己声明的局限（§7 p9；A.7 p19）
- 只研究 PTQ；决策只读首 token，不研究 rollout 过程中损伤如何累积（多步 agent 未覆盖）。
- 只有 5 个模型做了激活量化；第二模态只有 Qwen3-VL 一个家族，act-or-not 测试集没有通过有效性检查，因此不声称结论能迁移到视觉模态。
- embedding 不量化，名义比特数高于实际。
- 4-bit 拒答安全的结论只适用于 4B 及以上的当代 instruct 模型；Gemma-4-E4B 有 35.5% 参数保持全精度，不计入激活轴统计。
- 机制只是描述（对调用 token 的惩罚），没有解释；大模型为什么保留更多 margin 也没有解释。
- 外部测试只覆盖一个任务集、5 个模型；约 1/4 条件的斜率无法估计，只报告翻转率；多重比较只在一处做了校正。
- 3-bit 时 margin 与实际生成的一致性很弱（whether-to-call 的锚定率只有 30%，Qwen3-4B 只有 1.9%）；2-bit 的测量被视为"擦除"，基本不可解释。

## 方法问题与替代解释
- 【推断】which-tool "零翻转"的证据很弱：作者自写的 which-tool 题实际只有 8 个不同请求（重复 5 次），76% 的条件斜率无法估计。公开 BFCL/MetaTool 上 which-tool 在 3-bit 仍有 11–16% 的翻转，所以"which-tool 不受影响"只对自写题成立，作者自己也承认这一点。
- 【推断】3-bit 下大部分结论是两个指定 token 之间的相对偏好，并非实际生成：whether-to-call 的锚定率只有 30%。这更接近受约束解码下的行为，对自由生成的 agent 外推需要谨慎。
- 【推断】主力模型都偏小（4B 左右），大模型样本极少。"大模型更稳"只有 Qwen 系列内的拒答证据（1.7B→32B），对 27B 级别模型工具调用断崖位置的直接证据不足。
- 【猜测】RTN 用 group 64 是相对激进的设置；GGUF iq3_xxs 和 GPTQ 3-bit 的损伤明显更小（whether-to-call 翻转 10% / 21%），所以"3-bit 断崖"很大程度上取决于量化器。作者也说"there is no single 3-bit failure point"。
- 【推断】GPTQ 每个数字只来自一次运行；同一模型重复运行时翻转率最多相差 13 pp（Phi-4-mini 41% vs 54%，p18），单次比较的置信度有限。
- 【推断】BF16 参考模型本身就有符号噪声（Qwen2.5 系列 3.4%，Qwen2.5-1.5B 达到 6.7%），会让低翻转率的判断偏乐观或偏悲观。

## 对"约 27B 模型自己压缩自己（多轮递归）"研究设计的启示
1. **比特数安全区**（有论文证据）：
   - 权重 8-bit 与 4-bit（GPTQ/GGUF q4_k_m 等校准方法）下决策基本保持（GGUF q4_k_m 的 whether-to-call 翻转 4%，GPTQ 4-bit 为 7%，Table 6）。3-bit 是否崩溃取决于量化器：RTN 47% vs GGUF iq3_xxs 10%。2-bit 普遍擦除。
   - 激活不要低于 8 bit（A4 毁掉 margin，旋转也只能部分挽救）；KV cache 低于 8 bit 没有对所有模型都安全的宽度，而且结果必须注明具体方案。
   - 嵌入层和输出头保持全精度，是本文所有结论的前提。
   - 【推断】论文中最大的 Qwen3-32B 在 3-bit 下拒答零损失、Qwen2.5-14B 的应调用侧翻转只有 2.5%，说明大模型 margin 更宽；但 27B 级模型工具调用断崖的直接数据缺失，需要自己测。
2. **评测应包含的数据集/指标**：
   - BFCL whether-to-call（live-simple + live-irrelevance，正负两侧分开统计）、BFCL live_multiple（which-tool 与 argument fill）、MetaTool，以及 BFCL v4 multi_turn_base（本文中最敏感的 benchmark 类别：25.5→7.5）。
   - XSTest 拒答（forced choice + opener），附加实际生成检查。
   - 除聚合准确率外，每轮都要报告**配对决策翻转率**和拟合的 c、b、σ，并把应调用/不应调用两侧分开（方向性崩塌可能被平均掉）。
   - 增加一个"实际生成层面"的调用完成率与工具名正确率检查，因为 3-bit 下 margin 与输出脱钩。
3. **递归场景特有的风险**：
   - 【推断】如果每一轮都在上一轮已经量化过的模型上再量化，且乘法律逐轮近似成立，存活 margin 会按 c 的乘积衰减。即使单轮 c=0.86（4-bit 中位数），多轮之后有效 c 也会快速下降。这一点论文没有验证，属于推断。
   - 论文证据：常数在 3-bit 时不能跨模型迁移（误差 26.8 pp），所以**每一轮压缩后都必须重新对当前模型做配对校准**，不能沿用第 0 轮的参数。
   - 论文证据：困惑度不能指示该保护哪些层（Table 4）。如果 agent 用困惑度作为"压缩是否成功"的自评信号，可能看不到工具调用的崩塌。
   - 【推断】whether-to-call 崩塌主要表现为"不再调用工具"。对一个需要调用量化工具链来完成下一轮压缩的 agent 来说，这类失败会直接表现为 agent 停止行动，或改用文本描述来代替真实调用。因此递归协议需要检测"本轮 agent 是否真的发出了工具调用"。
