## 研究问题
SparseGPT/Wanda 等后训练剪枝用均匀或手工规则的逐层稀疏率；LLM-KICK 指出剪枝后事实知识严重崩塌（PPL 看不出）。作者提出由一个 LLM agent 迭代决定每轮剪哪些层、剪多少，以保住知识与能力。

## 方法细节
- 层敏感度画像（p.5–6）：每个线性层计算 Wanda 指标 S=|W|⊙‖X‖₂（式 1），取非零权重的第 10 百分位作为层敏感度；梯度重要性 G=平均 |∇W L|（式 2，每 3 轮算一次）；两者在所有层上做 z-score（式 3）。层画像 P={z_s, z_g, 当前稀疏率 ρ}。
- Agent（p.6–7）：每轮调用 **gemini-3-flash-preview**（温度 0.5），输入：当前/目标稀疏率、按 z-score 排序的层画像、当前与基线 PPL、上一轮反馈。输出 JSON：reasoning、stop_pruning、layer_decisions=[(层名, 额外稀疏 δ∈[0.01,0.15])]。
- 自反思（p.7）：把上一轮决策、稀疏增益、PPL 变化百分比和定性评语（如"Excellent…"/"Poor…"）喂回下一轮 prompt（Reflexion 式 verbal feedback，无参数更新）。
- 回滚（式 4，p.7）：若单轮 PPL 相对增幅 >15% 则恢复 checkpoint 并给负反馈。
- 执行：按 agent 给的 δ 用 Wanda 准则在该层内剪权重（Algorithm 1，p.8）——即**非结构化**逐层稀疏。
- **谁在剪谁**：决策者 Gemini-3-flash（闭源 API）；被剪的是 Qwen3-4B、Qwen3-8B（预训练模型，p.8）。**不同模型**。论文明确定位为"foundation model 指导另一个 foundation model 的压缩"（p.3, p.5, p.14），没有"self"说法。
- 修改形式：逐层选择额外稀疏率（数值决策）+ 停止信号；不写代码、不生成新算法。
- 多轮递归：有多轮迭代（21/40 轮）与上下文内的"学习"，但决策者固定为 Gemini，被剪模型从不成为决策者 → 不是递归自改进。
- 加速测量：**无**。只报稀疏率、MMLU、FreebaseQA、WikiText-2 PPL；未测 latency/throughput。且 agent 产出的是非结构化稀疏，一般难以直接带来加速（作者自己在 p.4 承认非结构化剪枝常难获实际加速）。
- 实现：128 条 C4 校准样本、序列 2048；激活 16 样本、梯度 8 样本、PPL 32 样本；单张 A100 80GB（p.9）。

## 方法问题与替代解释
- 【推断】基线不公平：agent 方法是**非结构化**（逐层 Wanda）稀疏，而基线是 2:4/4:8 **半结构化** magnitude 剪枝（论文称作"structured"）。非结构化 Wanda 在同稀疏下本就远好于 N:M magnitude；缺少"均匀稀疏率 Wanda（非结构化）"和"OWL"这一最关键对照，无法把增益归因于 agent 决策。
- 【推断】数字自相矛盾：Table 2/3 写 ~43%/45.58% 稀疏，Table 4 写最终 50.73%/50.46%；基线 PPL 在 Table 2 是 9.72、Table 4 是 22.06（可能是 32 样本 vs 全测试集，以及稀疏率计数口径不同），作者未解释。
- 【推断】"19× FreebaseQA" 只在 8B 上成立；4B 上为 2.08 vs 0.51（绝对值都接近崩塌，dense 32.43）。
- 【推断】无方差、单次运行，无 agent 随机性（温度 0.5）的重复实验；无与非 LLM 搜索（贪心按 z-score 剪）的对照，难以证明 LLM 推理本身有贡献——agent 学到的规则（剪 z<-1 的层）可能就是一个简单启发式。
- 【推断】无任何推理效率测量，"压缩"只体现为稀疏率。

## 与每个 core claim 的关系
- C1：**部分相关但未覆盖**。LLM 决定并（经 Wanda 工具）执行压缩，但决策者 Gemini ≠ 被剪 Qwen3，不是"自己的权重"；且未测推理效率，只报稀疏率与能力保持。
- C2：**未覆盖**。无 LoRA/adapter，无微调。
- C3：**未覆盖**。多轮是同一决策者的迭代+上下文反思；被剪模型不当编辑者，编辑能力与被编辑模型无共同提升。
- C4：**部分覆盖**。动作最终作用于权重（逐层稀疏），但动作空间是"层名+额外稀疏率"；不涉及量化、adapter、合并。
