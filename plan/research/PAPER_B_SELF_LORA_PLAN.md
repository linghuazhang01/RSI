## 0. 一页摘要

**候选标题**
- *Models that Operate on Themselves: Recursive Self-Editing of LoRA Adapters*
- *Edit Yourself: LLMs Programming Their Own Adapters*

**一句话卖点**：模型不只给自己准备训练数据，还在训练之后用代码直接修改自己的 adapter，像做外科手术一样。改过之后，它会不会成为更好的"外科医生"？

**设定**：
- 模型先用梯度在新任务上训练一个原始 LoRA（A_raw）。
- 装上 A_raw 的模型阅读诊断信息，写一段编辑程序，对自己的 adapter 栈做权重空间操作，包括逐层缩放、截断 rank、丢层、与历史 adapter 插值或合并、正交化等，不再训练。
- 编辑结果由固定的外部评测验收，通过后的模型成为下一轮的编辑者。
- 不借助更强的外部模型；主实验也不专门训练编辑能力。

**研究问题**
- **RQ1（单轮）**：同等评估预算下，模型自己写的训练后编辑，能否胜过不编辑、人工合并规则、解析式截断和非 LLM 搜索？在连续学习中，它能否改善"学新任务"和"不忘旧任务"之间的取舍？
- **RQ2（递归，核心）**：编辑过自己之后，模型去编辑一个**固定**模型在**未见任务**上的 adapter 时，效果是否更好？这种提升是否超出了普通任务训练本身带来的变化？
- **RQ3（行为）**：模型偏好哪些算子、改动哪些层？失败模式是什么？

**我们要检验的主张**（结果出来前都是假设）
1. 同预算下，LLM 编辑改善了目标任务与遗忘之间的取舍。
2. ΔE_edit 在未见任务上稳定为正，即编辑本身让后继者更会编辑。
3. 当前编辑者接任优于冻结编辑者。

**我们不主张的**：
- 新的 LoRA 算子，算子来自 TaDA、PARA、SLoRA、TIES；
- "首次让 LLM 写代码改权重"，权重空间编程（WSP）一线已经做了；
- "首次后代接任"，MASS 已经做了。

## 2. 方法

### 2.1 模型表示：冻结基座 + adapter 栈
第 t 轮的模型为 M_t = θ0 + Σ_k A_k：基座 θ0 冻结，每个 A_k 是一个 LoRA。这样做有三个好处：
- 所有编辑都在 adapter 空间里进行，成本低，也可以回头修改历史 adapter；
- vLLM 支持同时挂载多个 LoRA，候选不必合并进基座就能评测；
- 随时可以回滚到某个历史栈。

### 2.2 每一轮的流程

```
第 t 轮（父模型 M_t = θ0 + 当前 adapter 栈），任务 T_t
1. 训练 raw adapter：在 T_t 的训练集上训练 LoRA，得到 A_raw，3 个种子。
   保存训练进度 25 / 50 / 75 / 100% 四个 checkpoint，作为编辑素材。
2. 编辑者 R_t = M_t ⊕ A_raw，即装上 raw LoRA 之后的模型。
   这样才是"同一个 checkpoint 编辑它自己的 adapter"。
3. R_t 调用诊断工具，写 edit(adapters, stats) -> new_stack，在沙箱里执行。
4. L1 评分：score = 目标 dev 增益 − λ × 保留集 dev 下降。
   返回具体数字、K 条错题和历史记录；每轮最多评测 32 个候选。
5. 选最优候选提交 dev2 验收（L2），每轮最多提交 3 次。
6. 通过：M_{t+1} = Apply(编辑程序, R_t)。
   编辑改动了历史 adapter 时，替换栈里对应的成员，不要把已经包含旧 adapter 的合并结果再追加一次。
   全部不通过：如果 Raw 能通过验收，就用 Raw；否则保留 M_t（跳过该任务），并记录。
7. 对四个分支分别测 E_{t+1}（§2.6）。
```

### 2.3 raw LoRA 配置
- pilot 阶段固定：r = 16、α = 32、作用于所有线性层、学习率 1e-4、2–3 个 epoch，接近 SDFT 的 r16 / α32。
- 扩展阶段（B-P3）改为由模型自选配置。
- raw 配置在所有分支、所有代之间保持一致，这样 ΔE_train 才可比。

### 2.4 诊断工具与算子库

具体设计和依据见 `METHOD_DESIGN.md` §3，这里只列要点。

**预先算好的诊断表**（固定程序生成，所有代相同，不计入预算）：每个 (层, 模块) 一行，包括：
- ΔW 基础量：范数、相对范数、紧凑奇异值、有效秩；
- **基座对齐（intruder 分数）**：唯一有因果对照的零数据遗忘信号；
- 与历史 adapter 的归一化主角度和符号冲突率；
- 相对变化 |ΔW|/|W0| 的高分位比例；
- 在目标输入和保留集输入上的激活作用比；
- 层深度和模块类型；
- **checkpoint 轨迹表**：每个 checkpoint 的目标 dev 分数和保留集 token-KL。

**按需调用的工具**（计入预算）：`dev_report(candidate)` 返回目标和各保留集的变化量（附置信区间）、保留集 token-KL、输出长度和格式失败率、2–3 个"编辑前对、编辑后错"的样例；`ablate(group)` 把相邻 4 层的 attention 或 MLP 置零后看分数变化。

**算子库（Level 1）**：

| 类别 | 算子 |
|---|---|
| 缩放 | `scale(全局 / 层 / 模块, s)` |
| 插值 | `interpolate(A, B, λ)`，明确支持 checkpoint 之间、与历史 adapter 之间的插值 |
| 低秩 | `truncate_rank(layer, k)`、`svd_reweight` |
| 抗遗忘 | **`intruder_scale(layer, λ, ε)`**（新增）、**`regmean_preserve(layer, α)`**（新增）、`orthogonalize(A_new, A_old)` |
| 稀疏 | **`relchange_prune(density)`**（新增，替换 `magnitude_prune`）、`drop(layer/module)` |
| 合并 | `ties`、`task_arithmetic`；`dare` 只作 TIES 的预处理 |

删除 `project_out`：Deafening Silence 显示它会切断补偿，把遗忘放大 1.6–2.4 倍。

- **Level 1（主实验）**：只能设置上述算子的参数并组合使用。
- **Level 2（B-P3）**：允许在受限 API 内用 torch 写新算子，输出形状和 rank 上限受约束。

**沙箱**：无网络、限时、只能调用白名单 API；检查输出形状是否不变、数值是否有限、rank 是否不超过上限。

**agent 外壳**：开源编码 agent 外壳，与 Paper A 共用。外壳、system prompt 和反馈格式在所有代之间保持不变。

### 2.5 三层反馈

| 层 | 编辑者看到什么 | 数据 |
|---|---|---|
| **L1 搜索反馈** | 具体数字、K 条错题、历史候选记录 | 目标任务 dev、保留集 dev：都是训练集的**信号切片**（`search` 池） |
| **L2 验收门** | 只有"通过 / 不通过"和粗粒度原因 | 目标任务 dev2、保留集 dev2：训练集的**验收切片**（`gate` 池） |
| **L3 留出评测** | 永远看不到 | §3.3 的留出集（benchmark），每代结束后评测，只用于报告 |

LoRA 容量大，信号题可能被直接"记"进权重（Gödel Agent 就把验证集上见过的错题硬编码进了策略），所以 Paper B 比 Paper A 更需要把 benchmark 挡在循环之外。

**L2 验收门**（默认值，B-P0 结束后预先登记最终值）：
- 目标任务 dev2 不低于 Raw 的 dev2 减去 ε（假设 ε = 0.5 分）；
- 保留集 dev2 的每一项都不低于**第 0 代**减去 δ（假设 δ = 2 分）。门槛相对第 0 代，不相对上一代，防止退化逐代累积；
- 数值合法，rank 不超过上限。

**其他规则**：
- **不用模型自评做门**。When AI Reviews Its Own Code 证明自评门会逐代退化。
- **主实验只用确定性判分**：精确匹配、单元测试、执行结果、IFEval 的规则检查。
- **dev2 的使用次数预先规定**，每轮最多提交 3 次，否则 dev2 也会变成自适应选择的一部分。

### 2.6 编辑能力 E_t 与四分支协议

**E_t 的测法**：
- 让一个编辑者去编辑**固定的被编辑模型**（θ0）在**未见任务**上训练出的 raw LoRA；
- 预算固定：每个任务、每个种子 16 次候选评测；
- 测编辑后相对 raw 的提升，在 E-test 上计算，取 3 个种子的平均。

**固定 raw LoRA 库**：
- 为两个 E 任务（§3.3）各训练 3 个种子的 raw LoRA，每个种子保存 4 个 checkpoint；
- 这套库在所有代、所有分支之间完全不变。

**测量规则**：
- 每次测 E_t 都开新会话，不进入主循环历史；
- 不同分支用相同的初始 prompt、相同的采样种子，以便配对比较。

**每个父 checkpoint 上保留四个分支**：

| 分支 | 内容 |
|---|---|
| Parent | M_t，训练前的模型 |
| Raw | M_t ⊕ A_raw，只做了普通任务训练 |
| LLM-edited | 在同一个 Raw 上执行 LLM 写的编辑 |
| Non-LLM-edited | 在同一个 Raw 上执行最好的非 LLM 编辑 |

**报告**：
- ΔE_train = E(Raw) − E(Parent)：普通训练本身带来的编辑能力变化；
- ΔE_edit = E(LLM-edited) − E(Raw)：编辑本身带来的变化；
- ΔE_nonLLM = E(Non-LLM-edited) − E(Raw)：如果这一项也为正，收益就不能只归因于 LLM 自编辑。

**"稳定为正"的判据**（预先登记）：在至少 2/3 的代上，ΔE_edit 的 95% 置信区间下界大于 0，并且 ΔE_edit 大于 ΔE_nonLLM。

### 2.7 编辑能力从哪里来
- **主实验不显式训练编辑能力。** 编辑者能力的变化只来自"自己的 adapter 栈变了"，这样才能干净地回答"权重的变化是否让模型更会编辑"。
- **扩展变体（B-P3）**：把成功的编辑程序当作训练数据，用 ReST^EM 训练一个"编辑技能"LoRA，类似 SEAL 和 Self-Developing 的外层训练。数据同样完全由模型自己产生。

## 3. 实验设置

### 3.1 模型

| 用途 | 模型 | 理由 |
|---|---|---|
| Pilot 和核心实验 | **Qwen3-8B** | Search over Self-Edit 用的就是它，SEAL 用 Qwen2.5-7B，可以直接对照；成本低 |
| 扩展（B-P3） | **Qwen3.8 27B** | 与 Paper A 共用模型和基础设施 |

成本参考：MASS 在 27B 上做一轮 LoRA SFT，用了 17.2M token、约 6×H100 × 19 小时。本方案每个任务的训练数据少得多；编辑本身不需要训练，主要成本在评测。

### 3.2 选任务的标准
Paper B 需要**能训 LoRA 的任务**，要求有训练集、LoRA 训练后有可见提升、能测遗忘，所以任务角色和 Paper A 不同。

### 3.3 数据与切分

总原则：**循环只看训练集，benchmark 全部留出。** 每个领域一份训练集，切成 `search`（dev，200 题）、`gate`（dev2，200 题）和 `train`（训练 raw LoRA 的数据）；benchmark 全部放在 `test` 池，只进 L3。切分按固定的题目 ID 或段落 ID 和固定种子生成，并记录哈希；训练集在切分前对所有留出集做精确匹配和 13-gram 近似重复去污染。细节见 `data/README.md`，文献依据见 `plan/research/DATA_CONFIG.md`。

任务限定为五类：数学、代码、闭卷知识、指令遵循、简单工具调用。在 Paper B 中它们的角色如下：

| 类别 | 在 Paper B 中的角色 |
|---|---|
| 闭卷知识 | T1 训练任务（SQuAD 知识注入）；TriviaQA、ARC 作保留集 |
| 数学 | T2 训练任务 |
| 代码 | T3 训练任务 |
| 指令遵循 | 保留集，每代都测 |
| 工具调用 | 编辑能力测试任务（E 任务），从不进入训练序列 |

**连续任务序列**（按顺序学，每学一个任务就是一代）：

| 代 | 任务 | train（训练 raw LoRA） | dev（信号切片） | dev2（验收切片） | L3 留出集 | 训练集的文献依据 |
|---|---|---|---|---|---|---|
| T1 | 知识注入：SQuAD 无原文问答（SEAL 设置） | SQuAD train 段落，采用固定的增广配方 | 50 段（50 个不同标题） | 另 50 段（另 50 个标题） | SEAL 的评测集（200 段、974 题） | SEAL、Search over Self-Edit；能直接对比 SEAL 的 47.0 和 Search 的 45.1 / 50.3 |
| T2 | 数学 | GSM8K train + MATH train 的 `train` 池（14,137 题） | MATH train 信号切片 200 | GSM8K train + MATH train 验收切片各 200 | MATH-500、GSM8K test 1,319、AIME 2024+2025 | ReST-EM、WSP；DAPO-Math（WHALE）可作第 4 代的难题数据 |
| T3 | 代码 | APPS 入门级 train 的 `train` 池（1,997 题，每题可取多份参考解） | APPS 信号切片 200（执行测试用例） | APPS 验收切片 200 | HumanEval+ 164、MBPP+ 378、LiveCodeBench 131 | ReST-EM（APPS → HumanEval） |

主实验跑 T1 → T2 → T3，共 3 代。这是查新报告里"让差异站得住的最小实验"。算力允许时，可以加 DAPO-Math 难题作为第 4 代。

**保留集**（每代都测，用来测遗忘）：

| 领域 | dev（信号切片） | dev2（验收切片） | L3 留出集 | 为什么选它 |
|---|---|---|---|---|
| 指令遵循 | IFEval 135 条 | IFEval 另 135 条 | IFEval 其余 271 条；IFBench 300 条（领域外） | 微调数学或代码会不会伤指令遵循，正是要测的遗忘；切法沿用 WSP-Scope 的 270/271 |
| 闭卷知识 | TriviaQA train 200 | TriviaQA train 另 200 | TriviaQA 2,000 | 敏感的知识探针；闭卷知识很难靠 LoRA 注入，适合测遗忘 |
| 选择题推理 | ARC train 200 | ARC train 另 200；GPQA Main 去掉 Diamond 125 | MMLU-Pro 2,000、GPQA-Diamond 198 | 通用推理，作对照 |
| 已学过的旧任务 | 各自的 dev | 各自的 dev2 | 各自的留出集 | 测连续学习中的遗忘 |

**编辑能力测试任务**（工具调用，从不进入训练序列，只用来测 E_t）：

| E 任务 | raw LoRA 的训练数据 | E-dev（编辑者看到的反馈） | E-test（报告用） | 备注 |
|---|---|---|---|---|
| **E-Seal** | Seal-Tools train 的 `train` 池（11,619 条） | Seal-Tools train 信号切片 200 | Seal-Tools test（in-domain 700 + out-domain 654）；BFCL 作领域外 E-test | TT-SI 中 SealTool train 上的 SFT 把 Qwen2.5-1.5B 从 66.4 提到 70.2，说明 LoRA 有可见提升 |

**只在最后测的评测**（L3，只测第 0 代和最终代）：
- 数学 LoRA 的额外分布外测试：AMC23、OlympiadBench；
- 工具调用的额外测试：T-Eval、MetaTool；
- 可选：MT-Bench、AlpacaEval 2，需要固定的 LLM judge，不进主结果。

多轮 agent 评测（τ²-bench、Terminal-Bench、SWE-bench）不在这次的五类任务里，不再测。

## 4. 实验矩阵

种子默认是 3 个训练种子，每个种子对应一份 raw LoRA。

### E1 动机：连续自训 LoRA 会遗忘，固定规则修不全（B-P0）
- **设置**：8B 上按 T1 → T2 → T3 训练 raw LoRA，不用 LLM；用网格或随机方式暴力扫简单算子（缩放、截断、插值）；同时跑 TIES、PARA、SLoRA。
- **度量**：在一份**可丢弃的 pilot holdout** 上测提升空间，不看封存的 test。
- **输出**：Figure 2，保留集分数随代数的曲线：Raw、TIES、SLoRA、暴力扫描的上界。
- **成立条件**：
  - 单任务提升小于约 1 分，但遗忘明显减少：论文主线定为"抗遗忘编辑"；
  - 两边都几乎没有空间：方向不成立，及早止损。

### E2 单轮比较（B-P1，回答 RQ1）
- **设置**：8B，在每个任务上，LLM 编辑者与下列基线对比，算子空间相同、评估次数对齐（32 次）。
- **基线梯子**（借鉴 SEAL，从弱到强）：
  1. 不编辑（A_raw）；
  2. 最好的单个 checkpoint、标量插值扫描；
  3. TA / TIES / DARE 网格；
  4. PARA、TaDA、SLoRA；
  5. **全局缩放 s 的帕累托前沿**、**checkpoint 选择或插值的前沿**、LiNeS 深度线性缩放、intruder 缩放的 λ 网格；
  6. 规则组合基线：SLoRA 截断 + 全局缩放 + checkpoint 选择，参数在 dev 上网格选择；
  7. 随机搜索、CMA-ES（Nevergrad）；
  8. LoraHub：按原公式 (ΣwA)(ΣwB) 实现，并加一个 Σw·ΔW 变体；
  9. EvoGM：用官方代码，并报告 Single Best 下限；
  10. **本方法**：R_t 自编辑；
  11. 外部强模型当编辑者：只作上界，不进主循环。
- **主表必须报告本方法在全局缩放和 checkpoint 两条前沿之上多出的部分**：文献中影响最大的变量一直是全局系数。
- **公平性检验**（借鉴 EvoGM）：把本方法的关键信息，例如诊断统计和错题，也提供给 CMA-ES 的初始化，看优势是否来自信息而不是 LLM 推理。
- **成本**：同时报告评估次数、GPU 小时和生成 token 数；逐层消融、诊断前向和候选筛选都计入预算。
- **输出**：Table 1 基线梯子；Figure 3 学新任务和不忘旧任务的取舍前沿。
- **成立条件**：LLM 不比 CMA-ES / EvoGM 差，并且满足以下任一项：成本更低；在 E 任务上泛化更好；在取舍前沿上占优。

## 10. 论文怎么写

### 10.1 叙事主线
**改进的对象和改进的执行者是同一个模型。改动它，也就改动了下一次改动的质量。**

借鉴 Self-Rewarding 的写法，同时看两条轴：一条是任务能力和遗忘，另一条是编辑者能力 E_t。

### 10.2 引言的写法
- **第一段**：SEAL 证明了模型可以写"怎么更新自己"的指令，但更新后的模型用完就丢；WSP 证明 LLM 能读写权重，但执行者是外部前沿模型，被改的是别的模型。
- **第二段**：真正的自我改进，要求被改进的模型成为下一个改进者，并且直接作用于自己的权重。
- **第三段（先用实验展示问题，借鉴 Self-MoE）**：
  1. 自编辑类方法都在训练**之前**选数据和配置，模型从不碰训练好的权重；
  2. 训练后的权重编辑要么是固定规则，要么由外部模型执行；
  3. 没有人测过"编辑过自己之后，是否更会编辑"；
  4. B-P0 的证据：连续训练 LoRA 后保留集下降，TIES 和 SLoRA 只能修复一部分。
- **研究问题方框**（借鉴 EvoGM）：*编辑自己的权重，会不会让模型更会编辑权重？*

### 10.3 核心洞见
- **把编辑 adapter 当作代码生成任务。** 这仿照 Self-Rewarding "把奖励建模当成指令遵循任务"的思路：让模型用自己最擅长的形式修改权重。
- **用 Text-to-LoRA 的负面结果作动机**：相似任务的 LoRA 在权重空间里并不相邻，所以直接生成权重数值很难泛化，结构化的代码编辑更合适。
- **造一个新名词**（借鉴 SEAL 的 self-edit）：例如 **self-surgery** 或 **adapter self-programming**，用来统一缩放、截断、合并、正交化这些动作。

### 10.4 先发制人的框架段（借鉴 FT-Dojo）
明确说贡献**不在**新的 LoRA 算子，而在"模型自己选择、组合算子并递归编辑"的过程，以及由此得到的发现。再配一段"受控协议"：所有条件固定，只改变谁来当编辑者。

### 10.5 贡献
1. **框架**：训练后由模型自己编程编辑 adapter，并递归接任。
2. **公平比较**：同预算下与人工规则、解析截断、非 LLM 搜索（LoraHub、CMA-ES、EvoGM）对比，并把关键信息移植到基线上做公平性检验。
3. **编辑能力迁移**：四分支协议，测 ΔE_edit 在未见任务上是否为正。
4. **行为分析**：模型学会用哪些算子、失败模式是什么。

### 10.6 结果分支

| 实际结果 | 论文的落点 |
|---|---|
| ΔE_edit > 0，并且大于 ΔE_nonLLM | "自我编辑可以复利" |
| ΔE_edit ≈ 0 | "任务上的提升不会迁移成编辑能力"，接着用 ReST^EM 显式训练编辑技能，作为第二个贡献 |
| ΔE_edit < 0 | "任务专精与编辑能力冲突"，用配方 / 数据交换实验定位机制 |
| ΔE_nonLLM 和 ΔE_edit 一样大 | "改变编辑者权重的是编辑本身，而不是 LLM 的推理"，这也是一个发现 |
| LLM 输给 CMA-ES | 收窄为"递归编辑中的能力迁移"分析论文 |

### 10.7 章节结构（正文 9 页）

| 节 | 内容 | 页数 |
|---|---|---|
