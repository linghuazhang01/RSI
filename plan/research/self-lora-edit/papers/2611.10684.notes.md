## 研究问题
把公开 LoRA adapter 依次事后合并（不再训练）看作持续学习：指令微调后基座原有的能力算作 Task 0，每合并一个 adapter 算一个新任务。论文问的是，测这种设定下的遗忘需要哪些前提。作者的立场是：这个方向的瓶颈在测量基础设施，而不在新的合并方法。论文不提出新的 merger。

## 方法细节
- **处理对象**：从 HuggingFace 下载的**别人训练好的公开 LoRA**（math、code、general nlp、medical，表 2/表 3，p.7），不是自己为下游任务训练的 raw LoRA。合并对象是这些 adapter 的 delta，合并结果是 θ0 + Σ f(Δt)（p.3）。
- **具体操作**：
  1. **Adapter 审计（两项检查）**：(a) 声明的基座字符串要和被测基座完全一致；(b) 重构 delta 的总 Frobenius 范数（Σ_ℓ ||B_ℓ A_ℓ s||_F^2）^{1/2} 要大于 1.0（p.3，附录 G）。
  2. **合并规则**：naive sum、Task Arithmetic λ=0.5、TIES d=0.5、DARE d=0.5、MagMax。超参用原论文推荐值，另外扫了 d/λ=0.3（附录 D，表 8）。
  3. **按 adapter 的系数坐标搜索**：λ 候选为 {−0.5, 0, 0.5, 1.0}，每个 adapter 依次试，在 GSM8K 的 n=200 probe 上只在比当前最好值更高时才接受（附录 C，表 7）。这是无梯度搜索。
  4. **逐 block 消融重要性**：把第 b 个 transformer block 的所有 delta 置零，看 probe 准确率变化 I_b（算法 1，附录 E，n=50）。
  5. **正交投影 merger**（附录 M）：每一步把新 adapter 的 delta 投影到此前所有 delta 列空间的正交补上再相加，是 OSRM 类方法的受控实现。
  6. **增强审计信号**（附录 J）：基座哈希、tokenizer 兼容性、10 条 prompt 上的 KL / top-1 一致率。
- **谁做决策**：固定规则（审计阈值、各 merge 规则）加上小规模坐标搜索。没有 LLM 参与诊断或写编辑代码。
- **是否持续多任务**：是，按“顺序合并”的意义。附录 L 给出按 code→math→general nlp→medical 逐步合并的遗忘曲线。但每一步没有训练，任务指的是“加一个现成 adapter”，不是“在新任务数据上训练”。
- **是否先训练 raw LoRA 再事后处理**：否。作者自己不训练任何 adapter，全部用公开 adapter。

## 数据集与评测、模型规模
- 模型：Llama-3.1-8B-Instruct（主实验，32 block，224 个 LoRA 目标层）；Mistral-7B-Instruct-v0.3（跨家族复现，只有 2 个 adapter 通过审计，只报 GSM8K）。普查还覆盖了 Llama-3.2-1B/3B 和 Qwen2.5-7B（附录 I）。
- 评测：GSM8K（受保护任务，1,319 题，strict-match）、HumanEval（164 题 pass@1）、MATH-500（4-shot）。general nlp 的 TruthfulQA-MC2 只在单 adapter 参考评估里出现。用 lm-eval-harness 默认设置、greedy 解码（附录 F）。
- **dev/probe/test 划分（第 3 节，附录 E，表 9）**：
  - GSM8K 训练集切成 probe 集 P（train[0:50]，用于 block 重要性）和 α 选择集 S（train[50:250]）。
  - 测试集 1,319 题只用于最终报告。
  - 负系数坐标搜索用的是 n=200 probe（表 9）。【推断】这 200 题是否就是 S（train[50:250]），文中没有明确说。
  - 作者把这种划分称为“leakage-free”，并批评以往工作用测试集调参。

## 关键实验与数字
- **表 1（p.4），4 个审计后 adapter 全量合并，全测试集**：
  - 基线（不合并）GSM8K/HE/M-500 = 0.707/0.628/0.154
  - naive 0.603/0.445/0.142（GSM8K −10.5pp，HE −18.3pp）
  - TA λ=0.5 0.705/0.561/0.170
  - TIES d=0.5 0.712/0.543/0.172
  - DARE 0.622/0.457/0.144
  - MagMax 0.685/0.524/0.168
  - 结论：TA 和 TIES 在 GSM8K 上和基线相差在一个标准误以内。
- **附录 H 表 11（p.12），审计效应**：审计前的组合（含错基座的 Blackroot）naive 合并 GSM8K 为 0.491（−21.7pp），审计后的复现为 0.615（−9.2pp），差 12.4pp，几乎全部来自那一个错基座 adapter；近零范数 adapter 只带来 −0.3pp。
- **附录 C 表 7（p.9），负系数**：坐标搜索在 math adapter 上取 λ=−0.5 时 probe 最好，probe 准确率从 0.405 升到 0.490（+8.5pp）。但在全测试集上 GSM8K 只有 0.672（比基线低 3.5pp，比 naive 高 6.9pp），HE 0.555，M-500 0.150，**没有胜过 TA/TIES**。作者只把它当作“搜索空间里的发现”，不当方法。
- **附录 C 图 4（p.10），逐 block 消融**：32 个 block 里有 14 个重要性为负，也就是置零这些 block 的 delta 会让 GSM8K 下降、这些 delta 对受保护任务是有益的；它们集中在 0–4 和 29–31 层。12 个为正，集中在 10–19 层。冻结 block 30 在 probe 上损失 16pp。作者据此认为按 block 或按方向取负号可能是更合理的推广，但**没有实际做按 block 的编辑并在测试集上评估**。
- **附录 M 表 17（p.16），正交投影 merger**：在审计后的组合上 GSM8K 0.635，比 naive 的 0.615 高 2pp；在审计前组合上 0.523，比 0.491 高 3.3pp。审计带来的效应（约 11pp）比合并方法之间的差异大一个数量级。
- **附录 L 表 16（p.15），逐步遗忘**：naive 和 DARE 单调下降（0.685→0.615，0.704→0.580）；TA/TIES/MagMax 在每一步都保持在 0.68–0.72。
- **附录 I 表 12/13，普查**：随机抽 80 个公开 LoRA，只有 6 个（7.5%）通过审计；在可加载的 adapter 里，基座不匹配占 66%。
- **附录 B 表 6，单 adapter 参考**：没有一个 adapter 单独使用时能提升 GSM8K，所以“不合并的基线”本身就是受保护任务的上限参照。
- **附录 K，种子与采样稳健性**：3 个种子下 GSM8K 的种子标准差为 0.003–0.015，排序不变；self-consistency@8 和 pass@10 下模式也一致。

## 作者自己声明的局限（p.4–5，附录 M）
1. 合并实验只做了两个 7–8B 家族，跨规模合并留作以后。
2. 审计是必要条件但不充分：adapter 可能能通过审计却很弱，也可能范数很高但语义有害（后门等）。
3. 负系数搜索只是 4 adapter × 4 候选、n=200 probe 的扫描，只算发现，不是方法。
4. TA/TIES/DARE 只用推荐默认值。
5. SA-LoRA、OSRM、LoRA-LEGO、LoRI 没有忠实复现。
6. Mistral 上的 HumanEval 因为 chat 模板敏感，推迟到以后做。

## 方法问题与替代解释
- 【推断】表 7 里有个内部不一致：code 行 λ=1.0（此时所有 adapter 都是 1.0，也就是 naive）的 probe 是 0.420，math 行 λ=1.0 又是 0.430，但正文说 naive 的 probe 是 0.405。greedy 解码下同一配置应该给出同一个值。这说明 probe 评估有噪声，或者每一行的上下文配置不同。n=200 的标准误约 ±0.035（附录 F），+8.5pp 只略大于 2σ，而且测试集结果也证明它没有泛化成对 TA 的优势。
- 【推断】图 4 的 naive probe 是 0.44（n=50），表 7 是 0.405（n=200），两者用的是不同的 probe 集。
- 【推断】主表只用单个种子，加上 lm-eval 版本漂移约 1pp（附录 H 的复现说明）。TA 和 TIES 的差距都在误差范围内。
- 【推断】使用的 adapter 本身大多不能提升自己的目标任务（表 6），所以在这个组合上，“合并后保持基线”几乎就等于最优。这个场景的上升空间很小，结论不一定能推广到 adapter 真正有用的场景。
- 【推断】这里“持续学习”的含义（合并现成 adapter，关注 Task 0 能力的保持）和 B'（每轮自己训练新任务 LoRA 并累积多任务能力）不同。可塑性主要通过各 adapter 自己的目标基准间接衡量。

## 与 core claims 的关系
- **C1（同一模型自编辑自己的 LoRA）**：**没有覆盖**。编辑和决策靠固定规则和小规模坐标搜索，没有 LLM 编辑者；处理的是公开 adapter，不是模型为自己训练的 adapter。
- **C2（同预算下胜过无编辑、人工 merge 规则、非 LLM 搜索）**：**没有覆盖，但提供了基线和参照**。论文在同一协议下比较了 naive/TA/TIES/DARE/MagMax、坐标搜索（含负系数）和正交投影 merger，结论是 TA/TIES 已接近不合并的基线，坐标搜索在测试集上没有胜过 TA/TIES。这提醒 B'：在类似设定里，人工规则可能已经很强，非 LLM 搜索容易在小 probe 上过拟合。它没有任何 LLM 写的编辑，也没有固定评估预算下的公平对比（坐标搜索 16 次评估，merge 规则不需要评估）。
- **C3（递归、编辑者能力的代际测量）**：**没有覆盖**。
- **C4（持续多任务，用 adapter 空间操作控遗忘，不用外部强模型，固定外部评估）**：**部分覆盖**。“顺序合并 adapter 算持续学习”“用 adapter 空间的合并、负系数、正交投影控遗忘”“不用外部模型”“probe / α 选择 / test 三方分离的固定外部评估”这几点都做了，尤其是评估协议与 B' 的 dev / dev2 / sealed test 思路很接近。但它没有每任务自训的 raw LoRA，也没有累积 adapter 栈加多轮编辑者。
- **作为基线怎么复现**：
  1. 用它的 merge 规则组（TA λ∈{0.3,0.5}、TIES d∈{0.3,0.5}、DARE、MagMax、naive）作为 C2 的“人工 merge 规则”基线，用到 B' 每一轮“新 raw LoRA 加旧 adapter 栈”上。
  2. 复用它的按 adapter 系数坐标搜索（候选 {−0.5, 0, 0.5, 1.0}，在 probe 上贪心接受），作为“非 LLM 搜索”基线。这个搜索的评估次数很容易对齐，4 adapter × 4 候选 = 16 次。
  3. 复用逐 block 置零消融（算法 1）作为诊断工具，或者作为“逐 block 丢层”的固定规则基线。
  4. 复用附录 M 的增量正交投影（Δ_orth = Δ − U_cum U_cum^T Δ）作为“对旧 adapter 正交化”的规则基线。
  5. 评估协议可以直接参照：probe 和选择集取自训练集，测试集只用一次，并报告单 adapter 参考分数。
