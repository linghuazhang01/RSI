- 标题：Evolutionary Optimization of Model Merging Recipes
- 作者：Takuya Akiba, Makoto Shing, Yujin Tang, Qi Sun, David Ha（Sakana AI）
- 版本：arXiv v2，2025-01-27（pages.md 第 15 行 `arXiv:2403.13187v2 [cs.NE] 27 Jan 2025`）。v1 发布于 2024-03；【推断】v2 正式发表于 Nature Machine Intelligence（2025），但 PDF 正文没有写明
- 阅读范围：全文 28 页（正文 p1–18，参考文献 p19–21，附录 A–C p22–28），源文件 `src_2403.13187/2403.13187.pages.md`（1725 行，pdftotext，无空页）

## 研究问题
社区里的模型合并主要靠人凭直觉挑模型、调配方。作者想知道能否用进化算法自动搜索合并配方，同时在参数空间（PS，权重怎么混）和数据流空间（DFS，token 依次经过哪些模型的哪些层）里做优化，把不同领域的模型（日语 LLM 和英语数学 LLM、日语 LLM 和 VLM）合成一个具备组合能力的新模型（p1–2，第 48–60 行）。

## 方法细节
- **被合并的对象**：**全模型**（都是 Mistral-7B-v0.1 的微调后代，13B 实验用 Llama-2-13b 的微调后代）。按 task vector（θ_k − θ_base）做合并，不是 LoRA。
- **PS 合并**：DARE + TIES-Merging，每层给出"稀疏化密度 + 混合权重"两类配置参数（这里的"层"指输入/输出 embedding 或一个 transformer block），用 CMA-ES 优化（p5 第 298–307 行）。
  - **但最终报告的模型用的是最简单的设置**：每个源模型整体当作一层，每个模型只配两个 DARE-TIES 参数（density 和 weight），3 个模型一共 6 维。作者说由于数据有限，逐层配置等更复杂的设置**没有带来明显提升**（p9 第 545–550 行）。这一点和"逐层系数"的问题直接相关。
  - 演化得到的权重之和接近 2，超过 1，说明放大各模型贡献比简单插值更有效；日语模型的密度最高（p9 第 552–567 行，Fig. 3 p10）。
- **DFS 合并**：只保留串联、不随输入变化的推理路径。把 M 个层按顺序排好、重复 r 次，用指示数组 I（长度 T=M×r）决定每层是否保留，另有缩放矩阵 W∈R^{M×M} 用来缓解层间分布偏移（p6 第 322–353 行）。实验中 M=64，r=3，T=192（p7 第 425 行）。
- **PS+DFS**：先做 PS 合并，把结果放回候选池，再做 DFS（p6 第 357–361 行）。
- **优化器和预算**：
  - PS：用 Optuna 实现的 CMA-ES，初始值 0.5，σ=1/6，种群大小 4+⌊3 ln n_params⌋（6 维时为 9），**1000 trials**。fitness 是在 1069 条训练样本上的准确率，选训练准确率最高的那次 trial（p7 第 418–424 行）。【推断】总计约 1000 次全量评估，每次约 1069 条生成，约 107 万次 greedy 生成。
  - DFS：EvoJAX 的 CMA-ES，**100 代 × 种群 128**（约 12,800 次评估），每次在 batch 200 上评估；留出最后 200 条做验证，选验证集上最好的 snapshot（p7 第 425–430 行）。
- **有没有 LLM 参与决策**：**没有**。纯 CMA-ES 数值搜索。LLM 只是被合并的对象和被评估的对象。（VLM 基准的 QA 是借助 GPT-4V 构造的，那属于数据构造，不参与搜索，p15 第 939 行。）
- **校准数据量**：数学任务用 GSM8k 测试集中 ID 250–1318 的 1069 条，翻译成日语后作为优化集，与 MGSM-JA 测试集（ID 0–249，250 条）不重叠（p7 第 398–407 行）。VLM 用 Japanese Visual Genome VQA 中另一个不重叠的子集（p15 第 943–945 行）。
- **答案判定**：最后一个数字正确，且推理过程用日语书写（用 fasttext 检测语言），zero-shot pass@1，greedy 解码（p7 第 409–416 行）。

## 数据集、评测、模型规模
- LLM：MGSM-JA（250 条）；JP-LMEH 的 9 个任务（JComQA、JNLI、MARC、JSQuAD、JAQKET、XLSum、XWino、MGSM、JCoLA）。
- VLM：JA-VG-VQA-500；JA-VLM-Bench-In-the-Wild（42 张图、50 个问题），指标为 ROUGE-L。
- 规模：7B 源模型（合并后 PS 为 7B，DFS 为 10B）；13B 源模型（合并后 13B–21B）；VLM 为 8B–12B。

## 关键实验与数字
- **Table 1（p8，第 451–467 行）**，MGSM-JA / JP-LMEH：源模型 Shisa 9.6/66.1，WizardMath 18.4/60.1，Abel 30.0/56.5；**Ours(PS) 52.0/70.5**；Ours(DFS) 36.4/53.2；Ours(PS+DFS) 55.2/66.2；GPT-3.5 50.4；GPT-4 78.8；Llama2-70B 18.0。
- **Table 3（p11，第 640–663 行）** 是与基线的对比，和 C2 最相关：
  - 不做优化的合并（用 mergekit 默认超参，取自一个社区教程 [34]，p10 第 630–633 行）：TIES-Merge 4.4/63.7；**DARE-TIES 35.2/66.3**；Frankenmerging 0.0/16.1。
  - 微调（在同样 1069 条上训练 3 epoch，lr 在 {1e-5, 5e-5, 1e-4} 中挑最好）：LoRA-Shisa 20.8/66.4；**LoRA-WizardMath 43.2/55.9**；LoRA-Abel 40.0/52.8；Full 微调 19.2–36.4，同时 JP-LMEH 明显下降（43.4、37.5）。作者把这一点解释为微调更吃数据、更容易灾难性遗忘（p11 第 686–690 行）。
  - 干扰实验（PS 加入 0/1/2/4/8 个无关模型，并加入权重归一化）：50.0 / 46.8 / 46.8 / 48.4 / 40.8（第 659–663 行），表明性能会下降但不会崩溃。
- **Table 4（p13，第 763–773 行）**，13B：源模型 ELYZA 13.2，MetaMath 8.0；PS 31.2；DFS(2+1) 23.2；PS+DFS 34.0；去掉 W 后 PS+DFS 26.4，说明缩放矩阵 W 关键（p13 第 800–802 行）。DFS 中源模型的排列顺序会造成超过 10 个点的差异（第 787–790 行）。
- **DFS 剔层发现（p13 第 816–820 行，Fig. 5 p14）**：DFS 跳过了 MetaMath 的第 30 层。手动删掉这一层、不做其他修改，MGSM-JA 就升到 10%（原为 8.0）。这是一个"单层删除/消融"式编辑带来提升的实证。
- **Table 5（p16，第 992–1005 行）**，VLM ROUGE-L：LLaVA 14.3/41.1；PS 19.7/51.2；PS+DFS 20.4/47.6；TIES 16.0/46.5；DARE-TIES 9.4/36.0；Passthrough 7.3/26.7。
- **附录 B（p22）**：只用开源许可模型合成的 EvoLLM-JP-A，MGSM-JA 52.4，JP-LMEH 69.0。
- **Table 6（p23）**：JP-LMEH 完整对比，7B 合并模型达到 70B 级别的水平。

## 作者自己承认的局限
- 合并模型会继承源模型的缺陷，有时输出缺乏逻辑连贯性；没有做指令微调或对齐，可能出现事实错误（p17 第 1077–1081 行）。
- 源模型需要人工挑选（p16 第 1027–1029 行），未来可以用进化来选源模型。
- DFS 只用了串联、不随输入变化的路径（p6 第 322–323 行）；W 的规模随层数平方增长；如果某个源模型微调时间长得多，简单缩放就不起作用（p13 第 802–809 行）。
- DFS 推理时显存需求大，所以没有做 DFS 的干扰实验（p12 第 734–736 行）。
- 逐层的 PS 配置在数据有限时没有带来收益（p9 第 545–548 行）。

## 方法问题与替代解释
-【推断】**基线不公平**：TIES/DARE-TIES 基线直接用 mergekit 默认超参（来自社区教程），没有调参，而 Ours(PS) 是在同一个 DARE-TIES 参数化下用 1000 次评估调出来的。所以 Table 3 中 52.0 对 35.2 的差距，本质上衡量的是"调参与不调参"的差别，不是方法类别的差别。缺少"给随机搜索或网格搜索同样 1000 次预算"的对照。
-【推断】**没有随机搜索对照**：PS 只有 6 维，随机搜索或粗网格在 1000 次评估内很可能也能接近 CMA-ES 的结果，论文没有比较。
-【推断】**优化集来自 GSM8k 测试集的翻译**（ID 250–1318），与 MGSM-JA 测试题同分布同来源；PS 直接按训练准确率选最好的 trial，没有单独的 dev 用于选择（DFS 有验证集）。存在对 GSM8k 风格过拟合的可能，不过测试题本身不重叠。
-【推断】微调基线只训 3 epoch，lr 从 3 个值里"挑最优"，论文没说按什么挑（可能是按测试集）。
-【猜测】JP-LMEH 提升（70.5）部分可能来自 task vector 放大（权重和接近 2）带来的整体"去噪"或格式改进，而不只是能力组合。
- 优点：PS 编辑完全不需要训练，评测和测试分离做得相对清楚（DFS 有验证集），并且明确展示了 LoRA 微调同时伤害通用能力（JP-LMEH 从 66.1 降到 55.9 或 52.8）的遗忘现象。

## 与 core claims（C1–C4）的关系
- **C1（同一模型通过代码自编辑自己的 LoRA）**：**未覆盖**。由外部的 CMA-ES 算法合并多个**全模型**；合并器不是被合并的模型，也不写代码、不调用诊断工具。论文还提到"模型群体自我改进"的愿景（p17 第 1037–1039 行），但只是展望，没有实现。
- **C2（同等评估预算下胜过人工合并规则和非 LLM 搜索）**：本文是 C2 中"进化搜索"基线的代表。它自己证明了进化搜索胜过**未调参**的 TIES/DARE/Frankenmerge 和 LoRA/全量微调（Table 3），但没有与 LLM 生成的编辑比较，也没有做等预算的随机搜索对照。
- **C3（递归、编辑者能力 E_t）**：**未覆盖**。PS→DFS 的两阶段算是一种"把合并结果放回候选池再合并"，但只有一层，不是递归，也不存在编辑者。
- **C4（持续多任务、遗忘控制、无外部强模型、固定外部评测）**：**部分相关但未覆盖**。论文观察到微调会造成 JP-LMEH 遗忘，而合并能保持通用能力（Table 3），但设定是一次性跨领域合并，不是持续多任务、逐轮加 adapter；搜索过程中不依赖外部强模型；评测分为优化集和测试集，没有 dev2 接受这一层。
- 另有一点与 B' 的操作集合有交集：DFS 发现"删掉单个层就能提升"（p13），PS 发现"权重和大于 1 的放大"比插值更好。这两种操作（层删除、整体缩放）都在 B' 的编辑操作集里，不过本文是在全模型或 task vector 层面由进化算法找到的。

## 作为 C2 中"非 LLM 搜索基线"的复现建议
- **适配到 LoRA**：把 B' 的每个候选 adapter（本轮原始 LoRA、历史 adapters、训练轨迹 checkpoint）的 ΔW=BA 当作 task vector，用 DARE-TIES 合并。搜索变量为每个候选的 (density∈[0,1], weight∈[0, ~1.5])，可选逐层版本（每层 2×K 维）。原文的最简版本是每个模型 2 个参数。
- **优化器**：Optuna `CmaEsSampler`，初始值 0.5，σ0=1/6，种群 4+⌊3 ln n⌋，其他用默认值。fitness 是 B' 的 dev 分数，用 dev2 做接受、sealed test 做报告（比原文多一层选择隔离）。
- **预算**：原文 PS 是 1000 trials（每次在约 1069 条样本上评估），DFS 是 100 代×128。C2 要求等预算，应把 trial 数设成和 LLM 编辑者一样的候选评估次数；同时建议报告"CMA-ES 跑满 1000 次"的上限曲线（性能对评估次数），并加入同预算的随机搜索作为对照（原文缺这一项）。
- **人工规则基线**：TIES、DARE-TIES 至少要给两档：mergekit 默认超参（与原文一致）和小网格调参后的版本，避免出现原文那种"未调参基线"的不公平。
- DFS（层重排）对 LoRA adapter 不太适用；【推断】可以把它退化成"逐层保留/丢弃 + 逐层缩放"的二值或连续掩码，交给 CMA-ES 搜索，这对应 B' 里的"丢层 / 逐层缩放"操作。
