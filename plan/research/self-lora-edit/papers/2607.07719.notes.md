## 研究问题
在任务序列上做 LoRA 式 PEFT 时，所有更新都叠在同一个冻结的 W0 上，新任务会覆盖旧任务。作者的问题是：能不能利用预训练权重的谱结构，决定哪些子空间先改、哪些后改，并找到一种跨任务的机制让知识延续下去？

## 方法细节
- **处理对象**：训练过程本身，加上任务边界处的**当前有效权重 W_eff**。它不是对训练好的 raw LoRA 做事后编辑，而是一种训练时的 PEFT 参数化，外加任务间的重分解。
- **具体操作**：
  1. **谱初始化（第 3.2 节）**：对 W0 做随机 SVD，用前几个奇异分量初始化主 adapter，思路与 PiSSA 相同。
  2. **elbow 选秩（式 8，第 3.3 节）**：用相邻奇异值比值加能量阈值 ρ=0.8，在截断的谱预算里选出每层的 r*，r 限制在 [8,16]，最后实现成秩掩码。
  3. **两阶段训练（式 9）**：先只训主子空间，过了边界 τ 后再按 γ(t) 打开残差 adapter，残差用更低的学习率。
  4. **递归合并（recursive consolidation，式 10–12，第 3.5 节）**：每个新任务开始前，对上一任务结束时的有效权重 W_eff^{(t-1)} 做 topSVD(·, k_t)，前 k_t 个分量作为“慢”主成分 W_slow（用低秩因子存储，学习率很小或延迟升温），剩下的作为冻结残差 W_res，再新建一个初始化接近零的“快” adapter ΔW_fast。任务结束后把三者相加，然后再做一次 SVD 合并。效果上，每个任务的 LoRA 都被融进权重，**不保留单独的 adapter 栈**。
  5. **TaskBank 变体（第 3.6 节）**：每个任务一个独立分支，旧分支冻结，评估时用 oracle 告诉模型该用哪个分支。作者把它当作隔离上界。
  6. 附录 A 另有单 adapter 的秩冻结和前向保持的秩扩展（老秩只参与前向、不接收梯度）。
- **谁做决策**：全部是固定算法，超参是 ρ、elbow 比值、rmax/rmin、τ 和学习率。没有 LLM 参与，没有搜索。
- **是否持续多任务**：是。6 个 GLUE 任务顺序训练：SST-2→MRPC→QNLI→RTE→QQP→MNLI（式 14）。
- **是否先训练 raw LoRA 再事后处理**：基本不是。递归合并发生在每个任务训练结束后，算是一种事后的 SVD 重分解，但处理对象是整个有效权重（包括 W0 的主成分），目的是给下一个任务重新参数化，没有根据评估去选择或修改这个任务的 LoRA。

## 数据集与评测、模型规模
- 数据：GLUE 6 任务，全部转成带候选标签词的 prompt。训练时生成标签 token，评估时选序列损失最低的候选标签。每个任务训练 200 步，max len 256，**每个任务最多 1000 条评估样本**（p.10）。
- 模型：Qwen3-8B（主实验）、Llama-3.1-8B-Instruct、Mistral-7B-v0.3、InternLM2.5-7B-Chat；另外在 Llama-3-8B 上做秩分配研究。adapter 只挂在 q_proj/v_proj（InternLM 挂在融合的注意力投影和输出投影上）。
- 指标：FinalAvg（训练完最后一个任务后，在所有任务上的平均分）和 AvgForget（每个任务的最好分减去最终分，再取平均，式 2–3）。作者指出最后一个任务的遗忘按定义恒为 0。
- **dev/probe/test 划分**：论文**没有说明**有独立的 dev/test。【推断】评估很可能用的是 GLUE 验证集的子集，而表 5 的基线秩扫描是按这同一批评估的最终平均分挑最好的 rank 来报告的，ρ 的敏感性分析也在同一批评估上做（表 9），所以超参和配置的选取与最终报告没有分开。

## 关键实验与数字
- **表 3（p.11），Qwen3-8B，3 个种子**，FinalAvg / AvgForget：
  - LoRA 0.8634/0.0414，PiSSA 0.8621/0.0418，DoRA 0.8551/0.0487
  - AdaLoRA 0.8597/0.0133（遗忘最低，但分数低）
  - O-LoRA 0.8722/0.0257
  - 静态 ReCoLoRA（不做递归合并）0.8821/0.0240
  - TaskBank（oracle 路由）0.8957/0.0000
  - 注意：表 3 里没有包含递归合并的主方法。
- **表 4（p.11），Mistral 单 adapter**：静态 ReCoLoRA 0.8031/0.0912，和 LoRA（0.8044/0.0959）基本持平；O-LoRA 0.8255/0.0675 更好。作者承认静态版本在不同 backbone 上不稳定。
- **表 5（p.13），递归 ReCoLoRA 对比按 rank 扫描后挑最好的基线，单种子 42**：
  - Qwen3-8B：0.8866/0.0135，LoRA r=64 为 0.8804/0.0290
  - Mistral：0.8634/0.0163，LoRA r=64 为 0.7979/0.1053，差 +0.0654
  - InternLM：0.8802/0.0177，LoRA 为 0.8747/0.0242
  - Llama-3.1：0.8320/0.0621，LoRA 为 0.8522/0.0551（负例）
  - 另外，PiSSA 在 Mistral 和 InternLM 上只有约 0.52，【推断】疑似基线训练崩溃。
- **三种子复查（p.12，只复跑了 ReCoLoRA）**：Qwen3-8B 0.8863±0.0004，Mistral 0.8324±0.0303（相对 LoRA 的增益从 0.0654 缩到约 0.0345，其中一个种子低于 LoRA），InternLM 0.8746±0.0049（和 LoRA 基本持平），Llama 0.8465±0.0104。作者的结论是：Qwen 和 InternLM 上优势稳定，Mistral 上有利但对种子敏感，Llama 上接近打平。
- **表 8 消融（p.18，Qwen3-8B，静态版本）**：去掉两阶段（one-stage）后从 0.8821 降到 0.6548，遗忘从 0.0240 升到 0.2331；随机初始化 0.8497；固定秩 16 为 0.8658；动态恢复 0.8566。
- **表 9（p.19），ρ 敏感性**：ρ=0.6/0.8/0.9 分别为 0.8750/0.8821/0.8849，遗忘 0.0324/0.0240/0.0197。
- **表 6/表 7（附录 B）**：Llama 上冻结旧秩可以把遗忘从 0.0631 降到 0.0283，但分数也会下降，体现了稳定性和可塑性之间的权衡。

## 作者自己声明的局限（第 6.2 节，p.14）
1. TaskBank 依赖 oracle 路由，而且每个任务存一个分支；真正部署需要学到的路由器和分支压缩。
2. 递归模型对 backbone 敏感，SVD 阈值、残差学习率、慢更新调度可能要针对每个模型家族分别调。
3. 只用了 GLUE 分类和单一任务顺序；AvgForget 偏向最后一个任务；需要更长的指令和推理任务流、更多任务排列。

## 方法问题与替代解释
- 【推断】最关键的主表（表 5）只用了单种子，而且基线取 3 个 rank 中最好的一个。这在评估集上相当于 3 选 1，对基线有利；ReCoLoRA 自己的超参也没有在独立 dev 上选。三种子复查只跑了 ReCoLoRA，没有跑基线。
- 【推断】有内部不一致：第 5.1 节正文说 ReCoLoRA 用 7.67M 参数，表 3 写的是 6.85M（7.67M 是 LoRA 的参数量）；表 5 中 ReCoLoRA 的可训练参数是 23.7–35.3M，和表 3 的 6.85M 差很多，因为递归版的慢因子也是可训练的。不同表之间的方法配置差异较大。
- 【推断】递归合并让慢成分以小学习率更新、快 adapter 每个任务重置，本质上是一种降低有效学习率、限制漂移的正则。它的低遗忘可能主要来自“每个任务改动更少”，而不是谱结构本身。论文没有和“LoRA 加上更低学习率或更少步数”这类对照比较。
- 【推断】每个任务只训练 200 步、评估最多 1000 条，规模小。GLUE 任务彼此相近（MNLI、QNLI、RTE 都是蕴含类），遗忘可能被低估。
- 【推断】TaskBank 遗忘为 0 是结构决定的（oracle 加上分支冻结），不提供关于方法本身的信息。

## 与 core claims 的关系
- **C1（同一模型自编辑自己训练出的 LoRA，事后、写代码、免训练）**：**没有覆盖**。没有 LLM 编辑者。递归合并虽然在任务边界做 SVD 重分解，但那是固定的训练流程一环，而且 ReCoLoRA 是在训练中控制更新的子空间（谱初始化、两阶段、慢/快分解），不是对训练好的 raw adapter 做事后编辑。
- **C2（同评估预算下胜过无编辑、merge 规则、非 LLM 搜索）**：**没有覆盖**。对比的是 PEFT 训练方法（LoRA/PiSSA/AdaLoRA/DoRA/O-LoRA），没有 merge 规则、搜索或评估预算这些概念。
- **C3（递归、编辑者代际能力）**：**没有覆盖**。标题里的 “Recursive” 指每个任务前递归地对有效权重做 SVD 重分解，和“被编辑的模型成为下一轮编辑者”完全无关。【推断】查新报告里需要专门说明这一点，避免名词上的混淆。
- **C4（持续多任务，用 adapter 空间操作控遗忘，不用外部强模型，固定外部评估）**：**部分覆盖**。持续多任务、靠低秩和谱空间操作控遗忘、不用外部模型都做了。但它的操作是训练时的参数化加上对有效权重的合并，不是对 adapter 栈做事后编辑；没有 dev/test 分离和验收机制；它把 adapter 融进权重，而不是维护一个 adapter 栈。
- **作为基线怎么复现**：
  1. 作为“训练时的持续 PEFT 方法”基线，和 B' 的“raw LoRA 加 LLM 事后编辑”在同一任务序列、同一训练预算（每个任务的步数）下比较 FinalAvg 和 AvgForget。
  2. 最小复现：用官方代码，对 q/v_proj 做随机 SVD 初始化，ρ=0.8，r∈[8,16]（静态版）；递归版在每个任务边界对 W_eff 做 topSVD(k_t)，最小秩 8、最大秩 256，慢因子用小学习率，快 adapter 秩为 k_t+3。
  3. 如果 B' 也用 GLUE 6 任务顺序（SST-2→MRPC→QNLI→RTE→QQP→MNLI），可以直接和它的 Qwen3-8B / Llama-3.1-8B 数字对照，但要注意它没有 dev/test 分离。
  4. 也可以把“对当前有效权重或 adapter 做 SVD 截断并以 elbow 选秩”作为 B' 中 LLM 可调用的一个操作或一个固定规则基线（单独应用于每轮 raw LoRA）。
