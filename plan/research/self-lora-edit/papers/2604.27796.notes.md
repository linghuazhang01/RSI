## 研究问题
LoRA 的 rank 通常对所有层统一设定，难以选好。AdaLoRA、SoRA、DoRA 这类在训练中自适应调整 rank 的方法，又会增加训练复杂度和不稳定性。作者主张"先训练，后调参"（Train First, Tune Later）：先用较高 rank 训练普通 LoRA，训练完成后再用 SVD 做**不需要数据**的全局 rank 重分配和压缩。

## 方法细节
- **被编辑的对象**：**单个已训练好的 LoRA adapter**，覆盖所有层类型（q、k、v、o、两个 MLP 矩阵），初始 rank r=16（p3、p6）。
- **操作**：
  1. 用 QR 分解得到 B = Q_B R_B、Aᵀ = Q_A R_A，再对 r×r 的交互矩阵 M = R_B R_Aᵀ 做 SVD。这样拿到精确的 compact SVD，复杂度是 O((d1+d2)r² + r³)，不需要拼出完整的 ΔW（p4）。
  2. 把**全模型所有 adapter 的奇异值**汇总，设一个**全局阈值 τ**，低于 τ 的分量直接丢弃（式 2）。剩下的用 √Σ 对称地分回 B̂、Â（式 3）。于是各层 rank 不同（0 ≤ r̂ ≤ r），整层奇异值都很小的 adapter 会被整个丢掉，相当于"丢层"（p4）。
  3. 阈值有两种选法：γ-PARA 先定平均目标 rank r̄ = γr，再取全局排序后的第 B_tgt 个奇异值（式 12）；ϵ-PARA 按保留能量比例 ϵ 来定 τ（式 14）。主实验用 γ=0.25，即 16 压到平均 4（p6）。
- **谁做决策**：固定的解析规则，没有学习器，也没有 LLM。唯一的人为选择是 γ 或 ϵ；作者提到 γ 可以"借助验证集搜索"来定（p5）。
- **理论依据**：Eckart–Young–Mirsky 定理说明，按 Frobenius 范数截断最小奇异值是最优的（p5）。
- **预算与数据**：完全免训练、免数据，只需一次 SVD；评估只在最终测试时进行。

## 数据集、评测与模型规模
- 视觉：SigLIP2-Base 视觉编码器，CIFAR-10/100、Pets、Flowers、Cars、Food-101、EuroSAT（表 1，p7）。
- NLU：RoBERTa-Base，GLUE 中的 MNLI、SST-2、CoLA、QNLI、MRPC（表 2，p7）。
- 常识推理：Gemma3-4B-IT 在 Commonsense-170k 上训练，测 BoolQ、PIQA、SIQA、HellaSwag、WinoGrande、ARC-C/E、OBQA（表 3，p8）。
- 数学：Gemma3-4B-IT 在 MetaMathQA 上训练，测 GSM8K、MATH（表 4，p8）。
- 基线：LoRA（按"参数量一致"的说法，推测是原生 rank 4，正文没有明确写出）、AdaLoRA、SoRA、DoRA（rank 16→4）、GoRA（预算等价 rank 4）、DyLoRA（rank 1–16），以及 Fisher-PARA 和 Local pruning 两个消融。单张 H100。
- 第 6 页写了要做"model merging"实验，但**全文找不到任何合并结果**。

## 关键实验与数字
- **表 1（p7）视觉**：PARA 平均 88.83，LoRA 84.30，DoRA 82.39，GoRA 82.45，AdaLoRA 76.96。CIFAR-100 上 PARA 79.08，LoRA 68.11，差距异常大。
- **表 2（p7）NLU**：PARA 86.45，LoRA 85.59，GoRA 84.49，AdaLoRA 68.55。
- **表 3（p8）常识推理**：PARA 60.4，LoRA 58.7，DoRA 57.6。
- **表 4（p8）数学**：PARA 平均 61.8（GSM8K 78.2、MATH 45.5），LoRA 60.8（77.5、44.1）。
- **图 3、4（p6）Stanford Cars**：丢掉低能量的尾部奇异值时，精度在很宽的范围内保持稳定；反过来丢掉少数几个高能量方向，精度会灾难性下降。作者还称"较高 rank 的压缩版 adapter 略好于父 adapter"，把这解释为去噪（p6），但图中的具体数值不在文本里。
- **图 5、6（p7）多 rank 部署**：PARA 子 adapter 优于 DyLoRA 和同 rank 的原生 LoRA。
- **图 7（p9）**：PARA 与基于 Fisher 的重要性选择（Fisher-PARA）精度接近持平，而后者需要 50 个 batch 的梯度。
- **表 5（p9）全局 vs 逐层均匀截断**：全局阈值一致更好，例如 MRPC 86.76 对 83.17，Food 86.40 对 84.49。

## 方法问题与替代解释
- 【推断】主表没有给出 rank-16 父 adapter 的数字，"LoRA"这一行很可能是原生 rank 4。因此 PARA 胜出也可能来自"用更高 rank 训练"本身，而非全局分配。CIFAR-100 上 +11pp 的差距很可能主要反映原生 rank-4 训练不充分（或调参不同）。
- 【推断】没有多种子，也没有标准差；AdaLoRA 在 MNLI 上只有 50.86，接近随机水平，说明基线可能没有调好。
- 【推断】"压缩后略好于父 adapter"只在 Cars 这一个数据集上以图的形式给出，幅度小，但对 B' 很重要：它提示单纯的 SVD 截断本身就可能带来增益（去噪或正则化效果）。
- 【推断】第 6 页声称做了模型合并实验，但文中没有对应结果，可能是删减后留下的文字。
- 【推断】γ 的选择要么固定为 0.25，要么"由验证集搜索"，但搜索的预算和协议没有说明。

## 与 core claims 的关系
- **C1**：**未覆盖。** PARA 是固定的解析算法，不是模型自己做诊断和编辑。不过它的诊断（奇异值谱）和操作（rank 截断、整层丢弃）正是 B' 的工具和算子之一。
- **C2**：在"非 LLM 的固定规则"一类里，它是必须纳入的基线：零搜索成本、免数据，而且可能单独就超过 no-edit。如果 LLM 编辑者带来的增益主要来自 rank 截断，PARA 就能直接把这部分解释掉。
- **C3**：**未覆盖。**
- **C4**：**未覆盖。** 它处理的是单任务、单 adapter 的压缩，不涉及多任务、遗忘或 adapter 合并。
- **作为 C2 基线如何复现**：
  1. 对每轮新训练的 raw LoRA 直接做 PARA：QR+SVD，全局阈值。γ 取 {0.125, 0.25, 0.5}，ϵ 取 {0.9, 0.95, 0.99}。在 dev 上选最好的配置，**并把这几次 dev 评估计入评估预算**。
  2. 必须同时汇报 rank-16（或你实际用的 rank）父 adapter 的 no-edit 结果，以及逐层均匀截断（Local pruning）的结果。
  3. 实现很简单（式 1–3、12、14），官方代码尚未公开，需要自行实现。
  4. 可以再做一个"PARA 加上整层丢弃"的组合基线，与 LLM 写出的"截断加丢层"编辑做对照，看 LLM 是否带来了超出解析规则的增益。
