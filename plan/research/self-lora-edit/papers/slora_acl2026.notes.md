## 研究问题
持续学习中的灾难性遗忘，有没有办法缓解而不限制模型学新任务的能力？作者的假设是：后续任务 LoRA 更新里“不重要的成分”属于噪声，会干扰前面任务的知识。验证这个假设的预实验是两任务顺序训练（Amazon 之后 Yahoo，Llama3-8B）：训练完后按比例丢掉第二个任务 LoRA 中不重要的成分（DropSecond），任务 1 的准确率反而超过 Seq-LoRA；丢第一个任务的成分（DropFirst）则一直在掉（图 1，p.2；附录 B.3，p.14–15）。

## 方法细节
- **处理对象**：每个任务训练完的 raw LoRA 增量 Δθ_k = B_k A_k，按模块逐个处理（Q/K/V/O/up/gate/down，图 6）。处理的不是当前有效权重，而是单个任务的增量矩阵。
- **具体操作（式 3–5，p.4）**：
  1. 对 Δθ_k 做 SVD，得到 UΣV^T（实现里用随机 SVD，附录 C.2）。
  2. 对候选秩集合 C 里的每个 c，计算 Grassmann 相似度 φ_c = ||U_ref,c^T U_c||_F^2。其中 U_ref,c 是参考权重前 c 个左奇异向量，参考权重固定用预训练基座 θ0（第 4.3 节）。
  3. 取 c* = argmax φ_c，只保留前 c* 个奇异分量重构，得到去噪后的 Δθ̃_k。其余分量当作噪声丢掉。
  - 本质上是**按奇异值大小做秩截断，截断位置由“与基座主子空间的重合度”决定**，属于固定的闭式规则。【推断】论文正文和附录都没有给出候选集 C 的具体取值。
- **谁做决策**：固定算法。不用 LLM，不搜索，也不用任何 dev 分数选 c*。c* 完全由权重几何决定。
- **两种变体（第 4.4 节，算法 1/2，p.17–18）**：
  - SLoRA-Pre（在线）：训练任务 k 的 LoRA 时，以 θ_{k-1}（前面任务去噪后累加的结果）为起点；训练完马上去噪，并入后再训下一个任务。
  - SLoRA-Post（离线）：先把所有任务的 raw LoRA 存进 buffer，最后统一并行去噪再相加。【推断】算法 2 第 6 行写的是在 θ0 上训练每个任务，而图 2(b) 标注训练阶段是 Sequential，两处说法不一致，没有讲清楚 Post 的训练是否从前一任务的权重接着训。
- **是否持续多任务**：是。主实验 TRACE 8 个任务；标准 CL 基准 4 任务 × 3 种顺序；长序列 15 任务（附录 B.5）。
- **每个任务是否“先训练 raw LoRA 再事后处理”**：是。作者明确说是 post-hoc、不需要正则、不改训练过程、不用旧数据或梯度（p.1、p.3）。
- **合并方式**：去噪后的各任务增量直接相加：θ_K = θ0 + Σ Δθ̃_i（式 2）。没有缩放系数，没有 TIES/DARE，也没有对旧 adapter 做正交化。
- **理论部分（附录 A）**：在 Assumption 1（子空间演化假设）下证明，参考权重取 θ_{t-1} 时历史对齐分数 A(t) 趋于 0，取 θ0 时趋于常数 C。假设本身比较强，见下文“方法问题”。

## 数据集与评测、模型规模
- TRACE 8 任务（表 7，每个任务 5,000 条）：C-STANCE、FOMC、MeetingBank、Py150、ScienceQA、NumGLUE-cm、NumGLUE-ds、20Minuten。指标分别为 Acc / ROUGE-L / SARI / Edit similarity。顺序固定，epoch 数为 5/3/7/5/3/5/5/7。
- 标准 CL 基准：AG News、Amazon、Yelp、DBpedia、Yahoo，3 种顺序（表 8、9）。长序列 15 任务沿用 O-LoRA 的 Order-4。
- 模型：Llama3-8B-Instruct、Llama3.1-8B-Instruct、Qwen2.5-7B-Instruct（完整对比）；Qwen2.5-14B、Qwen2.5-32B（只比 Base / Seq-LoRA / SLoRA）。
- LoRA 设置 r=64、α=128，lr 2e-4，4×A100。
- **dev/probe/test 划分**：论文没有说明有单独的 dev 集。c* 本身不用数据选。但消融（表 4，选择策略、相似度度量、参考模块）是在 TRACE 前 4 个任务上直接报告最终分数，看起来就在测试指标上比较设计选择。【推断】设计选择的选取与报告没有分开。

## 作者自己声明的局限（p.10）
1. 需要白盒访问基座权重，黑盒 API 场景下用不了。
2. 随机 SVD 去噪带来少量额外计算。
3. SLoRA-Post 要缓存所有 raw 更新，显存/存储开销随任务数增长。

## 方法问题与替代解释
- 【推断】c* = argmax ||U_ref,c^T U_c||_F^2 这个式子的值会随 c 单调不减（c 越大，两个子空间的重叠能量越大），按字面计算，argmax 很可能总是取 C 里最大的 c。实际效果取决于 C 的取值或某种归一化，论文没有交代。图 6 的保留率在 0.2–1.0 之间，说明实现中可能有归一化（比如除以 c）。这一点影响复现。
- 【推断】核心操作其实就是“秩截断加固定选秩准则”。SLoRA 胜过 Seq-LoRA 的部分原因可能只是“任意适度的秩截断或缩放都能减少干扰”。论文没有和“固定比例截断”“固定缩放 λ”“Task Arithmetic λ<1”等简单事后基线比较（表 4 的 min/minor 是在同一框架里换选择方向，不是等预算的简单截断）。
- 【推断】没有 dev/test 分离：设计选择（表 4）和报告用的是同一批测试分数；不同模型上 Pre 和 Post 互有胜负（表 1–3、表 11），没有给出事前选哪个的规则。
- 【猜测】32B 结果里 Seq-LoRA 的 Py150 异常低，可能是训练崩坏或解码问题，会放大增益。
- 理论部分的 Assumption 1（不同任务创新方向几乎正交、与参考子空间正交）是为了得出结论专门设定的，Theorem 1 的证明比较粗（比如 ||R_t||_2 ≈ ||R_t||_F）。

## 与 core claims 的关系
- **C1（同一模型自编辑自己的 LoRA，用代码，免训练）**：**没有覆盖**。SLoRA 确实对训练后的 raw LoRA 做免训练的事后权重空间编辑（SVD 截断），也是“先训练、再事后处理”的流程，这一点与 B' 的流水线形状一致。但决策者是固定的闭式算法，没有 LLM 参与诊断或写代码，更没有“模型编辑自己”。
- **C2（同评估预算下胜过无编辑、人工 merge 规则、非 LLM 搜索）**：**没有覆盖**。SLoRA 是一个可以拿来作对照的“人工规则”。论文没有比较 TIES/DARE/Task Arithmetic，没有搜索类基线，也没有评估预算的概念（c* 不需要评估）。
- **C3（递归、编辑者能力随代际提升 E_t）**：**没有覆盖**。没有编辑者这个概念，也没有代际。SLoRA-Pre 的“下一任务从去噪后的模型继续训练”只是顺序训练，不是“被编辑的模型成为下一轮编辑者”。
- **C4（持续多任务，用 adapter 空间操作控遗忘，不用更强外部模型，固定外部评估）**：**部分覆盖**。持续多任务、只靠 adapter 空间操作（事后 SVD 去噪）控遗忘、不用外部模型（核心方法不用；RCL 基线用了 GPT-4），这几点 SLoRA 都做了，所以“持续学习中对每个任务的 raw LoRA 做事后权重空间处理来降遗忘”这一设定已被 SLoRA 占据。没有 dev/dev2/sealed test 这类外部验收机制。
- **作为基线怎么复现**：
  1. 在 B' 的每一轮里，用同一份 raw LoRA，按算法 1（Pre）计算 ΔW=BA，逐模块随机 SVD，用基座 W0 的前 c 个左奇异向量算 φ_c，取 c* 截断后并入；或者按算法 2（Post）最后统一处理。
  2. 需要自行设定 C（比如 {r/8, r/4, r/2, r}），并确认 argmax 是否需要归一化，可以参考官方代码。
  3. 作为“固定规则型事后编辑”的强基线，与 LLM 写的编辑在同一 raw LoRA、同一评估集上对比。还应补上“固定比例截断”“TA λ 扫描”，以区分 SLoRA 的特定准则和一般截断带来的收益。
  4. 设置建议直接用 TRACE 8 任务（Llama3.1-8B 有现成数字，Seq-LoRA 52.81，SLoRA-Pre 60.19），方便和已发表结果对照。
