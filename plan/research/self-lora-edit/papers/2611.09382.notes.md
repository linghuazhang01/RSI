## 研究问题
在 Takehi 等人博客（WSP）的框架下系统考察三件事：WSP 能把模型的哪些能力提升多少（Capabilities）；针对单任务的编辑能否迁移到其他任务（Generalization）；编辑过程是否可靠、可复现（Limitations）。

## 方法细节
- **编辑者**：GPT-6 Astra，maximum reasoning effort（附录 A，p.10）。
- **被编辑者**：Qwen3.5-0.8B 和 Qwen3.5-9B 的**基座全量权重**中 transformer block 内的参数。token embedding、final norm、lm_head 和架构都不许改（第 2 节 p.3，附录 F p.19）。实际编辑落在 mlp.down_proj 的单列或 rank-1 更新、attention o_proj 中单个 head 的块（置零或缩放），9B 还改过 q_proj 的 gate 行（附录 C，表 5、表 6，p.12–15）。**编辑者与被编辑者不是同一 checkpoint，也不涉及 LoRA 或 adapter**（LoRA 只在引言里作为背景出现过一次）。
- **编辑方式**：在持久的 Python kernel（CPU，没有 GPU）里写代码，调用 load/save_edit/drop_edit 改张量，用 float32 计算、以 bf16 存储。形式化为 θ_{t+1}=bf16(θ_t+Δθ_t)，其中 Δθ_t 是由 agent 生成的编辑程序（式 1，p.3）。禁止梯度、优化器和迭代拟合，也禁止在 kernel 里模拟前向（附录 F RULES，p.21）。
- **诊断信息**：每次搜索有 50 次成功的 forward 请求，分两类。G 是生成，返回准确率、长度、截断比例和配对比较；TF 是 teacher forcing，返回 token logprob、top-k、隐状态、MLP 激活和注意力。另外最多可以跑 300 次 Python 分析（附录 A，表 3，p.10）。
- **多轮**：一次搜索内是“诊断—编辑—探测—选择或回退”的迭代（图 2，p.3；表 9 列出了 Math Primary 全部 50 次请求，p.17–19）。最后由编辑者自己决定提交编辑后的权重还是保留原权重。**每次搜索都从原始 checkpoint 开始，被编辑后的模型不担任下一轮编辑者，也没有跨任务累积编辑**。
- **对照**：只和未编辑的基座做配对比较。Math Primary 轨迹里有轨迹内的消融、反向方向、单个等范数随机正交方向和剂量扫描对照（附录 E，p.17）。**没有同预算的梯度微调、LoRA、随机或进化搜索，也没有 TIES/DARE 等 merge 规则对照。**

## 数据集与评测、模型规模
- 7 个基准（表 1 p.4，表 4 p.11）：
  - MATH：dev 为 GSM8K 和 MATH 训练集加 AIME，test 为 MATH-500
  - MMLU-Pro：dev 为 70 道 validation，test 为 12,032 题
  - IFEval：541 条官方 prompt 按 270/271 切分
  - GPQA：dev 为 Main 去掉 Diamond，test 为 Diamond 198 题
  - MedXpertQA：dev 为 MedQA 加 5 道 dev，test 为 Text 子集 2,450 题
  - SciBench：dev 112 题，test 580 题
  - SciCode：dev 15 条链，test 65 条链
- 模型：0.8B 和 9B 两个规模；thinking 打开；temperature 0.6，presence penalty 1.5，上限 32,768 token，seed 0（表 3）。
- 一共 16 条轨迹：7 个基准 × 2 个规模，再加上 0.8B Math 的两次复跑。

## 关键实验与数字
- 表 2（p.5）：
  - 0.8B 的 held-out 提升：Math 从 8.35 到 37.80（+29.45），GPQA-D +4.42，IFEval 从 21.40 到 58.12（+36.72），SciBench 从 1.38 到 18.49（+17.11），SciCode 0 到 0。MedXpertQA 和 MMLU-Pro 最终保留了原权重。
  - 9B：IFEval +1.85，SciBench +3.03，SciCode +1.54；Math 候选在 dev 上 +29.69，held-out 却是 −0.35，最终没有采用。
- 6/16 条轨迹最终保留原权重（摘要；p.4 第 3.2 节；表 2 中带 * 的行）。
- 第 3.4 节和图 4（p.6）：三次独立的 Math 搜索分别得到 +29.45、+5.00、+27.30。三次都改了第 23 层的 MLP down_proj，但结构不同：分别是单列（1,023 个 bf16 值）、稠密 rank-1（1,037,572 个）、rank-1（1,981,083 个）（图 5，表 7，p.7、p.16）。
- 图 6（p.7）：跨任务迁移。0.8B 的 Math 编辑版在 GPQA-D 上 28.28（+3.03）、IFEval 33.58（+12.18）、SciBench 21.48（+20.10）。迁移有正有负。
- 图 7（p.8）：0.8B 在所有基准上的 dev 提升都大于 9B，作者解释为基线越低、可提升空间越大。
- 附录 D（p.16）：0.8B MedXpertQA 的候选 B 把截断数从 502 降到 296，准确率却下降 0.65 个点，因此保留原权重。
- 附录 E（p.17）：Math Primary 在 6 个互不相交的 dev 集（共 1,152 题）上从 126 题升到 484 题（10.94% 到 42.01%）；AIME 两组都是 0/64。剂量扫描在 α=1 时最好；等范数随机方向是 10/48，目标编辑是 20/48。
- 附录 C（p.13）：Primary 的编辑方向是“犹豫词（Wait/However/…）减去推进词（Therefore/So/…）”的 readout 差，作用在第 23 层第 507 列。

## 作者自己声明的局限
- 在 50 次请求的预算内经常找不到可靠的干预（p.8 "Limited Search Budgets"）。
- dev 上的提升不一定能转化为 held-out 提升；反复评测的计算成本很高；成功编辑和泛化的机制都不清楚；多处联合编辑的效果、dev 数据规模和多样性的影响都没研究；长程推理和 agentic 任务没有评估（第 4 节 p.8）。
- 搜索结果依赖路径，不同独立轨迹得到的解差别很大（p.6）。
- dev 结果是自适应选出来的，没有做多重比较校正（附录 B，p.11）。

## 方法问题与替代解释
- 【推断】0.8B 上的大幅提升主要来自抑制思考循环和截断（Math Primary 的方向就是“犹豫词对推进词”，F1 时 128 个样本中 111 个撞了上限），与博客 Exp 8 的机制相同。Math 编辑版迁移到 SciBench 后的 21.48 甚至高于专门针对 SciBench 的编辑（18.49），这进一步说明改的是通用的“完成回答”能力，不是任务知识。
- 【推断】每个“模型×基准”只有一条轨迹，held-out 只评一次（seed 0）。文中给了 SE 公式，但表 2 没报置信区间，所以 GPQA +4.42（198 题）这类小幅差异可能不显著。
- 【推断】9B 的 Math 在 dev 上 +29.69、held-out 却 −0.35，原因是 9B 在 MATH-500 上已有 97.7% 的天花板，dev 集（含 AIME）分布不同。这说明 dev 和 test 分布不匹配，加上自适应选择，可能产生过拟合。
- 【推断】Prompt 和目标中途会改（Math Rerun 1 在第 46 次请求后才把目标从“循环”放宽到“整体能力”），所以三次复跑并不是严格的同条件重复。
- 【猜测】没有等预算的非 LLM 搜索对照（例如在 down_proj 列上随机缩放或置零、按 dev 选优）。考虑到 0.8B 的瓶颈是截断，简单搜索也可能找到类似的编辑。

## 与 core claims 的关系
- **C1（同一 checkpoint 自编辑其 LoRA）**：**未覆盖**。外部的 GPT-6 Astra 编辑 Qwen3.5 的基座权重，不是自编辑，也没有 adapter。
- **C2（同评测预算下胜过 no-edit、merge 规则、非 LLM 搜索）**：**仅部分**。只证明了胜过 no-edit（而且只在部分基准上，6/16 条轨迹保留原权重）；没有 merge 规则对照，也没有等预算的随机、进化或 LoraHub 式搜索对照。轨迹内的“单个等范数随机方向”只是机制对照，不是同预算的搜索基线。
- **C3（递归，被编辑模型担任下一轮编辑者，测 E_t）**：**未覆盖**。编辑者固定，每次搜索都从原始权重重新开始，没有跨代测量。
- **C4（持续多任务、adapter 空间里控制遗忘、不用更强的外部模型）**：**未覆盖**。有“跨任务迁移”评估（图 6），但这是单次编辑后的旁路评测，不是持续学习，也没有遗忘控制操作；而且依赖更强的外部模型。
- 总体：这是对 WSP 的系统性实证复现和扩展。它最接近 B' 的部分是“LLM 写代码、用诊断工具改权重、外部 dev/test 验收、可以回退”这套流程；但编辑对象（基座稀疏方向，而非自己训练出的 LoRA）、编辑者身份和递归都不同。它报告的“dev 选优在 held-out 上失效”和“不同轨迹方差大”，对 B' 的 dev2/sealed test 设计有直接参考价值。
