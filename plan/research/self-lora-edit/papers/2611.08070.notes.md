## 研究问题
Takehi et al. 的 "weight-space programming"（WSP）博客/技术报告声称 GPT-6 Astra 能直接读写网络权重。本文只审计 **读权重（reading）** 这一侧：一个通用 LLM 在零工具、零前向、不给数据集/类名的条件下读入小 CNN 的全部原始权重文本，它的推断到底是"沿权重流追踪计算"，还是"网络边缘的局部算术 + 对公开数据集的记忆先验"。

## 方法细节
- **"编辑者"/读者是哪个 LLM**：Claude Opus 5.5（claude-opus-5-5，xhigh effort），通过 Claude Code CLI 非交互模式调用，工具/MCP/记忆全部关闭（p6 §4.4）。
- **被读的模型**：作者自己训练的 3 种小 CNN（Model 1: 16/32/64 通道；Model 2: 13/33/77；Random: 62/68/25），约 12.4–12.7 万参数（p5 §4.1）。读者 LLM 与被读网络 **完全不是同一模型**，也不是同一类模型（LLM vs 小 CNN）。
- **编辑方式**：**无编辑**。作者明确写"We do not test weight editing"（p3 第 115 行）；Table 7 中"Weight editing works the same way"一项为 Not tested，编辑实验"在完成前被停止"（p13 第 579 行）。
- **诊断信息**：只给权重文本（3 位小数）、层公式、BN running stats；不给数据集名、类名、归一化常数、优化器、增广（p6 §4.3，附录 B 给出完整 prompt）。不允许代码执行或前向。
- **多轮/递归**：无。每个问题一个全新会话、单次回答（部分会话因 128k 输出上限触发自动续写，p15）。被读模型从不成为下一轮读者。
- **基线比较**：无与梯度训练、随机方向编辑、非 LLM 搜索的比较（因为没有编辑）。对照是数据层面的：标签置换（reordered）、权重打乱（shuffled）、架构对比、熟悉度不同的数据集、准确率对比。

## 数据集与评测、模型规模
- 数据集：CIFAR-10、KMNIST、Cats vs Dogs、Fast food（3000 张）、SAT-6（Table 1，p6）。
- 评测：原始问题"训练于哪个数据集"打 pass/partial/neutral/fail；修订问题打图像类型 correct/partial/wrong，类名按"同位置/任意位置"计数（附录 C，p19）。评分由 Claude Code 依预写规则完成，无第二评分人（p7）。
- 规模：读者为前沿闭源 LLM；被读网络约 12.5 万参数。

## 关键实验与数字
- Table 1（p6）：各网络测试准确率；SAT-6 高准确率 99.57%，"三步更新"低准确率网络 36.01%（低于多数类 37.12%）。
- Table 2（p8）：CIFAR-10 对照。原始权重→CIFAR-10（90%）；输出重排（车辆类移到 2/4/5/7）→仍答 CIFAR-10（72%），找到了新索引上的分组但 9 对类名全错；打乱权重→CIFAR-10 best guess（45%），且未识别出权重被打乱。（第 349 行）
- Table 3（p9）：KMNIST 两个模型都被认作 MNIST（80%/85%）；Fast food 被认作 CIFAR-10（45%/50%）；Cats vs Dogs 一次 CIFAKE（30%）一次正确（35%）。
- Table 4（p9）：修订问题下 CIFAR-10 Model1/Random 均 10/10 同位置正确；KMNIST 0/10；KMNIST Random 会话无答案（耗尽输出 + 安全停止）。
- Table 5（p10）：SAT-6 高准确率网络被判为"动物照片/CIFAR-10"（70%/45%），0/6 类别；低准确率网络 4/6（但为通用场景猜测，类别置信度 3%）。（第 442 行）
- Table 6（p10）：读到"深绿"特征偏向输出 4（实际是 trees），结论"frog"；"blue"特征实际与蓝色负相关（−0.44）。
- §5.5（p10–11）：会话自述只细读首末层、抽样中间层；部分追踪性论断（top-heavy 空间证据、通道索引偏移 2）经核验失败。SAT-6 中 4 条通道→输出论断有 3 条正确。
- Table 7（p13）：对"去魅化"解释各组成部分的证据等级汇总。
- Table 8/9（p17）：全部会话结果；Table 10（p20）：引用数值核对，绝大多数无误（如 CIFAR-10 Model2 34 项 0 错），说明局部算术准确。
- 局部算术亮点：从 BN 统计 + PyTorch 默认值推断"约 3 步 Adam"（p2、p17 注）。

## 作者自己声明的局限（§7，p14–15）
- 只测一个模型、一个 effort 等级；大多数条件只跑一次单种子，无置信区间/显著性检验。
- 无工具，手算 12.5 万权重本身可能不可行；关于"未追踪"的证据是间接的、基于自述；未做前向通道测试。
- Prompt 混杂：原始问题诱导给出"知名数据集"名；标签置换等对照只在原始问题下跑过；KMNIST 被描述为 RGB；所有输入都是 32×32，形状先验仅间接支持。
- KMNIST 归一化在 padding 后计算，背景值偏向 MNIST。
- 低准确率网络同时也是训练很少的网络，二者不可分；只有一对。
- 三个会话触发了 128k 输出上限续写；无第二评分人；数据集版本未记录 commit；闭源模型行为漂移。

## 方法问题与替代解释
- 【推断】"无工具、无代码"设定与 WSP 原报告（有 Python 环境、前向预算）差异很大，结论只能约束"零工具心算读权重"，不能外推到"带诊断工具写代码编辑权重"的场景。作者本人也在 Future Work 第 4 条承认这一点（p15）。
- 【推断】样本量极小（关键的标签置换只 1 次），"依赖记忆的标签顺序"结论是定性的。
- 【推断】评分由同公司另一 Claude 实例完成，存在评分者-被测同源偏差，虽作者声明被测会话不可见这些工作。
- 【猜测】若给 Python 工具和小量前向，读权重能力可能大幅提高，届时"边缘算术 + 先验"的描述未必成立。

## 与 core claims 的关系
- **C1（同一 checkpoint 自编辑自己的 LoRA，代码、免训练）**：不覆盖。读者 Claude Opus 5.5 读的是外部小 CNN，不是自身；无编辑、无 LoRA、无代码。
- **C2（同评估预算下胜过 no-edit / TIES/DARE / 非 LLM 搜索）**：不覆盖。无编辑，无任何合并/搜索基线。
- **C3（递归、被编辑模型当下一轮编辑者，测 E_t）**：不覆盖。单轮单次会话。
- **C4（持续多任务、遗忘控制、无更强外部模型、固定外部评估）**：不覆盖。
- **对"LLM 能否有意义地编辑权重"可行性的证据**：**偏负面但间接**。表明零工具条件下前沿 LLM 对权重的"语义理解"主要依赖记忆先验，只有局部统计（BN、输出层符号、初始化尺度）可靠；作者在 §6.5（p13）提出：基准提升的编辑应证明依赖"理解"而非对权重的搜索。对 B' 而言可作为动机/风险论据："LLM 写出的编辑是否只是搜索"需要随机/非 LLM 搜索在同预算下的对照，这与 C2 的设计目标一致。正面一点：局部低维统计（类似范数、谱、符号结构）LLM 能准确计算，这与 B' 使用的诊断工具（范数、奇异值谱）类型接近，但本文中 LLM 不能调用工具。
