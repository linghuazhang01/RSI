## 研究问题
Coding agent 的表现由 policy 和 harness 两部分共同决定。只优化 harness，模型本身不会变强；只优化 policy，它只能从固定 harness 引出的轨迹里学习。已有的联合方法依赖外部的 harness proposer，而且 policy 一变，failure mode 也跟着变，优化目标在移动。本文提出 Self-HPO：让当前的 policy 自己担任 harness proposer，交替做 harness 搜索（H-step）和 RL（P-step）。下一轮的 harness 搜索集取自 RL 中始终没解出来的难题。

## 方法细节
- **模型**：Qwen3.5-35B-A3B 作为基座 policy。种子 harness 是 mini-SWE-agent，ReAct 循环中执行 bash（§3.1，p4；附录 A，p16）。用 SGLang 部署，用 slime 框架做 RL/SFT，硬件为单节点 8×B200。
- **H-step（§2.2，Algorithm 1，p3–4）**：固定 P_t。P_t 同时担任解题者和 harness proposer。proposer 以 coding agent 的形式工作，有 shell 权限，可以查看父 harness、它在搜索集上的轨迹、**搜索集任务的参考修复（reference fixes）**、之前候选的输出，以及自己逐轮追加的笔记（附录 D，p19）。每个 H-step 生成 K=6 个候选，每个候选在搜索集 S_t 上每题跑一次，按 resolve rate 选出最好的作为 H_{t+1}。harness 的搜索空间是继承种子 agent 的 Python 子类加 prompt 模板，可以重写 step()、拦截提交等（附录 D，p18）。
- **P-step（§2.3；附录 A，p16 第 1144 行起）**：固定 H_{t+1}，**从 P_t 继续训练**，在训练集 D 上做 on-policy RL。优化器是 GRPO 加 Orchard 的 BAR：每题采样 8 条轨迹，从中选 4 条组成成功率在 0.25–0.75 之间的平衡组，凑够 32 组即 128 条轨迹作为一个 batch，做一次优化更新。Adam，常数学习率 1e-6，weight decay 0.01，熵系数 1e-4，不加 KL，clip 区间为 0.2/0.28。每个 P-step 做 50 次更新。**全文没有提到 LoRA**，【推断】是全参数 RL（学习率 1e-6，单节点 8×B200）。
- **谁做什么**：
  - 训练数据：P_t 在 H_{t+1} 下的 on-policy rollout，奖励由可执行 verifier 给出（二值）。训练任务池是人类构建的 2,484 题（SWE-rebench、SWE-rebench V2、Scale-SWE）。
  - 超参、训练算法、训练代码：**全部由人类固定**（GRPO+BAR、lr、更新次数等），policy 不参与决定。
  - harness（执行脚手架代码和 prompt）：由当前 policy P_t 编写，这是模型唯一的“作者”角色。
  - 评判：harness 候选按搜索集上的 resolve rate 评（可执行测试），RL 奖励也来自可执行 verifier，都不是 LLM judge。
  - 被训练的模型：Qwen3.5-35B-A3B，与 proposer 是同一个 checkpoint。
  - **外部模型**：Self-HPO 设定下没有外部模型。对照组 HPO 用 **Opus 4.8** 作为固定的外部 proposer。SFT 基线蒸馏的是 Opus 4.8 的轨迹。Meta-Harness 基线也用 Opus 4.8（§3.1，p4）。另外，proposer 能看到人类写的参考修复，这属于外部信息，但不是来自模型。
- **轮次**：2 轮（H1→P1→H2→P2），停止条件是难题集在两轮之间趋于稳定（§3.1）。
- **每轮从哪里开始训练**：从当前 P_t 继续训练，不重置到 P0（附录 A，第 1144 行）。
- **训练后的模型在下一轮承担的角色**：
  - harness proposer（H-step 2）：P1
  - 搜索集上的解题者（H-step 2）：P1
  - RL 的初始化和采样者（P-step 2）：P1
  - 下一轮搜索集：由 P-step 1 中 P1 的训练轨迹选出的难题
  - 训练方案、超参：始终是人类固定的配置，模型不承担这个角色

## 数据集与评测
- 训练和搜索：2,484 个 Python 仓库任务。初始搜索集 S0 是从中随机抽取的 300 题。
- 评测：SWE-Bench Verified（500 题，主基准），SWE-Bench Multilingual（300 题，OOD），SWE-Bench Pro 公开 V2（642 题，OOD）。指标是 resolve rate，报告 3 次评测的均值和标准差（avg@3）。step 上限 250，temperature 和 top-p 均为 0.95。
- 基线：RLVR（只更新 policy，用种子 harness）、Self-Harness（只更新 harness，用 base policy 当 proposer）、SFT（蒸馏 Opus 4.8）、Meta-Harness（Opus 4.8 当 proposer）、HPO（Opus 4.8 当 proposer，加 RL）。

## 关键实验与数字
- **Table 1（p5，第 392–400 行）**：
  - Base：61.0 / 54.2 / 58.3，平均 57.8。
  - RLVR：67.5 / 56.3 / 61.8，平均 61.9。Self-Harness：65.2 / 54.3 / 60.7，平均 60.1。
  - **Self-HPO：69.5 / 59.7 / 65.2，平均 64.8**。
  - 外部设定：SFT 平均 54.6，Meta-Harness 63.5，HPO（Opus 4.8）71.6 / 61.4 / 66.0，平均 66.3。
- **Fig.3（p6）和 Fig.6（p17）**：轨迹为 Base 61.0 → H1 64.3 → P1 67.8 → H2 68.6 → P2 69.5（SWE-Verified）。同样从 H1 出发，只继续做 harness 搜索的 Self-Harness 分支停在 65.2。
- **Table 2 消融（p6，第 496–506 行）**：注意，这些消融都以 **HPO（Opus proposer）71.6** 为参照，不是在 Self-HPO 上做的。P-step 改成 SFT 为 67.2，改成 RFT 为 70.5；搜索集固定不变为 70.1；proposer 换成当前 policy 自己（即 Self-HPO）为 69.5（−2.1）。
- **Table 3 交叉评测（p6，第 522–530 行）**：行是 harness，列是 policy。H0：61.0 / 61.7 / 64.4；H1：64.3 / 67.8 / 68.1；H2：64.5 / 68.6 / 69.5（列依次为 P0/P1/P2）。H2+P2 比 Base 高 8.5，超过 H2 单独 3.5 和 P2 单独 3.4 之和 6.9。
- **Fig.4（p7）**：pass@8 从 80.0 升到 84.8；在 Base 下属于 Hard、Medium、Easy 的题上，pass@1 分别 +6.1、+17.2、+12.9，在 Resolved 组上 −2.2。最后一个 P-step 中零成功组的比例降到 6.5%，RLVR 一直在 11–17%。
- **是否测量了编辑者能力随轮次的变化**：**没有直接测量**。最接近的证据是 Table 3：在固定的 recipient P0 下，H2（P1 编写）得 64.5，H1（P0 编写）得 64.3，差 0.2，在标准差 ±1.1/±1.5 之内。但 H2 是在 P1 下、用不同的搜索集和父 harness 搜出来的，混杂因素很多。论文没有做“P0 和 P1 分别当 proposer，为同一个 solver 搜 harness”这样的对照，所以无法区分“作者变强”和“搜索条件不同”。

## 作者自己声明的局限
- 论文**没有单独的 Limitations 节**。文中零散承认了几点：Self-HPO 比用外部 Opus 4.8 当 proposer 低 2.1（§3.3），外部模型有帮助但不是必需；Self-HPO 的提升在 Resolved 组上不是均匀的，有 −2.2（§3.4）；案例研究里的 PR-intent 提醒属于误报（附录 E）。

## 方法问题与替代解释
- 【推断】只做了 2 轮，而且停止条件依赖难题集是否稳定，递归能否持续改进没有证据。
- 【推断】消融都在 HPO（外部 proposer）上做，Self-HPO 本身没有“固定搜索集”“SFT/RFT 替代”这些消融。
- 【推断】harness proposer 能看到搜索集任务的人类参考修复，这是一种额外的监督信号。“自我改进”里含有人类标注信息。
- 【推断】每个候选 harness 在搜索集上每题只跑一次，选择时噪声较大。训练只跑一次（没有训练 seed 的方差），报告的 ±std 只是评测的方差。
- 【推断】Table 3 显示 H1 下 P2 只比 P1 高 0.3，H2 下高 0.9，第二轮的增益较小。
- 【推断】这里的“编辑”指 harness 代码，不是训练配方或权重。模型对自身权重更新的影响只是间接的：它改变 harness，从而改变 RL 收集到的轨迹分布。

## 与 core claims 的关系
- **B1**：**基本不覆盖**。同一个 checkpoint 编写的是 harness（执行脚手架和 prompt），训练数据只是它自己的 on-policy rollout。harness 会间接影响数据分布，但模型**不决定**超参、训练算法、LoRA 配置或训练代码，也不生成 adapter 权重。这些都是人类固定的（附录 A）。
- **B2**：**部分覆盖**。权重更新作用在同一个模型上，下游 SWE 基准有提升（Table 1）。但更新方式是 RL，【推断】为全参数，不是 LoRA adapter。而且 harness 和权重是一起部署的。
- **B3**：**结构上覆盖 harness 作者这一角色，但没有测量**。P_{t+1} 成为下一轮的 harness proposer（附录 C 的 Table 5 把这一点列为与 WHALE 等方法的主要区别）。不过只做了 2 轮，编辑能力本身是否提升没有被隔离测量（见 Table 3 的讨论）。
- **B4**：**在 Self-HPO 设定下覆盖**。没有外部模型参与提议、数据或评判，评判来自可执行 verifier。但论文同时报告了用 Opus 4.8 当外部 proposer 的 HPO 版本，以及 Opus 4.8 的蒸馏和 Meta-Harness 基线。另外，proposer 能读取人类参考修复。
