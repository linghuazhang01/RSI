## 研究问题
LLM 能否像人类一样，自主修改自己的内部表示（权重）来应对概念漂移和陌生任务？作者把“模型自己的权重”当作可以探索的环境，用元学习和 RL 让 LLM 自己提出权重修改策略（self-edit），并把验证有效的策略存进知识库，以兼顾可塑性和稳定性。

## 方法细节
- **整体流程**（§4，p4；Fig.1 p5，改编自 [34]）：
  1. 用参数生成器为目标任务采样一个初始 LoRA，作为探索起点。
  2. 一个“基于基础模型的 agent”（用 RL 训练的 LLM）提出权重修改策略（adaptation strategy，AS）。
  3. 执行策略并在评测集上验证，有效的策略加入知识库。
  4. 训练分三个难度级别：Level I 只用知识库里的单个 edit；Level II 用 edit 链；Level III 开放探索。
- **LoRA 初始化器（参数生成）**（§5.1，p5–7）：
  - 用 Sentence-BERT（all-MiniLM-L6-v2）给任务 prompt（或少量无标签样本）做嵌入，送入 hyper-convolutional decoder（按 DnD/RPG 的做法），直接输出 LoRA 参数。
  - LoRA 加在 Qwen2.5-0.5B-Instruct 的 q/k/v/o 和 gate/up/down 投影上。每个 LoRA 矩阵是 8×896，【推断】rank=8（第 251 行）。
  - decoder 的训练目标是 MSE：用 prompt 批去回归在 ARC-e/c、BoolQ、HellaSwag、OBQA、PIQA、WinoGrande 上预先训练好的 LoRA checkpoint。这些 checkpoint 先用 lr 1e-4 训 75 步，再用 lr 1e-5 训 50 步，每一步都存一次（p6）。
- **种子知识库**（p7–8）：人工挑选了 5 个策略族，作者称是“经过试错挑出来的”：
  - TTT：用 TTL 做输入困惑度最小化，可调 ttl_steps、lr、batch_size、shuffle；
  - LoRA 后处理：two-subspace mixing，可调 λ；
  - 类 SQLM/R-Zero/SEAL 的自生成数据（论文只列了这一族，没有说明实际实现）；
  - TTS：多个 adapter 做路由或集成（max_confidence、majority_vote、sum_logprobs 等）；
  - 潜空间方法：SLOT，可调 times 和 lr。
  
  每个 AS 是一个 JSON，只包含 family 和少量超参。
- **外层 RL**（p8；Algorithm 1 p10）：目标函数沿用 SEAL 的写法，模型根据上下文 C 生成 AS，按 AS 更新得到 θ′，用 θ′ 在 τ 上的表现作为 reward。优化方法是 ReST-EM：每轮采样 15 个 AS，用二值 reward（是否提升）过滤后做 SFT，只迭代 2 轮（脚注 7，第 392–395 行）。
- **谁做什么（关键）**：
  - 生成适配策略（超参/策略选择）：形式上是 LM_θ，也就是 Qwen2.5-0.5B-Instruct 自己。但脚注 8（第 397–399 行）承认 0.5B 模型难以输出结构化结果，这种情况下“验证和格式化”交给了 **Qwen2.5-7B-Instruct**。所以策略生成环节**有一个更大的外部模型参与**。
  - adapter 权重：由一个**单独训练的 hyper-conv decoder** 生成，**不是由 LLM 自己生成**；decoder 的训练目标是人工准备的 LoRA checkpoint。
  - 训练数据：没有由模型自生成训练数据的环节。TTL 用的是目标任务的 128 条无标签样本；“用 proposer/solver 自博弈在线生成评测集”只出现在方法描述中（p4），【推断】Level I 的实验里似乎没有真正实现，实验部分没有任何描述。
  - 评判/reward：在评测集 τ 上的准确率（二值的“是否提升”）。
  - 被训练的模型：Qwen2.5-0.5B-Instruct（预训练模型），既通过 RL 更新策略生成能力，也是 LoRA 和各种策略的作用对象。
  - 是否同一 checkpoint：从 Algorithm 1 的记号看，策略由 LM_θ 生成，也作用在 θ 上，形式上是“同一个模型”（沿用 SEAL 的设定）。但文中没有讲清楚“RL 更新后的策略模型”和“被 LoRA 和策略修改后的 θ′”之间是什么关系。
- **更新方式**：生成 LoRA（rank 8）+ 按 AS 做后处理或测试时训练；策略模型本身用 ReST-EM（SFT）更新。【推断】从 Algorithm 1 看，RL_Update 作用在 θ 上，但论文没有说明是全参数还是 LoRA。
- **多轮/递归**：ReST-EM 迭代 2 轮。**只完成了 Level I**（Table 1 的标题写的就是“SOLAR Level I”），Level II 和 Level III 只有算法描述，没有实验。论文没有展示“被适配后的模型在下一轮担任编辑者，编辑能力随轮次提升”。

## 数据集与评测
- 训练 decoder 用的数据：ARC-e、ARC-c、BoolQ、HellaSwag、OBQA、PIQA、WinoGrande 上预训练好的 LoRA checkpoint。
- 域内评测：ARC-e、ARC-c、BoolQ、HellaSwag、PIQA。
- 域外评测：GSM-MC、MATH-MC（GSM8K 和 MATH 的多选版本）、DivLogicEval、SocialIQA、CodeMMLU。
- 指标：准确率（%）。shot 数**没有说明**。SOLAR 和 TTL 能看到目标数据集的 128 条无标签样本。
- 基线：任务特定 LoRA 的平均、TTL、DOM（LoRA 合并）、DnD。
- 计算资源：4×A6000，实际只用了 2 张；当前版本训练约 4 天（脚注 12）。

## 关键实验与数字
- **Table 1（p11，第 505–515 行）**：
  - SOLAR 域内：ARC-e 74.7、ARC-c 55.5、BoolQ 58.8、HellaSwag 48.3、PIQA 60.1，平均 59.5。
  - SOLAR 域外：GSM-MC 30.3、MATH-MC 24.5、Logic 25.1、Social 55.0、Code 35.6，平均 34.1。
  - DnD 域内平均 49.0，域外平均 25.7；SOLAR 分别高 10.4 和 8.4 个百分点。相对 TTL 高 25.2 和 7.3，但在 Logic 上低 1.1。
- **最终选中的策略**（p11）：
  - ARC-e、PIQA：TTT（ttl_steps 25、lr 1e-5、bs 4）；
  - ARC-c、SocialIQA：LS（times 5、lr 0.1）；
  - BoolQ、GSM-MC、MATH-MC：LoRA TS-mixing（λ=0.5）；
  - HellaSwag、Logic、Code：TTS 集成（例如 20 个 prompt 批 + max_confidence）。
- **消融**（§6.4，p11–12）：用图影响力加多样性的方法挑选 128 条初始 prompt，平均只提升 0.3%，作者据此认为 SOLAR 对初始 prompt 批不敏感。

## 作者自己声明的局限
- 目前依赖人工挑选的种子知识库（结论，p12）；没有专门针对“生成式 LoRA”的优化策略可参考，只能靠试错挑选（脚注 6）。
- 只实现了 Level I；更高级别非常耗时，当前版本已经要约 4 天（脚注 12）。
- 采样数（15）和迭代数（2）都是写死的（脚注 7）。
- 0.5B 模型难以输出结构化结果，需要借助 7B 模型做验证和格式化（脚注 8）。
- 训练阶段计算开销大，推理阶段快（结论）。

## 方法问题与替代解释
- 【推断】“策略”的搜索空间很小：只有 4 个族，每个族 1–4 个超参。从结果看，每个任务最终选中的就是一个族加一组固定超参。这更接近“在小型离散/连续超参网格上，靠评测集 reward 做选择”，而不是模型真正发明了适配方法。
- 【推断】reward 用的是评测集 τ 上的表现，论文没有说明 τ 与最终报告的测试集是否分开（方法中提到“如果有就单独切分评测集”，实验中没有交代）。如果没有分开，就等于在测试集上挑选策略，Table 1 的提升会被高估。
- 【推断】HellaSwag 从 DnD 的 26.5 跳到 48.3，用的是 20 个 adapter 的集成（TTS）。这部分增益主要来自测试时集成带来的额外计算，和基线在计算量上不对等。
- 【推断】LoRA 平均基线在 BoolQ 上只有 14.7%，低于二分类的随机水平 50%，说明基线可能存在格式或解析问题，与基线相比的差值未必可靠。
- 【推断】没有方差和多种子结果；workshop 论文的实验细节（shot 数、评测协议、RL 更新的参数）缺失较多。
- 【猜测】策略生成中有多少比例需要 7B 模型“修正”，论文没有报告，因此无法判断最终的 AS 有多少真正出自 0.5B 模型。

## 与核心主张（B1–B4）的关系
- **B1（同一模型自己写适配方案：生成数据 + 决定超参/LoRA/训练代码，或直接生成自己的 adapter）**：**部分覆盖，但有明显折扣。** 形式上是 Qwen2.5-0.5B 自己生成 JSON 适配策略（选策略族 + 超参），这是“同一模型决定如何更新自己”的一个弱形式。但是：
  1. 模型不生成训练数据；
  2. 不写训练代码；
  3. 不决定 LoRA 结构；
  4. LoRA 权重由单独训练的 hyper-conv decoder 生成，不是 LLM 自己生成；
  5. 结构化输出需要 7B 模型协助。
- **B2（adapter 作用于同一模型并提升下游表现）**：**覆盖。** 生成的 LoRA（rank 8）和后续修改作用于 Qwen2.5-0.5B 本身，在 10 个 benchmark 上提升（Table 1）。
- **B3（递归：被适配模型在下一轮当编辑者，编辑能力和任务能力共同提升）**：**基本不覆盖。** 只有 2 轮 ReST-EM 的策略模型更新，只完成了 Level I。论文没有说明“被 LoRA 适配后的 θ′”会成为下一轮的策略生成者，也没有测量编辑能力随轮次的变化。知识库的扩充（Level II/III 的“加入 K”）没有实验。
- **B4（没有更大的外部模型参与）**：**违反（程度较轻）。** 脚注 8 说明需要时由 Qwen2.5-7B-Instruct 做验证和格式化。另外 Sentence-BERT 编码器和 hyper-conv decoder 也是外部组件，但它们不比目标模型大。
- 总结：SOLAR 是“参数生成器给出初始 LoRA + 同一个小 LLM 用 ReST-EM 学习从固定策略库中挑选适配策略”。在 Topic B 的论文中，它最接近“同一模型决定如何适配自己”，但缺少自生成数据、自写训练代码和递归编辑者，而且有 7B 模型辅助，实验也只停留在 Level I。
