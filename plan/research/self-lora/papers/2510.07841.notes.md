## 研究问题
常规 agent 微调依赖大规模离线数据，成本高，且有冗余样本、分布偏移、遗忘等问题。作者想知道：能否在推理时只针对模型"拿不准"的测试输入，让模型自己造少量相似样本、做一次临时的参数更新，从而提升 tool-calling agent 的准确率。本质上属于 test-time training（TTT）加 self-instruct 式数据增广。

## 方法细节
三步流程（Algorithm 1，p.5；Fig. 1，p.1）：
1. **不确定性估计 H（Self-Awareness，§3.1，p.5–6）**：对每个测试输入 x_i，用模型对每个候选动作（候选函数名，由正则从可用工具列表中抽出，见 G.1，p.23）算 NLL，经 Relative Softmax Scoring 归一化，取 top-1 与 top-2 概率之差 u(x_i)。u < τ 判为不确定。默认 τ = 0.95（App. D，p.20）。不用 ground-truth。
2. **数据合成 G（Self-Augmentation，§3.2，p.6–7）**：以不确定输入为 seed（不带标签），用手写 prompt（Fig. 8，p.22）让 LLM 生成 K 个改写后的 (input, output) 对，output 是函数调用 JSON。主实验 K = 1（App. E.1，p.21）。
3. **测试时微调 T（Self-Improvement，§3.3，p.7）**：用这 K 条合成样本对模型做 LoRA SFT，得到临时参数 θ_i*，对 x_i 推理，**随后把参数重置回 θ0**，再处理下一个样本（Algorithm 1 第 16–17 行，p.5；§3.3 p.7）。

角色分工（关键）：
- **被训练的模型**：Qwen2.5-1.5B-Instruct（主实验），另有 Qwen2.5-7B-Instruct 消融（Fig. 3，p.9）。
- **谁生成数据**：TT-SI 中就是被训练的同一个 Qwen2.5-1.5B-Instruct checkpoint（App. E.1 p.21；G.2 p.23），vLLM 采样，temperature 0.7，JSON 解析失败最多重试 5 次。TT-D 变体改用 **GPT-5-mini** 生成（G.2，p.23；§4.1 p.8），这是更强的外部模型，作为对照。
- **谁决定训练方案**：作者人工固定。LLaMA-Factory，LoRA rank 8、α 16，作用于所有线性层，5 epoch，lr 1e-4，warm-up 0.03，batch size 1，cosine 调度（G.3，p.24）。模型**不**决定超参、LoRA 配置或训练代码。
- **谁评判**：没有 LLM judge。合成样本的标签不做正确性校验，只做 JSON 格式解析。"是否需要更新"由基于模型自身似然的 H 决定，阈值 τ 由人设定。最终评测是 benchmark 规则匹配（soft-match，G.4，p.24）。
- **是否同一 checkpoint**：TT-SI 中，生成器、不确定性估计器和被训练模型都是同一个基座 checkpoint θ0。生成器本身**不更新**；作者把"生成器与 agent 共同进化"列为未来工作（p.10–11）。
- **更大外部模型**：TT-SI 不用；TT-D 用 GPT-5-mini。
- **是否多轮/递归**：否。每个不确定样本单独训一个临时 adapter，用完即丢，参数每次重置为 θ0。没有"适配后的模型再去当编辑者/生成器"的循环。论文提到的 "iterative" 只是指逐样本重复这一流程（p.7）。
- 另有 TT-SI + ICL 变体：把生成的样本放进上下文而不训练（Insight 3，p.8）。

## 数据集与评测
- Benchmark（§4 p.7；G.4 p.24）：NexusRaven（318 个测试样本）、SealTool（294）、API-Bank（Level 1–2，文中写 316 和 361 两个数）、ToolAlpaca（文中写 271 和 103 两个数）。测试集划分沿用 Lin et al. 2025。
- 指标：函数名、参数及其取值/类型的正确率，采用作者自定的 soft-matching（忽略大小写和细微词形差异）。作者称该调整让分数变化 2–3%（G.4，p.24）。
- 推理设置：Input/Output（直接预测，零样本 prompting）、Majority Vote（5 次采样）、Pass@5（Table 1，p.8）。解码 temperature 0.7。
- 对比基线：Base prompting、1-shot ICL、在 SealTool 训练集（约 13k）上的 SFT，以及用 xLAM 数据做 OOD SFT 的规模曲线（Fig. 2，p.9）。
- 每个设置重复 5 次（不同种子/样本），报告均值±标准差（p.7）。
- 硬件：单张 A40。**测了时延**（Table 4，p.25），**没测显存**。

## 关键实验与数字
- **Table 1（p.8）主结果**，Qwen2.5-1.5B。Input/Output 平均：Base 54.66 → TT-SI 60.14（+5.48）→ TT-D 61.08（+6.42）。Majority Vote：58.05 → 61.90（+3.85）→ 63.58。Pass@5：65.88 → 69.34（+3.46）→ 71.99。分 benchmark 看，TT-SI 在 NexusRaven 上 44.03→50.08，SealTool 66.67→72.43，API-Bank 70.08→74.34，ToolAlpaca 37.86→43.70。
  - 注意：正文 p.8 写成 "54.66%→65.62%"，与表中 60.14 不一致，应是笔误。
- **Fig. 2 左（p.9，SealTool）**：Base 66.37，ICL 67.74，SFT（13k）70.20，TT-SI 72.43，TT-D 73.92，TT-SI+ICL 68.36，TT-SI w/o H（全部样本都训）73.47。作者以此称样本量约少 68×（190 条 vs 13k，Insight 2，p.8）。
  - 注意：同为 SealTool Base，Fig. 2 中是 66.37，Table 1 中是 66.67，不完全一致。
- **Table 2（p.9）阈值 τ**：τ = 0.35 时 51 条不确定，准确率 68.10；τ = 0.95 时 190 条（65%），72.43；全选时 294 条，73.47。
- **Fig. 3（p.9）规模**：1.5B 66.67→72.43（+5.76）；7B 80.95→83.97（+3.02）。
- **Fig. 4（p.10）**：只在"确定"样本上训练为 70.07，只在不确定样本上为 72.43，全部样本为 73.47。
- **Table 3（p.21）不确定性估计器**：TPR 96.10，FPR 53.46，F1 55.43，Youden J 42.64；Perplexity 基线的 J 为 18.89。
- **Fig. 9（p.23）"作弊"上界**（直接在测试集上训练）：ICL 100，SFT 79.25，TTT 78.89；对比之下 TT-SI 72.43，TT-D 75.17。
- **Table 4（p.25）时延**（SealTool）：H 0.87 s、G 3.45 s、T 2.05 s、推理 0.89 s。不确定样本端到端约 7.26 s/条，确定样本 1.76 s/条，总计约 36 分钟；SFT 需 7966.6 s，作者称墙钟加速 3.7×。该统计**排除**了 LoRA merge、存盘和 vLLM 重新加载的开销，作者承认这部分才是主要额外时延（p.25）。

## 作者自己声明的局限（p.10–11）
- 阈值 τ 需人工设定，最佳性能对 τ 敏感，如何自动学习 τ 仍未解决。
- 能力受基座参数上限约束：预训练中没有的知识，单靠自我改进学不到，需要检索等外部知识。
- 未来工作：自我进化；让模型自己决定合成样本数量（引用 SEAL，Zweiger et al. 2025）；当前只优化 agent，不优化数据生成器，可考虑二者共同进化；扩展到数学、医疗领域。
- I/O 和合并开销未优化（App. H）。

## 方法问题与替代解释
- 【推断】合成标签不经任何校验，K = 1。收益可能主要来自对输出格式（tool_call JSON 结构）和工具名的"sharpening"或格式对齐，而非任务知识的提升。作者自己也把 ICL 的增益归因于格式和置信度（Insight 3，p.8），但没有做"只学格式"的对照。
- 【推断】评测用自定义 soft-match，解码 temperature 为 0.7。Base 与 TT-SI 都在同一协议下比较，但绝对数与其他论文不可直接比较。
- 【推断】不确定性估计依赖候选函数名的封闭集合（正则抽取），方法只适用于有离散候选动作的 tool-calling 场景，难以直接推广到开放生成任务。
- 【推断】数字内部有若干不一致：Table 1 与正文的平均值不同（60.14 vs 65.62）；Table 4 说明写"190 uncertain + 194 certain"，而 SealTool 共 294 条，应为 104；API-Bank（316/361）和 ToolAlpaca（271/103）的测试集规模表述前后矛盾；SealTool Base 有 66.37 与 66.67 两个数。不影响定性结论，但影响可复现性。
- 【推断】"TT-SI w/o H"（73.47）高于 TT-SI 主设置（72.43）。不确定性过滤的价值主要在省算力，而非提升准确率。
- 【猜测】每个测试样本训一个 adapter 再重置，属于实例级 transductive 适配；收益能否在 batch 或流式场景中累积，没有实验。
- 【推断】"68× 更少数据"比较的是 190 条测试时合成样本与 13k 训练集，但 TT-SI 用的是测试输入本身作 seed，信息来源不对等。

## 与 Topic B core claims（B1–B4）的关系
| Claim | 论文做了什么 | 没做什么 | 覆盖判断 |
|---|---|---|---|
| B1 同一模型撰写自己的适配（数据 + 训练方案 / 或直接生成 adapter 权重） | TT-SI 中同一个 Qwen2.5-1.5B 生成训练数据（含标签），也用自身似然判断是否需要更新 | LoRA 配置、超参、训练代码全部由人固定（r=8, α=16, 5 epoch, lr 1e-4）；模型不决定"如何更新"；不生成 adapter 权重 | **部分覆盖**：只覆盖"自生成数据"这一半 |
| B2 adapter 用回同一模型以提升下游任务 | 是：LoRA 加在同一基座上，在 4 个 tool-calling benchmark 上平均 +5.48 | adapter 是逐样本的临时适配，用完即丢，不是持久的能力提升 | **覆盖**（以临时、实例级的形式） |
| B3 递归：适配后的模型成为下一轮编辑者，编辑能力与任务能力共同提升 | 无 | 每次重置回 θ0；生成器不更新；作者把生成器与 agent 共同进化列为未来工作 | **未覆盖** |
| B4 无更大外部模型参与数据生成、决策、评判 | TT-SI 满足：无外部模型，也无 LLM judge | TT-D 变体用 GPT-5-mini 作为对照（并更好）；不确定性阈值、prompt、训练配置均为人工设计 | **TT-SI 覆盖** |

结论：TT-SI 是"同一小模型自生成数据 + 人工固定 LoRA 方案 + 单轮临时适配"。与 Topic B 最接近的部分是 B2 和 B4，以及 B1 的数据部分。它**不涉及**模型自主决定训练方案或权重，也**没有递归**的自我编辑（B1 的决策部分、B3）。论文本身还提示了 SEAL（Zweiger et al. 2025）这一更接近 B1 决策部分的相关工作，需要单独核查。
