## 研究问题
作者认为现有的递归自我改进（RSI）几乎只在“机器可免费验证”的格式上闭环，例如代码测试、精确匹配和选择题。而且现有系统通常只改一个面：数据、harness 或权重。本文要做三件事：
1. 把数据 D、harness H、模型 θ 三个面放进同一个 loop kernel，作为三个可组合的算子（Data-RSI、Harness-RSI、Model-RSI）。
2. 用一个调度 agent（RSI2 Agent）决定算子的执行顺序（水平轴），并改写各算子自己的提议策略（垂直轴）。
3. 用一个 meta agent（MetaRSI2 Agent）在每个 term 结束后改写调度策略本身。
另外，论文还用 45 个系统的统计提出了五条“定律”，核心论点是验证格式决定了 RSI 能在哪里闭环。

## 方法细节
- **目标系统**：S=(D, θ, H)（Eq.1，p7）。θ 包括可训练参数、adapter，以及产生它们的训练配置。
- **Loop kernel**：Observe → Diagnose → Propose → Validate → Execute → Select → Export（Eq.8，p10）。Diagnose 和 Propose 由语言模型完成，其余五个阶段是确定性代码。判断“改得好不好”的权力全部在固定代码和固定评估器手里（Definition 4.1，p9–11）。
- **三个算子**（§4.2，p11–15）：
  - Data-RSI：从执行轨迹中抽取四维学习签名 κ（知识、推理、验证、干扰），由 QueryGen 角色生成 directive。之后进入“对抗生成”：Operator 角色出题并给答案，Anchor 角色在看不到答案的情况下盲解，两者一致才接受（Eq.13，p13）。再经过 contract（确定性 schema）加 semantic re-solve 的双门（Eq.14），最后去重，并与密封评测集比对去污染。
  - Harness-RSI：对五槽 genome（system prompt、memory、内置工具、skills、MCP）打 typed patch（Eq.15–17，p13–14）。只有严格优于历史最好才会被晋升。
  - Model-RSI：在一个**有界的 recipe 空间**里提议训练方案（Eq.18，p14）。这个空间包括可训练参数集、adapter 放置位置、目标模块、参与的层（R_arch），adapter 族与容量，即 rank 和 scaling（本文配置为 LoRA，R_adapt），lr、schedule、batch、梯度累积（R_optim），序列长度（R_seq），checkpoint 间隔和早停（R_ckpt）。每个 recipe 提交前会先对照训练后端的能力声明做检查。
- **训练起点**：**每个候选都从固定基座 θ0 出发**，在累积数据集 D′ 上训练，不接着上一轮的 adapter 继续训（Eq.19 和下方说明，p14 第 933 行；附录 F 的 “Fixed-base cumulative training”，p46）。数据带 loss mask，只计算 assistant 位置的损失；训练步数受数据集大小约束。被晋升的 checkpoint 会回到 kernel 的 **Execute 阶段**，作为后续 rollout 的新基座（p15 第 976 行）。
- **晋升**：一个独立评估层在 adaptation split 上用固定评估器 Q 给每个 θ_j 打分，只有严格优于 θ_best 才晋升（Eq.20，p14）。另有一个密封评估器 Q⋆，只在冻结后打开一次。
- **可组合性**：定义了“新鲜度”（Definition 4.3，Principle 4.4）。允许 D→H、D→M、H→D、M→D、M→H 五条跨算子边，以及 D→D、H→H 两种自环。禁止 H→M 和 M→M，理由是此时的数据集早于最近一次改变能力的步骤（Eq.23，p15）。
- **调度与 meta 层**：RSI2 Agent 在每个决策点选择水平轴（扩展算子序列）或垂直轴（由 RSI2 Sub-Agent 在契约约束下改写某个算子的 policy，要过 Eq.27 的四项检查）。MetaRSI2 Agent 在每个 term 结束后改写 RSI2 Agent 的指令面 ϕ（Eq.28–29，p17–18）。
- **谁做什么（逐角色列出）**：
  - 生成训练数据：目标模型 Qwen3.5-35B-A3B 自己承担 Data-RSI 的 Diagnose/Propose、QueryGen、Operator（出题）和 Anchor（盲解）（p13；§5.1，p21 第 1358 行起）。语义 verifier 的 re-solve 也是模型驱动的，【推断】同样由目标模型承担。
  - 决定超参、LoRA 配置、训练方案：Model-RSI 的 Propose 阶段由目标模型在有界 recipe 空间里提议（Eq.18）。附录 B 的 Table 10（p45）规定 Model-RSI 的可变面是 recipe 提议指令、候选数和停止启发式，动作面是 adaptation recipe、优化调度和候选策略；**训练代码和后端（training code & backend）、数据内容与划分、评估器、奖励和发布规则都属于受保护面**。所以模型**不写训练代码**，只在枚举好的旋钮里选值。
  - 评判：确定性代码加固定评估器 Q，以及密封的 Q⋆。外部信号只有 verifier 或执行 oracle。数据侧的“正确性”由同一个模型的盲解来认证（Anchor），论文自己承认这只能证明自洽，证明不了正确（p13）。
  - 调度和 meta：RSI2 Agent、Sub-Agent、MetaRSI2 Agent 都由目标模型担任（p21）。Transition adapter 是有界的模型调用（附录 C，p43），论文没写由哪个模型承担，【推断】是目标模型。
  - 被训练的模型：Qwen3.5-35B-A3B（MoE，总参数 35B，激活 3B），用 LoRA 训练。
  - **有没有更大的外部模型**：论文明确说没有更强的外部模型参与提议、合成、评判或调度，训练数据里也没有外部模型的输出（p21 第 1358–1365 行；p22 第 1432 行）。唯一需要留意的是 §5.1 的去污染步骤写的是“独立的基于模型的验证”（p21 第 1380 行），没说用的是哪个模型。
- **被训练后的模型在下一轮担任哪些角色（论文没有说清楚）**：论文只明确说了被晋升的 checkpoint 会回到 Execute 阶段做 rollout（p15）。它还说下一个 term 从“已发布的后继系统”开始（p20），并且所有模型驱动的角色都“在目标模型上实例化”。但论文**没有逐个角色说明** Diagnose/Propose、Operator/Anchor、RSI2 Agent 等提议角色在下一轮用的是基座 θ0 还是新晋升的 θ（LoRA 后的模型）。【推断】既然 S 的 θ 被替换，后继系统的提议角色很可能用的是新权重，但文中没有给出证据，也没有任何实验验证这一点。另外，新一轮的训练对象仍然是从 θ0 重新开始训的 LoRA，不是在 θt 上继续训。
- **轮次**：主表 Table 3 是 1 个 term（term 内部是多步算子序列）。§5.4 做了连续 5 个 term（Fig.11、Table 4）。前沿模型的 harness 路线做了 3 个 term（Fig.12）。每个 term 重新计量相同的预算。
- **前沿模型路线**（§5.3）：Gemini 3.1 Pro、DeepSeek V4 Pro、Claude Opus 5、Kimi K3、GPT-5.6 Sol、GLM-5.2 各自在 {D, H} 子集上改进自己，不涉及权重，每个模型同时担任自己的提议者和评判者。
- **论文没有报告的数字**：LoRA 的 rank、lr、batch 等具体取值，合成数据条数，GPU 小时，每个条件的预算绝对量，统统没有给出。

## 数据集与评测
- 可执行轨道：Terminal-Bench 2.1（89 题），SWE-bench Pro（731 题的公开测试集）。环境容器化，用隐藏 verifier 判定。
- 闭式轨道：GPQA-D-hard100（从 GPQA-Diamond 选出、预先冻结的 100 道较难题，ID 见 Table 11），AIME 2025+2026 共 4 套 60 题。按精确匹配或数值匹配计 pass@1。
- 所有数字都是 5 个外层 seed 的均值，**没有给标准差**。主指标是 Eq.5 定义的部署改进产出，在密封 split 上对发布的后继系统只评一次。
- 基线：No improvement；三个单算子各给满预算；Human fixed D→M→H；Random admissible composition；Static router（基于签名的路由，没有跨 term 学习）。

## 关键实验与数字
- **Table 3（p22，第 1399–1408 行）**，一个 term，目标模型为 Qwen3.5-35B-A3B：
  - 冻结初始系统：TB2.1 23.6，SWE-Pro 10.3，GPQA-h100 71.2，AIME 55.0。
  - Data-RSI 平均 +2.8，Harness-RSI 平均 +6.6，**Model-RSI（只做 LoRA）平均 +3.9**（TB 27.0，SWE 14.0，GPQA 75.4，AIME 59.3）。
  - Human fixed D→M→H +7.3，Static router +7.3，Random +4.5。
  - MetaRSI-v1：31.9 / 19.5 / 83.8 / 68.3，平均 +10.9。比最好的固定顺序组合高 3.6，比最强的单算子高 4.3（p22）。
- **Fig.10（p23）**：6 个前沿模型在 TB2.1 上走 harness 路线改进自己，提升 +5.6 到 +9.2，均值 +7.3。
- **Fig.11 和 Table 4（p24–25）**：连续 5 个 term。带 meta 更新时累计 +26.2，不带时 +20.7。单 term 增益衰减：带 meta 从 +7.2（term 2）降到 +1.4（term 5），不带 meta 从 +4.9 降到 +0.7。带 meta 时 policy 编辑保留率 68%（不带为 38%），调度 regret 8.2%（不带为 16.5%）。不带 meta 的路径到 term 5 时在 GPQA-h100 上回退 0.2。
- **Fig.11(c)（p24，第 1576–1585 行）**：这是唯一一个“改进者能力”的对照实验。term 2 在同一个 S1 上分叉，用相同预算比较原始改进者和 meta 更新后的改进者，平均增益分别为 4.9 和 7.2。按基准拆开，meta 版本的优势为 TB +1.6、SWE +1.7、GPQA +2.6、AIME +3.3。**注意**：两个分支的差别在于改进者的“策略和指令”（ϕ 和算子 policy，都是文本），**不是权重**。
- **Fig.12（p25）**：前沿模型连续 3 个 term 走 harness 路线，均值增益依次为 +7.3、+2.8、+1.2，累计 +11.3。
- **是否测量了编辑者/配方作者能力本身随轮次的变化**：Fig.11(c) 和 Table 4 测的是“改进者”（调度器和算子 policy 的文本）的质量变化。**没有实验隔离“权重变化带来的作者能力提升”**。例如，论文没有用不同代的权重（θ0 与 LoRA 后的 θ）担任 Model-RSI 的 recipe 作者或 Data-RSI 的出题者，去编辑同一个固定的 recipient。也没有单独报告只跑 Model-RSI 的多轮曲线，或者 recipe 由模型提议和使用固定默认 recipe 的对比。

## 作者自己声明的局限
- §6.2 “放大器不是源头”（p26）：三个算子只是重新分配模型已有的能力。对于模型从未表现出的能力，合成数据的作者正是缺这项知识的那个模型，所以闭环没法自举出新知识，真正的增益必须从外部引入。Law 5（p31–32）把这一点正式表述出来。
- Anchor 盲解只能证明自洽，证明不了正确，模型缺失的知识无法被认证（p13）。
- 实验只覆盖可执行代码和闭式科学（rung 1）。论文的动机是开放领域，但开放领域没有做实验，只给了展望（§6.4–6.5）。
- 物理世界的闭环会遇到不可逆和高延迟的问题，需要分级保真度和人工授权（§6.5）。
- 在新领域中，预计需要人在环中担任调度者（p18）。
- H→M 被禁止。Model-RSI 必须用晚于上一次能力变化的数据集，因此每次训练前都要重新跑 Data-RSI。

## 方法问题与替代解释
- 【推断】可复现性弱。LoRA 的 rank、lr、数据量、GPU 预算这些 Model-RSI 的关键信息全部缺失，只有“同预算”的说法。Model-RSI 单独 +3.9 的增益没法判断是来自 recipe 的选择，还是只是“自蒸馏和过滤后的数据”本身。
- 【推断】没有标准差。TB2.1 只有 89 题，1 题约等于 1.1 分，5 个 seed 的均值差几分是否显著，论文没有检验。
- 【推断】“下一轮由谁当作者”不清楚。权重始终从 θ0 重新训练，而“改进者变强”的证据来自文本 policy 和 ϕ 的改写。所以论文的递归是“文本层的改进者递归”，加上“数据累积”，而不是“权重变化让作者变强”。
- 【推断】Data-RSI 的出题者和认证者是同一个模型（只隔离了输入），共享的错误无法被发现。最终的正确性依赖外部 verifier 和密封集。
- 【猜测】GPQA-h100 是人工选出的“较难 100 题”，选择过程（selection seed rsi2-gpqa-hard100-002）是否和基线相关，会影响增益的解释。闭式题上 Harness-RSI（只改 prompt）就能 +7.6/+8.3，说明增益有相当一部分来自提示格式，未必来自能力提升。
- 【推断】前沿模型实验里，每个模型都只做自己的提议者，并非“小模型被大模型帮助”，所以不违反 B4。但它是 harness 路线，不涉及 LoRA。

## 与 core claims 的关系
- **B1（同一个 checkpoint 自己生成训练数据，并决定如何更新自己）**：**大部分覆盖**。同一个目标模型既生成训练记录（Operator/Anchor/QueryGen），又在 Model-RSI 里提议 LoRA recipe，包括 rank、scaling、目标模块和层、lr、schedule、batch、序列长度、checkpoint 和早停（Eq.18，Table 1，Table 10）。没覆盖的部分有三点：训练代码和后端是受保护面，模型不写训练代码；recipe 只能在有界的枚举空间里选，晋升由确定性代码决定；模型不直接生成 adapter 权重。
- **B2（adapter 作用在同一个模型上，提升下游任务）**：**覆盖**。LoRA 训在 Qwen3.5-35B-A3B 自身上，Model-RSI 单独使用时 4 个基准平均 +3.9（Table 3）。
- **B3（训练后的模型成为下一轮的编辑者，编辑能力和任务性能共同提升）**：**部分覆盖，或者说没有证实**。框架有多 term 的递归，后继系统进入下一 term。但是：①每次 LoRA 都从 θ0 重训（Eq.19）；②论文没有明确说新权重在下一轮承担哪些提议或作者角色，只明确提到 Execute 阶段的 rollout；③“改进者变强”是通过改写 meta 层的文本 policy 实现并测量的（Fig.11c），没有任何实验隔离“权重变化让编辑能力变强”；④没有测量“编辑者能力”和“任务性能”随权重共同提升。
- **B4（没有更大的外部模型参与）**：**覆盖**。论文明确说没有更强的外部模型参与提议、合成、评判或调度，训练数据中也没有外部模型输出，唯一的外部信号是环境 verifier（p21）。小的不确定点在于去污染步骤的“基于模型的验证”没说用的是哪个模型。
