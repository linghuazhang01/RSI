## 研究问题
Agent 的表现同时取决于模型权重 θ 和 harness 代码 h（harness 管系统提示、工具 schema、上下文管理、解析与执行逻辑、终止策略）。只优化其中一个时，另一个固定的部分可能成为瓶颈。已有的联合优化方法（如 FST、BetterTogether）只把文本 prompt 作为可调变量。本文要回答两个问题：如何把“权重训练”和“对整个可执行 harness 的搜索”协调起来；每个阶段跑多久再切换。

## 方法细节
- **框架**：在两个阶段之间交替（坐标下降式）。第一阶段固定 h_k，训练得到 θ_{k+1}；第二阶段固定 θ_{k+1}，搜索得到 h_{k+1}，然后进入下一轮（Eq.4，p4；Algorithm 1，p5）。
- **权重更新**：online rejection-sampling fine-tuning（RSFT）。用当前冻结副本 θ_old 在 h_k 下对每个 prompt 采样 G=8 条轨迹，只保留二值 verifier 判为正确的轨迹，对模型生成的 token 做 SFT（token 归一化的 log-likelihood，Eq.2，p3）。超参见 Table 1（p15）：lr 1e-7，SFT minibatch 64，prompt batch 256，每组被接受的轨迹只训 1 个 epoch。**全文没有提到 LoRA**；【推断】是全参数 SFT（lr 只有 1e-7，也符合全参数的量级），但论文没有明说。
- **harness 搜索**：Meta-Harness（MH，Lee et al. 2026）。proposer 通过文件系统工具查看已归档的 harness 源码、得分和轨迹日志，每次迭代写出 M=3 个候选 harness，在 D_harness（256 题，每题 1 条 rollout）上打分，保留归档中得分最高者（Eq.3，p4）。
- **谁做什么（这是关键）**：
  - 训练数据：被训练的模型（Qwen3.5-2B/4B）自己在当前 harness 下生成 rollout，再由 verifier 过滤。数据由**同一 checkpoint 的 on-policy 采样**产生。
  - 训练方案/超参/训练代码：由人类**固定**（Table 1）。被训练的模型不决定任何超参、LoRA 配置或训练代码。
  - harness 代码：由外部的 **Claude Opus 4.7** 作为 proposer 编写（Table 1，p15，第 962 行）。
  - 评判：Math 用规则化 boxed 匹配；Chess 用 python-chess 检查合法性并与参考着法比对；**SearchQA 用 GPT-5.4-mini 当 LLM judge**（附录 B.3，p16，第 1020 行）。这个 judge 同时用于训练时的轨迹接受、候选 harness 打分和测试评测。
  - 被训练的模型：Qwen3.5-2B（SearchQA、Math），Qwen3.5-4B（Chess），均为预训练好的模型（p6，第 389 行）。
  - 结论：数据生成者 = 被训练者（同一 checkpoint），但“编辑者”（harness proposer）是更大的外部模型 Claude Opus 4.7，SearchQA 的评判者也是外部模型 GPT-5.4-mini。
- **多轮**：主实验固定调度 (E, I)=(0.6, 6)，即每轮训练 0.6 epoch、搜索 6 次迭代；完成的轮数为 SearchQA 6 轮、Math 9 轮、Chess 6 轮（Table 1）。更新后的 θ_{k+1} 在下一轮作为 harness 下的执行 agent 和 RSFT 的采样者，**但不担任编辑者**，proposer 一直是 Claude Opus 4.7。
- **Adaptive WHALE**：给每个阶段设 patience 停止规则（附录 A.1 的 Algorithm 2）。权重阶段在训练 reward 的滑动平均（W=T_min=P_w=0.2 epoch）不再提升时停止；harness 阶段至少跑 J_min=6 次迭代，之后连续 P_h=2 次没有出现新的最佳训练分就停止。

## 数据集与评测
- SearchQA：D_weight 共 18,946 题（HotpotQA 14,801 + NQ 4,145）；D_harness 256 题；D_test 700 题，取自 2Wiki、Bamboogle、HotpotQA、MuSiQue、NQ、PopQA、TriviaQA，每个 100 题；检索语料为 Wikipedia 2018，用 FAISS 建索引（p5）。
- Math：D_weight 为 DAPO-Math-17K（17,917 题）；D_harness 256 题；测试集为 AIME 2024 + AIME 2025，共 60 题；可调用 Python 工具（参照 ReTool 的做法）。
- Chess：来自 Lichess 谜题库，D_weight/D_harness/D_test 分别为 16,384/256/256，三者互不重叠。
- 指标：mean@8 准确率（每题采样 8 条，temperature 1.0、top-p 1.0、top-k 20）。设定为 agentic 零样本加工具，没有 few-shot。
- 基线：weight-only（只用 RSFT）、harness-only（只用 MH）、FST（复用 WHALE 的更新方法和调度，但 harness 搜索只能改 system/user prompt）、stagewise（先用完全部权重预算，再用完全部 harness 预算）。

## 关键实验与数字
- **主结果**（Fig.1b p1；Table 2 p17，第 1093–1096 行）：
  - SearchQA 平均：harness-only 38.29，weight-only 38.27，FST 35.34，WHALE 48.34。
  - Math 平均：0.42 / 15.42 / 17.92 / 24.79。
  - Chess：19.82 / 22.17 / 25.68 / 29.83。
  - WHALE 比单组件基线高 7.67–24.38 个百分点，比 FST 高 4.15–13.00 个百分点（p2，第 134 行）。
- **瓶颈分析**（Fig.3 p7，§6.1）：
  - SearchQA 的瓶颈主要在 harness：harness-only 只用 weight-only 5.79% 的 rollout 就追平了它的峰值；检索准确率从 26.88% 升到 60.61%，WHALE 达到 65.41%。
  - Math 的瓶颈主要在权重：weight-only 把截断率从 95.83% 降到 30.83%；harness-only 最高只有 0.42%。WHALE 第 1 轮的 harness 阶段只用 4,608 条 rollout，就把格式准确率从 0.83% 提到 4.38%。
- **交替 vs 分阶段**（Fig.4 p8，Table 3 p17）：stagewise 在 SearchQA 上为 43.02，在 Math 上为 15.63；WHALE(0.6, 6) 分别高 5.32 和 9.16 个百分点，并且分别只用 stagewise 29% 和 49% 的 rollout 就超过了它。
- **调度消融**（Table 3）：(0.2, 6) 最好，SearchQA 50.09，Math 28.33。Math 的 (0.2, 2) 训练不稳定，被中途停止。
- **Adaptive**（§6.2.3 p9，Table 3）：SearchQA 达到 52.82，为全场最佳，所用 rollout 比 (0.6, 6) 少 23%；Math 为 26.46，比手调最佳的 28.33 低 1.87 个百分点。各轮实际阶段长度的中位数为 0.24 / 0.29 epoch，harness 搜索 I=7 次（Fig.6 p10）。

## 作者自己声明的局限
- 正文没有单独的 Limitations 节。结论（p9–10）只把“换用其他权重更新和 harness 搜索算法”“扩展到更大模型和更多领域”列为 future work。
- 作者在 §6.1 提到，rollout 计数只算目标 agent 的 rollout，**不含 proposer 的计算开销**。
- 作者在 §6.2.1 提到，长时间的 harness 搜索会对 D_harness 过拟合，例如 Math 上 stagewise 只比 weight-only 高 0.21 个百分点。

## 方法问题与替代解释
- 【推断】“rollout 更省”的结论没有计入 Claude Opus 4.7 的调用成本，与纯权重方法的效率比较并不对等。
- 【推断】harness 的改进本质上是把一个前沿大模型的知识（比如为 SearchQA 写的检查清单和多轮检索策略）注入小模型的运行环境，增益中有一部分可以看作外部大模型的“蒸馏/提示工程”，而不是小模型的自我改进。
- 【推断】SearchQA 的训练过滤、harness 打分和测试评测共用同一个 GPT-5.4-mini judge，harness 有可能学会迎合这个 judge 的偏好。附录 B.3.1 的 rubric 专门禁止多候选答案和整段引用，【猜测】searched harness 里的“只写一个具体值”指令正好在利用这个 rubric。
- 【推断】Algorithm 1 最后返回的是在 D_test 上准确率最好的 (θ_k, h_k)，所有方法都报告 best-so-far 测试准确率（Fig.2 说明），这相当于用测试集做 checkpoint 选择，绝对数值偏乐观。不过各方法都这样处理，相对比较仍可参考。
- 【推断】Math 测试集只有 60 题，mean@8 的方差不小；文中没有报告多个随机种子。

## 与核心主张（B1–B4）的关系
- **B1（同一模型给自己写适配方案：生成数据 + 决定超参/LoRA 配置/训练代码，或直接生成 adapter）**：**部分覆盖，而且只覆盖了数据这一半。** 训练数据确实来自同一 checkpoint 的 on-policy rollout（RSFT 自训练）。但超参和训练流程由人类固定；被模型以外的东西修改的是 harness 而不是训练配置，且 harness 由外部的 Claude Opus 4.7 编写。模型没有决定任何 LoRA 或超参，也没有生成 adapter 权重。
- **B2（adapter 作用于同一模型并提升下游表现）**：权重更新作用于同一个模型，并在下游任务上有提升。但更新方式不是 LoRA，【推断】是全参数 RSFT，论文没有提 LoRA。
- **B3（递归：被适配后的模型在下一轮当编辑者）**：**不覆盖。** 多轮交替是有的，更新后的模型在下一轮也继续当 rollout 采样者，但编辑者（harness proposer）始终是固定的 Claude Opus 4.7。论文没有测量“编辑能力”随轮次的提升。
- **B4（没有更大的外部模型参与）**：**明确违反。** Claude Opus 4.7 负责编写 harness，GPT-5.4-mini 在 SearchQA 上当评判。
- 总结：WHALE 是“外部前沿 LLM 改 harness + 小模型 RSFT 自训练”的交替方案。它与 Topic B 的共同点只有“同一模型自生成训练数据”和“多轮交替”。
