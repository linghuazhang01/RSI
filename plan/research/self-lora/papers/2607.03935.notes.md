## 研究问题
现有的自演化框架（AlphaEvolve、FunSearch、test-time RL 等）通常把 harness 当作固定的，包括 prompt、memory、检索和评估器。但人写的评估器可能有漏洞，可能被 reward hacking 利用；guidance 部分也可能提供很差的搜索先验。HASE 让同一个模型在一个多轮动作空间里，既能提交任务解，也能编辑被选中的 harness 组件。同时用 RL 更新这个模型的权重，从而让权重、harness 和解共同演化。

## 方法细节
- **模型**：Qwen3-8B，只用这一个模型（p1、p6）。用 VeRL 框架做 GRPO，advantage 估计器是 entropic adaptive-β（附录 D，p13），训练中使用 FSDP 和 vLLM。**全文没有提到 LoRA**，【推断】是全参数 RL。
- **两类 harness**（§3.1，p2–3）：
  - Guidance 组件：prompt、memory 格式、检索脚本、上下文选择。可以自由编辑。
  - Evaluation 组件：本地评估器，即 validator 和 scorer，给出可能不准确的 proxy 分。只有在 proxy 和真实世界 oracle（不可编辑，比如排行榜）出现分歧时才允许修复。
- **统一动作空间**（§3.2）：模型在沙箱里可以用 ls、cat、grep、replace、overwrite 查看和修改被列入白名单的 harness 文件，也可以直接提交解，最后用 done 结束。论文没有额外的规划器决定何时改 harness。
- **算法**（Algorithm 1，§3.3，p4）：训练分若干 phase，每个 phase 含若干个 GRPO epoch。rollout 内对 harness 的编辑只在该轨迹内生效。奖励只看最终解的质量（由本地评估器打分），harness 动作本身不单独给奖励。如果一次 guidance 编辑让该轨迹得分超过当前持久 harness，就按 PoC 分进入候选池（附录 A.3）。phase 结束时，一个确定性控制器负责过滤、排序和验证候选，把最佳的稳定版本提交为持久 harness。评估器的编辑只有在能修复更多 mismatch 样例、并且不破坏接口和不回归时才被接受（§3.5）。
- **谁做什么**：
  - 训练数据：同一个 Qwen3-8B 的 on-policy rollout。论文提到每个 phase 由 orchestrator 生成 32 个 prompt（p6 第 421 行），但没说 orchestrator 是模型还是模板。【推断】更可能是固定脚本。
  - 超参、训练方案、训练代码：由人类固定，例如 Heilbronn 实验 batch 32、PPO mini-batch 32、每 phase 1 个 epoch，alpha 实验 3 个 phase、每 phase 3 个 epoch。模型**不**决定超参、LoRA 配置或训练代码。
  - harness 编辑（prompt、memory、检索代码、validator 代码）：由同一个 Qwen3-8B policy 编写（Fig.1 说明，p3；p7 第 504–506 行强调控制器从不自己提代码）。
  - 评判：任务奖励来自本地评估器（规则或代码）。评估器修复以真实世界 oracle 为锚。harness 是否提交由确定性控制器在验证集上判断。S2D 的 phase 评审写的是用“greedy base-Qwen3-8B 解码”在验证集上评估候选（附录 A.4，第 788 行）。附录 C 又说最终报告用的是“同一个最终 policy”（第 920 行）。评审到底用基座还是当前 policy，前后表述不完全一致。
  - 被训练的模型：Qwen3-8B，与编辑者是同一个模型，权重持续更新。
  - **外部模型**：训练闭环中没有。GPT-OSS-120B、Claude Code（作为 Meta-Harness 的 proposer）、Llama3、GPT-4.1、o3 等都只是基线，数字直接引自 Meta-Harness 和 CogAlpha 两篇论文（Table 2、Table 3）。alpha 实验结束后，用 4 个外部 LLM（Gemini、ChatGPT、DeepSeek、Claude Sonnet）对 30 个因子做了**事后泄漏审计**（附录 B.3，p12–13），它们不在训练环中。
- **每轮从哪里开始**：Algorithm 1 在整个训练过程中持续更新 π_θ，从当前 θ 继续训练，不重置。
- **训练后的模型在下一 phase 承担的角色**：只有一个模型。更新后的 policy 在下一 phase 同时担任解题者、guidance 编辑者和 evaluator 修复者。提交决定由确定性控制器做出，训练配方由人类固定。
- **轮次**：Heilbronn 共 8–12 个 phase（Fig.3）。circle packing 约 12 个 phase（Fig.2）。S2D 有 phase 0–4（Table 4）。alpha mining 有 3 个 phase。

## 数据集与评测
- Symptom2Disease（S2D）：沿用 Meta-Harness 的划分，训练 200、验证 50、测试 212，共 22 类。测试时单次贪心解码，harness 冻结（附录 A.4）。
- Alpha 因子挖掘：CSI300（CogAlpha 整理的 754 个成分股），预测 10 日收益。训练 2011–2019，验证 2020，测试 2021–2024。用 Qlib 模拟，包含交易成本和涨跌停约束。指标为 IC、RankIC、ICIR、RankICIR、AER、IR（§4.2.2，附录 B）。
- Circle packing：圆放入单位正方形，以 AlphaEvolve 的 SOTA 2.635983 为对照。
- Heilbronn 三角形：N=11，用面积归一化后的最小三角形面积，已知 SOTA 为 0.0365。

## 关键实验与数字
- **Table 2（p7，第 439–452 行）**：S2D 准确率。GPT-OSS-120B 的 zero-shot 63.2、few-shot 67.9、MCE 83.0、ACE 77.8、Meta-Harness 86.8；Qwen3-8B five-shot 59.4；**HASE（Qwen3-8B）86.98 ± 0.38**。这里的 ±std 来自同一个最终 policy 和 harness 的 5 次评测，不是训练 seed。
- **Table 3（p8，第 532–539 行）**：CSI300。HASE 的 IC 0.0308、RankIC 0.0302、ICIR 0.3414、AER 0.1435、IR 1.70；GPT-OSS-120B 分别为 0.0300、0.0318、0.2501、0.0789、0.8015。
- **Fig.2（p5）**：circle packing 中，初始 validator 缺边界和重叠检查，被 exploit 时 proxy 为 35.46、oracle 为 0。第一次修复后对齐在 2.607072。之后因为 1e-8 的容差再次被 exploit，第二次修复把容差收紧到 1e-12，最终得分 2.635983，与 AlphaEvolve 的 SOTA 持平。
- **Fig.3（p6，第 423–433 行）**：Heilbronn。完整共演化在 Phase 8 达到 0.036082。FREEZE 基线（权重冻结，只修评估器）停在 0.021880。这是论文中唯一的“权重是否必要”消融。
- **Table 4（p11）**：S2D 训练中，Phase 0 之后每个 episode 平均约 2.3–2.4 次工具编辑、约 1.2 次读操作。
- **是否测量了编辑者能力随轮次的变化**：**没有**。论文没有让不同 phase 的 policy 去编辑同一个固定的 recipient，也没有单独度量 harness 编辑质量随权重变化的曲线。FREEZE 消融说明的是权重更新对任务分数的作用，和“作者能力”无关。S2D 和 alpha 实验没有做 harness-only 或 weight-only 的拆分。

## 作者自己声明的局限（§6，p9）
- 不是穷尽式的规模研究，每个领域都还可以做更难的设置。
- 采用了偏保守的工程选择：可编辑组件有白名单，评估器修改需要先出现 proxy 和 oracle 的分歧，phase 评审只提交接口合法的补丁。这些限制可能会拒掉一些有用但改动较大的修改。今后可以扩大可编辑面、加强测试、使用信息更丰富的 mismatch 集。

## 方法问题与替代解释
- 【推断】基线数字直接引自其他论文（Meta-Harness、CogAlpha），协议和解码设置不完全相同，算不上严格的同条件对比。
- 【推断】S2D 测试集只有 212 题，±0.38 只反映评测时的方差。训练只跑一次，没有训练 seed 的方差。
- 【推断】S2D 和 alpha 实验缺少消融，看不出提升来自 harness 还是 RL 权重。Qwen3-8B 从 five-shot 59.4 到 86.98 的提升里，有多少是 harness（检索和 memory 代码）带来的，无法拆分。
- 【推断】phase 评审用的模型（基座还是当前 policy）表述不一致，这会影响“哪个 checkpoint 在评判”的判断。
- 【猜测】circle packing 和 Heilbronn 的结论基于单次运行和 log 尺度的曲线，“与 SOTA 持平”可能对 seed 很敏感。
- 【推断】“编辑”针对的是任务 harness（上下文、检索、评估器代码），不是训练配方。

## 与 core claims 的关系
- **B1**：**基本不覆盖**。同一个模型生成自己的 on-policy 训练轨迹，并编辑 harness 文件（prompt、memory、检索和验证代码）。评估器修复会改变奖励函数，从而间接影响训练信号。但模型**不决定**超参、训练算法、LoRA 配置，也不写训练代码，更不生成 adapter 权重。
- **B2**：**部分覆盖**。权重更新（GRPO，【推断】全参数，不是 LoRA）作用在同一个 Qwen3-8B 上，任务表现提升（Fig.3 中 FREEZE 与完整共演化的对比）。但最终部署的是“新权重加演化后的 harness”，两者的贡献在 S2D 和 alpha 上没有拆开。
- **B3**：**结构上覆盖，但没有测量**。只有一个模型，更新后的 policy 自然在下一个 phase 继续担任 harness 编辑者和解题者。但没有任何实验测量或隔离“编辑能力”随权重的提升。
- **B4**：**覆盖训练闭环这一部分**。没有更大的外部模型参与数据、提议或评判。外部大模型只出现在基线数字里，以及事后的 4-LLM 泄漏审计中（不在训练环内）。
