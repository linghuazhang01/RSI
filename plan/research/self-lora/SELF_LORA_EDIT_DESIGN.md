# 模型写代码编辑自己的 LoRA：研究方案

日期：2026-11-14
状态：方向方案，尚未做 pilot。下文引用的数字都来自已全文精读的论文笔记（`novelty/rsi-model-edit/papers/`、`novelty/self-lora/papers/`），新检索到、只看过摘要的论文会单独标注。

---

## 0. 一句话

先用梯度训练得到原始 LoRA，再让模型**写代码，在权重空间里编辑自己的 adapter**：逐层缩放、截断 rank、丢弃部分层、与历史 adapter 插值或合并、正交化等，不需要再训练。编辑结果由固定的外部评测验收。验收通过的模型成为下一轮的编辑者。

研究要回答两个问题：
1. **单轮**：模型自己写的权重空间编辑，在同等评估预算下，能否胜过"不编辑"、人工合并规则和非 LLM 搜索？
2. **递归**：编辑过自己之后，模型是否更会编辑 adapter？也就是给一个**固定的、别的模型**做编辑时，效果是否也变好？

## 1. 新颖性现状（只是快速检索，还不是正式查新）

- **已全文读过的最近工作是 Self-Developing（2410.15639）。** 模型自己写 Python 合并函数，把三个外部 7B 微调模型的任务向量合并到种子模型 M0 上，GSM8K 从 70.1 提到 76.1（Table 1，p.6）。和本方案的区别有三点：
  - 合并对象是现成的外部模型，不是模型为自己训练的 adapter；
  - 合并结果不会接任下一轮，算法始终作用于固定的 M0；
  - 写代码的能力靠外部 DPO 管线提升，模型不会对自己执行编辑。
- **非 LLM 的合并或编辑搜索很多，下面这些只看过摘要，后续必须全文读完。**
  - LoraHub：无梯度优化 LoRA 的组合系数；
  - Sakana 进化合并（2403.13187）；
  - EvoGM（2605.29295，ICML 2026）；
  - TaDA（逐层缩放加子空间过滤）；
  - TIES、DARE。
  这些是本方案必须正面对比的基线。
- **快速检索没有找到**"LLM 写代码编辑自己的 LoRA，并递归接任"的工作。
- **同类先例的警示**：LLM 搜索不一定比随机好。AutoQS 中，单个搜索种子下 LLM 的最佳 Macro3 是 73.85，随机变异是 73.45（Table 2）。两个搜索种子的 Macro7 相差 0.94（Table 8）。注意这是分差，不是方差，而且和前面的 Macro3 不是同一个指标。所以第一个 pilot 就要做这组对比。

## 2. 方法

### 2.1 模型表示：冻结基座 + adapter 栈

第 t 轮的模型表示为 M_t = θ0 + Σ_k A_k：基座 θ0 冻结，每个 A_k 是一个 LoRA。

为什么这样做：
- 所有编辑都发生在 adapter 空间，便宜，也可以回头修改历史 adapter；
- vLLM 支持同时挂多个 LoRA，候选 adapter 不需要合并进基座就能评测，评测成本低；
- 遗忘可以控制：任何时候都能回滚到某个历史栈。

### 2.2 每一轮的流程

```
第 t 轮（父模型 M_t = θ0 + 当前 adapter 栈）
1. 训练原始 adapter：
   在任务 T_t 的训练集上训练 LoRA，得到 A_raw。
   pilot 阶段用人工固定的配置；第二阶段改为模型自选配置。
   同时保存训练轨迹上的几个 checkpoint，给编辑提供素材。
   编辑者 = R_t = M_t ⊕ A_raw：先装上 raw LoRA，再由这个权重状态生成编辑程序。
   这样做才符合"同一个 checkpoint 编辑它自己的 adapter"。
2. 诊断工具（编辑者 R_t 可以调用）：
   - 每层或每个模块的 ‖BA‖、奇异值谱、有效 rank
   - A_raw 与历史 adapter 在各层的余弦相似度（判断干扰）
   - 逐层消融：去掉第 l 层的 adapter 后，dev loss 的变化
   - dev 上的错题样例；保留集（旧任务 + 通用能力）的分数
3. 编辑：模型写 edit(adapters, stats) -> new_adapter，
   只能调用一套受限的算子库（见 2.3），在沙箱里执行。
4. 评测候选：dev 集上的目标任务增益 − λ × 保留集下降，
   同时满足约束（rank 上限、数值有限、形状不变）。
   每轮生成 N 个候选（例如 16–32 个），可以带反馈迭代几次。
5. 验收：最优候选在 dev2（与 dev 不重叠）上通过固定的门槛后，
   得到 M_{t+1} = Apply(编辑程序, R_t)，下一轮由它的后继当编辑者。
   如果编辑改动了历史 adapter，就替换栈里对应的成员，
   不要把已经包含旧 adapter 的合并结果再追加一次。
   dev2 的使用次数要预先规定（或每轮换新分片），否则它也会变成自适应选择的一部分。
   test 集封存，只在最后报告。
```

**每个父 checkpoint 都保留四个分支，用于归因**：

| 分支 | 内容 |
|---|---|
| Parent | M_t，训练前的编辑者 |
| Raw | M_t ⊕ A_raw，只做了普通任务训练 |
| LLM-edited | 在同一个 Raw 上执行 LLM 写的编辑 |
| Non-LLM-edited | 在同一个 Raw 上执行最好的非 LLM 编辑 |

用同样的初始 prompt、历史、工具、固定被编辑模型和 raw-adapter 测试库测编辑能力 E，并分别报告：
- ΔE_train = E(Raw) − E(Parent)：普通训练本身带来的编辑能力变化；
- ΔE_edit = E(LLM-edited) − E(Raw)：编辑本身带来的变化。

如果 Non-LLM-edited 分支也让 E 提升，就不能把收益只归因于 LLM 自编辑。

### 2.3 算子库（受限 API，模型写代码组合这些算子）

| 类别 | 算子 | 作用 |
|---|---|---|
| 缩放 | scale(layer/module, s) | 削弱过拟合层，或增强有效层 |
| 低秩 | truncate_rank(layer, k)、svd_reweight(layer, f(σ)) | 去掉噪声方向，减小 adapter |
| 稀疏 | drop(layer/module)、magnitude_prune(density) | 只在关键层保留更新 |
| 组合 | interpolate(A, B, λ)、task_arithmetic、ties、dare | 与历史 adapter 或训练轨迹上的 checkpoint 组合 |
| 抗干扰 | orthogonalize(A_new, A_old)、project_out(subspace) | 减少对旧任务的覆盖，降低遗忘 |
| 自由组合 | 用 torch 在受限 API 内写新算子（规定输出形状和 rank 上限） | 留出发现新编辑规则的空间（类似 Self-Developing） |

分两级推进：
- **Level 1**：只能设置算子参数，相当于一个低维决策空间，和自量化的"逐层分配比特"同构；
- **Level 2**：允许写新算子。先做 Level 1，跑通后再开放 Level 2。

### 2.4 编辑能力从哪里来

主实验**不显式训练编辑能力**。编辑者能力的变化只来自"自己的 adapter 栈变了"，这样才能干净地回答"权重变化是否让模型更会编辑"。

第二阶段可以加一个变体：把成功的编辑程序当训练数据，用 ReST^EM 训练一个"编辑技能"LoRA，类似 SEAL 和 Self-Developing 的外层训练。这个 LoRA 的数据同样完全由模型自己产生。

## 3. 实验设计

### 3.1 模型

- **Pilot 用 Qwen3-8B 或同级 8B 模型。** Search over Self-Edit 用的就是 Qwen3-8B，SEAL 用的是 Qwen2.5-7B，可以直接对照，成本也低。
- **主实验用 27B。** 建议选和自量化那篇相同的模型，两篇可以共用基础设施。
- **成本参考**：MASS 在 27B 上做一轮 LoRA SFT，用 17.2M token，花了约 6×H100 × 19 小时（p.17）。本方案每个任务的训练数据少得多；编辑本身不需要训练，主要成本在评测。

### 3.2 任务（要求：有训练集、能自动评测、能测遗忘）

| 任务 | 训练 → 评测 | 选它的原因 |
|---|---|---|
| 知识注入 | SQuAD 无原文 QA（SEAL 设置：50 段训练、200 段验证） | 能直接对比 SEAL 的 47.0 和 Search 的 45.1 / 50.3 |
| 数学 | GSM8K 训练 → MATH-500 | 有标准答案 |
| 代码 | MBPP 训练 → HumanEval+、MBPP+ | 能执行验证 |
| 科学 / 工具调用 | 采用 SDFT 的 Science（2,674 / 507）和 Tooluse 划分，或 BFCL | 有遗忘对照数据 |
| 保留集 | MMLU-Pro、IFEval，加上之前学过的任务 | 测遗忘 |
| **编辑能力测试** | 编辑者从没训练过的新任务（例如 TableBench、FinanceIQ） | 用来测 E_t（见 3.4） |

任务按顺序进行（连续学习），这样"抗干扰"类编辑才有用武之地。

### 3.3 对照组

| 对照 | 回答的问题 |
|---|---|
| 不编辑（A_raw） | 编辑有没有用 |
| 人工规则：TIES、DARE、task arithmetic，λ 在 dev 上网格调优 | 是否胜过常规合并 |
| **非 LLM 搜索，算子空间和评估次数都相同**：随机搜索、CMA-ES / 进化、LoraHub 式系数优化 | 是 LLM 的推理在起作用，还是任何搜索都行（**最关键**） |
| 外部强模型当编辑者（只作上界，不进主循环） | 离上界还差多少 |
| 每轮都由冻结的 θ0 当编辑者 | 接任有没有贡献 |
| 连续编辑 vs 每轮从 θ0 重新开始 | 历史是带来收益，还是累积误差 |

### 3.4 指标

- **目标任务**：相对 A_raw 的提升，以及相对基座的提升。
- **遗忘**：保留集分数和旧任务分数。
- **编辑者质量**：合法程序的比例、通过验收的比例、单位评估预算换来的提升。
- **编辑能力 E_t（核心指标）**：让 M_t 当编辑者，去编辑一个**固定的**模型在**新任务**上训练出的 A_raw，测量编辑后的提升。被编辑的模型、新任务和预算都固定，这样才能分清"作者变强了"和"被编辑的模型更容易提升"。
- **成本**：GPU 小时、编辑者生成的 token 数、评测次数。
- **统计**：至少 3 个训练种子，报告方差。dev、dev2、test 三者严格分开。

## 4. Pilot 顺序（每一步都有判断条件）

**P0 先测可提升空间**（8B，不用 LLM）
- 做法：在 3 个任务上训练 LoRA，用网格或随机方式扫简单算子（逐层缩放、截断 rank、与旧 adapter 插值），在一份**可丢弃的 pilot holdout** 上看相对 A_raw、TIES 和 PARA 还能提升多少。不能看最终封存的 test 集来决定方向。
- 判断：
  - 单任务提升小于约 1 分，而连续学习的遗忘能减少很多：把论文目标定为"抗遗忘编辑"；
  - 两种情况都提升很小：这个方向不成立，及早止损。

**P1 单轮 LLM 编辑者 vs 非 LLM 搜索**（8B）
- 做法：在相同的算子空间和评估次数下比较。
- 判断：
  - LLM 不比进化或随机搜索差，且搜索成本更低或对新任务泛化更好：继续；
  - LLM 明显更差：先改诊断工具和反馈设计，再试一次。

**P2 递归接任**（8B）
- 做法：跑 3–5 轮任务序列，加上"冻结编辑者"和"固定被编辑模型下的 E_t"两个对照。这是整篇论文的核心结果。

**P3 扩展**
- 换到 27B；
- 让模型自选 LoRA 训练配置；
- 开放 Level 2 自由算子；
- 加入编辑技能的 ReST^EM 训练。

## 5. 风险

1. **训练好的 LoRA 可能已经接近最优，事后编辑的空间小。** 从合并类文献的动机推断，收益更可能出现在多任务干扰和遗忘上，所以 P0 要先测。
2. **非 LLM 搜索可能一样好。** AutoQS 已经显示了这种风险。如果真是这样，论文的论点就要转向"迁移到新任务"或"搜索成本更低"。
3. **在 dev 上评估大量候选会产生选择偏差。** 必须用 dev2 验收、test 封存。
4. **模型写的代码要在沙箱里跑。** 要求无网络、限时、只能调用白名单 API，并检查输出形状和数值是否有限。
5. **递归可能退化。** R-Zero 在共享参数时第 1 轮就到峰值，之后下降。递归自训练崩塌那篇也显示自评门会失效。所以验收必须用固定的外部评测，不能让模型自评。

## 6. 和自量化那篇的关系

两篇共用"模型给自己做逐层决策"这个框架：自量化决定每层用几比特，自编辑 LoRA 决定每层的缩放、rank 和组合方式。递归、对照组（冻结编辑者、固定被编辑模型）和评测协议也可以共用。可以作为两篇独立论文，也可以在讨论部分互相引用。
