## 研究问题
LLM 在 4 bit 以下做仅权重 PTQ 时，均匀量化的精度会断崖式下降。混合精度可以把更多 bit 分给敏感模块，但在 LLM 规模上自动做 bit 分配很难：可学习的方法需要 QAT，代价过高；基于 Hessian 等静态代理指标的方法看不到跨模块交互，而且每换一个预算就要重算；搜索类方法（如 AMQ 的进化搜索）很贵，也不保证严格满足预算。GAMMA 想在纯 PTQ 流程中学到模块级精度偏好，严格满足全局平均 bit 预算，并让一次学到的分数复用于任意预算。

## 方法细节
- **候选池**：先用现成的 PTQ 方法（主实验用 QTIP，附录 E 用 AQLM）把每个线性模块分别量化到候选 bit 宽 B = {2, 3, 4}，得到预量化权重 W_b。之后所有权重冻结，只学习 bit 选择参数（§3.1–3.2，p.3）。
- **粒度**：每层 7 个线性模块（q, k, v, o, up, gate, down），每个模块选一个 bit 宽（§3.2，p.3）。推理时每个模块是单一 bit 宽，可以直接复用现成 kernel（App. B，p.13）。
- **Stage I：可微分数学习**（§3.3–3.4，p.3–5）
  - 每个模块对候选 bit 宽有一组 logits，经 Gumbel-Softmax（τ 固定为 1）得到概率 p，混合权重 W_mix = Σ p_b · W_b（Eq. 6–7）。
  - 目标：teacher-forced 的逐层隐藏状态重构 MSE，即把 FP16 的上一层输出喂给混合精度的当前层，与 FP16 当前层输出比较（Eq. 3–5）。
  - 预算约束：期望平均 bit 宽 b̂(p)（按参数量加权）通过增广拉格朗日推向 b_target，λ1、λ2 可学习并做最大化（Eq. 9）。
- **Stage II：离散化**（§3.5，p.5）：以 s = p 作为分数，解 0-1 背包式整数规划（Eq. 11）：每个模块选一个 bit 宽，使分数和最大，且参数加权平均 bit 不超过 b_target。可用 DP 或 ILP 求解，作者称开销可忽略。换预算时只需重解 ILP（score reuse）。
- **校准数据**：从 RedPajama 采样 1024 条、长度 2048 的序列（§4.1 p.5；App. H p.15）。附录另用 WikiText 做了热力图对比（App. I）。
- **优化超参**（App. H，p.15）：batch size 8，1120 步，lr 5e-3，SGD，Gumbel 温度 1。
- **搜索/分配成本**：
  - Qwen3-8B 在 A100 上 Stage I 约 1 小时，Stage II 可忽略（§5.2 p.10；App. H p.15）。
  - Table 6（p.13）：GAMMA 在 Llama3.1-8B、Qwen3-8B、Qwen3-14B 上分别耗时 1.33 / 1.51 / 2.43 h，HAWQ-V2 为 1.28 / 1.63 / 2.88 h。
  - AMQ 的搜索约 4 小时（p.10）。
  - 显存开销约为模型权重大小的 2–3 倍（p.14）。
  - 注意：成本里不含为每个候选 bit 宽先跑 QTIP/AQLM 量化的时间（作者假定候选已存在，局限中有提及）。
- **非 LLM 的经典分配基线**：作者自己为 LLM 重实现了 HAWQ-V2（Hutchinson 估计 Hessian trace + ILP，App. C p.13–14），另有 AMQ（进化搜索）。

## 数据集与评测
- **模型**：Llama3.1-8B-Instruct、Qwen3-8B、Qwen3-14B（主表），Qwen3-32B（App. F，Table 11）。**没有 27B 模型。**
- **零样本 benchmark**（§4.1 p.5）：ARC-e、ARC-c、PIQA、HellaSwag、WinoGrande、BoolQ，取六项平均。用 OpenCompass 的**生成模式**评测，套 chat template，Qwen3 关闭 thinking。解码 temperature 0.7、top_p 0.8、top_k 20（App. H，p.15）。未报告重复次数或方差。
- **生成类与困惑度**（App. A，Table 4，p.13）：GSM8K（acc）、RULER（最长 32K）、WikiText2 / C4 困惑度。shot 数未说明。
- **基线**：AQLM（均匀固定精度）、AMQ（搜索式混合精度）、QTIP（同一 backbone 的均匀精度），以及 HAWQ-V2 重实现。
- **速度**：**测了解码吞吐**（App. B，Table 5，p.13）。AQLM 后端，Triton kernel，A100，batch 1，生成 128 token，取 10 次平均。**没有测显存占用或模型实际字节数**，"更小内存"只按平均 bit 宽推算。

## 关键实验与数字
- **Table 1（p.6）主表**（Avg.）：
  - Qwen3-8B 3.0 bit：AQLM 68.17，AMQ 74.16，GAMMA 81.16（FP16 为 81.97）。2.5 bit：64.53 / 72.11 / 76.77。3.5 bit：74.63 / 80.81 / 81.46。
  - Llama3.1-8B-Instruct 3.0 bit：AQLM 69.92，AMQ 76.68，GAMMA 78.31（FP16 79.60）。2.5 bit 时 GAMMA 73.86，仅比 AMQ（73.69）高 0.17。3.5 bit 时 78.73 vs AMQ 78.72。
  - Qwen3-14B 3.0 bit：AQLM 79.84，AMQ 83.00，GAMMA 83.75；3.5 bit 时 AQLM 83.66，GAMMA 83.84，差距很小。
  - 摘要里"比固定精度高 12.99"和"比 AMQ 高 7.00"都来自 Qwen3-8B 3.0 bit 这一个格子（p.6）。
- **Table 2（p.9，印刷 p.7）同 backbone 对比**：Qwen3-8B 上 QTIP 3 bit 为 76.33，GAMMA 3.0 为 81.16，GAMMA 2.5 为 76.77。Qwen3-14B 上 QTIP 3 bit 为 81.21，GAMMA 2.5 为 83.11。Llama 上 QTIP 3 bit 为 77.58，GAMMA 3.0 为 78.31。
- **Table 3（p.10）候选集与分数复用**：ternary {2,3,4} 在 2.5–3.5 bit 下为 79.36–82.41，binary {2,4} 为 77.52–82.07；从 3.0 bit 复用分数时为 79.18–81.36；AMQ 为 72.11–80.81。表中未写明模型。AMQ 行与 Table 1 的 Qwen3-8B 吻合，但 GAMMA ternary 的 2.5/3.0 bit（79.36/82.28）与 Table 1 中 Qwen3-8B 的 GAMMA（76.77/81.16）对不上。
- **Table 5（p.13）吞吐**：Qwen3-8B 上 AQLM-4bit 18.95、AQLM-2bit 18.45、GAMMA-2.5bit 18.49 tok/s。Qwen3-14B 上 AQLM 为 16.67–16.88，GAMMA 为 16.45–16.78。结论是混合精度相对均匀量化的吞吐差距在 3% 以内。**但低 bit 并不比 4 bit 更快**，因此论文没有展示真实的加速收益，只说明了"没有额外开销"。
- **Table 6/7（p.13）对比 HAWQ-V2**（Qwen3-8B，QTIP 后端）：3.5 / 3.0 / 2.5 bit 下 HAWQ-V2 为 78.43 / 75.24 / 75.41，GAMMA 为 81.46 / 81.16 / 76.77，提升 +1.36 到 +5.92；耗时相近。
- **Table 8（p.14）消融**（Qwen3-8B）：把增广拉格朗日换成 DNAS 式乘性惩罚，下降 2.56–3.45；把重构损失换成 CE，下降 0.95–3.29。但 2.5 bit 时 CE-Loss 变体的 ARC-e/ARC-c（86.42/74.92）反而高于 GAMMA（83.95/72.88）。
- **Table 9（p.15）AQLM 后端**：例如 Qwen3-14B 上 AQLM-3bit 为 76.63，GAMMA-3.0 为 83.92。
- **Table 10（p.15）**：Stage I 软分数与 Stage II 离散分配的 Pearson r 在 0.746–0.988 之间。
- **Table 11（p.16）Qwen3-32B**：FP16 84.83，QTIP-3bit 85.13，GAMMA-3.0 85.97，GAMMA-2.5 84.63，即量化后反而高于 FP16。
- **Fig. 4（p.9）/ App. I**：2.5 与 3.0 bit 的分配模式余弦相似度 0.9755；RedPajama 与 WikiText 校准下为 0.9913。k_proj 一贯分到更高精度，v_proj 接近最低精度。

## 作者自己声明的局限（p.11）
- 依赖多个 bit 宽的预量化候选权重，质量受 PTQ backbone 限制。
- 候选集或模块粒度变大时，离散分配的求解可能变贵。
- 评测覆盖零样本分类、GSM8K、RULER，尚未覆盖代码生成和开放对话。

## 方法问题与替代解释
- 【推断】评测采用生成模式加 temperature 0.7 采样，且无重复次数和方差。多处量化模型超过 FP16（Qwen3-32B 3.0 bit 85.97 > 84.83；Llama 3.5 bit 时 ARC-c 等单项也有），说明单次测量噪声可能达到 1–2 分，很多"小幅领先"（如 Llama 2.5 bit 时比 AMQ 高 0.17、Qwen3-14B 3.5 bit 时比 AQLM 高 0.18）不具统计意义。
- 【推断】基线数字有内部矛盾：Llama 上 AQLM 3.0 bit（69.92）低于 AQLM 2.5 bit（71.23），不单调；Table 9 中 Llama 的 AQLM-3bit 为 76.72，Table 1 的 AQLM 3.0 却是 69.92，同名基线相差近 7 分；Table 3 与 Table 1 的 GAMMA 数字对不上。AQLM 如何实现 2.5/3.5 bit 的均匀配置也没有说明。最显眼的 +12.99 正来自 AQLM 偏弱的 Qwen3-8B 3.0 bit 格子。
- 【推断】最公平的同 backbone 对照是 Table 2（QTIP 3 bit vs GAMMA）。Qwen3-8B 上的差距（76.33 vs 81.16）远大于 Llama（77.58 vs 78.31），说明收益依赖模型。
- 【推断】速度方面只证明"混合精度不拖慢"，没有证明"更低 bit 更快"：AQLM 2/3/4 bit 吞吐几乎相同。所谓的部署收益其实是内存，而内存没有实测。
- 【推断】经典非 LLM 分配基线 HAWQ-V2 是作者自行重实现的，实现质量无法独立验证。不过它给出了有用的参照：Qwen3-8B 3.0 bit 下 HAWQ-V2 为 75.24，已经高于 AMQ（74.16）。可见一个便宜的 Hessian trace + ILP 基线就已相当强，GAMMA 在此之上再提升约 1.4–5.9。
- 【猜测】分配模式在不同预算和校准集之间高度稳定，k_proj 高、v_proj 低。这暗示一个简单的按模块类型的启发式规则也许就能拿到大部分收益，论文没有做这种规则基线。
- 【推断】Stage I 的 1–2.4 h 成本不含为每个候选 bit 宽预先跑 QTIP 量化的时间，总成本被低估了。

| A3 目标是保住能力的同时获得真实推理效率，并由固定的外部评测判定 | 目标是在平均 bit 预算下保持精度；用固定的 OpenCompass 六项零样本和 GSM8K/RULER/PPL 评测；测了吞吐（只说明没有额外开销） | 没有实测内存；低 bit 没有带来吞吐提升；评测存在采样噪声 | **部分覆盖**（作为问题设定和评测协议可直接参考） |

结论：GAMMA 与 Topic A 在"自我决策 / 递归 / LLM 推理分配"这几个核心新颖点上**没有重叠**，但它是 A4 的强基线和实验协议来源。可直接借用的设置包括：8B–32B 模型；B = {2,3,4}；模块级粒度；QTIP/AQLM 后端；目标平均 2.5/3.0/3.5 bit；RedPajama 1024×2048 校准；六项零样本加 GSM8K/RULER/PPL；Qwen3-8B 上 Stage I 约 1 h、AMQ 约 4 h、HAWQ-V2 约 1.6 h。若 Topic A 用约 27B 模型，最接近的参照是 Table 11 的 Qwen3-32B。另外需注意：Topic A 若要声称"真实推理效率"，应当实测内存和吞吐，本文这两项都较弱。
