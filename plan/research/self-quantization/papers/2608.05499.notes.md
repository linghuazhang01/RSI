## 研究问题
视觉 DNN（CNN 和 ViT）的剪枝和量化通常依赖专家手调。统一压缩比忽略了各层敏感度的差异；GETA 这类联合优化方法需要大量数据；profiling 信息也没有接入压缩决策（Sec.1.1 p.2–3）。作者希望用一组 LLM agent，根据实测的 profiling 证据自动决定逐层剪枝率、逐层比特和恢复策略。

## 方法细节
- **提出策略的 LLM 和被压缩的模型是不是同一个**：不是，而且不属于同一类模型。planner 通过 OpenRouter 调用外部 LLM，主实验默认用 **Claude Opus 4.8**（p.16 Sec.4.4.3）；鲁棒性实验另外比较了 6 个 planner，包括 GPT-5.5、Qwen3.7 Max、DeepSeek V4 Pro、Gemma 等（Fig.7）。被压缩的是 ResNet-20/50、VGG7、ViT-Small、DeiT-Tiny、Swin-Tiny 这些**视觉分类模型**。论文没有压缩任何 LLM。
- **5 个 agent**（Sec.3 p.6，Fig.1）：
  - ProfilingAgent：用 ptflops 统计 MAC 和参数，用 torch.profiler 统计 CPU/GPU 耗时，再做 DepGraph 逐组、逐剪枝率的敏感度扫描，输出 CSV，并由 LLM 汇总成架构简报（Sec.3.1，Fig.2）。
  - PrunerAgent：LLM 为每个组或每层指定剪枝率，多阶段逼近用户设定的目标。每一阶段都从原始模型重放累积的剪枝组。策略非法时允许修复一次（Algorithm 1，p.9）。
  - FineTuningAgent：按精度下降 δ 和两个阈值（τ1=2%，τ2=4%）决定跳过恢复、用 PEFT 恢复，还是两阶段恢复（PEFT 后接全量微调）。PEFT 方法（LoRA、DoRA、rsLoRA、PiSSA、LoRA+）和超参由 LLM 选择。恢复后与恢复前比较，保留更好的那个（Sec.3.4，Fig.3）。
  - QuantAgent：LLM 为每层选择比特，候选为 {2*,4,6,8,16,32}，其中 2 bit 只给 VGG 这类架构用。用户可选 conservative、balanced、aggressive 三种 prompt 风格。用 Brevitas 插入 fake-quant 后做 QAT，并以全精度 teacher 做 KD；QAT 超参由 LLM 选，KD 温度和权重可由用户指定。之后可选做一轮 post-QAT KD，只有精度提升时才保留（Sec.3.3，Fig.4，Eq.1–2）。
  - EvaluationAgent：确定性组件，不使用 LLM，在固定的验证清单上测 Top-1/5、参数量和 Rel.BOPs（Sec.3.5，Eq.3–4）。
- **动作空间**：逐层结构化剪枝率、逐层权重和激活的比特宽度、恢复方法及其超参、QAT 超参。**不涉及** group size 和校准数据的选择（校准样本数算作 QAT 超参，由 LLM 设定）。
- **代理指标与真实评估**：管线内用验证集准确率决定是否恢复，用参数量跟踪剪枝目标。最终指标是 Rel.BOPs，按 MAC 乘以 b_w 乘以 b_a 计算的理论值。
- **搜索预算**：不是“采样大量候选再评估”的搜索。每个剪枝阶段 LLM 只出一份方案（阶段数由用户设定），量化也只出一份方案，基本是单路径规划。论文**没有报告** LLM 调用次数和成本，只在 Fig.7 中标注了每百万 token 的价格。
- **是否多轮、被压缩模型是否当 proposer**：剪枝是多阶段的，前一阶段结果会反馈给下一阶段的 LLM。但被压缩的视觉模型不可能当 planner，**没有递归**。

## 数据集与评测
- ImageNet-1k：训练只用 200K 张子集（每类 200 张），在全部 50K 验证图上评测（p.14）。Table 2 额外用全量训练集做约 5 个 epoch 的 post-QAT KD。
- CIFAR-10：5 个架构，外加 VGG7。
- 指标：Top-1、Top-5、参数量、Rel.BOPs。
- **没有实测推理速度或显存**。torch.profiler 的耗时只作为 profiling 输入。量化是 Brevitas 的模拟量化，压缩后模型没有部署测速【推断】。
- 没有 agent 或工具调用能力的评测，因为被压缩的是分类模型。

## 关键实验与数字
- **Table 1（p.14）**，ImageNet，200K 训练，conservative，不做 post-QAT KD：
  - DeiT-Tiny：66.52 → 67.90（+1.38），Rel.BOPs 5.63%
  - ResNet-50：80.13 → 72.73（−7.40），7.74%
  - Swin-Tiny：80.61 → 74.16（−6.45），6.17%
  - ViT-Small：79.87 → 76.50（−3.37），5.93%
- **Fig.5（p.14）**：同样 200K 预算下，GETA 掉到 51–59% Top-1，APQF 保持 68–77%（第 903 行）。GETA 由作者用其公开代码重跑。
- **Table 2（p.15）**，全数据：APQF 的 ΔTop-1 在 ViT-Small、Swin-Tiny 上比 GETA 差（−1.61 对 −1.31，−3.02 对 −0.83），但 Rel.BOPs 约低 3 倍（5.73 对 19.37 等）。需要注意 GETA 只量化权重，APQF 同时量化权重和激活（p.15）。
- **Table 3（p.15）**，CIFAR-10 与 GETA 对比：APQF 在 4 个模型上 Rel.BOPs 更低，DeiT-Tiny、ResNet-50、Swin-Tiny 的精度还超过了各自的基线。
- **Table 4（p.16）**，VGG7/CIFAR-10：APQF 在 0.41% BOPs 时为 93.15%（+0.20），GETA 在 0.41% 时为 92.57%；APQF 在 0.36% 时为 92.68%。其他方法的数字都是从原文引用的，基线也不相同（92.95 对 93.05）。
- **Fig.6（p.17）**，消融（CIFAR-10，大致同 BOPs）：Full、Uniform（统一剪枝率加统一比特，即 DepGraph + Brevitas）、w/o profiling 三组。Uniform 掉点最多，去掉 profiling 掉点较少。**正文没有给出具体数字**，只有柱状图。这是唯一的“非 LLM 分配”对比，而且对比对象只是统一配置，**没有**和 HAQ、HAWQ、随机搜索、进化或贝叶斯搜索在同预算下比较。
- **Fig.7（p.17）**，Swin-Tiny/CIFAR-10 上 6 个 LLM planner 的精度都在 97.4–97.9% 之间（第 1091 行）。Claude Opus 4.8 精度最高。

## 作者自己声明的局限
- 目前只做了图像分类，扩展到 SAM、LLM、VLM 留作未来工作（Sec.6 p.18）。
- LLM planner 有随机性，偶尔给不出可用方案。便宜模型和去掉 profiling 时失败更多。
- 剪枝、微调和 QAT 计算量大，算力限制了配置数和重复次数，也就是说没有多次重复实验。
- 仍需人工参与：选择 LLM、采样设置、部分 KD 超参，以及剪枝目标和量化激进程度都由用户设定。完全放开时失败率会上升。

## 方法问题与替代解释
- 【推断】EvaluationAgent 用固定的验证清单做两件事：一是选择“恢复前后哪个更好”，二是决定“post-QAT KD 是否保留”。CIFAR-10 和 ImageNet 的验证集同时也是报告精度的评测集，存在在测试集上做模型选择的风险。
- 【推断】ImageNet 上 DeiT-Tiny 的基线只有 66.52，而 GETA 测得同模型约 72.01（Table 2）。APQF 的基线偏低，所以 “+1.38 / +2.99” 的提升可能主要来自 KD 和微调修复了一个偏弱的起点，而不是压缩策略本身。CIFAR-10 上压缩后超过基线，也可以用额外的 KD 和微调训练来解释。
- 【推断】Rel.BOPs 是理论指标。把激活和比特按 2/4/6 bit 计入，并不代表真实硬件上能加速，论文没有任何实测延迟。
- 【推断】Fig.6 消融没有数值，也没有方差，无法判断 LLM 分配比统一分配好多少。“LLM 规划”和“经典逐层敏感度分配”（例如直接按 CSV 设阈值）之间没有对比，所以 LLM 推理本身的贡献没有被单独分离出来。
- 【推断】与 GETA 的比较不同条件：GETA 只量化权重，APQF 量化权重加激活，而且两者的基线精度和评测管线都不同。
- 相关线索：论文引用了作者前作 ProfilingAgent（arXiv 2509.05584），以及 Kodathala & Vunnam 的 “LLMs can compress LLMs: Adaptive pruning by agents”（arXiv 2601.09694，ref [70]，p.5、p.22）。后者用基础模型当剪枝 agent 去压缩 LLM，与 Topic A 可能更接近，建议另行查证。

## 与 Topic A 核心主张的关系
- **A1（同一 checkpoint 为自己的权重决策并执行）**：**未覆盖**。planner 是外部 LLM（默认 Claude Opus 4.8），被压缩的是视觉 CNN 和 ViT，不是同一模型，连模态都不同。执行由固定的 agent 流水线（DepGraph、Brevitas、PEFT 代码）完成，LLM 只输出 JSON 式的策略和超参。
- **A2（递归，被压缩模型当下一轮 editor）**：**未覆盖**。剪枝有多阶段反馈，但被压缩的模型不是 planner，也没有研究 editor 退化。
- **A3（真实推理效率加能力保持，含 agent 和工具调用，外部固定评测）**：**未覆盖或很弱**。只有理论 Rel.BOPs，没有实测速度和显存。能力只看分类准确率，没有 agent 或工具调用评测。评测由确定性的 EvaluationAgent 完成，但同一验证集也参与了模型选择。
- **A4（LLM 推理给出的分配在同预算下优于或持平经典非 LLM 分配）**：**部分覆盖**。LLM 给出逐层剪枝率和比特，在大致相同的 BOPs 下比统一剪枝率加统一比特更好（Fig.6，无数值），与 GETA、DJPQ、Bayesian Bits 等非 LLM 联合方法相比互有胜负（Table 2–4，条件不一致）。没有与非 LLM 搜索（随机、进化、BO、HAQ/HAWQ）在同搜索预算下的对比，也不涉及 LLM。
