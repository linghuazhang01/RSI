                                                      Quantization reduces LLM deployment costs, but effective strategies must bal-
                                                      ance model quality and storage. LLM-driven search can automate strategy de-
                                                      sign through repeated proposal and evaluation. This process must identify useful
                                                      strategies within a limited evaluation budget. The key challenge is that actual
                                                      quantization is expensive, while inexpensive proxies may not reflect quantized-
                                                      model performance. To address this challenge, we present AutoQS, an Automated
                                                      Quantization Strategy Design with LLMs. AutoQS keeps weight precision fixed
                                                      and searches group-size allocations across layers and operators under deploy-
                                                      ment constraints. Evaluation history guides coordinated LLM proposals, while
                                                      deterministic validation ensures compatible allocations. An inexpensive quality
                                                      proxy evaluates candidates, and an candidate repository retains alternative alloca-

                                                      Qwen2.5-7B-Instruct show that AutoQS improves seven-task average accuracy

                                                      tively, at four-bit weight precision.


                                         1        I NTRODUCTION

                                         Quantization reduces the storage and memory requirements of large language models (LLMs) by
                                         representing weights with fewer bits (Frantar et al., 2023; Lin et al., 2024). Preserving model qual-
                                         ity under this compression requires careful choices about how quantization is applied throughout
                                         the model. Even at a fixed weight precision, quantization granularity remains an important design
                                         choice. In group-wise quantization, groups of weights share quantization parameters, such as scales.
                                         Smaller groups provide finer granularity at the cost of additional metadata. Because model compo-
                                         nents respond differently to quantization, a uniform allocation need not provide the most effective
                                         use of this granularity (Dong et al., 2019; Heo et al., 2024). Designing a heterogeneous allocation
                                         therefore requires coordinating decisions across layers and operators while respecting the configu-
                                         rations supported by the quantization implementation.
                                         Existing research provides two complementary foundations for automating this process. Quanti-
                                         zation methods improve how low-precision weights are obtained. GPTQ, a post-training quantiza-
                                         tion method for generative pre-trained transformers, uses approximate second-order information to
                                         reduce reconstruction error (Frantar et al., 2023). Activation-aware Weight Quantization (AWQ)
                                         protects salient weight channels using activation statistics, while OmniQuant learns calibration pa-
                                         rameters to improve low-bit reconstruction (Lin et al., 2024; Shao et al., 2024). Automated alloca-
                                         tion methods, including Hardware-Aware Automated Quantization (HAQ), further demonstrate the
                                         value of using evaluation feedback to choose quantization configurations (Wang et al., 2019). In
                                         parallel, LLM-driven systems such as FunSearch and Evolution of Heuristics automate program and

2024). Recent systems further show how evaluation feedback can guide subsequent LLM-generated
changes during iterative search (Ye et al., 2024; Novikov et al., 2025). These developments motivate
an analogous approach to quantization strategy design, where proposed allocations are evaluated
and the resulting evidence informs later proposals.
Applying this approach to quantization introduces two connected difficulties. First, a proposed strat-
egy must become a valid allocation before it can be evaluated. Changes across layers and operators
must satisfy shared-configuration requirements, and differently expressed proposals may encode
the same allocation. Second, evaluating a valid allocation at full fidelity requires constructing and
testing a quantized checkpoint. Repeating this process for every proposal would consume the ex-
perimental budget quickly. Inexpensive proxies support broader exploration, but their scores do not
directly establish downstream accuracy or the size of a materialized checkpoint. These difficulties
raise a central question. How can LLM-driven search turn quantization proposals into executable
strategies and improve them using a limited number of actual quantization evaluations?
We address this question with AutoQS, a framework for Automated Quantization Strategy De-
sign with LLMs. AutoQS keeps weight precision fixed within each run and searches group-size
allocations across layers and fusion-compatible operator groups. To turn proposals into executable
strategies, it combines structured LLM edits with deterministic validation. The LLM receives a
parent allocation, previous evaluation results, and a candidate repository, and proposes sparse edits
that can jointly change several operator decisions. Each proposal is checked for consistency with the
parent and for compatibility with the supported quantization configurations. Equivalent allocations
are detected from their canonical representation, and deterministic novelty repair seeks an unseen
valid alternative when an allocation is repeated. This gives the LLM scope to propose coordinated
changes while enforcing the concrete requirements of the quantization implementation.
Multi-fidelity optimization provides a precedent for combining inexpensive approximations with
costly target evaluations (Kandasamy et al., 2017). AutoQS adopts this broad evaluation princi-
ple through low-cost candidate assessment and periodic evaluation of quantized checkpoints.
Valid, unseen candidates receive a scalar proxy score together with diagnostic statistics and a storage
estimate. Maintaining a population of evaluated candidates can provide varied contexts for subse-
quent LLM proposals, as demonstrated by FunSearch (Romera-Paredes et al., 2024). In AutoQS, the
candidate repository supports parent selection and retains alternative allocation patterns for later pro-
posals. However, proxy-based exploration alone cannot verify the quality of the resulting quantized
models. AutoQS therefore complements this loop with periodic quantization and checkpoint
feedback. At a fixed interval, it evaluates the latest eligible candidate in the current search win-
dow. The selected strategy undergoes fresh GPTQ quantization (Frantar et al., 2023), followed by
development-task evaluation and checkpoint-size measurement. The resulting observations inform
later search decisions, connecting proposal generation to the behavior of actual quantized models.
The default protocol permits at most 20 such evaluation opportunities over 100 search iterations.
After candidate selection is frozen, a broader seven-task evaluation assesses the selected strategies
without feeding its results back into search.
At four-bit weight precision, AutoQS improves seven-task average accuracy over uniform-group
GPTQ and AWQ by 0.70 and 1.12 percentage points, respectively, on Qwen2.5-7B-Instruct.
Matched-seed ablations support the roles of LLM proposals and checkpoint feedback in improv-
ing search-time performance. Case studies further examine how the discovered strategies allocate
quantization granularity across model components and transfer to related models without additional
allocation search.
Our contributions are threefold as follows:

       • Automated quantization strategy design. We introduce AutoQS to automate heteroge-
         neous group-size allocation at fixed weight precision. The framework uses an LLM to
         propose coordinated strategy changes while enforcing operator compatibility and alloca-
         tion validity.
       • Search with periodic checkpoint feedback. We combine inexpensive candidate evalua-
         tion and candidate search history with a bounded schedule of actual quantization evalua-
         tions. Measured checkpoint quality informs subsequent search, while checkpoint material-
         ization provides direct storage measurements.

2     R ELATED W ORK

2.1   Q UANTIZATION S TRATEGY D ESIGN FOR L ARGE L ANGUAGE M ODELS

Post-training quantization (PTQ) reduces the memory and inference cost of large language mod-
els without retraining the full model. Representative methods mainly improve quantization fidelity
under a specified configuration. GPTQ uses approximate second-order information for one-shot
weight quantization (Frantar et al., 2023), AWQ protects activation-aware salient weights through
channel scaling (Lin et al., 2024), while SmoothQuant redistributes quantization difficulty between
activations and weights (Xiao et al., 2023). OmniQuant further optimizes clipping and equivalent
transformations using a small calibration set (Shao et al., 2024). These methods substantially im-
prove low-bit quantization, but the choice of quantization configuration itself remains an important
design variable.
A complementary line of work therefore treats quantization as a resource allocation problem. HAQ
automatically searches layer-wise mixed-precision policies using hardware feedback (Wang et al.,
2019), while HAWQ-V3 selects mixed-precision configurations by balancing model perturbation
against deployment constraints (Yao et al., 2021). Such methods primarily vary the precision as-
signed to different model components. AutoQS instead fixes the weight bit-width within each search
run and searches layer- and operator-wise group-size allocations. It therefore treats quantization
granularity allocation, rather than weight precision itself, as the strategy-design variable.

2.2   LLM-G UIDED S EARCH IN S TRUCTURED D ESIGN S PACES

Large language models have recently been used as semantic proposal operators inside iterative
search. Evolution through Large Models (ELM) uses an LLM as a mutation operator in evolutionary
program search (Lehman et al., 2023), while FunSearch couples an LLM with executable evaluation
and an evolving program population (Romera-Paredes et al., 2024). Evolution of Heuristics (EoH)
evolves heuristic ideas and implementations jointly (Liu et al., 2024), and ReEvo combines evo-
lutionary search with LLM-based reflection to improve subsequent proposals (Ye et al., 2024). A
common principle across these methods is that evaluated candidates and search history are fed back
to the LLM to guide later generations.
Most existing LLM-driven evolutionary systems operate over comparatively open-ended spaces such
as programs or heuristics. Quantization strategy search is more constrained: every proposal must
preserve the model structure and fixed precision, assign legal group sizes to all required operators,
and avoid repeatedly evaluating previously visited policies. AutoQS therefore uses the LLM as a
constrained strategy-search operator rather than as an unrestricted code generator. Model sensitivity
and search history guide coordinated policy changes, while policy validation, novelty checking, and
nearby refinement keep the search within a valid structured design space.

2.3   B UDGET-E FFICIENT AND D IVERSITY-P RESERVING S EARCH

High-fidelity evaluation is often the dominant cost in automated design. Multi-fidelity methods
address this problem by evaluating many configurations cheaply and allocating greater resources
only to selected candidates. Hyperband formalizes this idea through adaptive resource allocation and
early stopping (Li et al., 2018), while BOHB combines multi-fidelity resource allocation with model-
based search (Falkner et al., 2018). A similar tension arises in quantization search: inexpensive
proxies permit broad exploration, whereas fresh quantization and downstream evaluation provide
more faithful but substantially more expensive measurements.
Selecting candidates solely by a scalar proxy score can nevertheless concentrate the search on
highly similar configurations. Quality-diversity methods such as MAP-Elites instead retain high-
performing solutions across distinct regions of a search space (Mouret & Clune, 2015). AutoQS

3       M ETHOD
AutoQS searches for group-size allocations while keeping weight precision fixed. The framework
separates inexpensive candidate exploration from periodic evaluation of actual quantized models.
An LLM proposes changes to an existing allocation. Each proposal is validated and checked for du-
plicates, with deterministic novelty repair used to seek an unseen allocation before proxy evaluation.
Evaluated policies and their results are retained to guide subsequent proposals. Every five iterations,
the latest eligible candidate from the current search window is selected for fresh GPTQ quantiza-
tion. The resulting checkpoint provides measured task accuracy and storage cost. We first define
the allocation problem (Sec. 3.1), then describe candidate generation (Sec. 3.2), proxy evaluation
(Sec. 3.3), and periodic quantization (Sec. 3.4).

3.1      P ROBLEM F ORMULATION AND F EASIBLE A LLOCATIONS

Consider a pretrained transformer with L layers. The weight bit-width b is fixed within a search run
and is not a search variable. AutoQS instead assigns group sizes across layers and operator groups.
A group size controls how many weights share quantization parameters. Smaller groups provide
finer granularity but require more scale-related metadata. Different allocations can therefore change
quantization error and checkpoint size without changing the weight bit-width.

3.2   C ONSTRAINED LLM-G UIDED C ANDIDATE G ENERATION

The allocation space grows exponentially with the number of layers. Following the iterative mod-
ification of existing candidates in LLM-driven evolutionary search (Novikov et al., 2025), AutoQS
explores this space through edits to a parent allocation. The LLM receives the parent’s alloca-
tion and evaluation statistics, representative searched policies, and a summary of search history.
Sensitivity-related statistics are retained as auxiliary Stage-1 evaluation signals. They are not speci-
fied as explicit layer- or operator-level instructions to the LLM proposer.
Each mutation is expressed as one to four sparse, layer-level SEARCH/REPLACE blocks. These
blocks modify a small number of complete layer configurations. Several operator decisions can
change together, allowing the LLM to explore coordinated allocations without regenerating the en-
tire policy. Candidate alternatives inform the proposal, but all changes are applied to the currently
selected parent. For each modified layer, the proposal’s stated source configuration must match that
parent exactly. A mismatch invalidates the proposal. This prevents contextual examples or stale
allocations from becoming unintended modification targets.
The child policy is then checked against the feasible space in Eq. equation 1. Validation enforces the
fixed bit-width, supported group sizes, and required operator structure. A canonical representation
places the allocation decisions in a fixed order. Its hash identifies equivalent policies even when their
proposal text differs. Previously evaluated allocations are detected before another proxy evaluation.
A deterministic novelty-repair procedure is applied to seek an unseen allocation. Any repaired
allocation must satisfy the same validity checks and must be checked again for semantic duplication
before evaluation. This procedure separates the LLM’s proposal process from the strict assignments
required by the quantization implementation.
The candidate-generation procedure therefore consists of sparse LLM edits, validation, and deter-
ministic novelty repair. It does not include an independent local-refinement or neighborhood-search
operator. Novelty repair addresses repeated assignments; it is not a quality-driven local search.

Maintaining evaluated candidates as context for subsequent generation is also used in LLM-driven
program search (Romera-Paredes et al., 2024). AutoQS retains evaluated policies, their scalar proxy
scores, and individual diagnostic statistics in a candidate repository. The candidate records explored
allocations and provides earlier results for subsequent parent selection and proposal generation.
It also preserves access to different allocation patterns rather than limiting the search context to
one incumbent. Representative policies can include both high-performing and structurally different
allocations. The accompanying visited-policy record supports duplicate detection.
The inexpensive loop thus proceeds from proposal generation to validation, proxy evaluation, and
candidate records update. The recorded evaluation information supports the context used for later
proposals. This supports exploration between actual quantization attempts. Retaining different poli-
cies does not by itself establish their quality after GPTQ quantization, so the search also performs
periodic checkpoint evaluation.

globally fixed group size while keeping the weight precision fixed.
The behavior also extends beyond the Qwen2.5-7B base checkpoint. On Qwen2.5-7B-Instruct, Au-
toQS reaches 75.16 Macro7, compared with 75.12 for the dense model and 74.46 for uniform-G128

4.3     S EARCH E FFECTIVENESS

To isolate the contribution of the search mechanism, we compare three Qwen2.5-7B W4 runs using
the same search seed of 1234. The Full configuration uses the Qwen-Plus proposer and incorporates
physical-evaluation feedback into later search decisions. The No-feedback variant retains the same
proposer and physical evaluation schedule but removes physical feedback from subsequent search.

A     A DDITIONAL E XPERIMENTAL D ETAILS

A.1   S EARCH AND E VALUATION P ROTOCOL

For each AutoQS run, the weight bit-width is fixed throughout the search and is not itself a search
variable. The search instead assigns heterogeneous group sizes across transformer layers and oper-
ator groups from

                                    G = {−1, 16, 32, 64, 128}.

Different weight precisions are therefore evaluated through independent fixed-bit runs.
Unless otherwise specified, the formal search contains T = 100 iterations. Every valid unseen
candidate first receives the frozen low-cost Stage-1 evaluation. A high-fidelity physical evaluation
is scheduled every five iterations, yielding at most 20 physical evaluation opportunities per run.
For physical evaluation, the selected allocation is freshly instantiated using GPTQ and evaluated on
ARC-Challenge, PIQA, and BoolQ. We denote the unweighted mean over these three search-time
tasks as Macro3. The generated quantized checkpoint and its measured storage are retained together
with the physical evaluation result.
After search, frozen checkpoints are evaluated on seven downstream tasks: MMLU, HellaSwag,
ARC-Easy, ARC-Challenge, PIQA, WinoGrande, and BoolQ. Their unweighted mean is denoted
Macro7. These post-search Macro7 results are not fed back into search.
Because ARC-Challenge, PIQA, and BoolQ are already used in the search-time Macro3 evaluation,
the complete seven-task set should not be interpreted as fully held out. The remaining four tasks—
MMLU, HellaSwag, ARC-Easy, and WinoGrande— are not used in the Macro3 search objective.


A.2   S EARCH S EED AND E VALUATION S EED

For search-ablation experiments, the seed reported in the tables denotes the search/evolution seed.
Unless explicitly stated otherwise, post-search Final-7 evaluation uses random seed 1234. Search
stochasticity and post-search evaluation stochasticity are thus controlled separately.
This distinction is relevant when comparing multiple searches of the same model. For example,
differences between Qwen-Plus searches using seeds 1234 and 2026 arise from different search
trajectories rather than a change in the Final-7 evaluator seed.


A.3   Z ERO -S HOT Q UANTIZATION -P OLICY T RANSFER P ROTOCOL

To evaluate whether a searched allocation policy can be reused beyond its source checkpoint, we
perform zero-shot quantization-policy transfer.
The source allocation is selected using only source-model search-time Macro3 and is subsequently
frozen. For each target model, we perform no target-side allocation search, no target-side policy
adaptation, and no post-search Final-7 feedback. The frozen layer- and module-specific group-size
assignment is applied unchanged to the target architecture.
GPTQ calibration and packing are nevertheless performed freshly on the target weights. Thus, the
transferred object is the quantization allocation policy rather than the quantized source weights.


A.4   S EARCH B UDGET AND R ETAINED ACCOUNTING

The frozen canonical runs do not retain recoverable per-request LLM token-usage records or API-
cost accounting. We therefore report directly supported physical-evaluation and hardware quantities
rather than retrospectively estimating missing API costs.

D.3      W HAT AUTO QS O PTIMIZES C OMPARED WITH E XISTING Q UANTIZERS

The comparison in the main paper separates the quantization algorithm from the allocation policy.
In the reported W4 experiments, the external baseline configurations use a globally fixed group size
of 128. In contrast, AutoQS keeps weight precision fixed while exposing module-level group size
as a discrete search variable.
The legal allocation choices are

                                            G = {−1, 16, 32, 64, 128}.


GPTQ and AutoQS therefore operate at different levels of the overall quantization problem. GPTQ
determines how weights are quantized under a specified configuration, whereas AutoQS searches
which grouping configuration is supplied to the physical quantizer.
Likewise, AWQ and OmniQuant adapt scaling, clipping, or related quantization parameters, while
CALDERA modifies the weight representation. The additional degree of freedom explored by Au-
toQS is the structural allocation of grouping granularity across modules.
The meaning of “feedback” also differs across methods. In AutoQS, physical feedback refers to
downstream Macro3 measurements from freshly materialized quantized checkpoints that can influ-
ence later search decisions. This occurs at the allocation-search level rather than inside the weight-
reconstruction procedure.

E.1           S IZE OF THE A LLOCATION S PACE

The motivation for automated search is most apparent from the size of the allocation problem. With
five legal group-size choices per quantized module, a model with M quantized modules admits
                                                                                                                      |G|M = 5M
possible module-level assignments before any additional search constraints are considered.
For Qwen2.5-7B, the compiled policy covers 196 modules, giving
                                                                                                                  5196 ≈ 10137.0
possible assignments. For the 224-module LLaMA-7B and Llama2-7B policies, the corresponding
space is
                                       5224 ≈ 10156.6 .

Exhaustively evaluating these spaces is infeasible. Likewise, manually constructing a separate
group-size choice for every module does not scale with model size. AutoQS instead performs pro-
posal generation, legality checking, low-cost evaluation, periodic physical evaluation, and search-
state updates automatically under a fixed protocol.

E.2           M ACHINE T IME VERSUS H UMAN D ESIGN T IME

It is important to distinguish machine time from model-specific policy design effort.

Machine time. One-shot and calibration-based quantizers may require substantially less machine
time than a 100-iteration search. For example, GPTQ reports quantizing a 175B-parameter model in
approximately four GPU-hours under its hardware setting, while OmniQuant reports approximately
1–16 hours for LLaMA-2 models from 7B to 70B on a single A100-40GB GPU using 128 calibration
samples.
These values provide context but are not normalized runtime comparisons with our RTX 3090 ex-
periments because model scale, hardware, calibration workloads, and optimization objectives differ.

Human design time. The principal automation advantage of AutoQS is not a demonstrated uni-
versal reduction in raw GPU time. Instead, it automates repeated model-specific decisions over the
heterogeneous allocation policy.
A manually engineered heterogeneous allocation would require repeated decisions about which
modules should be modified, which group size each selected module should use, and whether the
resulting policy should be revised after quantization and evaluation. In AutoQS, these decisions are
executed by the fixed search procedure after the run is launched.

E.3   L IMITATIONS OF THE S TRATEGY AND T IME C OMPARISON

The preceding analysis has several limitations.
First, the fixed-G128 descriptions of external baselines refer only to the configurations evaluated in
the corresponding result tables. They should not be interpreted as claims that those methods could
never be combined with other grouping configurations.
Second, we do not report a numerical human-hours speedup because no controlled record exists
for the amount of researcher time required to manually design an equally strong heterogeneous
allocation. A retrospective numerical estimate would therefore be speculative.
Third, the current module-level structural analysis covers Qwen2.5-7B, LLaMA-7B, Llama2-7B,
and the matched-seed Qwen ablations. Qwen2.5-7B-Instruct is included in the accuracy experi-
ments, but its exact compiled module-level allocation is not included in the structural comparison
because the corresponding frozen policy artifact has not yet been recovered.
These limitations do not change the central observation that AutoQS turns a very large model-
specific discrete allocation problem into a reproducible automated search procedure, while post-
search Final-7 evaluation remains outside the search loop.
