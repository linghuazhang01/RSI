# 方法设计：自量化与自编辑 LoRA 具体怎么做

日期：2026-11-18
依据：
- `method-research/quant/SIGNALS_QUANT.md`：新读 13 篇全文，复用 16 篇已有笔记；
- `method-research/lora/SIGNALS_LORA.md`：新读 17 篇全文，复用 17 篇已有笔记。

两份调研的逐篇笔记都在 `method-research/*/papers/`。本文抽查过的数字都与原文一致，包括 AWQ Tab.1、EvoPress Tab.3/7、Q-Strata Tab.8、Intruder 论文 p.7、LoRA Learns Less Tab.S6、WSP 博客 Exp 8。

本文回答两个问题：
1. 之前的工作靠哪些信息来修改量化配置和 LoRA；
2. 我们的方法因此应该怎么设计。

标"【决定】"的是本文给出的设计选择；标"【待 pilot】"的是必须先实测才能确定的地方。

## 0. 结论先行

| | Paper A 自量化 | Paper B 自编辑 LoRA |
|---|---|---|
| 文献里最可靠的决策信息 | 整模型 KL（给配置排序最准，Spearman 约 0.98）+ 配对行为探针（唯一能看到工具调用和推理损伤的信号） | checkpoint 轨迹和全局缩放（影响最大的旋钮）+ 与基座子空间的对齐分数（唯一有因果对照的零数据遗忘信号） |
| 不该用来做决策的信息 | 权重幅值或权重重建误差（AWQ 中按权重选通道和随机差不多：22.37 vs 24.23）；逐层误差直接求和（EvoPress 中比均匀分配还差）；只看 PPL | HT-SR α、无标签熵、对角 Fisher、DARE 随机丢弃 |
| LLM 编辑者的价值可能在哪里 | 看到 KL 看不到的行为损伤，从而保护对工具调用和推理关键的模块 | 在全局缩放和 checkpoint 选择的前沿之外，找到逐层、逐方向的改法，同时兼顾目标任务和遗忘 |
| 最大的风险 | LLM 打不过同样使用 KL 的 ILP 或进化搜索 | LoRA 本身遗忘就少，事后编辑能救回的部分可能落在评测噪声里 |
| 我们能补上的空白 | 已有工作的决策者都不是被压缩的模型本身；也没有一篇对"agent 看到哪些诊断"做过干净的消融 | 没有一篇把遗忘或保留集信息反馈给 LLM，也没有和同预算非 LLM 搜索比较过 |

两篇共同的设计原则：
1. **诊断由固定程序预先算好，在所有代之间完全相同。** 编辑者变了，看到的信息不变，所以 E_t 的变化只能来自"决策"本身。
2. **编辑者的每个候选都由固定的外部评测器打分。** 评测器返回结构化数字和少量错误样例，dev2 和 test 永不回传。
3. **允许编辑者提交"保持原样"。** WSP-Scope 的 16 条轨迹中，有 6 条保留了原权重。
4. **必须有同预算的非 LLM 基线，并且基线使用同样的诊断信息。** 已有的 agent 压缩和编辑工作几乎都缺这一项。
5. **诊断信息消融本身就是一个贡献。** 已有工作都没有干净地做过。

## 1. 之前的工作靠什么信息做决定

### 1.1 量化：六类信号

| 信号 | 代表工作 | 证据说明了什么 | 成本 | 我们怎么用 |
|---|---|---|---|---|
| 纯权重统计（幅值、权重重建 MSE） | AWQ Tab.1、OWQ Tab.7、2609.01587 | 用来选通道或分比特基本无效。按权重选通道 22.37 PPL，随机 24.23，按激活 11.39 | 0 | 只用于计算字节数，不用于分配 |
| 激活 / 离群统计 | AWQ、OWQ、SliM-LLM | 层内决策（保留哪些列、AWQ 缩放）上很强，但不能直接告诉你每层该给几比特 | 一次校准前向 | 作为诊断表的一列，并用来标出可能崩溃的模块（"红旗"） |
| 二阶信息（Hessian trace、Fisher） | HAWQ-V2、SqueezeLLM | 成本高，只在 PPL 上验证过，没有下游任务证据；CompressionBench 中 Fisher 加权反而让 KL 变差 | 需要反向传播 | 只作为非 LLM 基线 |
| 逐层输出误差 | SliM-LLM、MixQuant、GAMMA | 比权重误差好，但直接求和做分配会失败（EvoPress Tab.3：NMSE-DP 29.00，均匀 12.19）；上游配置不同时，数值相差 2–3 个数量级 | 每个模块一次层前向 | 不用 |
| **整模型 KL / JSD** | EvoPress、Q-Strata、CompressionBench | 给配置排序最准：Q-Strata 中与测试 PPL 的 Spearman 为 0.98/0.99；EvoPress 中作为目标优于 PPL（7.49 vs 8.17）；约 64K token 就能稳定排序 | 每个配置一次整模型前向 | **主信号** |
| **配对行为探针** | 2608.06564、Flat Score、2504.04823 | 只有它能看到 KL 看不到的损伤：PPL 只涨到 1.01× 时，工具调用率从 .910 掉到 .450；3-bit 下"要不要调用"先崩 | 每个配置一次配对前向，外加少量生成 | **必须有** |

**可加性**（决定 `profile` 工具够不够用）：
- 平均比特 ≥ 3.5、只用 {3, 4, 8} 时，孤立测得的整模型 ΔKL 求和后，与组合搜索的差距约 ≤ 2–7%（Q-Strata、HIGGS、2609.01587）。
- 平均比特 ≤ 3 或用到 2-bit 时，求和会系统性低估损伤：Q-Strata 中稠密模型 2.5 bit 时差 26%。这时必须在当前配置的上下文里重新测，并对完整配置做评估。
- q 和 k 之间有强交互（OWQ Tab.13：保护 {Wk,Wq} 得 11.26，保护 {Wq,Wv} 得 111.57），要作为一组来测。
- 行为损伤是否可加，没有任何证据，所以行为探针必须在完整配置上测。

**agent 压缩工作里 agent 看到了什么**（CompressionBench、AutoQS、Self-Pruner、Adaptive Pruning、APQF、HAQA、TAP）：
- 都给结构化数字，例如 JSON、按 z-score 排序的层表、"配置差异 → 指标"的历史表；动作都约束在合法空间内，并带回滚机制。
- 最接近"信息消融"的三项都指向同一个方向：整模型的真实反馈比局部代理信号更有用。
  - AutoQS：去掉反馈 72.58，完整 73.85（单种子）；
  - TAP：去掉真实精度、只看排序相关时，大幅变差；
  - CompressionBench：整模型奖励推翻了 79 次本地排序中的 17 次。
- 失败模式：
  - 只看 PPL 时，能力在下降（CompressionBench 中 GSM8K 从 88 掉到 72）；
  - 用小规模选择题做反馈会过拟合（AutoQS 的搜索指标和最终指标相关系数只有 0.135）；
  - 产生非法配置。
- 没有一项工作和同预算的非 LLM 搜索做过比较；所有工作的决策者都不是被压缩的模型本身。

### 1.2 LoRA 编辑：四类信号

| 信号 | 代表工作 | 证据说明了什么 | 成本 | 我们怎么用 |
|---|---|---|---|---|
| **checkpoint 轨迹** | LoRA Learns Less、MagMax、Deafening Silence | 最强也最便宜的单一杠杆：HumanEval 在第 4 epoch 达到峰值 0.498，第 8 epoch 降到 0.437，同时保留分从 0.659 一路降到 0.552。较早的 checkpoint 常常在目标和遗忘两边都更好 | 训练时顺便保存 | 诊断表一列 + 算子 |
| **全局缩放 / 插值系数** | TIES 消融、Fisher merging、Sakana、MaLoRA | 几乎所有方法里影响最大的旋钮。TIES 去掉 Scale 降得最多；Sakana 发现逐层配置没有明显提升 | 每个候选评测一次 | 作为必须超越的基线前沿 |
| **与基座子空间的对齐（intruder / Grassmann）** | Intruder 论文、SLoRA | 唯一有因果对照的零数据遗忘信号：intruder 数与遗忘的 Spearman 为 0.971 / 0.59，与目标精度无关；缩小 intruder 方向可以减少遗忘，缩小对齐方向反而增加遗忘。代价是低秩时目标损失大：r=16、λ=0.3 时目标降 15% | 基座 SVD 只算一次并缓存 | 诊断表一列 + 新增算子 `intruder_scale` |
| 奇异谱 / 截断 | PARA、TSV、DG-Hard | 截尾部安全，截头部会崩；单任务约 +1 点 | 一次小 SVD | 诊断表 + `truncate_rank` |
| 相对变化 \|ΔW\|/\|W0\| | FAPM | LoRA 上剪掉 3%：通用能力 +2.5 到 +5 点，目标降 ≤ 0.8；但另一篇论文重跑时结果差异很大 | 几乎为零 | 诊断表 + `relchange_prune` 算子 |
| 激活作用比 ‖ΔW h‖/‖W0 h‖ | TaDA | 32 条探针就够；探针门控是 TaDA 中贡献最大的组件（约 +1.2pp）；但没有人验证过它和保留集下降的关系 | 每个数据集一次前向 | 诊断表一列，并在 pilot 中验证 |
| 与旧 adapter 的重叠 / 符号冲突 | O-LoRA、TIES、TSV | 能说明多任务之间的干扰，对基座能力的遗忘只有间接证据 | 很低 | 诊断表一列 |
| Gram 矩阵 | RegMean | 在合并中效果强，一次前向即可；遗忘场景下没测过 | 一次前向 | 作为算子 `regmean_preserve`，不作诊断 |
| 有标签 dev 搜索 | LoraHub、EvoGM、Audit、WSP-Scope | 直接有效，但小 dev 上严重过拟合：WSP-Scope 9B 在 dev 上 +29.69，留出集上 −0.35 | 每个候选评测一次 | 评测器反馈，必须配 dev2 验收 |
| HT-SR α、熵、Fisher、DARE | AlphaLoRA、AdaMerging、Fisher merging、DARE | 证据弱、对生成任务有误导，或期望增益为零 | — | 不用 |

**LLM 驱动编辑工作里 LLM 看到了什么**（WSP 博客、WSP-Scope、Self-Developing、Robots、MetaRSI）：
- **只有两项真正的信息消融**，都说明"看得到行为"比"只看权重"重要：
  - 前向调用预算：10 / 25 / 50 次时，MATH-500 分别为 12.3 / 14.1 / 48.1；
  - 诊断丰富度：只看权重时 4 次全失败，加上注意力模式后 3 次全成功。
- **有效的交互形式**：会话内多轮"候选 → 分数加样例 → 保留或回退"，并允许拒绝。Self-Developing 不给上下文内反馈，只靠 DPO，3,000 个候选中只有 100–300 个能执行。
- **失败模式**：
  - 小 dev 上的选择偏差；
  - 路径依赖：同一设置三次独立搜索的结果是 +29.45 / +5.00 / +27.30；
  - 收益其实来自修格式或修循环；
  - 收益可以被简单对照解释，例如网格外的一个缩放系数。
- 没有一项工作把遗忘或保留集信息反馈给 LLM，也没有和同预算的非 LLM 搜索比较过。

**上升空间**：
- 训练正常的 8B LoRA，事后编辑带来的单任务增益预期只有 0–2 点。
- LoRA 本身遗忘就少：r=16 时 0.121 nats，全参微调是 0.6285。
- 事后编辑能救回 30–80% 的遗忘，但 IFEval 541 条 prompt 的标准误约 2 个点，救回的部分可能落在噪声里。

## 2. Paper A 的方法：Self-Quantization Agent

### 2.1 决策对象
配置 = {每个 (层, 模块组) 的比特数和量化器、group size、embedding 和输出头的精度、校准数据来源}。

**模块组**按调研结论划分：
- {q, k} 作为一组，因为两者有强交互；
- v、o、{gate, up}、down 各为一组。

所以每层 5 组。比特数 ∈ {3, 4, 8}，8 GiB 时加入 2。

### 2.2 预先算好的诊断（固定程序生成，所有代相同）【决定】

| 诊断表 | 内容 | 依据 | 成本（假设，待实测） |
|---|---|---|---|
| `profile_table` | 每个 (层, 模块组, 比特数)：在 BF16 上下文中，用 RTN 伪量化测得的整模型 ΔKL 均值、p99 和 top-1 一致率变化；另加 Δ字节数 | EvoPress、Q-Strata；SliM-LLM 搜索时用 RTN、最终用 GPTQ | 层数 × 5 组 × 3 档，每次约 64K token 的前向；27B 估计 5–10 GPU 小时 |
| `activation_table` | 每个模块的激活二阶矩、离群通道比例、最大值与中位数之比，并标出红旗模块 | AWQ、OWQ、HIGGS（70B 中 v_proj 灾难性） | 一次校准前向 |
| `behavior_sensitivity` | 每个 (层, 模块组) 单独降到 3-bit 时，工具调用决策 margin 的变化，用首 token 的 logit 差来测，"该调用"和"不该调用"分开 | 2608.06564：PPL 1.01× 时调用率腰斩；2504.04823：最后一层 up_proj 对推理关键 | 每组一次配对前向，探针 100 条 |
| `bytes(config)` | 精确的字节计算，包括 group 的 scale、zero 等元数据和 embedding / 输出头 | 2609.01587：group 粒度是最大的全局杠杆 | 0 |

第三张表是我们相对 CompressionBench 等工作的关键差别：编辑者能同时看到"KL 损伤"和"行为损伤"两个维度。文献显示两者并不一致，这正是 LLM 编辑者可能胜过 KL-ILP 的地方。

### 2.3 按需调用、计入预算的工具

| 工具 | 返回 | 什么时候必须用 |
|---|---|---|
| `profile_in_context(group, bits, quantizer, base_config)` | 在当前配置的上下文中重新测 ΔKL | 平均比特 ≤ 3 或使用 2-bit 时（可加性失效） |
| `evaluate(config)` | 真实 GPTQ/AWQ 量化后的整模型 KL、字节数，以及行为探针（2026-11-18 起只用训练集的信号切片，见 `DATA_CONFIG.md`）：Seal-Tools train 200 题（加构造的"不该调用"样例，调用翻转率）、MATH train + DAPO 各 100 题的准确率和输出长度、APPS 100 题、TriviaQA + ARC 各 100 题、IFEval 135 条；每项附置信区间和 2–3 条错误样例 | 每个候选都要用；这就是 L1 反馈 |
| `solve_allocation(weights, budget)` | 给定编辑者自己设定的目标权重，用多选背包求解比特分配 | 可选工具，见 2.5 |
| `submit(config)` | L2 的通过 / 不通过 | 每轮最多 3 次 |

### 2.4 编辑者的输出形式【决定】
编辑者写一段 Python 程序，读入上述诊断表和历史，返回一个配置。程序在沙箱里执行，并由校验器检查预算和合法性；不合法的程序允许修复一次。

选择程序而不是直接写 JSON 的理由：
- 和 Paper B 的"写代码编辑 adapter"同构；
- TAP 显示程序化的分配策略更稳定，Self-Developing 也是这种形式；
- 程序本身可以解释，便于分析模型保护了哪些模块。

### 2.5 是否允许调用求解器【决定】
- **主条件允许调用 `solve_allocation`。** 真实的工具使用就是让模型决定目标，例如"KL 加上 3 倍的工具调用 margin 损伤，并强制保护最后两层 MLP"，再交给求解器算。这样 LLM 的贡献就落在"该优化什么"，而不是算术上。
- **消融条件不提供求解器**，检验 LLM 自己能不能分配。
- **对应的非 LLM 基线是 KL-ILP**：用同样的 `profile_table` 和同样的求解器，只优化 KL。LLM 编辑者比 KL-ILP 多出的部分，就是"行为感知"和"推理"带来的价值。

### 2.6 反馈与历史
- 历史以表格形式给出：配置差异 → ΔKL / 探针结果 / 字节数 / L2 结果；同时保留当前最好的配置，可以随时回滚。
- 每轮最多 24 次 `evaluate`。
- 记录编辑者实际发出的工具调用数。调研提醒，量化后的模型可能先在"要不要调用工具"上退化，表现为不再行动或伪造调用（2608.06564 发现崩塌偏向"不调用"）。

### 2.7 非 LLM 基线（相同的诊断表、相同的 evaluate 预算）
1. 均匀 GPTQ / AWQ g128；
2. KL-ILP：用 `profile_table` 求解；
3. KL+行为 ILP：在 KL 上加固定权重的 `behavior_sensitivity`，权重在 dev 上网格选择。用来检验 LLM 是否只是学会了一个固定的加权；
4. EvoPress 式进化搜索，以整模型 KL 为目标，24 次评估；
5. GAMMA；HAWQ-V2 加 ILP（可选）。

### 2.8 诊断信息消融（新增的贡献）
相同评估预算下，比较四种条件：
1. 只给 `evaluate` 的反馈；
2. 加 `profile_table`；
3. 再加 `activation_table` 和 `behavior_sensitivity`；
4. 再允许 `profile_in_context`。

### 2.9 Pilot 必须回答的问题（并入 A-P0）
1. **可加性**：在 27B 上随机采 20–30 个组合配置，平均比特覆盖 3.0 / 3.5 / 4.0，比较孤立 ΔKL 求和与实际 KL 的 Spearman 和绝对误差。
2. **KL 能否预测行为**：同一批配置上，ΔKL 与 BFCL 翻转率、MATH 准确率的相关性；有没有"KL 份额小、行为伤害大"的模块。如果没有，`behavior_sensitivity` 表的价值就要重估。
3. **RTN 粗筛与 GPTQ 的排序是否一致**：决定 profile 的成本能否降一个数量级。
4. **探针噪声**：BF16 重复运行时翻转率的波动，决定探针要多少题。
5. **校准源**：GPTQ 在 3-bit 下，通用文本、自生成文本、推理加工具对话混合三种校准源对探针的影响。

## 3. Paper B 的方法：Self-Surgery（模型给自己的 adapter 做手术）

> **2026-11-18 变更**：Paper B 改为直接写 LoRA，见 `RSI_LOOP_DESIGN.md` §3。本节的诊断表和强基线继续有效；§3.3 的算子库变成程序可用的"栈操作"原语；"编辑 A_raw"的写法作废。

### 3.1 编辑对象
- 当前 adapter 栈 {A_1 … A_t}；
- 新训练的 A_raw 及其 25 / 50 / 75 / 100% 四个 checkpoint。

编辑者 R_t = M_t ⊕ A_raw。

### 3.2 预先算好的诊断（固定程序生成）【决定】

每个 (层, 模块) 一行，再附全模型汇总和按层汇总。Qwen3-8B 的层数要在实现时核实。

| 列 | 内容 | 依据 |
|---|---|---|
| 基础量 | ‖BA‖_F、‖BA‖_F/‖W0‖_F、紧凑奇异值 σ_1..σ_r、能量累计、有效秩、在全模型中的奇异值分位 | PARA |
| **基座对齐** | BA 的每个奇异方向与 W0 top-K 奇异子空间的最大余弦（intruder 分数），以及 SLoRA 的对齐曲线 | Intruder 论文、SLoRA：唯一有因果对照的遗忘信号 |
| 与历史 adapter 的关系 | 归一化主角度、符号冲突率、ΔW 余弦 | TSV、TIES；不用 O-LoRA 的未归一化度量 |
| 相对变化 | 每个模块中 \|ΔW\|/\|W0\| 落在高分位的比例 | FAPM |
| 激活作用比 | 在目标 dev 输入和保留集输入上分别算 ‖ΔW h‖/‖W0 h‖，以及两者之比；每个数据集 64 条输入 | TaDA；需要 pilot 验证 |
| 结构先验 | 层深度、模块类型，并附上文献给出的方向（浅层可以缩小、MLP 承载遗忘），注明"未在 Qwen 上验证" | LiNeS、DG-Hard |
| **checkpoint 轨迹** | 每个 checkpoint 的目标 dev 分数、保留集 token-KL、与最终 LoRA 的余弦 | LoRA Learns Less |

### 3.3 算子库（Level 1）【决定，在原算子库基础上调整】

| 算子 | 变化 | 理由 |
|---|---|---|
| `scale(target, s)`，target 可以是全局、某层或某模块 | 保留 | 影响最大的旋钮 |
| `interpolate(A, B, λ)`，包括 checkpoint 之间、与历史 adapter 之间 | 保留，**明确支持 checkpoint 插值** | 最强的便宜杠杆 |
| `truncate_rank(layer, k)`、`svd_reweight` | 保留 | PARA |
| **`intruder_scale(layer, λ, ε)`** | **新增** | 唯一有因果证据的遗忘算子 |
| **`relchange_prune(density)`** | **新增**，替换原来的 `magnitude_prune` | FAPM 中只按幅值剪 90% 会崩，按相对变化剪不会 |
| **`regmean_preserve(layer, α)`** | **新增**：把"基座在保留集上的输出"作为一个合并成员，用 Gram 矩阵闭式求解 | RegMean |
| `orthogonalize(A_new, A_old)` | 保留 | O-LoRA、TSV |
| `ties`、`task_arithmetic` | 保留 | 多 adapter 合并 |
| `drop(layer/module)` | 保留 | PARA、Audit |
| `dare` | 只作为 TIES 的预处理 | 期望增益为零 |
| `project_out` | **删除**，或者要求评测器单独报告它的保留集结果 | Deafening Silence：会切断补偿，把遗忘放大 1.6–2.4 倍 |

### 3.4 评测器反馈：每个候选返回什么【决定】
- 目标 dev 的变化量，以及各保留集的变化量（IFEval 按 prompt-level strict、IFBench、MMLU-Pro、TriviaQA 闭卷），都附 bootstrap 置信区间；
- 总分 = 目标增益 − λ × 保留集下降；
- **保留集 token-KL**：在固定的保留集 prompt 上，算 base 和候选之间的 teacher-forcing token KL。它比准确率稳定得多，可以先用来筛选；
- 行为统计：输出长度、截断比例、格式失败率；
- 2–3 个"编辑前对、编辑后错"的保留集样例 diff；
- 历史表：所有候选的程序摘要、算子参数和得分，外加剩余预算；
- dev2 和 test 永不回传；允许提交"保持原样"。

### 3.5 按需调用、计入预算的工具
- 逐组消融：把相邻 4 层的 {attention, MLP} 作为一组置零，看分数变化。每次消耗一次评估预算。
- 如果 pilot 发现激活作用比能预测逐组消融（Spearman > 0.6），就可以用它代替大部分消融调用。

### 3.6 必须打败的强基线（相同评估预算）
1. 不编辑；
2. **全局缩放 s 的帕累托前沿**；
3. **checkpoint 选择或插值的前沿**；
4. LiNeS 深度线性缩放（2 个参数的网格）；
5. intruder 缩放的 λ 网格；
6. PARA 截断的 k 网格；
7. SLoRA；
8. TIES 网格；
9. 同预算的随机搜索和 CMA-ES；
10. 规则组合基线：SLoRA 截断 + 全局缩放 + checkpoint 选择，参数在 dev 上网格选择。用来检验 LLM 是否只是重新发现了这个组合。

**主表必须报告 LLM 编辑者在全局缩放和 checkpoint 两条前沿之上多出的部分**，因为文献中最有影响的变量一直是全局系数。

### 3.7 诊断信息消融（新增的贡献）
相同评估预算下，比较四种条件：
1. 只给评测分数；
2. 加权重类诊断（基础量、基座对齐、历史关系、相对变化、结构先验）；
3. 再加激活作用比和 checkpoint 轨迹；
4. 再允许按需消融。

### 3.8 遗忘太小的风险与应对【待 pilot】
B-P0 先在 Qwen3-8B 上测：数学和代码的 raw LoRA，在几组 r / lr / 步数下，IFEval、IFBench 和知识类保留集各掉多少，置信区间多宽。

| 结果 | 应对 |
|---|---|
| 掉分 ≥ 2×SE | 按原计划，主指标用保留集准确率 |
| 掉分 < 2×SE | 以下三条一起做：(a) 采用仍然常见、但遗忘更明显的设置（较高学习率、较多 epoch、r=64 配小 α），并如实写出这样选的理由；(b) 主保留指标改用 token-KL，准确率作次要指标；(c) 连续三代之后遗忘会累积，以第 3 代的保留集作为主要比较点 |

### 3.9 Pilot 必须回答的问题（并入 B-P0）
1. 遗忘量是否足够大（见 3.8）。
2. intruder 分数在 Qwen 上能否预测保留集下降，即在不同 checkpoint、rank、学习率之间复现相关性。复现不出来，就把它降为次要诊断。
3. 激活作用比能否预测逐组消融的结果。
4. 在全局缩放和 checkpoint 两条前沿之外，还有多少空间：先画出这两条前沿，再看 LiNeS、intruder、截断能否超出。如果都不能，LLM 的上升空间接近零，任务设定需要重新考虑。
5. 装上数学或代码 raw LoRA 之后，模型写编辑程序和调用工具的能力会不会下降。如果会，这本身就是 RQ2 的一部分，要单独记录。
