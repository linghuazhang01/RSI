## 改进对象
- 被改进的是 **prompt（instruction 文本）**。optimizer LLM（PaLM 2-L-IT、PaLM 2-L、text-bison、gpt-3.5-turbo、gpt-4）读"历史 instruction + 训练分 + 3 条训练样例"的 meta-prompt，生成新 instruction；scorer LLM（PaLM 2-L、text-bison）**权重不变**（p8）。有一个设置是 PaLM 2-L 同时当 optimizer 与 scorer，即"改进自己用的 prompt"（Fig.4b p11）。
- 每步生成 8 条 instruction，meta-prompt 中保留最高分的 20 条，默认 200 步（p8, p10）。

## Signal 数据
- **数学**：**GSM8K train 的随机 3.5% 子集**，整个优化过程固定同一子集（p9）。GSM8K train 共 7,473 条、test 1,319 条（p8）。3.5% 约 262 条【按比例推算，论文未写条数】。meta-prompt 里的 3 条示例也来自训练集（p8）。
- **通用推理（BBH，23 个任务）**：每个任务取 **20% 样本做优化，其余 80% 做测试**（p11；Table 7 标题"20-80 train-test split"，p32）。BBH 每个任务最多 250 条（p8），因此每任务 signal 约 50 条【推算】。
- **代码**：无。
- 不是自生成任务；是 benchmark 自己的训练集（GSM8K）或从 benchmark 里切出来的不重叠子集（BBH）。

## Selection / acceptance 数据
- **默认不设验证集**（§5.4 p18）：训练准确率既是搜索信号又是最终选择依据。作者的理由：候选之间过拟合程度相近，所以训练分高者测试分也高。
- 支撑实验（Fig.11 p19）：在 BBH snarks、sports_understanding 上把样本切成 1/3 训练、1/3 验证、1/3 测试，验证曲线与训练曲线同升同降。
- ⚠ **Table 4（p9）与 Table 1（p1）标题都写"展示测试准确率最高的 instruction"**——即表中报告的"Top instruction"是按测试分在候选里挑的。正文 §5.2.1 只说优化结束后在完整 test 上评测找到的 instruction（p9）。【推断】表中头条数字（如 80.2）含有按测试分择优的成分，属于 selection-on-test。

## 最终评测数据
- 数学：**GSM8K 完整 test（1,319）**；迁移到 **MultiArith、AQuA**（Table 6 p15，用 GSM8K 上找到的 instruction，不再优化）。
- BBH：每任务剩余 80%。

## Signal 与 eval 是否重叠
- GSM8K：同 benchmark，train split → test split（**不同题，同分布**）。
- BBH：同一任务的**不同题**（随机 20/80 切分），同分布。
- MultiArith/AQuA：**不同 benchmark**（同领域迁移）。
- 题目层面不重叠，但 instruction 只针对单一 benchmark 的分布优化。

## 过拟合 / 泛化差距证据
- **作者明确承认**（§5.4 p19）：训练准确率常比测试准确率**高 5%–20%**（Table 7、Table 10）；建议用更大训练集、更少步数（早停）缓解。
- Table 7（p32，PaLM 2-L scorer，train/test/overall）中的典型差距：
  - causal_judgement：84.8 / 58.0（差 26.8）
  - navigate：92.0 / 75.0
  - geometric_shapes：76.0 / 57.0
  - logical_deduction_seven_objects：74.0 / 57.0
  - **tracking_shuffled_objects_seven_objects：OPRO 32.0 / 16.5，而人工基线 "Let's think step by step." 为 58.0 / 61.5**——搜索得到的 instruction 在测试上远差于不搜索的基线。
- GSM8K 上训练与测试接近：一步生成基线 64.4 train / 60.8 test；OPRO 第 5 步 "Let's do the math!" 78.2 train / 76.3 test（p18）。BBH sports_understanding：88.0 / 84.5（p18）。即：signal 集是 benchmark 自己 train split（数百条）时差距小；signal 只有每任务约 50 条时差距大。
- 跨 benchmark 迁移（Table 6 p15）：PaLM 2-L 上 GSM8K 找到的 instruction 在 MultiArith 95.3、AQuA 54.3，均高于基线；text-bison 上 AQuA 37.8，高于 step-by-step 的 31.9。迁移有正收益但幅度依模型而异。
- 敏感性（§5.2.3 p13）：语义相近的 instruction 在 GSM8K test 上可差 20 多点（71.8 vs 60.5 vs 49.4），说明小 signal 集上的分数噪声很大，选择容易被噪声主导。
- 作者结论部分（p21）：需要训练集至少几十条，才能不严重过拟合。

## 对我们两篇论文的启示
- OPRO 是"用 benchmark 训练 split / 同 benchmark 不重叠子集做 signal、同 benchmark test 做评测"的典型；即便题目不重叠，**小 signal 集（约 50 条/任务）也出现 5–27 点的 train→test 差距，并有在 test 上低于基线的案例**。这是对"benchmark search pool 太小"的直接警示。
- 有独立验证集时验证与训练同升同降（Fig.11），说明候选间排序可迁移；但**绝对增益会被高估**——我们的 gate 应使用独立集合，并报告 signal 分与 test 分两者。
- 要避免像 Table 4 那样按测试分挑报告对象：最终候选须由 gate（非 test）决定。
