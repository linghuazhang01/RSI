## 改进对象
- 与 DGM、SICA 相同：**coding agent 的代码仓库**，底座 LLM 冻结。新意在搜索策略：用整个子树（clade）的成功率估计"元生产力" CMP，再用 Thompson sampling 选择扩展节点，并把扩展和评测解耦（p6–7）。

## Signal 数据
- **代码 / SWE-bench**：
  - Sec 4.1–4.2：**SWE-Verified-60**，即 DGM 前两阶段的 60 题（p7）；
  - Sec 4.3：**全量 SWE-bench Verified，500 题**，共 8000 次评测（p9）。
- **代码 / Polyglot**：沿用 DGM 的设定（agent 看不到私有测试），用于 Sec 4.1–4.2（p7）。正文没写题量，只写"Polyglot"。
- 评测粒度是一个 agent 一道题，题目都来自评测 benchmark 本身，不是训练集，也不是自生成。
- 数学 / 通用推理：无。

## Selection / acceptance 数据
- 扩展用 clade 的成功 / 失败计数（CMP 估计），评测用节点自身计数，都采用 Thompson sampling（p6）。
- 最终 agent = 后验 ϵ 分位数最大的"best-belief agent"（p7；实验中 ϵ=1）。
- **与 signal 用同一批题**，没有独立验证集。

## 最终评测数据
- Table 2（p9）：SWE-Verified-60 上 SICA 50.0、DGM 53.3、HGM 56.7（初始 40%）；Polyglot 上 25.4 / 27.1 / 30.5（初始 20.3%）。这些都是**在搜索用的同一批题上**报告的。
- Sec 4.3.1（p9）：全量 SWE-Verified 上从 53.2% 提升到 61.4%，也是**同题**（500 题既用于搜索也用于报告）。作者在这里主动承认，排行榜高分不一定代表通用能力，人设计和机器设计的 agent 都可能对 benchmark 过拟合（p9）。
- Sec 4.3.2（p9–10，Table 3）：**SWE-bench Lite**，300 题，其中 93 题与 SWE-Verified 重叠：
  - Filtered（去掉 93 道重叠题，只留完全没见过的题）：初始 34.8% → HGM 40.1%；SWE-agent + GPT-5-mini 39.6%；
  - Standard（300 题）：44.0% → 49.0%；SWE-agent + GPT-5-mini 47.6%。
- Table 4（p10）：换成 GPT-5 后，Filtered 47.8%（SWE-agent 最好成绩 48.3%），Standard 57%（56.7%）。

## 过拟合 / 泛化差距证据
1. **元生产力与 benchmark 分数不匹配（MPM，Table 1 p8）**：以"当前节点 benchmark 分数"作为后代潜力的预测，与经验 CMP 的 Pearson 相关只有 0.285–0.444；HGM 的 clade 估计为 0.512–0.873。也就是说，单个 agent 在搜索子集上的分数不能很好地预测它能否带来更好的后代。作者在计算相关时还专门排除了目标泄漏（p8，App D）。
2. **同题提升 vs 未见题提升**：搜索集（全量 SWE-Verified）+8.2（53.2→61.4）；完全未见的 SWE-Lite Filtered +5.3（34.8→40.1）（p9–10）。收益仍在，但缩水约三分之一（我的计算）。
3. **重叠题会抬高"迁移"数字**：Standard（含 93 道重叠题）提升 +5.0，Filtered +5.3，两者接近。不过 HGM 相对 SWE-agent 的优势在 Filtered 上只有 +0.5（40.1 vs 39.6），Standard 上为 +1.4（49.0 vs 47.6）；换成 GPT-5 后，Filtered 上反而低于 SWE-agent（47.8 vs 48.3），Standard 上高 0.3（57 vs 56.7）。"超越人类设计"的结论对是否去掉重叠题很敏感。
4. 作者主动做了 Filtered 设定，并在 p9 明说排行榜高分可能是对 benchmark 的过拟合。这是本组论文中对 overlap 处理最规范的一篇。
5. SICA 基线在 SWE-Verified-60 上 360 次评测后反复超出上下文窗口，没有跑完（p9）。

## 对我们两篇论文的启示
- HGM 的 Filtered 做法可以直接借鉴：最终测试必须**显式去掉**与搜索池重叠的题目，并同时报告 Standard 和 Filtered。
- MPM 结果说明：在小搜索子集上的单点分数是很嘈杂的选择信号。若我们用 benchmark 小池子做 acceptance gate，应采用聚合统计（如后验分位数或多次评测），而不是单次最大值。
- 同题提升与未见题提升的比值（这里约 0.65）可作为我们预期 search→test 缩水幅度的参照。
