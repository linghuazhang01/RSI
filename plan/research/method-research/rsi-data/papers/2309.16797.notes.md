# 2309.16797 Promptbreeder — 阅读笔记（RSI 数据用法）

## 元信息
- 标题：Promptbreeder: Self-Referential Self-Improvement Via Prompt Evolution
- 作者：Chrisantha Fernando, Dylan Banarse, Henryk Michalewski, Simon Osindero, Tim Rocktäschel（Google DeepMind）
- 版本：arXiv 2309.16797（预印本）
- 文件：`src_2309.16797/2309.16797.pages.md`（64 页）
- 读的范围：正文 p1–9 读完；附录 A（术语）、B（典型进化曲线）、I（数据集，p24–25）、J.1–J.4（ETHOS prompt、数学实验设置 p27–28、变异算子统计）、K（Instruction Induction，Table 9 p36）、L（消融，Fig.4 p63）读过；J.5 之后与 K.1 的大量"最佳 prompt + 上下文"清单（约 p28–62）**略读**。

## 改进对象
- 被改进的是 **prompt**：task-prompt（通常两条顺序使用）+ mutation-prompt（改 task-prompt 的指令）+ few-shot 场景下的"正确解题过程"上下文。mutation-prompt 本身也被进化（self-referential），由同一个 LLM（PaLM 2-L）执行变异。LLM **权重不变**（p2, p5）。
- 二元锦标赛遗传算法，种群 50，通常 20–30 代（p8）；每个实验 1–2k 次 fitness 评估（App.J.2 p27）。

## Signal 数据
- **数学**：GSM8K、SVAMP、MultiArith、AddSub、AQuA-RAT、SingleEq（p8）。fitness = 每次从**训练集**随机抽 100 条问答的准确率（p5；App.J.2 p27）。没有官方 train/test 切分的 MultiArith、AddSub、SingleEq、SVAMP **随机对半切成训练/测试**（Table 1 注 p2；App.J.2 p27）。GSM8K、AQuA 用自带训练集（AQuA 消融图中出现 "AQUA_DEV" 字样，具体是 train 还是 dev 文中未说清）。
- **通用推理/常识**：CommonsenseQA、StrategyQA（p8）；具体用哪个 split 当训练集，文中未写明。
- **其他**：ETHOS 仇恨言论分类；APE 的 24 个 Instruction Induction 任务（App.K）。
- **代码**：无。
- Lamarckian 算子会把**模型自己生成的正确解题过程**反推成新 task-prompt，few-shot 上下文也来自模型自己的正确输出（§3.2.4–3.2.5 p8），即 signal 中有一部分是模型自生成内容，但正确性仍由训练集标签判定。

## Selection / acceptance 数据
- 无独立 dev/gate 集：训练 fitness 平台期后，取**整个进化过程中训练 fitness 最高的个体**，在测试集上评测一次（App.J.2 p27）。
- 消融（App.L, Fig.4 p63）比较的是**训练 fitness**（种群 10、200 次评估），不是测试分。

## 最终评测数据
- 上述各数据集的测试部分（对半切分数据集用另一半）；结果见 Table 1（p2）。例：zero-shot PB 在 GSM8K 83.9、MultiArith 99.7、SQA 71.8、CSQA 85.4、AQuA 62.2。ETHOS 89%（人工 prompt 80%，p9）。Instruction Induction 24 个任务中 21 个持平或超过 APE（Table 9 p36）。

## Signal 与 eval 是否重叠
- 全部是**同 benchmark、不同题**：GSM8K/AQuA 用 train→test；四个小数学集用同一数据集随机对半切。每个 benchmark 单独进化一套 prompt，没有跨 benchmark 迁移实验。
- 对半切分的数据集（MultiArith 等）本身很小，训练/测试同分布程度极高。

## 过拟合 / 泛化差距证据
- **没有报告训练 fitness 与测试准确率的对照**，也没有多次运行的方差（Table 1 为单值）——无法从文中直接读出 dev→test 差距。
- 明显的过拟合迹象（我的观察，非作者结论）：最优 prompt 中有与任务语义无关的内容，例如 ADDSUB 的第二条 prompt 是一句与数学无关的玩笑话、GSM8K 的第一条 prompt 只剩一个格式化片段；CSQA（常识问答）的最佳 prompt 却写着"解多选数学应用题"；SVAMP 第一条 prompt 只是三个不成句的词（App.J Table 6，p26）。这说明在 100 条小批量 fitness 上搜索，会选出利用 scorer 格式偏好的 prompt，而不是"更好的推理策略"。
- Table 1 中 OPRO 的 80.2 是 OPRO 按测试分挑出的 instruction（见 2309.03409 笔记），PB 拿来作基线比较。
- Instruction Induction（Table 9 p36）：Common Concept 0、Formality 7，低于 APE 的 27/65——部分任务上 PB 搜索结果明显劣于基线，作者未分析原因。

## 对我们两篇论文的启示
- Promptbreeder 代表"fitness 直接取 benchmark 训练集随机小批量、选最优后在同 benchmark test 报告"的做法；没有 gate、没有 signal/test 对照，是我们应避免的报告方式。
- 若 signal 小而噪（100 条），最好的候选可能是"格式技巧"而非能力提升；自编辑 LoRA 时也可能出现只学会输出格式的编辑。需要 gate 集独立、且尽量跨格式。
- 每个 benchmark 单独搜索也意味着结果不能说明通用能力提升；我们应至少做一项跨 benchmark 迁移。
