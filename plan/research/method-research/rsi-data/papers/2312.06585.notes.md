## 改进对象
**模型权重**。E-step：用当前模型对训练题采样，用二值奖励（MATH 对答案、APPS 跑测试用例）过滤；M-step：在过滤后的自生成解上做 SFT。每轮都**从基座预训练模型重新微调**，而不是接着上一轮（p5，作者说这样迁移更好，Fig 7 p11）。模型是 PaLM 2-S / S* / L。属于"有外部 verifier 的自训练"，不改代码或 prompt。

## selection / acceptance 数据
- Algorithm 1（p5）写了 M-step "reward 在 D_val 上提升就继续训练"，即用一个验证集决定每轮训练多久。**正文没有说明 D_val 来自哪个 split、多大**。这是一个未披露细节。
- 迭代次数是作者看 test 曲线讨论的（MATH 3 轮、APPS 2 轮），没有独立的选择集。

## 最终评测数据
- 同分布 test：MATH test、APPS (Introductory) test（p7）。
- 迁移（held-out）：GSM8K、HumanEval、2023 匈牙利高中数学期末考试（人工按评分细则打分，p13）、BBH（通用能力，p12–13）。

## signal 与 eval 是否重叠
- MATH/APPS：**同一 benchmark，不同 split（train→test）**，题目不重叠、分布相同。
- GSM8K、HumanEval、匈牙利考试：**不同 benchmark**，作者明确称为 held-out 迁移评测。匈牙利考试在 2023 年才出，作为"真实世界"新题检验（p13，Fig 10）。
- BBH：不同 benchmark、不同任务类型。

## 过拟合 / 泛化差距证据
- **训练集-测试集差距随迭代扩大（Fig 4，p9）**：训练集准确率随迭代近似线性上升，test 不跟随；MATH 第 1 轮后 test 提升很小，APPS 第 2 轮 test 反而回退。作者推测是在少量训练题上过拟合，APPS 只有 MATH 约三分之一大，所以更严重（p9）。
- **迁移也跟着回退（Fig 3，p8）**：APPS 多做迭代后，APPS test 和 HumanEval 都回退。
- **单轮 3 倍数据 vs 多轮**：单轮用 3 倍样本得 40.3%，低于第 2 轮 41%、第 3 轮 41.9%（p10）。
- **每轮从基座重训 vs 接着训（ReST）**：APPS 上两者差不多，但 HumanEval 迁移 ReST-EM 明显更好（Fig 7 p11）。说明"漂离基座"主要伤迁移，不伤同分布 test。
- **数据量消融**：4000 题比 2000 题略差，作者承认可能是微调方差，但没有多次重复（p11）。
- 匈牙利考试：作者指出一些数学专用模型 GSM8K 高、匈牙利考试差（Fig 10 p13），即只看熟悉 benchmark 会高估。
- 局限：方法需要中等规模的人类问题集和自动 reward（p13–14）。

## 对我们两篇论文的启示
- 这是"training split 做 signal、test split + 其他 benchmark 做评测"的经典模板：MATH train→MATH test + GSM8K/匈牙利考试；APPS train→APPS test + HumanEval。
- 关键证据：即使 signal 来自训练 split，**迭代多了 train 指标涨、test 停滞或回退**（Fig 4）。我们的搜索若反复在同一小池子上选，也会出现同类现象；需要一个独立的 gate 集，并报告搜索集与 test 的差距曲线。
- 小 signal 池（APPS 2342 题）更容易过拟合；搜索池规模要足够，或者限制迭代/接受次数。
- 每轮回到基座再应用改动（而不是累积漂移）有利于迁移；对应我们"始终相对原始 adapter / 原始权重定义编辑"的设计。
