## 改进对象
**模型权重**（全参微调）。第 t+1 轮：用第 t 轮模型对 SFT 数据集的 prompt 生成回答，把人写回答当 chosen、自生成回答当 rejected，用类 DPO 的 logistic 损失训练新模型区分两者（p4–5）。不需要奖励模型或外部偏好标注，但需要人写的 SFT 回答作为目标分布。

## 各领域 signal 数据
| 领域 | signal 数据 | split / 规模 | 是否自生成 |
|---|---|---|---|
| 通用（指令跟随/对话） | UltraChat200k（HuggingFaceH4/ultrachat_200k）中随机采 **50k prompt**，只取第一轮（p7，p16） | 第 0 轮合成数据 50k，之后每轮把上一轮 50k 与当前 50k 合并成 100k；每轮训练 2 epoch（p7） | prompt 和 chosen 回答来自已有 SFT 数据（GPT-3.5 Turbo 生成的对话语料）；rejected 回答由模型自生成 |
| 数学 / 代码 | 没有专门的数学或代码 signal 数据 | — | — |

基座 zephyr-7b-sft-full 本身就在 UltraChat200k 上 SFT 过，SPIN 是在同一份数据上再"榨"一次（p7 图 2 注释）。

## selection / acceptance 数据
- **没有独立的验证集**。正文和附录都没有提 dev split。超参（学习率在第 2–3 轮从 5e-7 降到 1e-7；第 3 轮把 β 从 0.1 调到 5.0，p15–16）和"第 3 轮已收敛"的判断，看的都是 Open LLM Leaderboard 上的分数（p7 "degree of improvement gradually approaches zero"）。【推断】超参和停止点实际是在最终评测 benchmark 上看出来的。

## 最终评测数据
- HuggingFace Open LLM Leaderboard 六项：ARC-Challenge（25-shot）、TruthfulQA（0-shot mc2）、Winogrande（5-shot）、GSM8K（5-shot）、HellaSwag（10-shot）、MMLU（5-shot）（附录 Table 1，p15）。
- 补充：MT-Bench、BBH 三个子任务（causal judgment、formal fallacies、sports understanding）、OpenBookQA（Table 6，p17）。

## signal 与 eval 是否重叠
- **不同 benchmark**：UltraChat 对话语料 vs 选择题 / 数学题 benchmark，没有 item 级重叠，也不是同分布。
- 但"选择"（超参与轮数）没有 held-out 集，等于用评测 benchmark 做模型选择。
- 论文未讨论 UltraChat（GPT-3.5 生成）与评测集之间的污染，也未做 decontamination。【推断】GSM8K 提升（26.76→38.97）是格式/风格对齐还是真实推理增益，论文没有区分。

## 过拟合 / 泛化差距证据
- **收益递减**：平均分 58.14 → 60.80 → 62.12 → 62.97 → 63.16（Table 4，p17），每轮增量 +2.66/+1.32/+0.85/+0.19。
- **不是所有任务都涨**：Winogrande 74.19 → 72.69（第 0 轮），MMLU 60.92 → 59.34（第 1 轮），到第 3 轮仍低于 SFT 基线（73.72、59.99）（Table 4，p17）。BB-sports 96.0 → 94.4（Table 6）。即平均分上升掩盖了部分任务回退。
- **对照：在同一 SFT 数据上多训 1 个 epoch 反而下降**：58.14 → 57.23（Table 5，p17）；Fig 5 中 SFT 第 2–3 epoch 提升不到 1%（p8）。
- **同一轮内多训 epoch 有上限**：第 0 轮训更多 epoch 也达不到第 1 轮的水平（Fig 4，p9）。
- 作者自述局限：目标分布固定为人写数据，性能上限被它限制（p8）。

## 对我们两篇论文的启示
- SPIN 代表"用训练型数据（SFT 语料）做 signal、用别的 benchmark 做 eval"的范式，signal 与 eval 天然不重叠；但它**没有 gate 集**，停止点和超参都看最终 benchmark——这是我们要避免的。
- 平均分掩盖单项回退（Winogrande、MMLU），我们的 gate 应逐 benchmark 设下限，而不是只看平均。
- 指令跟随方向：SPIN 是少数用通用指令数据（UltraChat）做 signal 的自改进论文，可作为我们 instruction-following 域"signal 用训练型对话数据、评测用 MT-Bench/IFEval 类 benchmark"的先例。
