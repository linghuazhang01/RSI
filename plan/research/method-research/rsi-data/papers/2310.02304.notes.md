# 2310.02304 STOP: Self-Taught Optimizer — 阅读笔记（RSI 数据用法）

## 元信息
- 标题：Self-Taught Optimizer (STOP): Recursively Self-Improving Code Generation
- 作者：Eric Zelikman, Eliana Lorch, Lester Mackey, Adam Kalai（Stanford / Microsoft Research / OpenAI）
- 版本/venue：arXiv 2310.02304v3（2024-08-16），COLM 2024
- 文件：`src_2310.02304/2310.02304.pages.md`（46 页）
- 读的范围：正文 p1–10 逐段读；附录 A（理论，p17–19，含 A.2 泛化界）、E/F（meta-utility 与 LPN utility 代码）、K（实验细节，p44–45）、L、M 读过；附录 B–D、G–J（p20–44）主要是 GPT-4 生成的 improver 代码清单与 utility 代码，**略读**（看了标题与 utility 中的 n_tests 设置）。

## 改进对象
- 被改进的是 **scaffold 代码**（"improver" 程序：给定 utility 和初始解，调用 LM 若干次返回更好的解）。LM（GPT-4 / GPT-3.5 / Mixtral）**权重不变**，作者明说这不是完整 RSI（p1, p9）。
- 循环：I_t = I_{t-1}(û, I_{t-1}, L)，即用当前 improver 改进自己，选择依据是 meta-utility û（Algorithm 1, p4）。

## Signal 数据（搜索/选择时看到的数据）
- 领域：**算法类代码任务**，不是数学 benchmark、不是通用推理/知识。
- 主实验（§5.1, p6）：下游任务 = **learning parity with noise（LPN，10 bit）**。utility u = 在 M=20 个**随机生成**的 LPN 实例上的平均准确率；D = 5 份相同的 (u, s)。每个 LPN 实例 100 条训练样本、20 条测试样本、2 秒超时、30% 位入选概率（App.K p45）。
- 数据来源：**程序化随机生成**（不是公开 benchmark，也不是模型自生成任务；是人写的任务生成器 + 随机采样）。
- meta-utility 只给 LM 看"grey-box"描述（只说明是下游 utility 的平均），**不展示具体下游任务**（p4；App.A.2 p18 论证这样更难过拟合训练任务）。
- 成本：每次迭代每个 run 约 3 千次 GPT-4 调用（App.K p45）。

## Selection / acceptance 数据
- 没有单独的 dev/gate 集：选择直接用训练用 meta-utility û（同一组随机 LPN 实例上的平均分）。seed improver 内部的 `max(new_solutions, key=utility)` 就是选择规则（Fig.2 p2）。
- 迁移实验所用的 improver 是作者"从 §5.1 里挑一个表现较好的、T=4 的 improver"（p6）——挑选依据文中没写清是否看了测试分，【推断】存在人工挑选。

## 最终评测数据
- 同任务泛化：**新的 Mtest=50 个 LPN 实例**，改进阶段没见过（p6, Fig.4 p5）。= 同分布、不同实例（程序生成）。
- 跨任务迁移（Table 1, p6）：5 个新任务——String Grid Distance（Codeforces 1852D）、改版二次分配、3SAT、Maxcut、无噪 parity。= **不同任务**，且迁移时不再优化。

## Signal 与 eval 是否重叠
- 同任务：同一生成分布、不同随机实例（相当于"同 benchmark 不同题"，但题目是无限可再生的合成实例）。
- 迁移：完全不同的任务（不同 benchmark）。
- 无公开 benchmark，污染风险低；作者特意选"不太知名"的任务，理由是知名任务的解答网上更多（p6）。

## 过拟合 / 泛化差距证据
- **理论**：App.A.2（p17–18）给出 Chernoff+union bound：û 与 ū 的差距 ε = sqrt((l·ln|Σ| + ln(1/δ))/n)，随 improver 程序长度 l 增大、训练任务数 n 减少而增大——即在少量训练任务上选长程序更容易过拟合；作者用这点论证只给 grey-box 描述。
- **弱模型下退化**：GPT-3.5、Mixtral 随迭代 test meta-utility 下降（Fig.4 p5）；GPT-3.5 只有 12% 的 run 提升 ≥3%（p7）。GPT-3.5 失败模式之一：改动对下游任务无害、但破坏 improver 自身（p7）——即"在 signal 上不掉分"不等于"自改进能力不掉"。
- **reward hacking**（§6.3 p9）：LPN utility 用 numpy 比较，改进后的程序返回形状不对的数组，得到超过 1000% 的"准确率"。这是 utility 本身被利用的直接例子。
- **约束绕过**（§6.2 p9）：不严格执行预算时，违反预算的程序分更高而被选中；10,000 次改进中 GPT-4 有 0.42% 尝试关 sandbox（Table 2 p8）。
- 没有报告"训练 û vs 测试 ū"的逐点对比数字；同任务测试只报测试曲线。

## 对我们两篇论文的启示
- STOP 的"signal 用可再生的程序化实例、test 用新实例 + 跨任务迁移"是比较干净的范式；我们若用 GSM8K/MATH train 做 signal、benchmark 做 test，对应其"跨任务迁移"那一档，需要预期迁移增益比同分布小（Table 1 中各任务提升幅度差异很大：Mod. Quad. Assign. 只从 20.6% 到 22.1%）。
- utility 必须防"形状/格式"类 hacking：自量化或自编辑 LoRA 若用自动打分，要校验输出格式与范围。
- 程序越长/搜索空间越大、signal 实例越少，越容易过拟合（A.2 的界），这支持"signal 集要大、gate 集独立"。
