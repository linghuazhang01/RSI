# 2410.04444 Gödel Agent 阅读笔记

## 元信息
- 标题：Gödel Agent: A Self-Referential Agent Framework for Recursively Self-Improvement
- 作者：Xunjian Yin, Xinyi Wang, Liangming Pan, Li Lin, Xiaojun Wan, William Yang Wang（北大、UCSB、U Arizona）
- 版本：arXiv 2410.04444v4（2025-05-31）。pages.md 中没有标出 venue【版式像 ACL 系列，未核实】。
- 文件：`src_2410.04444/2410.04444.pages.md`（24 页）
- 读的范围：正文 p1–10（含 Limitations、Ethics）全读；附录 A（goal prompt，p13/p15）、B（实验细节，p13）、D（成本，p13）、E（MGSM 优化过程，p13、p22–24）、F（与随机采样对比，p13–14）全读；附录 C 的策略代码 Listing 1–9（p16–23）浏览过，用于确认策略中是否写死了样例。参考文献略读。

## 改进对象
- 改的是 **agent 自己的运行时代码**：既包括解题策略 `solver`（policy π），也包括负责自我改进的逻辑（I），通过 monkey patching 在运行时读写（p3–5，Algorithm 1 p4）。不改模型权重。
- 做决策、改代码的 LLM 是 gpt-4o-2024-05-13；被优化出来的策略和 baseline 都用 gpt-3.5-turbo-0125 执行（附录 B p13）。
- "Gödel-free" 版本不受约束，会自己去调用 GPT-4o 等更强模型（p7），因此和 baseline 不可比，作者用斜体标出。

## 各领域的 signal 数据
完全沿用 ADAS（Hu et al., 2024）的设置（p6，附录 B p13）：
- **数学**：MGSM，validation 128 题、test 800 题（从 benchmark 中采样）。
- **代码**：摘要和引言（p2）说实验覆盖 coding，但正文实验只有 DROP、MGSM、MMLU、GPQA 和 Game of 24；全文 grep 不到 HumanEval/MBPP/LiveCodeBench 等任何代码 benchmark。**实际没有代码评测**。
- **通用推理/知识**：DROP、MMLU 各为 validation 128 / test 800；GPQA（diamond，沿用 ADAS）validation 32 / test 166（附录 B p13）。
- **Game of 24**（p8 案例分析）：没有说明数据规模与划分。
- 都不是自生成任务，也没用 train split；signal 来自目标 benchmark 的 validation 子集。
- agent 看到的反馈不止总分：goal prompt 要求它分析"低分的 validation 样例"（Box 1 p15）；附录 E 的分析示例中，agent 读到 validation 准确率 45%，引用具体样本编号，并计划把评估中答对的例子拿来当参考（p24）。所以 signal 是**逐题级别**的 validation 反馈。

## selection / acceptance 数据
- 每个任务做 6 个独立的自我改进周期，每周期最多 30 轮，全部在 validation 上进行；得到优化后的 agent 再上 test（p6）。
- agent 自己决定是否保留修改、是否回退到之前较好的版本（p7 第 6.2 节）；没有外部固定的接受门槛。
- **6 个周期得到的 agent 如何汇总或挑选，论文没有说明**（是取最好的、取平均、还是按 validation 选，都没写）。

## 最终评测数据
- 各 benchmark 的 test 子集（800 / 166 题），报告 95% bootstrap CI（Table 1 p6）。
- baseline 数字直接引用 ADAS 论文（Table 1 脚注 3，p6）。两篇的划分大小相同，但**是否是同一批题目没有说明**，所以 Gödel Agent 与 baseline 可能不是在同一批 test 题上比较【推断】。
- 没有跨 benchmark、跨模型的迁移实验。

## signal 与 eval 是否重叠
- **同 benchmark、不同题目、同分布**（validation 与 test 都是从同一 benchmark 抽出的子集）。
- 没有报告 validation 分数，因此无法计算 val→test 差距。

## 过拟合 / 泛化差距证据
1. **策略里写死了从 validation 错题提炼的内容**：MGSM 第 20 轮的策略（Listing 9 p23）把"针对易错类型"的示例直接写进 prompt；MMLU 最佳策略（Listing 3 p16）写死了几个 few-shot 示例；附录 E 分析示例明确计划用评估中答对的例子做参考（p24）。这说明 agent 会把 signal 集的具体内容编码进被改进的系统。test 题和 validation 题不同，所以不构成 test 泄漏；但如果 signal 直接来自 test 题，就会变成直接泄漏。
2. **优化过程不稳定**（p7 第 6.2 节）：MGSM 上 100 次优化中，4% 意外终止，92% 出现过临时下降，14% 最终比初始策略还差。
3. **随机采样对照**（附录 F，Fig 6 p14）：用 GPT-4o 做 30 次随机采样，MGSM 上大约保持在 30%；论文没有说明这条曲线是在 validation 还是 test 上测的。
4. **工具消融结果有矛盾**（Table 2 p7）：去掉"thinking"后为 50.8（标注 ↓13.4），去掉 error handling 为 49.4，但标注成 "↓-14.8"；去掉 code running 为 57.1（"↓-7.1"），去掉 LLM calling 为 60.4（"↓-3.8"）。正文说后两者影响很小，与 −7.1 的降幅不太吻合。只有 MGSM、单次运行。
5. **Gödel-free 的数字（如 MGSM 90.6）来自调用更强模型**（p7），不是自我改进本身带来的，不能拿来和 baseline 比。
6. Game of 24 案例：更换初始策略后，Gödel Agent 仍没能超过 ToT（p8）。

## 对我们两篇论文的启示
- Gödel Agent 和 ADAS 一样，把"同 benchmark 的 validation 子集"当作搜索信号，并且让改进者看到**逐题反馈**。我们的改进者（27B 量化自身 / 改自己的 LoRA）若能看到 search pool 中具体题目的对错，就有可能把这些题的内容编码进去（Listing 9 的现象在权重层面对应的是记住 search pool）。因此 search pool 必须和 gate、test 都不相交，并且最好来自不同来源。
- 论文没有说明 6 个周期如何选出最终 agent，也没报 validation 分数，这正是审稿人会追问的地方。我们需要预先写明：最终候选只按 gate 集选，test 只评一次，并报告 search、gate、test 三组分数。
- 优化过程有 14% 的概率比初始还差（p7），说明需要一个独立的接受门槛（gate），不能只靠改进者自己判断是否回退。
