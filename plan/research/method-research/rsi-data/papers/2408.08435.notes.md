## 改进对象
- 改的是 **agent scaffold 代码**（一个 Python `forward()` 函数，含 prompt、工作流、工具调用），不是模型权重。
- meta agent 是固定的 GPT-4o（gpt-4o-2024-05-13）；被设计出来的 agent 与 baseline 都用 GPT-3.5（gpt-3.5-turbo-0125）执行（p6, p29）。所以不是严格的"自我"改进：设计者与被设计系统所用模型不同，设计者本身不更新。

## 各领域的 signal 数据
所有 signal 都是**从目标 benchmark 中抽出的 validation 子集**，与 test 子集同 benchmark、不同题目。没有用任何 benchmark 的 train split，也没有自生成任务。
- **数学**：MGSM，validation 128 题、test 800 题，从 benchmark 中采样（附录 E p29）。
- **代码**：没有代码 benchmark。ARC 实验要求 agent 写变换代码来解题（p6），但任务本身是抽象推理，不是代码能力评测。
- **通用推理/知识**：
  - DROP（阅读理解，F1）、MMLU（多任务）：validation 128、test 800（p29）。
  - GPQA diamond：validation 32、剩下 166 题做 test（p29）。
  - ARC：只取 "Public Training Set (Easy)" 中网格 ≤5×5 的题，从中采样 validation 20 题、test 60 题（p6）。validation 和 test 都来自 ARC 的 **public training 集**，同分布、不同题目。
- 评估重复：ARC 与 GPQA 各评 5 次，其余评 1 次（p6, p29）。

## selection / acceptance 数据
- 搜索循环里只有一个信号：新 agent 在目标域 validation 上的分数，写进 archive，供 meta agent 参考（p4–5；Algorithm 1 p33）。没有单独的接受门槛（每个新 agent 都入档，只做"能运行、无报错"的自我反思修复，最多 5 次）。
- 报告阶段怎样从 archive 里挑 agent，正文**没有明说**用 validation 还是 test：
  - ARC：Fig 3 报告的是**所有**被发现 agent 的 held-out test 准确率曲线（p6）。
  - 跨模型迁移（Table 3）：明确写的是选 **GPT-3.5 上 test 准确率最高的 top-3 agent**（p8），即**用 test 做了选择**。
  - MGSM 跨域迁移（Table 2）：选 "top 3 agents from MGSM"，未说明排序依据；表中 MGSM 一栏 53.4/50.2/47.4 是 test 分数且恰好降序【推断：可能按 test 排序】。

## 最终评测数据
- 域内：上述各 benchmark 的 test 子集（800 / 166 / 60 题），报告中位数与 95% bootstrap CI（Table 1 p7）。
- 跨域：MGSM 上搜到的 agent 迁移到 GSM8K、GSM-Hard、SVAMP、ASDiv（数学内），以及 MMLU、DROP、GPQA（数学外）（Table 2 p8；Table 4/5 p20）。
- 跨模型：ARC 上用 GPT-3.5 搜到的 agent 迁移到 Claude-Haiku、GPT-4、Claude-Sonnet（Table 3 p9）。

## signal 与 eval 是否重叠
- 域内主结果：**同 benchmark、不同题目、同分布**（validation 与 test 都是从同一 benchmark 随机抽的子集；ARC 两者都来自 public training 集）。
- 跨域迁移结果：**不同 benchmark**（signal = MGSM validation，eval = GSM8K/GSM-Hard/SVAMP/ASDiv/MMLU/DROP/GPQA）。
- 跨模型：同 benchmark（ARC），执行模型不同。
- 论文没有报告任何 validation 分数，因此**无法直接计算 val→test 差距**。

## 过拟合 / 泛化差距证据
1. **跨域迁移出现排名翻转，部分低于手工 baseline**（Table 2 p8；Table 5 p20）：
   - 数学内迁移效果强：MGSM 最佳 agent（Dynamic Role-Playing）在 GSM8K 69.5 vs 最好的手工 baseline LLM Debate 43.6；GSM-Hard 31.2 vs Role Assignment 18.0。
   - 数学外：同一个 agent 在 MMLU 只有 62.4，低于 CoT 65.4 与 COT-SC 65.9，也低于在 MMLU 上直接搜的 69.6；在 GPQA 三个 MGSM agent 是 28.6/28.7/29.9，低于 Self-Refine 31.6 与 LLM Debate 31.4，也低于 GPQA 上直接搜的 34.6。论文把 GPQA 描述为"match"baseline（p20），实际中位数更低。
   - 结论：源域最好的 agent 不一定在目标域最好（MGSM 第 1 名在 MMLU 是三者中最差）。
2. **跨模型迁移排名翻转**（Table 3 p9）：GPT-3.5 上 test 最好的 Structured Feedback and Ensemble Agent（13.7）迁到 Claude-Sonnet 为 38.7，低于手工 Self-Refine 39.3；迁到 Claude-Haiku 为 5.0，低于 Self-Refine 6.3。GPT-3.5 上排第 3 的 Dynamic Memory agent（12.7）在 Sonnet 上最好（48.3）。作者在 p11 也承认，对 GPT-3.5 最好的复杂反馈机制，在更强模型上不如更简单的设计。
3. **单次运行方差大**（Table 6 p34）：数学域空初始化得到 67.5，有初始化只有 53.4；其他三个域则是有初始化更好。每个设置只有一次搜索，没有多 seed，搜索本身的随机性可能和"改进"一样大。
4. **validation 很小**：MGSM/DROP/MMLU 只有 128 题，GPQA 32 题，ARC 20 题，且只评 1 次（GPQA/ARC 5 次）。30 轮（ARC 25 轮）在这么小的集合上择优，存在过拟合 validation 的可能，但论文没有给出 val 与 test 对比来量化。
5. **用 test 选择**：Table 3 的 top-3 是按 test 准确率选出来的（p8），所以跨模型迁移结果的"源模型"一侧存在 test 选择偏差。

## 对我们两篇论文的启示
- ADAS 代表 agent-design 类 RSI 的标准做法：**在目标 benchmark 的小 validation 子集上搜索，在同 benchmark 的不相交 test 子集上报告**。这种"同 benchmark 不同题"的做法被后续工作（Gödel Agent 等）沿用，但 ADAS 本身没有报告 val→test 差距，所以它不能证明这种做法安全，只说明这种做法常见。
- 真正能说明"改进是否通用"的证据来自**换 benchmark**（MGSM→GSM8K 等）和**换模型**。结果是：同领域内迁移较好，跨领域迁移会掉到 baseline 以下，换模型会出现排名翻转。对应到我们的设计：如果搜索信号来自某 benchmark 的 search pool，最终至少要在**同领域但不同来源的 benchmark** 上测试，才能说明改进不是针对该 benchmark 的格式或分布。
- 要避免 ADAS 在 Table 3 用 test 挑 top-k 的问题：最终候选只能按 search/gate 集的结果选出，test 只用一次。
- 小 validation（128 题）加单次运行时，搜索方差可能和效果一样大（Table 6）。我们的 gate 集应足够大并做多 seed，同时报告 search 分数和 test 分数。
