# 2512.07419 TAP 阅读笔记

## 1. 元信息
- 标题：Towards Training-free Automatic Proxy Discovery via Large Language Models for Mixed Precision Quantization（TAP）
- 作者：Haidong Kang*、Jun Du*、Guo Yu（*共同一作）
- 机构：东北大学计算机与通信工程学院；北京交通大学软件学院；南京工业大学智能制造研究院
- 版本：arXiv:2512.07419v3 [cs.LG]，2026-09-20（p.1）。未标注会议。
- 阅读范围：pages.md 全部 p.1–p.9（PDF 共 9 页）。**正文引用的 App. A–G（简单 prompt、prompt 工程细节、扩展消融、局限、可视化、相关工作）不在 arXiv 版本中**，因此无法核对 prompt 原文与"直接 prompt 不稳定"的具体数据。

## 2. 做的是什么决策
- 最终决策：CNN/ViT 的**逐层（卷积还包括逐通道）比特分配**，权重比特 {2,4,8}，激活固定 8 bit 或也在 {2,4,8} 中选（p.4 "Search Space and Constraints"）。
- 但 **LLM 不直接输出比特**：LLM 生成的是"代理（proxy）"——一段自然语言推理 T + 可执行代码 C，代码给各层/通道打敏感度分，再由代码里的比特分配函数按目标压缩率 ζ 把分数映射成比特（p.4–5，Step 0："2/4/8 bits for convolutional channels, 4/8 bits for linear layers"）。即 LLM 做的是"程序搜索"（类似 FunSearch/EoH），在 proxy 空间里进化。
- 被量化的模型：**CNN 与视觉 Transformer**（ResNet18/50、MobileNetV2、ViT-B、DeiT-B、Swin-B），数据 CIFAR-10/ImageNet，另称有 VOC/COCO（p.5），但正文没有检测结果表。**没有 LLM 被量化**。

## 3. 驱动决策的信息（LLM 看到什么）
决策者：主实验用的 LLM 正文没有明说；消融比较了 **Deepseek-chat、Qwen3-max、Grok 3**（Table 9，p.7–8）。LLM 参数始终冻结。

**每次调用 LLM 的输入**（p.4 §3.2）：
1. 结构化 prompt π，指定操作类型：初始化 / 变异 / 交叉；三个 prompt 模板 T1–T3（模板内容在缺失的 App. C）。
2. 有界上下文窗口 C_t：已有 proxy 的自然语言推理逻辑、敏感度打分的可执行代码、以及**历史比特分配表现**（fitness）。上下文从"上下文库"K 中采样，K 保存每代 top-10% 高 fitness proxy 的逻辑与性能（Alg. 1 第 18 行，p.5）。
- 初始化模板内容（p.4，转述）：任务描述（为卷积/线性层打敏感度分并分配比特）、输入输出契约（输入为架构元数据和压缩目标；输出为通道级/层级敏感度分数）、先验知识（如"分数越高越敏感，应给更多比特"）。
- 变异模板：基于单个 proxy 调整打分统计量或比特分配函数参数；交叉模板：融合两个父 proxy，例如卷积层打分取自 f1、线性层打分取自 f2（p.4）。
- 格式：代码 + 自然语言；每个候选必须包含"推理逻辑、可执行代码、比特分配函数"三部分（p.5 Step 0）。

**LLM 看不到的**：论文声称 proxy 只能用架构/任务级元数据，**明确排除 Hessian、梯度、原始权重/激活张量**（p.4）。LLM 本身也看不到逐层诊断，只看到别的 proxy 的代码和它们的标量 fitness。
- 矛盾：Table 2 给出的示例 TAP proxy 为 ‖W_ij‖₂ · H_Aij · e^(−d_i/L)（p.2），用到了权重范数和（推测是）激活熵，且表中"Calibration Data ✓、16 samples"。与"排除原始权重/激活张量"的声明不一致。

**反馈信号（fitness，Eq. 6，p.4）**：
ϕ(f) = α·ρ_sens + (1−α)·Acc_quant
- ρ_sens：proxy 敏感度分与"实测量化误差"之间的 Spearman 相关；
- Acc_quant：按 proxy 分配比特后量化模型在 ImageNet-1k 上的 top-1（达到目标压缩率）；
- 文中还提到 β≥0 控制计算效率，但公式里没有 β（p.4）。概述又说会结合种群多样性、新颖性（p.3），公式中也没有。
- 违反契约（如产生非法比特）的 proxy 赋 ϕ=−∞（p.5 Step 2）。

**"DPO"控制器（Eq. 7–8，p.4–5）**：并不是真正的 DPO 损失。实际是对三个模板做乘性权重更新 w_t ← w_t·α·Fitness(T_t)/μ，再归一化成采样概率。偏好对 (f_prefer, f_disprefer) 的构造被描述了，但更新式里没有用到偏好对。

成本：作者称 5 代内得到好 proxy，**0.5 GPU-hour（RTX 3090）**（p.5）；Table 3 报告搜索代价 0.42/0.43 GPU-hour（p.6）。校准 16 样本（p.1、Table 2）。生成后应用 proxy：proxy 打分 0.0133 s、比特分配 0.0645 s（Table 7，p.7）。LLM API token 成本未报告。

## 4. 决策过程
LLM 驱动的进化程序搜索（Alg. 1，p.5）：
- 初始化种群 P0（初始化模板）→ 每代采样操作类型和模板（按 p(t)）→ LLM 生成候选 proxy → 在基准网络集合上逐个执行：打分→分配比特→量化→测 ImageNet top-1→算 ϕ → 按模板聚合 fitness 更新模板权重 → 更新上下文库（top-10%）→ P_t ∪ P'_t 取 top-N（同分保留更新的）。
- 种群 N ∈ {2,5,8,10} 做过消融，最好 N=8（Table 11）。
- 最终输出：最高 fitness 的 proxy；部署时 proxy 是一个闭式打分规则 + 分配函数（不再调用 LLM）。

## 5. 关键结果
- Table 3（p.6，QAT，搜索在 CIFAR-10 上做后迁移到 ImageNet，"TAP-C"）：ResNet18 72.63% / 0.42 GPU-h vs EMQ 72.28%/0.51、OMPQ 72.08%/0.45；ResNet50 76.72%/0.43 vs EMQ 76.70%/0.52、OMPQ 76.28%/0.46。注意 TAP-C 参数量更大（ResNet18 7.5M vs OMPQ/EMQ 6.7M；压缩率 83.18% vs 84.98%）。
- Table 4（p.7，ResNet18 PTQ）：TAP-C 70.26%（16 样本）vs EMQ 69.92%、OMPQ 69.41%（64 样本），但 TAP-C **#Params 8.9M vs 4.0M**，比较不在同一模型大小。
- Table 5（p.7，MobileNetV2 PTQ）：71.81%（16 样本，2.1M）vs EMQ 70.75%（1.5M）、OMPQ 69.62%（1.3M）。同样参数更多。
- Table 6（p.7，ViT）：TAP-C W*/A8，压缩 82%：ViT-B 83.56、DeiT-B 81.24、Swin-B 83.79；与 6/6 或 8/8 的均匀 PTQ 基线比较（位宽设置不同）。
- 作者宣称 DPO 模块使策略更新时间减少约 40%、fitness 波动幅度减少 25%（p.5），**没有表格、没有对照组描述**。

## 6. 隔离各信号价值的消融
- Table 8（p.7，α 消融，ImageNet）：ResNet18 在 α=0.1 最好 70.26；α=1（只用 Spearman ρ_sens、不用量化后精度）降到 62.48；α=0.5 为 68.07，0.7 为 65.86。MobileNetV2 同趋势：α=0.1 71.81，α=1 64.52。**这是本文唯一一个隔离反馈信号的消融**，结论与作者"对 α 不敏感"的表述相反：仅用敏感度–误差秩相关作为反馈会掉约 8 个点，**真实量化精度这个反馈信号是关键**（作者说"remains stable across a wide range"，与表中数字不符）。
- Table 9（p.8，换 LLM，4 次运行）：Deepseek-chat 平均 71.44、Qwen3-max 71.35、Grok 3 71.01；单次范围 70.59–71.81。表未注明是哪个模型/设置（从 71.81 推断是 MobileNetV2 PTQ【推断】）。
- Table 10（p.8）：5 个不同 16 样本校准批次，ResNet18 70.14–70.26，MobileNetV2 71.68–71.81。
- Table 11（p.8）：种群大小 N。
- **缺失的消融**：没有"去掉 DPO 控制器（均匀模板）"、"去掉上下文库/历史 fitness"、"去掉进化只用单次 prompt"、"直接让 LLM 输出逐层比特"的数字（若有可能在缺失的 App. D）；**没有与随机程序搜索或 EMQ 式非 LLM 进化在同预算下的对比**（EMQ 只作为外部结果出现在表中，预算未对齐）。也没有和 HAWQ 在同一模型大小下的对比（HAWQ ResNet18 68.5%，Table 3，大小未知）。

## 7. 关于可加性/交互的证据
无直接证据。fitness 中的 ρ_sens 衡量 proxy 分数与"实测量化误差"的秩相关，但没说明这个误差是单层量化测的还是整网络配置测的，也没报告单层敏感度能否预测组合配置。α=1 的结果（只优化秩相关时最终精度差很多）【推断】可以理解为"与某种误差秩相关好"不等于"组合配置好"，与可加性存疑的观点一致，但论文没有这样分析。

## 8. 作者声明的局限 / 失败模式
- 局限在 App. E，arXiv 版本中不存在。正文只说"未来进一步提升性能"（p.8）。
- **"直接 prompt 不稳定"的证据**：只有文字论断，没有数据。p.1 说"directly prompting the LLM yields unstable layer-wise bit allocations"，并归因于缺少把 proxy 与 MPQ 性能连起来的反馈信号；p.2 说简单 prompt（App. A）能产生候选，但因缺少任务感知反馈而"inconsistent performance"。**正文中没有对应表格、方差或例子**，App. A 不在 PDF 中。
- **无效代码**：Table 12（p.8）：不可执行 proxy 代码比例在第 1–10 次迭代为 ResNet18 40% / MobileNetV2 30%，11–20 为 20%/20%，21–30 为 10%/10%。非法比特 → ϕ=−∞（p.5）。注意这里迭代到 30，与"5 代内收敛"的说法并不一致。

## 9. 批判
- 内部矛盾较多【核查】：(i) "DPO" 实为乘性权重更新，偏好对未进入公式；(ii) 声称排除权重/激活统计，示例 proxy 却用了 ‖W‖ 和激活熵且需校准数据；(iii) fitness 公式中提到 β 和多样性/新颖性但公式没有；(iv) "5 代 / 0.5 GPU-h" vs Table 12 的 30 次迭代；(v) "microsecond-level search"（p.6）vs Table 7 的 0.0133 s 与 0.42 GPU-h；(vi) α 消融的叙述与数字相反；(vii) 0.42 GPU-h 的搜索代价要求每个候选在 ImageNet 上量化并测 top-1，在 3090 上 5 代×N 个候选似乎很难做到【推断】，且 QAT 结果的微调代价未计入。
- 对比不公平：PTQ 表中 TAP-C 的参数量是 EMQ/OMPQ 的 1.4–2.2 倍，精度更高不能归功于 proxy。
- "LLM 一次推理就推出最优比特分配"（p.6）的说法与方法不符：比特由进化得到的代码产生，LLM 不在部署时推理。
- 主实验用哪个 LLM 未说明。
- 没有方差/种子信息（除 Table 9/10）。

## 10. 对本项目（27B 自量化 agent）的启示
- **"让 LLM 写打分规则/分配函数，再用真实评测回传"是一条与"让 LLM 直接给逐层比特"不同的设计路线**。TAP 声称后者不稳定，但证据只是一句话，不能当作已证实的结论；我们若要采用"直接给配置"的 agent，需要自己测量不同种子下配置的方差。
- **真实端到端反馈比代理相关性重要**：Table 8 中 α=1（只用秩相关）比 α=0.1 低约 8 个点。对我们来说，profile 得到的逐层 ΔKL 只能作为先验，最终仍需外部评测器的组合配置反馈；只优化"ΔKL 排序和某误差的相关性"可能误导。
- **上下文中给"别的方案 + 它们的分数"**（上下文库 top-10%）是一种紧凑的历史表示，比原始日志更适合有限上下文的 27B 模型。
- **输出必须经过校验**：初期 30–40% 的代码不可执行，靠 −∞ fitness 淘汰。若我们的 agent 输出配置或代码，工具层需要 schema 校验与预算检查，并统计无效率作为一个指标。
- 模板选择的 bandit（乘性权重）是一种廉价的元控制，可用于在"探索新配置/局部修改/合并两个配置"之间分配外部评测预算。
- 本文没有提供"agent 看到哪部分诊断信息有用"的消融；问题 (2) 仍需我们自己做实验回答。
