## 2. 做的是什么决策
- **决策对象**：每个线性层中哪些**输入通道（权重列，column）**保留为 fp16（称 weak columns），其余列用低比特（3/4 bit）OPTQ/GPTQ 量化。这是**层内、列粒度**的混合精度（只有 fp16 vs w-bit 两档），不是逐层比特分配。
- **每层保留多少列 k**：由全局"额外比特预算"（如 3.01 bit = 每权重多 0.01 bit）**均匀**分配到 block 内各线性层（附录 D.2，p.12–13），不按层敏感度自适应。
- **附带决策**：量化参数（step size、zero point）用简单 2D 网格搜索加截断（truncation），以最小化量化前后差异（p.4–5）。
- 不决策：量化器类型（固定 OPTQ）、group size（默认 per-channel，Table 6 另测 group）、校准集（沿用 OPTQ 设置）。embedding 与 head 保持全精度（p.3）。

## 3. 驱动决策的信息
### 3.1 信号与公式
- 层级目标：min ||WX − ŴX||²（Eq.3，p.3），按输出通道分解为 Σ_i ||W_{i,:}X − Ŵ_{i,:}X||²；每个输出行的 Hessian 相同：H = 2XXᵀ（Eq.4，p.3），与行无关。
- 二阶近似：E_i ≈ ΔW_{i,:} H ΔW_{i,:}ᵀ（Eq.5，p.3；附录 A 证明，p.10：E_i 是二次函数，在局部极小处忽略一阶项）。
- **列敏感度（Eq.6，p.4）**：sensitivity_j = λ_j · ||ΔW_{:,j}||²，其中 λ_j 是 H 的第 j 个对角元，ΔW_{:,j} 是第 j 列的量化扰动。取 top-k 作为 weak columns。
- 关键观察：λ_j = 2·Σ_n x_{j,n}²，即**第 j 个输入通道激活的平方和（激活能量）**【推断：由 H=2XXᵀ 直接推出，论文未写成这一形式】。所以 "Hessian-only" 准则在数学上就是"激活幅度（二阶矩）"准则；激活离群通道 ⇒ λ_j 异常大 ⇒ 对应权重列敏感（p.3，Figure 1 左）。
- ΔW_{:,j} 具体用哪种量化器计算（RTN+搜索后的配置，还是 OPTQ 过程中的误差）论文未明确说明【推断：大概率是在已搜索配置下的 RTN 误差，因为选列发生在 OPTQ 之前】。
- Figure 2（p.4）：按影响排序的各输入通道累计误差显示，大部分误差来自少数通道。

### 3.2 数据
- 校准集：C4 中随机 128 段 × 2048 token（p.5），与 OPTQ 相同。
- 结果为 3 个随机种子的均值 ± 误差（p.5）。

### 3.3 成本
- H 与 OPTQ **共享**（OPTQ 本就要算 XXᵀ），所以选列只需取对角 + 一次量化误差计算，额外开销很小（p.7 "Quantization Speed"）。
- A100 上 66B 模型量化不到 3 小时（p.7）。
- 推理：自定义 CUDA kernel，低比特矩阵解压后 GeMV，再对 weak columns 对应的激活通道单独做一个 GeMV；3.01-bit 相对 OPTQ 3-bit kernel 的延迟开销见 Table 5（p.7），LLaMA-7B k/q/v/o 为 3.21%，文中称"最多 3.21%"，但同表 LLaMA-13B k/q/v/o 为 3.47%（文表小不一致）。
- 存储：weak columns 以 fp16 存 + 每列一个整数索引；开销约 0.3%（p.4）。OPT-175B 3.01-bit 比 3-bit OPTQ（约 63.1 GB）多约 260 MB（p.5）。

## 4. 决策过程
- **闭式规则**：每层算 Eq.6，取 top-k 列（p.4）。k 由预算闭式算出（附录 D.2，p.12–13）：
  - t = w + (16−w)/12 · r ⇒ r = (t−w)/(16−w) · 12（r·d² 为每个 OPT block 的 fp16 元素数，block 总元素 12d²）；
  - 自注意力每层 k = round(r/#layers · d)；FFN 层的 k 调整为与注意力层开销对齐。
- 3.01-bit 时，OPT key 层的 weak columns 平均贡献 0.00167 bit（约占 key 权重列的 0.15%）（p.5）。
- 小模型（125M/350M）用 0.05 extra bit，因为 0.01 bit 时几乎没有 weak column（Table 1 注，p.6）。
- 选完列后把 weak columns 重排到矩阵末尾再跑 OPTQ，这样 OPTQ 对其他列误差的补偿可以累积到 fp16 列里并被完整保留（p.4）。
- 有效比特按"storage-favored"方式计算；若用实际 kernel 采用的 zero-filled 低比特矩阵，3.01 变成约 3.012 bit（附录 B.2，p.10–11）。

## 5. 关键结果
- **OPT WikiText-2（Table 1，p.6）**：OPT-6.7B：fp16 10.86；OPTQ 3-bit 12.88；OWQ 3.01 11.21±.05；OWQ 3.1 11.14±.03；OPTQ 4-bit 11.14；OWQ 4.01 10.87。即 3.1-bit OWQ ≈ 4-bit OPTQ。OPTQ 基线默认带 TS+AO 选项（p.5）。
- **LLaMA WikiText-2（Table 2，p.6）**：LLaMA-7B：fp16 5.68；OPTQ 3 8.13；OWQ 3.01 6.66±.04；OWQ 3.1 6.41±.01；OPTQ 4 6.10；OWQ 4.01 5.94。
- Few-shot 平均（ARC-c/HellaSwag/MMLU）：Table 3（OPT，p.7）、Table 4（LLaMA，p.7）。LLaMA-7B：OPTQ 3 47.06 → OWQ 3.01 50.21（fp16 54.81）。
- PTB/C4：附录 Table 9–12（p.11）。
- 截断/配置搜索：OPT-6.7B 上 OWQ 的 Wiki2 PPL 从 12.14 降到 11.21；但把截断用到普通 OPTQ 上反而从 12.88 恶化到 48.26，原因是 key/query 层的 weak columns 数值特别大，被截断后误差巨大（p.5）。
- **有效比特扫描（Table 8，p.8，OPT-6.7B）**：3.005→11.38，3.01→11.22，3.05→11.19，3.10→11.17，3.20→11.15，3.30→11.13；延迟开销 2.89%→8.69%，内存开销 0.21%→10.95%。收益在 3.01 左右基本饱和。
- **与 group-wise 对比（Table 6，p.8）**：OPT-6.7B OPTQ 3/g128 Wiki2 11.55 vs OWQ 3.01 11.22；LLaMA-7B OPTQ 3/g128 6.56 vs OWQ 3.01 6.65（LLaMA 上 g128 OPTQ 在 Wiki2 上略优）。OWQ 3.01 的存储开销约为 g128 OPTQ 的 10%（p.8）；附录 D.1：3.01-bit ≈ g1024 的开销，3.1-bit ≈ g128 的开销（p.12）。OWQ+g128 叠加在 LLaMA-7B 上 6.40。
- WCT 微调（Figure 4/5，p.7–8）：与本项目关系较弱，略。

## 6. 隔离各信号价值的消融
- **选列准则对比（Table 7，p.8）**，WikiText-2 PPL：

| 准则 | OPT-6.7B | LLaMA-7B |
|---|---|---|
| λ_j·‖ΔW_{:,j}‖²（提出） | 11.23 | 6.64 |
| λ_j（仅 Hessian 对角 = 激活能量） | 11.25 | 6.76 |
| ‖ΔW_{:,j}‖²（仅权重误差） | 13.08 | 11.57 |
| Σ‖W_{:,j}‖（权重幅度） | 14.77 | 10.12 |

  - 结论：**几乎全部价值来自 λ_j（激活二阶矩）**；乘上 ‖ΔW‖² 只带来小幅额外收益（OPT 0.02，LLaMA 0.12 PPL）。只看权重误差或权重幅度的准则远差，甚至不如 OPTQ 3-bit（LLaMA 8.13）【推断：比较时假设 Table 7 是 3.01-bit 设置——表中第一列与 Table 1/2 的 OWQ 3.01 数值 11.21/6.66 接近；论文没写比特数】。
  - Table 7 标题写 "LLaMA WikiText-2"，但表里也含 OPT 行（排版小错）。
  - 没有"随机选列"基线；没有单独的"激活绝对值均值"准则（但如上所述，λ_j 本身就是激活平方和）。
- **act-order 的解释（p.6）**：OPTQ 的 act-order 按激活幅度排序量化列；OWQ 认为其收益来自"敏感度感知"；OWQ 上叠加 TS+AO 基本无收益（Table 1：OWQ 3.01 vs OWQ+TS+AO 相近，13B 上 11.48→11.14 是例外）。
- **预算消融**：Table 8（见上）。
- **截断消融**：p.5 的 12.14→11.21 与 12.88→48.26。

## 7. 关于可加性/交互的证据
- **层间交互证据（附录 C.2，Table 13，p.12，OPT-6.7B）**：在固定总预算下，只对指定层保留 weak columns：
  - {Wk,Wq} 11.26；{Wk,Wv} 19.87；{Wk,Wfc1} 22.25；{Wq,Wv} 111.57；{Wv,Wfc1} 89.92；
  - {Wk,Wq,Wv} 11.31；{Wk,Wq,Wfc1} 11.24；{Wk,Wq,Wout} 11.26；{Wq,Wv,Wout} 111.81。
  - 解读：**key 和 query 必须同时处理**；只缺其中一个就严重退化（缺 Wk 时 PPL > 89）。这是很强的**非可加/成对交互**信号——K 与 Q 的误差在 QKᵀ 处相乘【推断：机制解释是我的】，且 K/Q 的大值 weak columns 一旦被截断就会崩（与 p.5 的截断现象一致）【推断：未加 weak column 的层仍走带截断的配置搜索】。
  - 作者结论：按层敏感度分配不同的预算比例可能更好，但"rate tuning"代价过高，留作未来工作（p.12）。
- 层内：Eq.4 指出输出通道之间没有 Hessian 交互（各行共享同一 H），因此行间误差可加是精确的（层级 MSE 意义下）；但列之间通过 H 的非对角元存在交互，Eq.6 只用对角 λ_j，忽略了列间耦合（OPTQ 的误差补偿部分处理了这一点）。
- 没有测试"逐层单独测得的敏感度之和能否预测组合配置"。

## 8. 作者声明的局限
- 额外预算在各层间均匀分配；逐层调预算比例"代价过高"，是未来方向（p.12）。
- 小模型在 0.01 bit 预算下几乎没有 weak column，需要 0.05 bit（p.6）。
- 混合精度格式带来实际 kernel 延迟开销（Table 5、Table 8）。
- C4 校准 ⇒ C4 PPL 不是严格 zero-shot（p.11）。

## 9. 批判
- 【推断】"Hessian" 只是层级重建损失的 Hessian（2XXᵀ），与最终任务损失无关；其价值几乎全来自激活二阶矩。论文把它包装成 Hessian 准则，但 Table 7 说明它基本等价于"按激活能量选列"（即 act-order 用的同一统计量）。
- 【推断】有些结果不稳：OPT-13B OWQ 3.01 在 PTB（17.00 vs OPTQ 3-bit 16.40）和 C4（13.29 vs 13.16）上**比 OPTQ 还差**（Table 9/10，p.11）；LLaMA-65B PTB 的 OWQ 3.1 = 9.87±.87 比 3.01 的 8.33 还差，且方差大（Table 11，p.11）。正文没有讨论这些反例。
- 【推断】Table 7 没有随机选列、没有方差，也只在两个模型上做；"λ_j vs λ_j·‖ΔW‖²" 的差距（0.02/0.12）可能落在种子误差范围内（Table 1 的 ± 为 .05/.04）。
- 【推断】OPTQ 基线带 TS+AO，而 OWQ 带截断搜索；从 12.14→11.21 可以看出，OWQ 的增益有相当一部分来自"weak columns + 截断搜索"的组合，而不只是保留了 fp16 列。
- 【推断】有效比特按 storage-favored 方式算，但实际 kernel 用 zero-filled 格式（3.012 bit）；差别小，但口径不一致。
- 【推断】Table 13 只有一个模型、一个预算、单次结果（无 ±），只算轶事性证据。

## 10. 对本项目（27B 自量化 agent 的工具/诊断设计）的启示
1. **最便宜且有效的通道级信号就是激活二阶矩 diag(XXᵀ)**：它只需一次前向收集，并且 GPTQ 本来就要算 H。建议工具 `channel_stats(module)` 返回每输入通道的 λ_j（或激活 RMS）分布，包括 top-k 占比、尾部集中度，用来判断"该模块是否存在离群通道、保留少量 fp16 列/更小 group 是否值得"。Table 7 显示权重幅度或权重误差信号几乎没用，可以不提供。
2. **离群列保留的性价比极高、饱和极快**：0.005–0.01 bit 就能拿到大部分收益（Table 8）。agent 的动作空间里值得加入"每层保留 top-k fp16 列"这一选项，它与 bits/group 正交（Table 6），且存储开销可以闭式算出（附录 D）。
3. **模块间交互要显式探测**：K/Q 必须成对处理（Table 13），单模块 profile 可能严重低估或误判。建议 `profile` 工具支持模块组（例如同一 block 的 {q,k}），或至少提供 pairwise 交互检查，比较 ΔKL(q,k) 与 ΔKL(q)+ΔKL(k)。
4. **量化器超参与模块类型有交互**：截断/clip 搜索对普通 GPTQ 的 K/Q 层有害（12.88→48.26），只有在离群列被保护后才有益。因此"量化器选择"诊断应按模块类型（q/k vs 其他）分别给出，不宜全局一刀切。
5. OWQ 自己没有做跨层预算分配（明确留作未来工作），这正是 agent 可以发挥的空间；但它也提示：仅凭层级重建误差信号不能保证全局最优，需要用 KL 这类端到端信号复核。
