# 2607.23047 MixQuant（上游比特上下文边缘化的自适应混合精度）阅读笔记

## 1. 元信息
- 标题：MixQuant: Adaptive Mixed-Precision Quantization for Large Language Models
- 作者：Ashitabh Misra, Madhav Agrawal, Arham Jain, Tarek Abdelzaher
- 机构：University of Illinois at Urbana-Champaign
- 版本：arXiv:2607.23047v1，2026-07-25；标注 "Preprint"，无会议信息（p.1）。
- 读的页范围：p.1–p.15 全文（正文 p.1–11，参考文献 p.12–15）。**无附录**。

## 2. 做的是什么决策
- 决定**逐线性模块（per-linear-module）比特宽度**，B = {3,4,5,6,7,8}（p.5, p.7）。
- 量化器（AWQ 或 GPTQ）预先固定，不由分配器选择；但 MixQuant 会**重新估计量化器的校准参数 μ**（AWQ 的 smoothing 系数与 clipping 范围、GPTQ 的 Hessian），这是第二个“决策”（Stage 2，p.6）。
- 不决定 group size、embedding/输出头、校准数据来源。
- 设定是“自适应”：预算 M 在校准时未知，一次离线校准后部署时对任意 M 只做一次贪心求解（p.2, p.5 Eq.1）。
- 激活 8-bit，量化为模拟（quantize–dequantize 回 FP16）；内存按打包后的线性权重大小统计，不含 scale 开销（p.7）。

## 3. 驱动决策的信息
- **信号：上下文条件化的模块输出 NMSE**（p.6 Eq.3）
  d_ℓ(b; b_<ℓ) = E_x‖y_ℓ^(b, b_<ℓ)(x) − y_ℓ^fp16(x)‖² / E_x‖y_ℓ^fp16(x)‖²
  其中 b_<ℓ 是上游所有模块的比特（“上下文”）。
- **均场边缘化**（Stage 1，p.6 Eq.4）：上游比特独立均匀采样自 B，d̄_ℓ(b) = E_{b_<ℓ∼Unif}[d_ℓ(b; b_<ℓ)]，用 K=10 次蒙特卡洛估计（p.8）。每个采样上下文中，上游被量化模块的 μ 也在该上下文下重新校准（仅用于打分后丢弃，p.6）。结果是一张 L×|B| 的距离表 D，只依赖 (ℓ, b)，可服务所有预算。
- **计划感知的量化器参数**（Stage 2，p.6）：把可行内存区间 [M_min, M_max] 分 I=3 段，每段采样 J=5 个预算，用部署时的贪心分配器生成锚点计划，在这些计划诱导的激活上校准 μ，再对 J 组取平均得到 μ_i（GPTQ Hessian 平均是精确的；AWQ 是启发式）。
- **尾部惩罚**（Stage 3，p.7 Eq.5–6）：升级效率 e_ℓ(b) = (d̄_ℓ(b) − d̄_ℓ(b⁺)) / (P_ℓ(b⁺ − b))，再除以 1 + γ(b − b₀)，γ=10，使预算优先把模块从最低位宽拉起。
- **数据**：WikiText-2 train 随机 128 个窗口 × 2048 token（p.7）。
- **成本**：
  - 部署时贪心 O(L|B| log L)，可忽略；对照 ILP 在某些预算上要 "upwards of two hours"（p.11）。
  - **离线校准成本未报告**（无 GPU 时间、无前向次数）。【推断】Stage 1 需要对每个 (模块, 比特) 对做 K=10 次“上游随机量化 + 上游 μ 重校准 + 前向测 NMSE”；Llama-3.2-3B 有 28×7=196 个线性模块，× 6 比特 × 10 次 ≈ 1.2 万次上下文测量（若不同比特共享上下文可少于此），每次需要对上游重新跑 AWQ/GPTQ 校准，成本可能远超一次标准 GPTQ。Stage 2 需 15 次完整的“按计划量化 + 校准”。

## 4. 决策过程
- 把 min L(T(b, μ)) s.t. mem(b) ≤ M 用可加代理 Σ d̄_ℓ(b) 替代，写成多选背包 MCKP（p.5 Eq.2）。作者明确说：可加目标假设每个模块分数独立于计划其余部分，而 Stage 1 的边缘化“按定义”使之成立（p.5）。
- 求解：尾部惩罚贪心（Algorithm 1，p.7）——从全 3-bit 起，每步选惩罚后效率最高且放得下的升级。部署时查对应区间的 μ_i。

## 5. 关键结果
- 模型：Llama-3.2-3B、Llama-2-7B、Mistral-7B-v0.1；AWQ 与 GPTQ；评测 WikiText-2 word PPL + ARC-Challenge、PIQA、WinoGrande、MMLU 四大类（lm-eval-harness，p.8）。**有下游任务**。
- 基线（p.8）：四个“FP16 先验”打分 + 同一 ILP（Quant.Err.、KL Div、HAWQ-v2 [Hessian×量化误差]、Fisher）；以及 LIM、CoopQ 两个已有自适应方法（自带分配程序）。
- **Table 1（p.3）**：同一预算下 avg bitwidth 与质量不单调。Llama-3B ~1.25 GB：未加权平均 3.7 bit → PPL 17.1 / Acc 40.4；4.0 bit → 12.4 / 47.8；4.4 bit → 13.2 / 46.1。“位放在哪”比平均位宽重要。
- **Table 2（p.8，Llama-3.2-3B）**：1.25 GB 下 MixQuant AWQ PPL 10.70、Avg 55.6，最佳基线 HAWQ-v2 PPL 12.43 / Fisher Avg 48.5（+7.1 点）；GPTQ 11.19 / 54.0 vs HAWQ-v2 13.35 / 46.0（+8.0 点）（p.9 正文）。1.5 GB GPTQ 差距 9.1 点。1.75 GB：AWQ 59.0 vs Quant.Err. 56.7（+2.3）；GPTQ 58.9 vs Quant.Err. 56.0。
- **Table 3（p.9，Llama-2-7B）**：3.0 GB AWQ 48.8 vs Fisher 44.6（+4.2）；4.0 GB AWQ 52.1 vs 50.6（+1.5），GPTQ 51.7 vs 50.9（+0.8）（p.10 正文）。
- **Table 4（p.9，Mistral-7B）**：改进 2.1–3.7 点（p.9），如 4.0 GB AWQ 63.7 vs 61.6、GPTQ 64.0 vs 61.6。
- MixQuant 在所有 (模型, 预算, 技术) 单元格 Avg 与 PPL 均最优（p.8）。
- 【推断】预算对应的平均位宽：Llama-3.2-3B 线性权重约 2.8B 参数，1.25 GB ≈ 3.5–3.8 bit（与 Table 1 中 3.7–4.4 的未加权平均吻合）；Llama-2-7B 线性约 6.5B 参数，3.0 GB ≈ 3.7–4.0 bit，4.0 GB ≈ 4.9–5.3 bit。**即本文全部处于 ~3.5–5.3 bit 区间**，下限 3 bit。

## 6. 隔离各信号价值的消融
- **代理指标横向比较（同一 ILP，只换 FP16 上下文下的打分）**：Quant.Err.、KL、HAWQ-v2、Fisher 互有胜负，没有一种稳定最优。例：Llama-3.2-3B 1.25 GB AWQ：Avg 46.1 / 46.9 / 47.8 / 48.5；1.75 GB GPTQ：56.0 / 53.4 / 55.2 / 52.6（Quant.Err. 最好，KL 与 Fisher 最差）。Mistral 3.0 GB GPTQ Fisher 55.1 明显差于其他（57.1–57.8）。【推断】Hessian/Fisher 类“重要性”代理并不比简单的输出误差更好；纯 Fisher（只看重要性不看扰动大小）在 GPTQ 下常垫底。
- **Table 5 组件消融（p.10，Llama-3.2-3B 1.25 GB）**：
  - "Mem. budget"（无打分，只按模块大小填满预算的 ILP）：AWQ Avg 49.0、PPL 12.97；GPTQ 43.6、16.19。
  - "Greedy (rev.)"（反向排序）：40.3 / 37.1，崩溃。
  - "Stage1+Stage2+ILP"：55.6 / 55.3；MixQuant（贪心+尾惩罚）55.2 / 53.9，PPL 10.75 / 11.25（ILP 为 11.02 / 11.33）。
  - 【推断，重要】在 AWQ 1.25 GB 下，**不看任何敏感度、只按大小填预算的 Mem.budget（49.0）竟优于全部四个 FP16 先验打分 + ILP（46.1–48.5）**，以及 CoopQ（44.2）、LIM（40.4）。GPTQ 下 Mem.budget 43.6 与 KL/Fisher 持平、低于 HAWQ-v2 46.0。这说明在低预算下，FP16 上下文的孤立敏感度可能几乎不携带有用的排序信息。
- **缺失的关键消融**：没有“Stage 1 单独”（上下文边缘化表 + FP16 μ）vs “FP16 表 + FP16 μ”的对照，也没有“FP16 表 + Stage 2 μ”。因此 +7~8 点的提升**无法归因**到上下文条件化打分（交互）还是计划感知的 μ 重校准（更像是一种改进的量化器校准，类似 GPTQ 在已量化输入上顺序校准）。【推断】Stage 2 改变了量化后的权重本身，所以 MixQuant 与基线的差距混合了“分配”与“量化器质量”两个因素。
- **尾部惩罚 γ（Fig.4，p.11）**：相对 γ=0 的 PPL 变化很小（纵轴 0 到约 −3%），γ≈5 后饱和；且 Table 5 中贪心+尾惩罚并未超过无尾惩罚的 ILP 平均精度。
- 没有报告代理与真实精度的相关系数。

## 7. 关于可加性/交互的证据
- **上下文对敏感度的影响（Fig.2a，p.4）**：在 20 个随机量化上下文下，6 个代表性模块的 NMSE 与 KL 的相对跨度 (max−min)/min 达到**两到三个数量级**。注意：这是绝对数值跨度，不是跨模块排序的变化；作者没有报告 rank 相关。
- **上下文对分配的影响（Fig.2b，p.4）**：用 ILP 对每个上下文各解一次，逐线性层比特跨度 (max−min) 在所有内存界下都存在（图中最大到 5），即不同上下文给出不同分配。
- **结论性主张**：在 FP16 上下文下测得的逐层敏感度不代表真实全量化部署（p.2, p.6, p.11）；收益集中在低预算区间，预算接近最高均匀位宽时差距收敛（Llama-2-7B AWQ 4.2→1.5 点，GPTQ →0.8，p.10）。
- **非可加性的处理方式**：不是建模交互项，而是**把上游上下文当随机变量平均掉**（mean-field），保持可加 MCKP。作者另用尾部惩罚近似“低比特误差不可逆、向下游累积”的非可加效应（p.5, p.7）。
- 对 CoopQ 的第三方评测：在 B={3..8} 时 CoopQ 和 LIM 把分配推到 B 的两端（Fig.3，p.10），且在多数单元格不如 FP16 先验 + ILP（p.9–10）；作者解释为两者是在 {2,3,4} 这种窄集合上设计的。

## 8. 作者声明的局限
- 正文无独立 Limitations 节。提到：AWQ 参数平均是启发式（p.6）；ILP 太慢不适合自适应（p.11）；未来扩展到权重/激活/KV cache 联合分配（p.11）。
- 隐含承认：预算宽松时收益很小（p.10）。

## 9. 批判
- 【推断】最大问题是归因：Stage 2（在计划诱导的量化激活上重新校准 AWQ/GPTQ 参数）对所有基线都没有提供，基线都用 FP16 激活校准 μ。若把 Stage 2 也给基线，差距可能大幅缩小。论文没有做这个对照。
- 【推断】Fig.2a 只证明数值跨度大，NMSE 本身随上游误差累积而单调增大是平凡的；对分配有意义的是**跨模块相对排序**是否改变，Fig.2b 部分回答了（分配会变），但没给出“变了以后真实精度差多少”。
- 【推断】离线成本完全未报告，而 Stage 1 每个上下文都要重新校准上游 μ，可能很昂贵；"negligible deployment cost" 只指部署时贪心。
- 【推断】Table 2 中 FP16 先验方法在 1.25 GB 下 Avg 不如“只按大小填预算”，这让人怀疑基线实现或 ILP 目标的尺度（不同 bit 的 NMSE 是否可比）是否合理。
- 【推断】最低位宽 3、最高 8、激活 8-bit、模拟量化、内存不含 scale：与真实 2–4 bit 权重部署（GPTQ/AWQ group-128 kernel）不完全对应。
- 【推断】只评测 3B–7B 稠密模型；无 PPL 以外的长文本/生成类任务，但有 MMLU/ARC/PIQA/WinoGrande，比 CoopQ 好。

## 10. 对本项目（27B 自量化 agent 的工具/诊断设计）的启示
- **profile 工具应支持“上下文”参数**：profile(module, bits, quantizer, upstream_config) 而不只在 FP16 上游下测。最低成本做法：在 agent 当前候选配置（或若干随机配置）下测，而非全 FP16。
- **均场近似是便宜的折中**：如果给 agent 一张“上游随机量化平均后”的 (module, bits) 表，仍可用可加背包求解，不需要 pairwise 交互矩阵。但要注意成本：每个上下文都要重新校准上游 GPTQ/AWQ。
- **量化器校准输入的影响可能和分配一样大**：应允许 agent 选择“GPTQ Hessian / AWQ scale 用 FP16 激活还是已量化激活校准”，并作为可诊断项（这是本文未分离但可能起主要作用的因素）。
- **低预算时孤立敏感度可能比“按大小填”还差**：在 ~3.5 bit 平均预算下，agent 不应盲信 FP16 上下文的孤立 KL/NMSE/Hessian 指标；外部评测器的组合反馈更可靠。在 ~5 bit 预算下，各方法收敛（差 0.8–1.5 点），孤立 profile 足够。
- **代理指标横评**：输出 NMSE（Quant.Err.）、KL、HAWQ-v2（Hessian×误差）、Fisher 无稳定胜者；纯重要性（Fisher）不含扰动大小时偏差大——工具输出应是“该比特下的实际扰动后果”（ΔKL/NMSE），而非仅“重要性”。
- **尾部惩罚**：工具层面可提示 agent “避免把模块留在最低比特”，但实测增益 ≤3% PPL，属于次要启发式。
