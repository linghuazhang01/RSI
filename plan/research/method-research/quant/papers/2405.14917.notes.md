# SliM-LLM 阅读笔记（arXiv 2405.14917）

## 1. 元信息

- 作者：Wei Huang, Haotong Qin, Yangdong Liu, Yawei Li, Qinshuo Liu, Xianglong Liu, Luca Benini, Michele Magno, Shiming Zhang, Xiaojuan Qi
- 机构：香港大学、ETH Zürich、北京航空航天大学

- 读的范围：p.1–p.21 全文（正文 p.1–8，附录 A–K p.12–21；参考文献 p.9–11 略读）
- 代码：github.com/Aaronhuang-778/SliM-LLM

## 2. 做的是什么决策
- **层内、组级（group-wise）比特分配**：每个线性层的权重按输入通道切成连续的列块（group size β=128，Algorithm 1 中 `w[:, b:b+β]`，即一个"组"是整列块、跨所有输出行），每个组分配 {N−1, N, N+1} 比特之一（2-bit 目标时为 {1,2,3}，3-bit 目标时为 {2,3,4}）。
- **约束**：每层平均比特严格等于目标 N（|G_{N−1}| = |G_{N+1}|，"补偿约束"，Eq.4，p.5）。所以**不做跨层/跨模块分配**，每层平均比特一样，只是层内重新分配。
- **量化器参数校准**（SQC）：每组的 scale/zero 通过对一个缩放因子 τ 做网格搜索来确定。
- 不决定量化器类型（主线固定为 GPTQ 骨干；SliM-LLM+ 用 OmniQuant 骨干）、不决定 group size（固定 128，附录 F 有消融）、不决定校准数据（固定 WikiText2）。

## 3. 驱动决策的信息
### 3.1 元素显著性（salience）
- 定义 3.1（p.4，沿用 SparseGPT/OBS 思路）：δ_ij = w_ij² / [H⁻¹]_jj²，其中 H = (1/P) Σ_k x^[k]ᵀ x^[k] 是层重建问题的代理 Hessian（Levenberg-Marquardt 近似，即 2XᵀX 型），H⁻¹ 由 Cholesky 求得。注意论文写的是分母**平方**（与 SparseGPT 的 w²/[H⁻¹]_jj 不同）。
- 附录 G.1（p.16，Eq.8）进一步只保留对角近似：δ_ij ≈ (w_ij · ||x_j||₂²)²，即"权重幅值 × 输入第 j 通道激活二范数平方"的平方。也就是说它本质上是**一个 AWQ/Wanda 型的激活×权重显著性**，主导因素是激活离群通道（定理 1，p.4）。
- 组显著性 = 组内 δ 的平均（Algorithm 2 第 6 行，p.13）。按组显著性排序。

### 3.2 分配目标（SBA 的 KL）
- 目标（Eq.4，p.5）：argmin D_KL( x wᵀ || x (ŵ_sba)ᵀ )，x 为该层的校准输入激活，比较**该层**原始输出与混合精度量化后输出。
- KL 的具体形式（附录 D，p.14）：先对层输出做 softmax 变成概率分布再算 KL。不是模型最终 logits 的 KL，而是**逐层线性输出**的 KL（正文 p.5 有一处说"block outputs"，但算法与附录均写的是线性层输出 x wᵀ）。
- 搜索时 ŵ 用 `fakequant`（Eq.1 的 min-max RTN 量化，Algorithm 2 第 8–10 行），**不是**最终使用的 GPTQ+SQC 量化结果。
- 数据：从 WikiText2 随机取 128 条、每条 2048 token 作为校准集（p.6）。
- 成本：每层搜索次数为 m/(2β)；LLaMA-7B（m=4096, β=128）只需 16 次迭代（p.5）。每次迭代 = 对整层做一次 RTN 假量化 + 一次层前向 x ŵᵀ + 一次 softmax-KL。无反向传播，单张 A800 完成（p.6）。**论文没有报告端到端量化耗时或 GPU 小时**（grep 无 minute/hour）。

### 3.3 SQC（显著性加权量化器校准）
- 掩码：组内用 3-σ 规则选"显著部分"（w < μ−3σ 或 w > μ+3σ），约占 1% 元素（p.6）。文中写的是对 w 取 3σ，未说明是否对 δ 取，存在歧义。
- 损失（Eq.5）：||w_s − ŵ_s(τ)||² + ||w_us − ŵ_us(τ)||²，τ 在 [1−λ, 1+λ] 上均匀取 2n 个候选，λ=0.1, n=50（即 100 个候选），显著/非显著部分共享同一 (s,z)。
- 成本：每组 100 次假量化 + 误差计算，纯权重空间，无需激活。

## 4. 决策过程
- **SBA**：闭式排序 + 一维搜索（"双指针"）。按组显著性排序后，令 p 从 1 到 m/(2β)：最低显著的 p 个组 → N−1 比特，最高显著的 p 个组 → N+1 比特，其余 → N 比特；对每个 p 计算层输出 KL，取最小的 p*（Algorithm 2，p.13；附录 C 搜索曲线，Fig.7 p.15）。搜索空间只有 1 个自由度（p），排序本身由显著性决定，KL 只决定"混合比例"。
- **SQC**：对每组做 τ 的网格搜索，最小化 Eq.5。
- 然后进入 GPTQ 逐列块量化与误差补偿（Algorithm 1 第 10–12 行）。
- SliM-LLM+：SBA 不变，去掉 SQC，换成 OmniQuant 的可学习截断（LWC），梯度优化（附录 B.1，p.12）。

## 5. 关键结果
- **2-bit LLaMA，WikiText2 PPL（Tab.1，p.7）**：LLaMA-7B GPTQ 152.31 → SliM-LLM 14.58；LLaMA-13B 20.44 → 8.87；LLaMA-2-7B 60.45 → 16.01；LLaMA-2-13B 28.14 → 9.41；LLaMA-3-8B 210.00 → 39.66；LLaMA-65B 9.51 → 5.90。同表 QuIP 7B 29.74、PB-LLM 24.61。
- **3-bit（Tab.1，p.7）**：提升小得多：LLaMA-7B GPTQ 6.55 → 6.40，AWQ 6.46；LLaMA-2-7B 6.29 → 6.24（与 AWQ 持平）；LLaMA-3-8B 8.19 → 7.16。
- **4-bit（Tab.12，p.20）**：几乎无差别，LLaMA-7B GPTQ 5.85 / AWQ 5.81 / SliM-LLM 5.83（AWQ 反而更好）。
- **梯度量化器版本（Tab.2，p.7）**：2-bit LLaMA-7B OmniQuant 9.72 vs SliM-LLM+ 9.68；LLaMA-2-7B 11.06 vs 10.87；增益很小。
- **零样本（Tab.3，p.8）**：2-bit LLaMA-7B 六任务平均 GPTQ 39.65 → SliM-LLM 43.84；OmniQuant 49.11 → SliM-LLM+ 51.02。LLaMA-65B GPTQ 64.70 → 65.26。
- **MMLU/MathQA（Tab.13，p.20）**：2-bit 模型 MMLU 都在 23–27%（接近随机 25%），差异无实际意义。
- **其他模型（Tab.11，p.19）**：2-bit Gemma2-9B GPTQ 186.77 → 26.30；Mixtral 8x7B 16.38 → 7.44。
- **部署（Tab.5，p.8）**：2-bit LLaMA-7B 权重内存 2.2G → 2.3G，吞吐 83.9 → 61.2 token/s（约慢 27%）；3-bit 83.4 → 79.1。需要额外存储每组 2-bit 的比特宽度数组（附录 B.2，p.12）。

## 6. 隔离各信号价值的消融
- **分配准则（Fig.5a，p.7，OPT 1.3B–30B，2-bit）**：GPTQ（均匀）vs 随机选高/低比特组 vs head-tail（按空间顺序）vs SBA。文字结论：随机和 head-tail 无效甚至退化，SBA 一致显著改进。**只有图，无数值表**，从图看 y 轴为对数 10–80。这说明"有混合精度"本身不够，**排序信号**（显著性）才是收益来源。
- **SBA vs SQC（Fig.5b，p.7）**：二者各自都有提升，合用最好；同样只有图。
- **SBA vs ILP（HAWQ-v2 式）（Tab.4，p.8，LLaMA 2-bit WikiText2）**：ILP 17.55 / 9.51 / 9.27 / 7.46 vs SBA 14.58 / 8.87 / 7.33 / 5.90（7B/13B/30B/65B）。论文未详细说明 ILP 的目标函数和敏感度信号，只说 ILP 在 {1,2,3} 空间也得到等量 1/3-bit 组。
- **KL vs MSE 作为搜索目标（Tab.6，p.15，2-bit）**：MSE 32.50/27.58/15.14/13.28/21.94/16.86 vs KL 30.71/13.26/11.27/10.12/14.58/16.01（OPT-1.3B/2.7B/6.7B/13B、LLaMA-7B、LLaMA-2-7B）。KL 在 LLaMA-7B 上 21.94→14.58、OPT-2.7B 27.58→13.26 差异很大，LLaMA-2-7B 只差 0.85。
- **group size（Tab.7，p.15）**：3-bit 下 512/256/128 变化不大（LLaMA-7B 6.96/6.92/6.40）；2-bit 下更小组显著更好（LLaMA-3-8B 128: 39.66 → 32: 16.93）。
- **SQC 权重误差（Fig.8，p.16）**：OPT-1.3B 某通道平均绝对误差 0.0055 → 0.0039。
- **缺失的消融**：没有"换显著性定义"（如纯 |w|、纯激活范数、Fisher）的对比；没有把 SBA 的 KL 换成端到端 KL 或 PPL 的对比；没有跨层分配的对比；随机/head-tail 无数值。

## 7. 关于可加性/交互的证据
- 每层独立搜索、每层平均比特固定，因此**完全回避了跨层可加性问题**；也没有任何"单层测量能否预测整模型"的实验。
- 搜索阶段用 RTN 假量化估计 KL，但最终用 GPTQ（带误差补偿）+ SQC 量化；论文假设 RTN 下的最优比例在 GPTQ 下依然最优，**未验证**。
- 附录 C（p.13–14）指出一层内常存在多个低误差的比例组合（KL 曲线不是尖峰），暗示局部最优不唯一。
- SBA 与 SQC 在 Fig.5b 中合用优于单用，但无数值说明是否近似可加。

## 8. 作者声明的局限
- 现有部署工具对混合精度计算支持不足，GPU 上 1/2/3-bit 推理支持有限，影响低比特模型的推理优势（附录 A，p.12）。
- 1-bit 操作缺乏硬件支持，带来额外存储和计算开销（p.8）。

## 9. 批判
- 【推断】"显著性"在对角近似下退化为 (|w|·||x_j||²)²，和 AWQ 的激活感知准则高度同源；论文的创新主要是"按列块排序 + 每层守恒的 ±1 比特"而不是信号本身。
- 【推断】Eq.5 的 SQC 损失只是把显著和非显著误差**等权相加**，数学上等于整组 MSE；所谓"显著性加权"并没有在公式中体现权重系数，其收益更可能来自 τ 网格搜索（相当于截断/缩放搜索）。
- 【推断】增益集中在 2-bit 且主要相对于 GPTQ 2-bit 崩溃的基线（152.31）；3-bit/4-bit 增益很小甚至不如 AWQ（4-bit LLaMA-7B）。2-bit 的绝对 PPL（LLaMA-7B 14.58、LLaMA-3-8B 39.66）仍远离可用。
- 【推断】附录表格有可疑数字：Tab.9（p.19）3-bit LLaMA-7B C4 6.14、LLaMA-2-13B C4 5.26 低于 FP16（7.08、6.46），后者与 WikiText2 数值相同，疑为抄写错误；Tab.14（p.20）2-bit LLaMA-2-70B SliM-LLM 权重内存 23.5G 而运行内存 4.4G，自相矛盾，且 23.5G 远大于 GPTQ 的 16.4G。Algorithm 2 第 11 行写成 ŵ_l ∪ ŵ_l ∪ ŵ_h（应含 ŵ_N）。
- 【推断】Fig.5 的关键消融（随机 vs 排序）只有对数坐标图、只在 OPT 上做，没有 LLaMA 数值，证据强度有限。
- 【推断】KL 是对单层线性输出做 softmax 后再算，这个 softmax 在物理上没有意义（线性层输出不是概率），更像是一种归一化的分布对齐度量；它比 MSE 好的原因论文只给了"信息熵"直觉。
- 【推断】部署吞吐下降 27%（2-bit 7B），"与均匀量化效率匹配"的说法偏乐观。

## 10. 对本项目（27B 自量化 agent 的工具/诊断设计）的启示
- **排序信号比"是否混合精度"更关键**：随机分配 ±1 比特无效甚至有害（Fig.5a），所以给 agent 的工具必须提供有效的排序信号，而不是只让它随意调比特。
- 组级显著性 ≈ (|w|·激活通道范数)² 只需一次校准前向即可算出，成本极低，适合作为 `profile_salience(module)` 类廉价诊断；但它只用于**层内**排序，不能直接比较不同层。
- **KL 优于 MSE 作为分配目标**（Tab.6），与本项目 `profile(module,bits,quantizer) → KL 增量` 的设计方向一致；但 SliM-LLM 的 KL 是逐层线性输出 softmax-KL，不是最终 logits KL，后者在本项目更有意义且需验证。
- 搜索时用 RTN 估计、最终用 GPTQ 量化存在代理偏差；本项目如果 profile 工具用 RTN 估计而最终选 GPTQ/AWQ，需要显式告诉 agent 或提供"按量化器"的 profile。
- 层内 ±1 比特守恒 + 一维搜索非常廉价（7B 每层 16 次），可以作为 agent 的一个"层内微调"子动作；跨层预算分配仍需其他信号（本文不提供）。
- 2-bit 下 group size 影响巨大（Tab.7），group size 应作为 agent 的一级旋钮，并配合存储开销计算。
