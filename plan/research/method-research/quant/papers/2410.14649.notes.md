# EvoPress（arXiv 2410.14649）阅读笔记

## 1. 元信息
- 标题：EvoPress: Accurate Dynamic Model Compression via Evolutionary Search
- 作者：Oliver Sieberling, Denis Kuznedelev, Eldar Kurtic, Dan Alistarh
- 机构：ETH Zürich；Yandex Research；IST Austria；Red Hat AI
- 版本：arXiv 2410.14649v2（2025-07-01），ICML 2025（PMLR 267）（p.1）
- 读的页范围：p.1–p.35 全文（正文 p.1–9，参考文献 p.9–12，附录 A 收敛证明 p.13–18，附录 B–G 消融/设置/补充结果 p.19–35）。附录 A 的漂移分析证明只略读结论。

## 2. 做的是什么决策
- 统一框架：给定"层级数据库"（每个单元独立压缩到若干档），为每个单元选一档，使总大小 ≤ 预算，最小化与原模型的输出差异（p.3–4）。
- 三种应用：
  - 深度剪枝：每个 attention / MLP 模块"保留或删除"，只允许同类型模块之间交换（p.6）。
  - 非均匀非结构化稀疏：每个线性层一个稀疏度档，相邻档相差固定 1M 权重（p.7）。
  - **非均匀量化**：每个线性层（q/k/v/o/up/gate/down）一个比特宽度，候选 2/3/4/5/6 bit，由 GPTQ（group size 128）生成；档间相差整数 1 bit；只允许**参数量相同的投影之间**交换比特（p.8）。
- 粒度：逐线性层（per-projection per-block）。不决定量化器种类、group size、校准数据（这些固定：GPTQ、g=128、Fineweb-Edu 8M token）（p.6, p.8）。
- 另有受限版本：只允许 vLLM 支持的 4/8 bit，且 qkv、up/gate 同块内同比特（Fig.4, p.8）。

## 3. 驱动决策的信息
- **信号：拼接模型与原模型之间的 KL 散度** D_KL(P_M ‖ Q_M̂)，在校准 token 上计算；fitness = KL 越低越好（p.4）。也就是说，信号是**整模型端到端**测出来的，不是逐层分数的和。
- 作者称约 64K token（Llama-3-8B 下约 8 条完整序列）就足以可靠判定压缩模型质量（p.4, 行 264）。
- **多步选择**（每代）：先用少量 token 评估全部 λ 个子代，挑出少数进入下一轮，下一轮用更多 token；最后一轮把父代加入（精英保留），用一个"完整"minibatch 比较，其 token 数约为第一轮的 20–50 倍（p.4）。
- 量化超参（Table 8, p.22）：150 代；每代 128 个子代；第 1 轮 2048 token → 留 16；第 2 轮 16384 token → 留 4；第 3 轮 131072 token → 留 1。
  - 深度剪枝：k(n−k)/1.5 代，32 子代，两轮 2048 token（留 2）/ 32768 token（留 1）；稀疏：400 代，64 子代，2048/16384/65536；"super-fast"：400 代，16 子代，512→8192 两轮。
  - 【推断】按 Table 8 计算，量化每代前向约 128×2048 + 16×16384 + 5×131072 ≈ 1.18M token，150 代约 1.8 亿 token 前向；论文没有直接给出这个总数。
- 层级数据库成本：每层×每档各做一次 GPTQ（校准 8M token Fineweb-Edu）（p.6）。数据库构建时间论文未单独报告。
- 突变：每次随机改变 min(randint(1,3), randint(1,3)) 个单元的档位，保持总压缩率不变（p.6）。
- 时间成本：
  - 量化：大部分提升在 2 GPU 小时内完成，完全收敛约 8 GPU 小时（RTX 3090，Llama-3.1-8B 2.25 bit / Llama-3-8B 3 bit，Fig.14, p.32）。
  - 稀疏：5–6 小时收敛；super-fast 版本略多于 1 GPU 小时（Fig.3, p.7–8）。
  - 深度剪枝：数分钟内超过基线，约半小时完全收敛（D.2, p.27）；带早停的运行时间在 31–58 分钟，10.0M–19.7M token 前向（Table 17, p.34）。
- 对比用的 DP 基线信号：逐层 NMSE = ‖Ŷ − Y‖²/‖Y‖²（层输出相对误差），求和后用 DP 求解，类似 SPDY 但省掉其昂贵的第二阶段随机搜索（p.8）。

## 4. 决策过程
- (1+λ) 进化算法（精英保留，单个体，无交叉）+ level-switch 突变（一个单元升一档、另一个步长匹配的单元降一档）+ 多步选择（Algorithm 1, p.4）。
- 初始化：目标档恰好存在时用均匀配置；目标处在两档之间（如 2.5 bit）时随机采样约 32 个配置，用少量样本挑最好的（p.5）。
- 理论：对 ‖x‖₁ = n−k 约束下的任意线性 fitness，期望 O(k(n−k)/λ) 代收敛（Theorem 3.1, p.5）。作者的论证是：既有基于"可加"的方法部分有效，说明 fitness 地形近似线性、平滑，适合局部爬山（p.2）。
- 早停（App. G）：训练集困惑度 20 代没有改善就停（p.33）。

## 5. 关键结果
- **反单调性的例子（Table 1, p.2）**：Llama-3-8B 深度剪枝。Dense 的 Wiki2/C4/FW 为 5.54/8.80/7.72；一种配置为 188.01/147.25/70.46，另一种为 24.39/35.53/26.24。按标题，"删掉严格更多的块"的那一种困惑度反而更低。配置本身是图示（橙色块），文本抽取看不到具体删了哪些块；【推断】24.39 那行删得更多。
- **量化 3 bit（Table 3, p.8）**，Wiki2 / C4 / 零样本平均：
  - Mistral-7B-v0.3：Uniform 5.54/8.57/66.3；DP 5.79/8.84/66.0；EvoPress 5.21/8.42/67.1
  - Llama-3-8B：Uniform 12.19/15.76/60.2；**DP 29.00/20.03/61.3**；EvoPress 7.49/12.03/64.3
  - Phi-3-Medium-14B：Uniform 5.18/9.05/70.0；DP 5.72/9.71/69.1；EvoPress 5.09/9.00/70.8
  - 要点：在三个模型上，**基于 NMSE 可加性的 DP 的困惑度都比均匀分配更差**；EvoPress 都最好。Llama-3-8B 零样本平均比均匀高 4.1。
- **2.25 / 2.5 bit（Table 16, p.32）**：基线是"随机 32 个 2/3 bit 混合配置取最好"。例如 Llama-3-8B 2.25 bit：Best-of-32 为 149.85/432.96，均值 36.8；EvoPress 为 23.93/43.17，均值 46.0。Llama-3.1-8B 2.5 bit：35.33 → 11.73（Wiki2）。
- vLLM 受限 4/8 bit 搜索也优于均匀（Fig.4, p.8，只有图）。
- 稀疏 70%（Table 2, p.7）：Llama-3-8B Uniform 85.84 / OWL 48.07 / EvoPress 28.76（Wiki2）。50% 和 60% 下也优于 OWL（Tables 14–15, p.30–31），但 50% 下差距很小（如 Mistral 均值 65.1/65.0/65.9）。
- 深度剪枝：所有基于打分的方法在约 31.25% 以上的剪枝率下崩溃；EvoPress 在删掉一半时仍可用（Fig.2, p.6；Tables 9–12, p.24–26）。
- 量化配置（Fig.15–16, p.33）：整体比较均匀；第 2 块和最后两块拿的比特更多；**第 1 块被压得最狠**（与稀疏相反，稀疏时第 1 块最不压）；v_proj 获得更多比特。作者据此认为"saliency"依赖压缩方法本身（p.9, p.32–33）。
- 种子鲁棒性（C.2, p.22）：16 个种子，Llama-3-8B 70% 稀疏，C4 均值 33.82，标准差 0.61（OWL 为 52.32）。

## 6. 隔离各信号价值的消融
- **KL 与 PPL 作 fitness（Table 7, p.21；Fig.5）**：量化下 KL 略好或持平。Llama-3-8B 3 bit：PPL-fitness 8.17/12.15/9.64，KL-fitness 7.49/12.03/9.56；4 bit 下两者几乎相同（5.86/9.46 与 5.86/9.44）。稀疏下两者相当。作者解释：KL 用了整个分布，PPL 只用真实 token；PPL 的好处是不用存 logits，省内存（p.20–21）。
- **端到端搜索 vs 逐层 NMSE + DP**：Table 3 是事实上的"信号消融"。逐层输出 NMSE 求和这个代理在 3 bit 下排序很差，Llama-3-8B 的 Wiki2 从均匀的 12.19 变成 29.00。
- **打分代理与真实 PPL 的相关性（App. D.4, Fig.10–11, p.28–29）**：Llama-3-8B 随机删块，131,072 token Fineweb-Edu。
  - 删 2/4/6 块时，"逐块单独删除的平均 PPL"能很好预测删掉整组后的 PPL。
  - 删 8/10/12 块时，平均余弦相似度和平方误差（含归一化版本）与最终 PPL 的相关性明显退化。
  - 未归一化的平方误差甚至出现负相关，因为激活范数随深度增长；归一化后才与余弦相当。
- 多步选择 token 数（Table 5, p.20）：第 1 轮 64–1024 token 对结果影响不大（Wiki2 15.87–17.25），C4/FW 随 token 减少而单调变差（C4 17.93 → 19.35）。
- 子代数（Table 6）：4 个子代明显变差，8–64 个相近。
- 突变率（Table 4, p.20）：恒定 1 次突变与 min(U(1,3),U(1,3)) 相当；恒定 15 次突变明显变差（Wiki2 27.01 vs 17.52）。

## 7. 关于可加性/交互的证据
- 核心论点："误差单调性"（逐层误差之和更低 ⇒ 整模型误差更低）一般不成立（p.1）。证据是 Table 1 的深度剪枝反例。
- 成立范围：作者明确说单调性在小压缩量下成立，到中等压缩率迅速衰减（D.4, p.28）；对量化，作者说线性/单调假设在高压缩区间（如低于 3 bit/参数）尤其不成立（p.3, 行 162）。
- 量化上的直接证据是间接的：没有像深度剪枝那样画"逐层分数和 vs 实际"的散点图，只有 Table 3 里 NMSE-DP 不如均匀。
- 方法内部的矛盾式立场：反对严格可加，又用"fitness 近似线性"来论证爬山有效（p.2, p.5）。【推断】更准确的说法是：局部近似可加（相邻配置的差异可预测），但全局排序不可加，因此需要端到端评估来纠正。
- 量化 fitness 地形不如稀疏平滑：档位少（实际只用 2/3/4 bit）、步长大，所以用了更多 token（p.22, p.32）。

## 8. 作者声明的局限
- 没有把不同压缩方法放进同一搜索空间（如量化 + 剪枝），也没有做更细粒度的结构化剪枝（p.9）。
- 深度剪枝中 attention 与 MLP 的删除数量被强制相等，放开这个约束留作未来工作（p.6）。
- 运行时间与数据量可以互相交换，因此跨方法比较运行时间很难（p.33）。
- 量化收敛不如稀疏平滑（p.32）。
- 低突变率有陷入局部最优的风险，但作者认为地形平滑，问题不大（p.19）。

## 9. 批判
- Table 1 是**深度剪枝**的反例，不是量化。量化上的"非可加"只由 DP-NMSE 输给均匀来间接支持。DP 输掉也可能是因为 NMSE 这个逐层指标本身差（没有考虑层对输出的敏感度权重），而不一定是可加性本身不成立。【推断】这两个因素在论文中没有分开：缺少"敏感度加权逐层误差（如 KL 或 Fisher 加权）+ DP"这一基线。
- DP 基线是作者自己实现的"简化 SPDY"，省掉了 SPDY 的第二阶段搜索（p.8），可能弱化了基线。
- 量化只用 GPTQ 生成的档；没有比较 AWQ/RTN 或 group size，也没有校准源的选择。
- 2.25/2.5 bit 的基线是"32 个随机配置取最好"，偏弱；没有和 HAWQ/ILP 类方法或 HIGGS 式线性模型比较。
- 搜索 fitness 用 Fineweb-Edu 校准 KL，评测用 Wiki2/C4/零样本；没有报告 fitness 与下游任务的分歧（如 Table 3 中 Llama-3-8B 的 DP PPL 更差但零样本均值更高，61.3 vs 60.2，说明 PPL 与任务精度并不总是同向）。
- 所有模型都 ≤14B；8 GPU 小时这个数字是 8B 规模的。【推断】27B 模型每次评估约 3 倍代价，且需要多卡存放档位数据库。
- 用户问到的 "ShearedLlama" 不在本文中；本文比较的是 ShortenedLlama（Kim et al., 2024）、ShortGPT、Weight Subcloning、滑窗余弦、SLEB、BlockPruner、OWL、BESA、DP(NMSE)。OWL 没有用于量化比较，因为 OWL 原作者发现它在量化上不如均匀（p.8）。

## 10. 对本项目（27B 自量化 agent）的启示
- **工具设计**：profile(module, bits, quantizer) → 单模块 KL 增量很便宜，但 EvoPress 的证据表明，单独测得的逐层增量求和在低比特（≤3 bit）区间可能严重误排。agent 必须还能调用 **evaluate_config(全配置) → 端到端 KL**，作为组合配置的仲裁。
- **信号**：端到端 KL 优于端到端 PPL（低比特下差距明显，4 bit 下相同），64K–131K token 量级已够区分候选。可以提供多保真度接口：低 token（2K）粗筛 → 高 token（131K）精评，与 EvoPress 的多步选择对应。
- **搜索方式**：局部、小步、保持预算不变的交换（一个模块 +1 bit、同尺寸模块 −1 bit）就已足够有效。agent 的动作空间可以设计成"成对交换"，并提供每步的 KL 变化。
- **先验**：模型首块被压得最狠，v_proj 获得更多比特，末两块更多比特（Llama-3.1-8B, 3 bit）。这些可以作为初始化提示，但作者强调这依赖压缩方法，不能直接迁移。
- **数据库**：需要预先构建每模块 × {2,3,4,8} × {GPTQ/AWQ/RTN} 的量化变体，且必须彼此独立地量化，否则拼接时会掉点（p.4）；【推断】这意味着 GPTQ 不能用前序层已量化的输入来顺序校准，或至少要检查拼接误差。
- **代价预估**：8B 模型约 8 GPU 小时（3090）收敛；27B 需要相应放大，最好结合 HIGGS 式线性模型做初始化，再用少量端到端 KL 评估修正。
