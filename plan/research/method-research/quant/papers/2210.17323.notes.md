# GPTQ: Accurate Post-Training Quantization for Generative Pre-trained Transformers — 阅读笔记

## 1. 元信息
- 标题：GPTQ: Accurate Post-Training Quantization for Generative Pre-trained Transformers
- 作者：Elias Frantar, Saleh Ashkboos, Torsten Hoefler, Dan Alistarh
- 机构：IST Austria、ETH Zurich、NeuralMagic（p.1）
- arXiv：2210.17323v2，2023-03-22（p.1 页眉）
- 会议：ICLR 2023（p.1）
- 读的页：p.1–p.9 正文，p.10 伦理/复现声明，p.13–p.16 附录 A（OBQ 对比、评测与计时细节、PTB/C4 困惑度、零样本表）；p.10–p.12 参考文献扫读。

## 2. 做的是什么决策
- **决策对象**：给定量化网格（比特数、逐行或逐组的非对称 min-max 网格），对每个线性层决定**每个权重量化到哪个网格点**，并**用剩余未量化权重补偿已产生的误差**（权重本身被改写，不只是取整）。
- **不决定**：比特数、group size、逐层比特分配、量化器选择——全部外部给定（全文所有层同比特；分组只作为"额外技巧"展示，p.9）。
- **粒度**：逐层（每个 Transformer block 含 6 个线性层，p.6），层内逐列（按列顺序），以 B=128 列为一个懒更新块（p.5）。

## 3. 驱动决策的信息
### 3.1 统计量：层输入二阶矩 / 层 Hessian
- 逐层目标（Eq.1，p.3）：`argmin_Ŵ || W·X − Ŵ·X ||²_2`，X 为 m 个校准样本经过网络后的该层输入。
- 该二次目标的 Hessian：`H_F = 2·X_F·X_F^T`（F 为尚未量化的权重集合，p.4）。H **只依赖层输入，不依赖权重**，因此所有输出行共享同一个 H 和 H^-1——这是 GPTQ 能把 OBQ 加速的关键（p.4）。
- OBQ 的单权重更新（Eq.2，p.4）：误差 `(quant(w_q) − w_q)² / [H_F^-1]_qq`；其余权重补偿 `δ_F = −(w_q − quant(w_q)) / [H_F^-1]_qq · (H_F^-1)_{:,q}`。逐块版本见 Eq.4–5（p.5）。
- 解读：`[H^-1]_qq` 越小，量化该权重造成的输出误差越大；补偿方向由 H^-1 的列（输入通道间的相关性）给出。相比 AWQ 只看对角的一阶幅值，GPTQ 用了**完整的输入协方差（含交叉项）**。

### 3.2 阻尼（damping）
- 对 H 的对角线加 λ，**λ 取对角线平均值的 1%**（p.5）；Algorithm 1 中写作 `H^-1 = (2XX^T + λI)^-1`（p.5）。
- 原因：大模型上反复块更新会累积数值误差，H^-1 变得不定，导致权重被朝错误方向大幅更新；"几乎必然"在几十亿参数以上模型的少数层出现（p.5）。小模型阻尼就够，大模型还需 Cholesky 重写（§3.4）。
- 论文**没有** λ 取值的消融。

### 3.3 校准数据
- **128 条随机 2048-token 片段，来自 C4**（≈26.2 万 token），代表通用网页文本；不使用任何任务数据（p.6）。
- C4 困惑度结果（Table 11/12，p.14）作者自己注明"不完全零样本"，因为校准来自 C4 训练集。
- 论文**没有**校准样本数或校准领域的消融（全文无此类实验）。校准敏感性证据只能从 AWQ 论文 Figure 8 获得（见 2306.00978 笔记）。

### 3.4 计算方式与成本
- Step 1 任意顺序（p.4）：OBQ 按贪心误差顺序逐个量化；作者发现在大层上**任意固定顺序**与贪心顺序差别很小，于是所有行按同一列顺序量化。复杂度从 `O(d_row·d_col³)` 降到 `O(max{d_row·d_col², d_col³})`。
- Step 2 懒批更新（p.4–p.5）：每次处理 B=128 列，块内完成后再全局更新，解决访存瓶颈，"大模型上约一个数量级加速"。
- Step 3 Cholesky 重写（p.5）：一次性用 Cholesky 分解预计算 H^-1 所需的行，配合轻度阻尼，数值稳定。
- 顺序量化（p.6）：每次加载一个 Transformer block 到 GPU，累积各层 Hessian 后量化；再把当前输入送过**已量化**的 block 得到下一 block 的输入——即后续层看到的是前面量化误差传播后的激活，作者称有"明显改进、几乎零额外成本"（无数值）。
- 前向次数：【推断】每个 block 对校准集前向两次（一次 FP 收集 X、一次量化后产生下一层输入），无反向传播。
- **运行时间 Table 2（p.7）**，单张 A100 80GB，完整量化：OPT-13B 20.9 分钟、OPT-30B 44.9 分钟、OPT-66B 1.6 小时、OPT-175B 4.2 小时；BLOOM-1.7B 2.9 分钟、3B 5.2 分钟、7.1B 10.0 分钟、176B 3.8 小时。对照：ZeroQuant-LKD 对 1.3B 模型需约 3 小时（p.6）。小模型（ResNet、BERT 等）上 GPTQ < 1 分钟，OBQ ≈ 1 小时（p.6）。
- 显存：每层需 d_col×d_col 的 Hessian；【推断】27B 量级模型 FFN down_proj 的 d_col 较大，H 可达数亿元素，仍可在单卡完成。

### 3.5 关于 act-order（按激活排序）
- **本论文（v2）正文与附录中没有 act-order / 重排序的内容**（grep "reorder/act-order/permut" 零结果）。论文只讲"任意顺序即可"（p.4）。
- 按 H 对角线降序量化（俗称 act-order / desc_act）是后来代码库加入的技巧；AWQ 论文中的 "GPTQ-R（reorder）" 即指此（AWQ p.7）。AWQ Table 4 显示：LLaMA-7B INT3-g128 下 GPTQ 8.81 → GPTQ-R 6.53（RTN 7.01），说明在某些模型上**列顺序很关键**，与本文"顺序不重要"的说法相矛盾——本文的结论只在 OPT/BLOOM 上验证。

## 4. 决策过程
- 闭式的**顺序贪心 + 二阶误差补偿**：按列顺序，对每列取最近网格点（RTN 式取整），然后用 H^-1 把该列误差闭式地分摊到后续未量化列。没有搜索、没有超参数优化（除 λ、B 固定）。
- 分组时，组的 scale/zero 在量化到该组时用**已被补偿更新过的权重**计算（p.8），所以分组与误差补偿配合良好。
- 不涉及跨层比特分配。

## 6. 隔离各信号价值的消融
1. **二阶补偿 vs 直接取整**：所有 Table 3/4/5 中 GPTQ 与 RTN 使用**完全相同的逐行非对称网格**（p.6），因此差异全部来自"用 H 做误差补偿"。这是 Hessian 统计量价值的直接证据：4bit 时价值随模型变大而减小（OPT-175B 只差 2.2→0.03 的部分，BLOOM 更小），3bit 时决定成败。
2. **贪心顺序 vs 任意顺序**：Table 8 显示 GPTQ（固定顺序）不逊于 OBQ（贪心），3bit 甚至更好（p.13）。但只在小模型上比较。
3. **group size**：
   - 3bit，175B（Table 5，p.8；p.7 文字）：g1024（≈0.02 额外比特/权重）平均改善约 0.2 PPL，g128（≈0.15 额外比特）再改善约 0.1，距 FP16 仅 0.1–0.3。
   - 4bit，中等模型 OPT-1.3B–30B（Figure 4，p.9）：分组"显著减少"精度损失（数值仅以图呈现，文本抽取不可读）。
   - 2bit（Table 7，p.9）WikiText2：OPT-175B FP16 8.34，g128 9.58，g64 9.18，g32 8.94，（对照：3bit 无分组 8.68）；BLOOM-176B 8.11 / 9.55 / 9.17 / 8.83（3bit 8.64）。≈2.2bit（g128）增加 <1.5 PPL，≈2.6bit（g32）增加 0.6–0.7。g8 三值量化 OPT-175B 9.20（p.9）。
4. **顺序量化（用已量化前缀的激活）vs 用 FP 激活**：只有文字描述"明显改进"，无数值（p.6）。
5. **阻尼 λ、块大小 B、校准样本数、校准领域**：**均无消融**。

## 7. 关于可加性/交互的证据
- 没有逐层敏感度组合实验，所有层同比特。
- 结构上的交互：顺序量化让后层的 Hessian 基于前层已量化后的激活计算，从而部分吸收前层误差（p.6）——【推断】这意味着单层独立测得的敏感度与"按顺序量化后的实际误差"可能不同，逐层 profile 应在一致的上下文（前缀已量化或未量化）中进行。
- OPT-66B 异常（p.7 脚注）说明模型特定的结构（死单元）会让"越大越好量化"的规律失效。

## 8. 作者声明的局限
- 加速来自减少访存，不减少计算；主流硬件缺乏 FP16×INT4 混合精度乘法支持（p.2、p.9）。
- 不涉及激活量化（p.2、p.9）。
- 主要关注生成任务/困惑度；压缩对偏见等次级指标的影响未研究（p.10 伦理声明）。
- 大批量、计算瓶颈场景下其 kernel 不直接适用（p.13）。

## 9. 批判
- 【推断】校准设置单一（C4，128×2048），没有任何关于样本数、领域、序列长度的消融；而后续 AWQ 的实验（AWQ Fig.8b）显示 GPTQ 跨域时多掉 2.3–4.9 PPL——GPTQ 本文对其"过拟合校准集"风险完全没有检验。
- 【推断】"任意顺序即可"在 OPT/BLOOM 上成立，但 AWQ Table 4 的 LLaMA-7B（8.81 vs reorder 6.53）证明顺序在有激活离群通道的模型上非常重要；对现代模型应默认开启按 diag(H) 排序。
- 【推断】主实验用逐行（无分组）网格，这让 RTN 显得特别差；在 g128 下 RTN 本身已"相当强"（AWQ p.7 的说法），GPTQ 相对 RTN 的优势在 g128 INT4 下会缩小到 0.0–0.3 PPL（AWQ Table 4）。
- 评测几乎全是困惑度与简单零样本，没有代码/数学/指令遵循；AWQ Table 8 显示 GPTQ 在 MBPP 上掉点明显（31.97 vs FP16 38.53），这种分布外退化在本文中看不到。
- 阻尼固定 1%，未研究其对精度的影响；Cholesky 稳定化是必要但非充分的（大模型仍需阻尼）。

## 10. 对本项目（27B 自量化 agent 的工具/诊断设计）的启示
1. **应暴露的统计量**：逐层的 `H = 2XX^T`（或其廉价摘要）：diag(H)（=激活平方均值，与 AWQ 的激活幅值高度相关）、条件数/有效秩、阻尼后是否正定。diag(H) 同时服务两件事：act-order 排序和"哪些输入通道敏感"。
2. **量化器选择**：GPTQ 相对 RTN 的价值主要体现在低比特（3bit 及以下）和无分组/大分组；在 4bit-g128 下增益很小（结合 AWQ Table 4）。建议 agent：4bit-g128 优先 RTN/AWQ（便宜、跨域稳健），3bit 及以下才考虑 GPTQ 或 AWQ+GPTQ；对代码/多模态等分布外能力敏感的模块慎用纯 GPTQ。
3. **校准数据是 GPTQ 的一个真实决策维度**：GPTQ 用完整二阶统计、权重被改写，校准分布错配的代价比 AWQ 大一个数量级（AWQ Fig.8b）。工具应支持：给定校准来源（通用/领域/模型自生成数据）分别 profile，并在 in-domain 与 held-out 两个评测集上报告 KL，以检测过拟合。默认基线：128×2048 token 通用文本。
4. **group size**：GPTQ 证据显示分组对 3bit 和 2bit 收益很大（2bit g32 vs g128：8.94 vs 9.58，OPT-175B），而额外存储开销小（g128≈0.15 bit，g1024≈0.02 bit）。agent 的存储预算计算应把 group 的 scale/zero 开销计入（论文给出了可直接用的换算），且"3bit-g128 vs 4bit-无分组"这类等预算替代方案值得作为候选。
5. **成本**：GPTQ 量化时间近似随参数量线性增长（13B 21 分钟、30B 45 分钟，A100），【推断】27B 全模型约 40 分钟级；对单模块 profile 则只需该 block 的前向 + 一次 Cholesky，适合作为 agent 工具，但应缓存每层 H 以便不同比特/group 重复使用（H 与比特无关，只与校准数据有关）。
6. **profile 的上下文一致性**：GPTQ 用"前缀已量化"的激活计算后层 H。逐模块 KL 工具应明确返回所用上下文（前缀 FP16 还是已量化），否则单独测量的敏感度与组合配置效果可能不一致。
