# 2502.14948 Sol-Ver: Learning to Solve and Verify — A Self-Play Framework for Code and Test Generation（v4，2026-03）

- 读的范围：正文 p1–8 全读；附录 B（迭代曲线）略读。源：`src_2502.14948/2502.14948.pages.md`。
- **改进对象**：权重（Llama 3.1 8B，SFT + DPO，fairseq2）（p5）。同一模型扮演 solver 与 verifier。
- **训练/信号数据**：**完全自生成**。用 Llama 3.1 8B 以 **OSS-Instruct（Magicoder-OSS-Instruct-75K）的开源代码片段**为灵感生成题目，题面模板取自 **MBPP、APPS、CodeContests 的训练集**；去重后 **103,280 道题**（p4–5）。代码与测试也由同一模型生成（测试 = 先生成输入，再多数投票生成期望输出，选覆盖率高、输出多样的测试，p5）。
- **每轮怎么用**：每轮生成解与测试并交叉执行；"至少一个解通过全部生成测试"即把该解和测试当作正确，SFT 用通过样本，DPO 用失败解作为 rejected（p3–5）。共 3 轮，每轮 SFT 后再 DPO（Table 1 p6）。每轮用多少题：未说明。
- **评测**：**MBPP**（代码 pass@1 greedy；测试生成用 MBPP gold 测试评估）与 **LiveCodeBench**（代码生成 + 测试输出预测；**版本/日期窗口未说明**）（p5）。没有 HumanEval。
- **是否不相交**：训练题目自生成，但借用了 MBPP/APPS/CodeContests 训练集的题面模板（p5）——与 MBPP 评测有"风格泄漏"风险，论文没做去污染检查。
- **关键数字**（Table 1 p6）：MBPP CodePass 38.60→41.00（Iter3+DPO）；LCB CodePass 18.23→27.24；LCB TestAcc 20.14→41.50。MBPP 上 SFT 阶段代码分几乎不动（38.60），提升主要来自 DPO。
- 局限：单模型单种子；只测 8B。
