# 2604.07864 ZeroCoder: Can LLMs Improve Code Generation Without Ground-Truth Supervision?（v2，2026-06-28）

- 读的范围：全文 p1–11（正文、实验、威胁效度）；参考文献略读。源：`src_2604.07864/2604.07864.pages.md`。
- **改进对象**：权重（GRPO，VeRL）。同一模型通过 prompt 交替扮演 Coder 和 Tester，两个角色联合训练（p2–3）。
- **训练/信号数据**：**APPS training split，5,000 题**（p6 Training Details）。不使用 APPS 的标准测试用例（fully label-free）；奖励来自"自生成代码 × 自生成测试"的通过矩阵，再由选择器（MaxPass / CodeT / B4）挑出伪正确解（p3–5）。
  - 训练前用初始策略做 rank-based 预过滤（τ=2），去掉低信息题。p6 正文说过滤后 1.5B/Qwen3-4B/Coder-7B 分别剩 1,377 / 1,396 / 990 题；但 Table 4（p10）写 Qwen3-4B 990、Coder-7B 1,396——正文与表格对不上，属于论文内部不一致。
  - DyB4 变体从过滤后的 APPS train 中拿 10 题带标签的 H 做校准（p6）。
- **每轮怎么用**：在线 RL，150 步、batch 32、每步每题 8 个 code rollout + 8 个 test rollout；lr 1e-6，KL 0.001（p6）。不是离散多轮。
- **评测**：代码生成：LiveCodeBench（**2024-10 至 2025-02 的题**，用以降低泄漏）、MBPP、APPS test 随机 300 题（intro/interview/comp = 60/180/60）、CodeForces 随机 300 题；测试生成：LCB（323 题有伪参考解）和 MBPP（p5）。Pass@1 greedy。
- **是否与评测不相交**：APPS train→APPS test 属同 benchmark 不同 split；作者说 CodeForces 子集与所用 APPS 题不重叠（p5）。MBPP、LCB 是不同 benchmark。没有 HumanEval。
- **关键数字**（Table 1 p7）：Qwen2.5-Coder-7B-Instruct 基线 CAvg 34.7 → ZeroCoder(B4(4,3)) 39.8；LCB 15.1→20.5，MBPP 83.6→84.9。Qwen2.5-1.5B 的 LCB 几乎不变（4.8→4.2~5.4）。只训 coder 的 Offline/Online 自测基线常常低于基座（如 Coder-7B Offline CAvg 31.1）。
- **数据选择相关发现**：过滤阈值 τ 先升后降；τ=4 时训练题骤减到 217–428 题（Table 4 p10），作者归因为数据太少而过拟合（p8）。去掉 mutation 奖励后 Coder-7B 平均代码分 42.2→35.3（p8）。
- 局限：只到 7B（p11）。单次运行，无方差。
