# 2605.16299 ACE: Self-Evolving LLM Coding Framework（ICLR 2026 RSI Workshop）

- 读的范围：正文 p1–9 全读；附录 A（对抗测试类型、消融 Table 3）读。源：`src_2605.16299/2605.16299.pages.md`。
- **改进对象**：权重，**LoRA，solver 与 adversary 各一个独立 adapter**；同一 backbone（Qwen3-4B-Instruct / Qwen2.5-7B-Instruct）交替扮演两个角色，不引入其他模型（p6）。solver 用 SFT，adversary 用 KTO + 长度正则（p6）。
- **信号来源**：solver 候选在 **ground-truth 测试 + 自生成对抗测试输入**上的执行结果表（式 1 p4）；对抗测试只看是否崩溃/报错，不需要模型推断期望输出（p4）。所以 solver 仍用到 GT 测试。
- **训练数据**：**CodeContests，约 4.5k 题**（p6）（与 CURE 的 4.5k 规模一致；切分是否相同未说明）。分析自演化动态时用固定 10% 子集（p6）。
- **每轮怎么用**：每轮 solver 每题采 16 个程序、adversary 生成 16 个测试输入（T=1.0）；按执行统计选代码做 SFT，构造偏好做 KTO；**共 5 轮**，4–5 轮后收敛（p6，Fig.4 p7）。
- **评测**：**MBPP**（split 未说明）、**LiveCodeBench v2**、CodeContests held-out 子集（p6）；pass@1/5/10，T=0.8。**没有 HumanEval**。作者把 CodeContests 当 ID、MBPP/LCB 当 OOD（p7）。
- **是否不相交**：CodeContests held-out 子集与训练集同分布（规模未说明）；MBPP、LCB 为不同来源。
- **关键数字（Table 1 p7）**：Qwen3-4B：MBPP@1 25.6→35.8，CC@1 41.7→46.7，LCB@1 32.4→37.5；Qwen2.5-7B：MBPP@1 24.1→28.8，LCB@1 30.4→38.9。注意 MBPP 基线分数（Qwen2.5-7B-Instruct 24.1）远低于常见报告值，评测协议可能不同【推断】。
- 消融（附录 Table 3）：去掉对抗测试或偏好优化时，训练集表现相近但 CodeContests 降约 4–5 点——训练集分数不能代表泛化（p8 及附录）。
