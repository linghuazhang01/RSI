## 研究问题
Task Arithmetic / Ties-Merging 这类基于 task vector 的多任务合并对合并系数 λ 非常敏感，且通常所有任务共享一个 λ、靠网格搜索；任务多、层多时无法搜索。能否**无需原始训练数据和标签**，自动学习每个任务（甚至每层）的合并系数（p.2, p.4–5）。

## 做了什么 edit/merge 决策
- Task vector：T_k = θ_k − θ_pre（p.5）。
- **Task-wise AdaMerging**：θ_MTL = θ_pre + Σ_k λ_k T_k，每个任务一个系数（p.5）。
- **Layer-wise AdaMerging**：每层 l、每个任务 k 一个系数 λ_k^l：θ^l = θ_pre^l + Σ_k λ_k^l T_k^l（p.5）。
- **AdaMerging++**：把 T_k 换成 Ties-Merging 处理后的 Φ(T_k)（trim / elect sign / disjoint merge）（p.5）。
- 决策变量即 "per-task / per-layer scale"，与我们算子库中的 per-layer scale 完全同构。

## 驱动决策的信息
- **信号**：合并后模型在**无标签测试样本**上的预测 Shannon 熵 H(ŷ) = −Σ_c p(ŷ_c) log p(ŷ_c)（p.6）。
- **目标**：min_λ Σ_k Σ_{x∈B_k} H(f_{θ_MTL(λ)}(x))，B_k 为任务 k 的一个无标签测试 batch（p.6–7）。
- **为何可用（证据）**：在 8 个任务合并后的测试集上，按熵分成 11 个区间，低熵区间平均损失更低（Fig.3a, p.6）；熵与逐样本损失的 Spearman 相关在全部数据（"ALL"）上为 0.87（p.6）；附录 Fig.10 称在 0–500 次迭代的各阶段相关性一直很高（p.18–19）。【注：Fig.3b 抽出的各数据集值约在 0.56–0.92 之间，但无法可靠对应到具体数据集。】
- **所需数据**：每个任务的**无标签测试输入**（transductive / test-time adaptation 设定）。不需要训练数据、不需要标签。
- **成本**：系数通过反向传播求梯度更新（p.7）；Adam，lr 0.001，batch 16，**仅 500 次迭代**，系数初始化为 0.3（p.15）。每步需要在 K 个任务的 batch 上做"合并模型前向 + 反向到 λ"（梯度要穿过整个网络，但只有 λ 是可训练参数）。单张 RTX 3090 上，ViT-B/32 达到 80.1 需额外约 125 分钟（Table 12, p.19）。
- **参数量**：8 个 task vector 共 907,589,640 参数；Task-wise 只新增 8 个系数，Layer-wise 新增 1,248 个（Table 11, p.18–19）。
- **内存**：需同时保存 θ_pre 与 K 个 task vector，并在前向中按 λ 动态组合【推断：对 LLM 规模内存压力大，文中未讨论】。

## 决策方式
- **梯度拟合系数**（无监督代理目标的 test-time 优化），非闭式、非网格。
- 超参（lr、迭代数 500、初始化 0.3、batch 16）文中未说明如何选；Task Arithmetic / Ties 基线 λ 默认 0.3（p.15）——Fig.1 显示 0.3 是这两个基线的最佳网格值（p.2），【推断】这一默认值本身来自在测试性能上扫描。
- 不使用带标签验证集；但优化与评估**用的是同一批测试输入**（转导式），【推断】这使得"无监督"结果在测试集上存在一定的拟合优势。

## 关键结果
- **ViT-B/32 八任务（Table 1, p.7）**：Pretrained 48.0；Individual 90.5；Traditional MTL 88.9；Weight Averaging 65.8；Fisher 68.3；RegMean 71.8；Task Arithmetic 69.1；Ties 72.4；Task-wise AdaMerging 71.1；Task-wise++ 73.7；**Layer-wise AdaMerging 80.1**；**Layer-wise++ 81.1**。
- **ViT-L/14（Table 2, p.8）**：Task Arithmetic 84.5，Ties 86.0，AdaMerging 90.8，AdaMerging++ 91.0，Traditional MTL 93.5。
- **ViT-B/16（Table 6, p.15）**：Task Arithmetic 73.8 → Layer-wise 84.9；Ties 77.0 → Layer-wise++ 85.7。
- **对未见任务的泛化（Table 3, p.8）**：合并 6 个任务、测 2 个未合并任务：MNIST+EuroSAT 未见任务平均 Task Arithmetic 61.7 → AdaMerging 70.0；RESISC45+SVHN：51.1 → 55.5。
- **分布偏移鲁棒性（Table 4, p.9）**：4 任务，clean 79.8 → 88.0；Motion Blur 69.4 → 80.6。但 Impulse Noise 下 EuroSAT 从 49.1 **降到** 30.8，Gaussian Noise 下 EuroSAT 55.4 → 41.2（p.9）——个别任务被牺牲。
- **学到的系数**：Task-wise 系数在 0.1413（Cars）到 0.4003（GTSRB）之间（Table 5, p.9）；Layer-wise 中浅层系数普遍小于深层，作者解读为浅层更依赖预训练权重（Fig.4, p.9）。

## 消融
1. **熵 vs 有监督交叉熵（Table 10, p.18）**：在测试集上用带标签 CE 学系数作为上界。Task-wise：监督 71.3 vs 无监督 71.1；Layer-wise：81.6 vs 80.1；Task-wise++：73.7 vs 73.7；Layer-wise++：82.0 vs 81.1。→ 熵作为代理目标损失约 0–1.5 点。注意 Layer-wise 监督版在 DTD（65.6 vs 59.1）、RESISC45（85.3 vs 79.2）上明显更好，无监督版在 EuroSAT/GTSRB/MNIST 略高——熵目标会偏向"本来就容易变自信"的任务【推断】。
2. **task-wise vs layer-wise（Table 1, p.7）**：Task-wise 只比 Task Arithmetic 高 2.0（71.1 vs 69.1），Layer-wise 高 11.0（80.1）；对 Ties 基线：Task-wise++ +1.3，Layer-wise++ +8.7（p.8）。→ **粒度（逐层系数）是主要增益来源**，而不只是"熵"。
3. **无标签数据量（Table 9, p.17）**：Layer-wise AdaMerging 用 0.1% / 1% / 5% / 100% 测试数据：74.0 / 77.5 / 80.1 / 80.1（Task Arithmetic 69.1）；Layer-wise++：77.9 / 80.6 / 81.0 / 81.1（Ties 72.4）。0.1% 时也有 +4.9 / +5.5 提升（p.16–17）；5% 已接近 100%。
4. **训练时间（Table 12, p.19）**：Layer-wise AdaMerging 随额外时间 +7.5/+12.5/+25/+50/+100/+125 分钟：71.1/72.1/74.5/77.1/79.7/80.1（基线 69.1）；作者概括为 +7.5 分钟提升约 2%，+50 分钟提升约 8%（p.18）。
5. **任务相关性（Fig.6/7, p.15–17）**：task vector 之间几乎正交（SVHN–MNIST 例外）；对不同相关程度的任务对，AdaMerging 都有效（图值不可读）。

## 批判
- **转导式设定**：系数在测试输入上优化再在同一测试集上评估（p.6–7），与"在 held-out 上评估"不同【推断：报告结果可能偏乐观】。
- **熵最小化的失败模式**：熵低≠正确。Table 4 中 EuroSAT 在噪声下大幅下降（49.1→30.8），Table 10 中 DTD、RESISC45 无监督明显落后监督——【推断】熵目标会把权重推给易于自信的任务、牺牲难任务；对生成式 LLM，降低 token 熵可能鼓励重复/模式坍缩，在指令遵循这种开放输出上尤其危险。
- 实验仅限 CLIP ViT 图像分类（C 类 softmax 熵定义清晰），无 NLP/LLM、无 LoRA 实验；对自回归生成的熵定义（逐 token 平均？序列级？）未讨论【推断】。
- 浅层系数小的观察只是可视化，没有和"浅层=通用"的直接因果检验。
- 学习率、迭代数、初始化 0.3 的选择未说明来源；500 步×K 任务前向反向在 8B/27B 上并不便宜【推断】。
- 只处理多任务互相干扰，不涉及"保持预训练模型通用能力"；θ_pre 能力的保持只能通过"系数小→更接近 θ_pre"间接体现。

## 对我们项目的启示
- **最可迁移的结论是粒度**：逐层系数（layer-wise scale）比逐任务系数增益大得多（+11.0 vs +2.0，Table 1）。我们的 per-layer scale 算子方向正确；且浅层系数小、深层大的模式（Fig.4）提示：新任务 LoRA 的浅层可能更应缩小以保护通用能力【推断，需在我们的 retention 评估上验证】。
- **信号选择**：熵是"无标签、可微"的代理，但 Table 10 表明它比有标签 CE 只差 0–1.5 点——**我们有带标签的 target dev 和 retention 评估器**，因此直接用有监督目标（或评估器分数）学/搜系数更可靠；熵最多作为便宜的预筛选。对 IFEval 类 retention，熵最小化可能误导（降低熵≠更遵循指令）。
- **成本参考**：1,248 个层级系数、500 步梯度即可收敛（p.15, p.19）；样本只需 1–5% 测试集（Table 9）。对我们：可把 "per-layer scale 向量" 作为 agent 程序的可微参数，用少量 dev 样本做几百步梯度（target loss − λ·retention 代理 loss，如在 retention 数据上与 base 输出的 KL），比让 agent 盲搜更高效【推断】。
- **单任务 vs 多任务 vs 遗忘**：本文只证据支持"多任务干扰下的系数学习"；对"单个新 LoRA + 旧能力保持"的场景，它对应的是 K=2（base 隐式 + 新 task vector）或 K=1 的退化情形，单系数自由度很小，增益主要应来自 layer-wise 粒度。
- **警示**：(1) 转导式优化会过拟合到评估样本——我们的评估器 dev 与最终 test 必须分开；(2) 熵目标会牺牲难任务，与我们 "target gain − λ·retention drop" 的权衡目标并不一致。
