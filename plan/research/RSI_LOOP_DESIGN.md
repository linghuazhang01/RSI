# RSI_LOOP_DESIGN：两篇论文怎样构成递归自我改进、怎样迭代、用什么反馈

日期：2026-11-18
状态：设计稿。Paper B 从"先训练 LoRA 再编辑"改为**直接写 LoRA**（用户 2026-11-18 决定）。本文取代 `METHOD_DESIGN.md` §3.1、§3.3 和 `PAPER_B_SELF_LORA_PLAN.md` §2.1–2.3 中与此冲突的内容；诊断表、强基线、数据配置（`DATA_CONFIG.md`）继续有效。
标注：【决定】是本文定下的设计；【假设】是没有文献依据、要在 pilot 里定的数值。

---

## 0. 结论

两篇用同一个骨架：

- **内层循环（一代之内）**：当前模型 M_t 当"改造者"，在固定预算内写程序、生成候选产物（A：量化配置；B：一个 LoRA），每个候选都在**训练集信号切片**上评分并把分数回传。挑出最好的候选，交给**训练集验收切片**做通过 / 不通过判定。
- **外层循环（代与代之间）**：通过验收的产物生成 M_{t+1}，**由它当下一代的改造者**。每代结束后在**留出集**上评测，只记录，不回传。
- **什么算递归自我改进的证据**：不是"产物分数涨了"，而是"**改造者本身的能力**随代数怎样变化"。用一个不随代数变化的固定任务测改造者能力 E_t，再用对照分支把 E_t 的变化拆成不同来源。

两篇的问题方向相反：
- **Paper A** 中，每一代的产物都更小，改造者自身可能**退化**。问题是：积累的经验能否抵消自身退化，闭环能走几代？
- **Paper B** 中，每一代的产物是一个写进自己权重的 LoRA。问题是：写过 LoRA 的模型，是否**更会写 LoRA**？

## 1. 共用骨架

### 1.1 两条跨代传递的通道【决定】

改造者从上一代继承两样东西，必须分开控制，否则无法说明改进来自哪里：

| 通道 | 内容 | 控制方式 |
|---|---|---|
| **权重通道** | M_{t+1} 的权重：A 是量化后的权重，B 是叠上新 LoRA 的权重 | 对照组用冻结的改造者 M_0 |
| **经验通道** | 跨代档案：以往所有候选的程序、配置、L1 反馈、验收结果 | 对照组每代清空档案 |

DGM、HGM 这类系统的增益有很大一部分来自档案，而不是权重变化。所以两篇都做一个 2×2：{当前改造者 M_t，冻结改造者 M_0} × {带档案，不带档案}。只有"M_t 胜过 M_0"这部分，才能归因于"权重被自己改过"。

### 1.2 内层优化：在程序空间里搜索【决定】

改造者每次输出的是**一段程序**，不是直接输出一个配置或一组数。程序读入诊断表、历史和工具结果，产出候选。搜索结构：

```
预算：A 每代 24 次 evaluate；B 每代 32 次 evaluate，另加梯度计算预算（§3.3）
4 条并行线程，每条 6–8 步：
  第 1 步：读诊断表 + 档案摘要，写第一版程序
  第 k 步：看到所有线程迄今的候选和反馈表，选择
           (a) 改进本线程最好的程序，或
           (b) 借用其他线程的思路重写
搜索结束：取信号分最高的 3 个候选，各用另外 2 个采样种子重跑信号评测，按平均分排序
提交：按顺序送验收门，最多 3 次；第一个通过的就是本代产物
```

- 并行线程加共享历史，参照 AIDE 和 DGM 的档案搜索；OPRO 式的"看历史再改"作为线程内部的更新方式。
- 重跑前 3 名是为了减轻赢家诅咒。AIDE² 中约 1/4 的被拒提案在公开信号上更高、在私有留出分上更低。

### 1.3 三层反馈【决定】

| 层 | 数据（见 `DATA_CONFIG.md`） | 改造者看到什么 | 用途 |
|---|---|---|---|
| **L1 信号** | 各领域训练集的 `search` 切片（200 题）；KL 上下文取自 `train` 池 | 分数、置信区间、相对参照的变化、2–3 个退化样例、成本 | 内层搜索 |
| **L2 验收** | 各领域训练集的 `gate` 切片（200 题） | 只有通过 / 不通过，加一句粗粒度原因；每代最多 3 次 | 决定能否接任 |
| **L3 留出** | benchmark 的 `test` 池 | 永远看不到 | 报告；计算 E_t、自压缩深度等指标 |

共同规则：
1. **不用模型自评做判定。** When AI Reviews Its Own Code（2606.28438）中自评门逐代退化，出现"橡皮图章"现象；Anosognosia 显示模型看不出自己被量化过。
2. **判分都是确定性的**：精确匹配、单元测试、IFEval 规则、调用匹配。
3. **门槛相对第 0 代**，不相对上一代，防止小退化逐代累积。
4. **噪声带**：开始前用 M_0 在每个信号和验收切片上重复跑 3 次，测出波动范围。候选的改进小于噪声带时，反馈里标为"无显著变化"。这是 RRSI 的做法：不加正则时 evolve +3.4，领域外只有 +0.6。
5. **数据访问由沙箱强制**：程序只能读 `train` 池的数据；信号和验收切片的题目与答案程序都拿不到，只能通过评测接口得到分数。这条防止 Gödel Agent 那种"把见过的错题硬编码进去"。

## 2. Paper A：递归自量化

### 2.1 一代的流程

```
输入：改造者 M_t（第 t 代量化模型），预算 B_{t+1}，档案 H_t，BF16 源权重 S（只读）
1. 诊断表（固定程序生成，所有代相同）：profile_table、activation_table、behavior_sensitivity、bytes
2. 内层搜索（§1.2）：M_t 写 quant_policy(diag, history) -> config
     config = 每组模块的 bit、group size、量化器、embedding 精度、校准数据来源
   evaluate(config)：真实量化 S，返回 L1 反馈（§2.2）
3. 提交验收：每个领域的验收切片 ≥ 第 0 代的门槛，且大小 ≤ B_{t+1}
4. 通过：M_{t+1} = quantize(S, config*)，接任改造者；H_{t+1} = H_t + 本代全部记录
   3 次都不通过：递归在此停止（记为停止边界）
5. 留出评测：五个领域的留出集 + 留出 KL；测 E_{t+1}
```

主设计每代都从 S 出发，递归只体现在"改造者换成了压缩后的自己"。"在上一代量化权重上继续压"作为 2×2 中的一臂（Paper A 计划 E3）。

### 2.2 L1 反馈的内容【决定】

每次 `evaluate` 返回结构化 JSON，例如：

```json
{"bytes_gib": 11.82, "budget_gib": 12.0, "decode_tps_b1": 41.3,
 "kl": {"overall": 0.087, "math": 0.112, "code": 0.095, "knowledge": 0.061, "if": 0.070, "tool": 0.103},
 "probes": {
   "math":      {"score": 0.71, "ci": [0.65, 0.77], "vs_round0": -0.04, "len_ratio": 1.18, "truncated": 0.03},
   "code":      {"score": 0.52, "ci": [0.45, 0.59], "vs_round0": -0.06},
   "knowledge": {"score": 0.63, "ci": [0.58, 0.68], "vs_round0": -0.02},
   "if":        {"score": 0.80, "ci": [0.73, 0.86], "vs_round0": -0.01},
   "tool":      {"score": 0.66, "ci": [0.59, 0.72], "vs_round0": -0.05, "false_call": 0.07, "missed_call": 0.04}},
 "regressions": [{"domain": "tool", "id": "...", "before": "...", "after": "..."}],
 "noise_band": {"math": 0.03, "code": 0.04},
 "budget_left": {"evaluate": 17}}
```

- KL 上下文：训练集 `train` 池的题面，加上 BF16 在训练题上自生成的推理文本（2504.04823：3-bit GPTQ 用推理类校准数据比 WikiText2 平均 +9.8）。
- 探针题目：MATH train + DAPO 各 100、APPS 100（沙箱执行）、TriviaQA + ARC 各 100、IFEval 135、Seal-Tools 200（加构造的"不该调用"样例）。
- 只看 KL 不够：CompressionBench 中 PPL 一路下降，GSM8K 却从 88% 掉到 72%。所以行为探针必须有。

### 2.3 怎样构成递归自我改进，测什么

| 量 | 定义 | 回答什么 |
|---|---|---|
| **E_t** | M_t 在固定任务（12 GiB 压缩 S、24 次 evaluate、新会话、不带档案）上的最终产物的留出 KL 和留出分数 | 改造者自身能力怎样随代数变化 |
| **E_t^档案** | 同上，但带上 H_t | 经验能否抵消退化 |
| **自压缩深度 D** | 每个领域留出分数都 ≥ 第 0 代 95% 的最大连续代数 | 闭环能走多远 |
| **2×2（计划 E3）** | {预算收紧，不收紧} × {重复量化，从 S 出发} × 改造者 | 把损伤拆成预算、重复量化、改造者退化三部分 |
| **权重 × 经验 2×2** | {M_t，M_0} × {带档案，不带档案}，都在固定的 12 GiB 任务上 | M_t − M_0 = 自身退化的代价；带档案 − 不带档案 = 经验的价值 |

预期的故事线【假设】：带档案时，前几代的 E_t 不降甚至上升，因为经验在积累；到某个比特数，改造者的代码能力和工具调用能力开始崩，E_t 断崖下降，D 就停在那里。如果确实如此，"经验的价值"和"自身退化的代价"会在某一代交叉，交叉点就是递归边界的解释。

## 3. Paper B：直接写 LoRA

### 3.1 表示和动作【决定】

- **模型**：M_t = θ0 + Σ_k A_k，基座 θ0 冻结，A_k 是第 k 代写入的 LoRA。
- **动作**：改造者写一段程序 `write_lora(task_spec, diag, tools) -> {module: (A, B)}`，输出每个目标模块的低秩分解，秩 ≤ 64【假设】，可以只写部分模块。
- **程序可用的原语**：

| 类别 | 原语 | 说明 |
|---|---|---|
| 无梯度构造 | `svd(module)`：读 W0 的奇异分解；`acts(ids, layer)`：在 `train` 池样本上取激活；`rank1(u, v, s)`、`from_direction(layer, vec)` | 奇异方向缩放（Transformer² 式）、激活差方向（steering 式）、闭式秩 1 编辑 |
| 梯度工具（计入预算） | `grad(ids, modules)`：对指定模块求损失梯度；`sgd(lora, ids, steps, lr)`：短训练 | 数据只能来自 `train` 池。普通 SFT LoRA 只是它的一种用法 |
| 栈操作 | `scale`、`interpolate`、`truncate_rank`、`intruder_scale`、`relchange_prune`、`regmean_preserve`、`orthogonalize`、`ties` | 来自 `METHOD_DESIGN.md` §3.3，作用对象是新写的 LoRA 和栈里的历史 adapter |

- **沙箱检查**：形状、数值有限、秩上限、总范数 ‖ΔW‖/‖W0‖ ≤ τ【假设】；数据访问只限 `train` 池。

为什么允许梯度：不用梯度的编辑主要是修行为，不是加能力。WSP 博客在 0.8B 上的大幅提升主要来自修好截断循环；WSP-Scope 在 9B 上的增益只有 +1.85 到 +3.03，数学编辑在留出集上 −0.35 被拒。去掉梯度工具作为消融，正好回答"不用梯度能走多远"。

### 3.2 一代的流程

```
输入：改造者 M_t，目标任务 T_t（训练集的 train / search / gate 三池），保留领域，档案 H_t
1. 诊断表（固定程序生成）：W0 和现有栈的逐模块统计（范数、谱、intruder 分数、与历史 adapter 的主角度），
   以及 M_t 在 T_t 和保留领域的 train 池样本上的激活统计
2. 内层搜索（§1.2）：M_t 写 write_lora 程序 → 沙箱执行 → 得到候选 LoRA A_cand
   evaluate(M_t ⊕ A_cand)：返回 L1 反馈（§3.4）
3. 提交验收（§3.4），最多 3 次
4. 通过：M_{t+1} = M_t ⊕ A_t*，接任改造者
   栈超过 4 个 adapter 时，由改造者自己写合并程序（同样要过验收）【假设】
   3 次都不通过：回退到基线 SFT LoRA（若它能过验收），否则保留 M_t 并记录
5. 留出评测；测四个分支的 E_{t+1}（§3.5）
```

任务序列沿用计划：T1 SQuAD 知识注入 → T2 数学 → T3 代码，算力允许时加 DAPO 难题作第 4 代。代码这一代和改造者的能力直接相关，因为改造者靠写代码来写 LoRA。它是否带来 E_t 的跳升，是一个现成的观察点。

### 3.3 预算【决定 / 数值为假设】

每代预算相同，所有基线用同样的预算：
- 32 次 `evaluate`；
- 梯度计算总量上限，以 GPU 秒计【假设：8B 上每代 2 GPU 小时，约等于一次标准 r16 SFT 的两倍】；
- 改造者生成 token 的上限。

梯度预算和 SFT 基线对齐，是为了排除"LLM 赢只是因为多训练了"。

### 3.4 L1 反馈和验收【决定】

每个候选返回：
- **目标任务**：T_t 信号切片上的分数、置信区间、相对 M_t 和相对基线 SFT LoRA 的差，以及 2–3 条错题；
- **保留**：
  - 相对 M_t 的逐 token KL，在保留领域训练集 prompt 上 teacher-forcing 计算，比准确率稳定，先用它筛选；
  - TriviaQA、ARC、IFEval 信号切片的分数；
  - 已学过任务的信号切片分数；
  - 2–3 个"写入前对、写入后错"的样例；
- **行为统计**：输出长度、截断比例、格式失败率；
- **LoRA 自身**：各模块范数、秩、intruder 分数、与栈里历史 adapter 的重叠；
- **成本**：已用梯度预算、剩余 evaluate 次数；
- **总分**：目标增益 − λ × 保留下降（λ 预先登记）。

验收【假设，B-P0 后登记】：
- 目标任务验收切片 ≥ 基线 SFT LoRA − ε；
- 每个保留领域的验收切片 ≥ 第 0 代 − δ；
- 已学过任务的验收切片不低于它刚学完时 − δ；
- 沙箱检查全部通过。

### 3.5 怎样构成递归自我改进，测什么

**E_t 的测法**【决定】：让改造者为**固定的基座 θ0** 在**从未进入训练序列的任务**上写 LoRA。
- 主 E 任务：E-Seal（Seal-Tools train → Seal-Tools test；BFCL 作领域外 E-test）；
- 预算固定：16 次 evaluate、固定梯度预算、新会话、不带档案；
- 结果取 3 个种子的平均；
- 指标是写出的 LoRA 相对基线 SFT LoRA 在 E-test 上的增益。

**每个父模型保留四个分支**：

| 分支 | 内容 | 用途 |
|---|---|---|
| Parent | M_t | 起点 |
| SFT | M_t ⊕ 固定配方 SFT LoRA（r16，同梯度预算） | 普通训练带来的变化 |
| LLM-written | M_t ⊕ M_t 自己写的 LoRA（主线） | 主线 |
| Non-LLM | M_t ⊕ 同预算的非 LLM 搜索结果（在 SFT 超参、checkpoint、全局缩放上做随机搜索或 CMA-ES，再加 `METHOD_DESIGN.md` §3.6 的规则组合） | 非 LLM 对照 |

报告：
- ΔE_train = E(SFT) − E(Parent)；
- **ΔE_write = E(LLM-written) − E(SFT)**：自己写 LoRA 这件事本身带来的编辑能力变化；
- ΔE_nonLLM = E(Non-LLM) − E(SFT)。

"稳定为正"的判据沿用：至少 2/3 的代上，ΔE_write 的 95% 置信区间下界 > 0，且 ΔE_write > ΔE_nonLLM。

再加 §1.1 的权重 × 经验 2×2：当前改造者 M_t 接任 vs 冻结改造者 M_0 写全部各代的 LoRA，各自带或不带档案。"M_t 带档案"胜过"M_0 带档案"，才是计划里主张 3（接任优于冻结）的证据。

**单轮比较（RQ1）也要报**：同预算下，LLM-written 对 SFT、Non-LLM、`METHOD_DESIGN.md` §3.6 的强基线，比较目标任务和遗忘之间的取舍。Search over Self-Edit 中模型自选配置输给了人工配置（45.1 vs 50.3），这是要正面回应的先例。

### 3.6 行为分析

记录每个程序用了哪些原语：纯构造、纯 SFT、构造加短训练、栈操作。看三件事：
- 随代数变化，策略是否从"调 SFT 超参"转向"有针对性的构造"；
- 写过代码任务 LoRA 之后，程序质量是否提升（可运行率、首次通过所用 evaluate 次数）；
- 失败模式：范数爆炸、格式崩溃、遗忘集中在哪些层。

### 3.7 扩展（B-P3）

- **元目标**：某一代的目标任务直接设为"让自己更会写 LoRA"，在一个 dev E 任务上用 E 作为 L1 信号，相当于 STOP 那种"改进改进者"的设定。STOP 中较弱的模型（GPT-3.5、Mixtral）测试端的元效用随迭代下降，并出现 reward hacking，所以只作扩展。
- **技能 LoRA**：把通过验收的程序和反馈当作数据，用 ReST^EM 训练一个"写 LoRA 技能"的 adapter，数据完全由模型自己产生。

## 4. 两篇的对照

| | Paper A | Paper B |
|---|---|---|
| 产物 | 量化配置 → 量化权重 | 低秩 ΔW（LoRA），叠加到栈上 |
| 改造者 | 上一代的量化模型 | 叠了上一代 LoRA 的模型 |
| 内层预算 | 24 次 evaluate | 32 次 evaluate + 梯度预算 |
| L1 主信号 | 训练文本上相对 BF16 的 KL + 五个领域探针 | 目标任务信号切片分数 + 保留 token-KL + 保留探针 |
| L2 验收 | 五个领域验收切片相对第 0 代，加大小预算 | 目标 ≥ SFT − ε，保留 ≥ 第 0 代 − δ |
| E_t 固定任务 | 12 GiB 压缩 S | 为 θ0 在 Seal-Tools 上写 LoRA |
| 递归问题 | 经验积累能否抵消自身退化；闭环能走几代 | 写过 LoRA 的模型是否更会写 LoRA |
| 关键对照 | 2×2 损伤拆解；权重 × 经验 2×2 | 四分支 ΔE；权重 × 经验 2×2 |

## 5. 预期失败模式和应对

| 失败模式 | 早期信号 | 应对 |
|---|---|---|
| 信号过拟合（赢家诅咒） | 信号分涨、验收分不涨 | 噪声带、前 3 名重跑、验收限次；报告信号 / 验收 / 留出三列差距 |
| 改造者在 B 中只会调 SFT 超参 | 原语统计几乎全是 `sgd` | 这本身是结果；同时看去掉梯度工具后的表现，以及 ΔE_write 是否仍为正 |
| A 中改造者过早崩溃（第 1 代就写不出合法程序） | E_1 远低于 E_0 | 细粒度预算序列（16 → 14 → 12 GiB）；简化动作空间 |
| B 中遗忘太小，抗遗忘无从体现 | 保留分数下降 < 2×SE | 主保留指标改用 token-KL；以第 3 代累积遗忘为主比较点（`METHOD_DESIGN.md` §3.8） |
| 档案让结果难以归因 | 带档案和不带档案差异巨大 | 本来就有权重 × 经验 2×2；E_t 主指标在不带档案的新会话里测 |
| 程序越权读数据或硬编码答案 | 信号分异常高、验收分低 | 沙箱只开放 `train` 池；程序和产物全部存档以便审计 |
