## 研究问题
单一模型上的自专精（Self-Specialization）会牺牲非目标领域的能力。论文问的是：能否在资源很少、不明显增加参数、不用更强教师模型的条件下，把一个单体 LLM 变成由多个自专精 LoRA 专家组成的组合式系统（MiXSE），让知识、推理、数学、代码几个方向同时提升而不互相拖累。

## 方法细节
- **形式化**（§2，p.3）：f_trans:(Θ0,{T_i})→Θ_comp=Θ0∪{ΔΘ_i}，要求 ΔΘ_i 是轻量的 LoRA，每个目标领域约 100 条种子，不假设有更大的教师模型。
- **专家构建**（§3.1，p.4）：对每个目标领域 T_i（knowledge、reasoning、math、coding，由人指定）：
  1. 种子：人从 MMLU、BBH、GSM8K 训练集各取 100 条；代码领域取 MBPP 训练集 100 条，改成 HumanEval 格式（附录 A，p.18）。
  2. 指令头脑风暴：基座 Θ0 以 3 条种子作为上下文示例，生成新指令（temperature 1，top-p 0.98）。
  3. 回答生成：Θ0 以 5 条种子作为上下文示例，贪心解码生成回答。
  4. 用自生成数据 D_i 训练 LoRA：θ_spec=θ0+θ_Bi·θ_Ai，rank 8，alpha 16，挂在所有模块，lr 3e-4，3 个 epoch，batch 32；每个领域 5K 条，共 20K 条。
- **MiXSE 组合**（§3.2，p.4–5）：每层输出 h=θ0x+Σα_i·ΔB_iA_ix，其中 α=top-k(softmax(θ_r x))，路由器 θ_r 是所有 LoRA 层共享的一个线性层。冻结专家，只用汇总后的自生成数据 D 以 LM 损失训练路由器（以保持专家的语义区分）。实现上用了 PEFT 和 XLoRA。
- **模型**：主实验用 Gemma-7B（预训练基座）；另外还在 LLaMA-2 7B/13B、Mistral 7B、LLaMA-3 8B 上做了实验。
- **谁生成、谁修改谁的权重**：同一个基座 LLM 生成每个领域的数据，这些数据用来训练它自己的 LoRA 专家和路由器。LoRA 训练、路由器训练、专家组合方式（top-k 路由）都是人设计的固定流水线；模型只产出文本数据。
- **人工输入**：4 个目标领域由人定；每个领域 100 条种子由人挑，且直接来自评测基准的训练集；每个领域单独的 prompt 模板由人写（Table 9–12 列出了基准里的子任务名，例如 BBH 的 27 类任务、MMLU 的 57 个学科）；超参、top-k、路由器结构也都由人定。
- **修改对象**：多个 LoRA adapter 加一个线性路由器，基座冻结。附加参数总共约 1%，激活参数为 7B+0.3%。
- **推理效率/压缩**：只讨论了“附加参数和激活参数的开销很小”（§4.8，Table 5），即把 LoRA-MoE 和 Mixtral/BTX 比参数规模。没有压缩、剪枝或量化，也没有推理加速的目标。top-1 路由是从效率出发的选择。
- **多轮递归**：没有。专家和路由器都只训练一轮，训练后的模型不会再去生成数据或修改自己。

## 关键实验与数字
- Table 1（p.6，Gemma-7B）：基座平均 47.8（MMLU 58.4 / BBH 56.1 / GSM8K 42.5 / HumanEval 34.1）。MiXSE 平均 54.3（65.6 / 61.1 / 52.5 / 37.8），即 +6.5。Knowledge 自专精模型 MMLU 64.0，但 BBH 掉到 41.7、HumanEval 掉到 28.0。Instance Merging（多任务微调）52.4，TIES 47.9，DARE 44.3。
- Table 2（p.7）：Top-1 54.3，Top-2 54.3，全部专家 53.0；随机路由 50.8；专家与路由器联合训练（专家不再具有语义区分）50.5。
- Table 3（p.8）：非目标任务平均：基座 50.4，Instance Merging 47.7，MiXSE 50.6。MATH 20.7→21.4，MBPP 37.8→39.6，TriviaQA 63.9→62.5（小幅下降）。
- Fig.4（p.8）：其他基座的平均分：LLaMA-2 7B 20.5→26.2，LLaMA-2 13B 27.5→35.0，Mistral 7B 37.5→41.9，LLaMA-3 8B 46.5→51.1（数值从图中文字抽取，配对按图的布局推断）。
- Table 4（p.9）：专家数 0/1/2/3/4 对应平均 47.8 / 43.6 / 49.8 / 52.9 / 54.3。
- Table 8（p.20）：只用种子训练，平均 48.4；MiXSE 54.3。
- 附录 D.3（p.20）：三次不同 few-shot 示例的运行，基座 47.9±0.56，MiXSE 53.6±0.60，Instance Merging 51.6±0.87；MiXSE 对 Instance Merging 的 p=0.03。

## 作者自己声明的局限（附录 B，p.18）
- 自生成数据可能有污染和噪声（作者引用 Self-Specialization 的 n-gram 检查来缓解这一担忧），需要更好的数据验证和噪声过滤。
- 受算力限制，模型和数据都没有扩展到充分规模。
- 没有优化 XLoRA 这个 MoE 模块本身。

## 方法问题与替代解释
- 【推断】种子直接来自 MMLU、BBH、GSM8K 的训练集，prompt 里还列出了基准的子任务清单（Table 9–10），所以“自专精”其实带有很强的基准定向信号。提升有一部分可能来自格式和分布对齐。Table 8 的“只用种子”只是部分排除了这种可能，因为种子作为 ICL 示例的作用在生成数据时依然存在。
- 【推断】路由器学到的“正确路由”，可能只是按格式或提示词的表面特征做区分（例如是否出现代码、是否是选择题），而不是语义。Fig.3 是按 token 和层平均的分布，没有在细粒度上验证。
- 【推断】Instance Merging 只比 MiXSE 低 1.9 分（D.3 里是 2.0），在 GSM8K 上还更高（53.5 对 52.5），所以“模块化比单体好”的幅度有限。
- 【猜测】对 Gemma-7B，MMLU 0-shot 被用作主指标，而 5-shot 下基座是 65.7、MiXSE 是 66.2（Table 7，p.19）。可见在 5-shot 设置下，增益几乎消失，主表的提升有一部分来自 0-shot 格式能力。

## 与每个 core claim 的关系
- **C1（模型自己压缩自身权重以提升推理效率）**：没有覆盖。没有剪枝、量化或推理加速；所谓“效率”只指附加参数少，而且由人设计。
- **C2（模型自己产出 LoRA 并应用到自己身上）**：部分覆盖，并且向多 LoRA 做了扩展。同一个 LLM 为 4 个领域分别自生成数据、训练出自己的 LoRA 专家，再用自生成数据训练路由器，最后组合回自身。但领域选择、种子、超参、训练代码、组合架构都由人固定；模型不决定超参或训练方案，也不直接生成权重。
- **C3（递归：编辑后的模型成为下一轮编辑者）**：没有覆盖。只训练一轮，MiXSE 不会再去生成新数据或产出新专家；没有多轮共同提升。作者称之为“self-improving”，但那是一次性的。
- **C4（权重层面的动作空间：压缩、adapter、合并）**：部分覆盖。动作落在权重层面：LoRA adapter 加 MoE 式组合，并且和权重合并方法（TIES、DARE）做了对比。但组合方式是人定的固定 top-k 路由，模型不会在 adapter、合并、压缩之间做选择，动作空间里也没有压缩操作。
