# Self-Rewarding Language Models：叙事拆解（STORY）

> 本文件不重复 notes.md 里的数字，只分析作者"怎么讲故事"，供模仿叙事结构用。页码指 paper.pages.md 中的 Page 编号。

## 1. 元信息
- 标题：Self-Rewarding Language Models
- Venue：ICML 2024（arXiv 2401.10020，v3 2025-03）
- 作者与机构：Weizhe Yuan、Richard Yuanzhe Pang、Kyunghyun Cho、Xian Li、Sainbayar Sukhbaatar、Jing Xu、Jason Weston；Meta 与 NYU。
- 篇幅特点：正文约 12 页，结构非常"瘦"：引言、方法（2 节）、实验（指令遵循 + 奖励建模两块）、相关工作、结论、局限。没有单独的分析章节，分析散落在实验小标题和附录里。

## 2. 一句话卖点
**奖励模型不该冻结：让同一个 LLM 给自己打分、用这些分数训练自己，结果"做题能力"和"打分能力"在迭代中一起变强。**

作者希望读者带走的是"两条轴同时提升"（both axes），也就是结论里说的"良性循环"（virtuous circle）。AlpacaEval 上超过 Claude 2 / Gemini Pro / GPT-4 0613 只是让这个想法显得可信的"招牌数字"。

## 3. 开场钩子
- **摘要第一句是宏大愿景**：要做出超人智能体，就需要超人水平的反馈信号。这是一个很强的 framing，一开始就把问题从"RLHF 的工程细节"提升到"超人对齐的天花板"。
- **引言第一段则回到具体机制**：先肯定 RLHF/DPO 有效，然后指出两种做法都受限于人类偏好数据的规模和质量；RLHF 还额外受限于冻结的奖励模型（p.1）。
- 写法是"摘要放愿景，引言放机制"。摘要负责让人想读，引言第一段负责让审稿人点头。注意引言第一段没有任何实验证据，瓶颈是靠逻辑论证（"被人类水平卡住"+"冻结后不会学习"）立住的。

## 4. Gap 怎么陈述
- **被指为不足的点有两个，并且被压缩成两个形容词**：bottlenecked by human performance level（人类水平上限）和 separate frozen reward models（分离且冻结）。摘要和引言都重复这两点。
- **证据方式**：几乎没有实证证据，靠概念论证。引言把 RLHF 和 DPO 并列，说明"无论有没有显式奖励模型，都卡在人类数据上"，这样把 DPO 这条看似绕开奖励模型的路也一并堵住。
- **相关工作里的"逐个击破"**（p.11–12）：每个相关方法都被归结为"奖励是固定的"：RLHF（固定 RM）、RLAIF/Constitutional AI（固定的独立 RM）、PCO（迭代但 RM 固定）、ReST（固定外部奖励）、SPIN（需要人类回答，追上人类后就卡住）。相关工作每一段的落点都回到同一个 gap，这让 gap 显得系统性而非偶然。

## 5. 核心洞见 / 关键想法的包装
- **关键想法**：把奖励建模也当成一种指令遵循任务（LLM-as-a-Judge），于是"会做题"和"会打分"可以放进同一个模型、互相迁移。
- **包装手法**：
  1. **类比多任务迁移**（p.1）：像预训练和多任务指令微调能带来任务间迁移一样，把奖励模型并入同一系统，就能让奖励建模和指令遵循互相迁移。这个类比让"为什么打分能力会自己变好"显得理所当然。
  2. **两种技能的列表化**（p.2）：模型要同时具备 (1) 指令遵循 (2) 自我出题与自我评判。方法被拆成两个可以记住的名词：Self-Instruction creation 和 Instruction following training。
  3. **命名**：标题即方法名，"Self-Rewarding" 是动名词短语，直接说明机制；数据集也有短名 IFT / EFT / AIFT，读者容易跟踪"哪轮数据训哪个模型"。
  4. **关键措辞**："让模型自我修改自己的训练集"（self-modify its own training set，p.3）——把数据生成说成"自我修改"，与自我改进主题一致。
- **诚实脚注**：p.3 脚注 1 承认主实验里 prompt 由一个固定模型生成，不是被训练的模型，并指向附录 A.5。这是把"不够纯"的部分放到脚注 + 附录的典型处理方式。

## 6. Figure 1 讲了什么，为什么有效
- 内容：一张两段式流程图。左半"Self-Instruction creation"（生成新 prompt → 生成回答 → 自己打分），右半"Instruction following training"（选偏好对 → DPO），底部一条箭头"Next iteration model"回到左边。
- 为什么有效：
  - **闭环箭头就是论点本身**：图里最重要的元素是"下一轮模型"回到起点的那条线，直观表达"打分者在变"。
  - **只有两个盒子**：把复杂流水线压成两步，读者 5 秒内能复述。
  - **图注最后一句重复卖点**：整个流程可迭代，带来指令遵循和奖励建模两方面的提升。图注本身就是一个迷你摘要。

## 7. 贡献列表
- **原文没有显式的编号贡献列表**。贡献隐含在引言最后两段（p.2）：
  1. 方法：提出 Self-Rewarding LM 与迭代 DPO 训练框架。（方法）
  2. 发现：指令遵循能力随迭代提升。（实证发现）
  3. 发现：奖励建模能力也随迭代提升，因此每一轮能给自己提供更好的偏好数据。（实证发现，也是核心卖点）
  4. 愿景：有可能得到超过只用人类种子数据训练的奖励模型。（展望）
- 启示：没有贡献列表也能成立，前提是"一个想法 + 两个发现"足够简洁。

## 8. 实验如何支撑每个 claim
实验章节（§3.2）就按两条轴分成两个小节：3.2.1 指令遵循能力，3.2.2 奖励建模能力。每个小段落的**粗体小标题本身就是一句结论**（例如"第 2 轮优于第 1 轮和 SFT 基线"），读者只扫小标题就能得到全部主张。

| 主张 | 对应实验 / 表 |
|---|---|
| 加入 EFT（评判训练）不损害指令遵循 | 图 3：M1 vs SFT 基本持平（作者明说这是"正面结果"） |
| 指令遵循随迭代提升 | 图 3 GPT-4 两两对比（M2>M1、M3>M2）；表 1 AlpacaEval 2.0 |
| 与强系统相比也有竞争力 | 表 1 排行榜，额外加两列"是否蒸馏 / 是否私有数据"，凸显自己只用小种子集 |
| 自动评测可信 | 图 5 人类评估（作者盲评 50 条）；表 2 MT-Bench |
| 提升来自哪些任务 | 图 4 / 图 11 按类别、复杂度、长度的细分 |
| 不损失通用能力 | 表 3 NLP benchmark |
| 奖励建模能力随迭代提升 | 表 4（五个与人类偏好对齐的指标） |

- **基线选择**：只有一个内部基线 SFT（只用 IFT 数据），加上"自己的前一轮"。外部比较只出现在排行榜（表 1）里，而且是"引用排行榜数字"，不是复现。这种做法把实验成本降到最低，并把比较聚焦在"迭代是否有用"上。
- **诚实的负面结果**：
  - 数学与逻辑推理基本不提升（图 4、表 2），作者归因于 Open Assistant 种子 prompt 中推理任务少。
  - NLP benchmark 部分下降（表 3），作者借用 InstructGPT 的"alignment tax"说法来消化，并把它转成未来方向。值得注意：小标题写的是"没有丢失能力"，而表中 ARC、NQ 等逐轮下降，属于偏乐观的措辞。
  - 生成长度显著变长（p.8），作者在正文和局限里都承认。
  - 只加正样本 SFT 不起作用（附录 A.4），被用来论证"偏好对才是关键"。

## 9. 分析与消融：回答"为什么有效"
- **评判 prompt 的重要性**（p.11，附录 A.2）：加分式 5 分 prompt 与多选式 prompt 的对齐精度差距巨大。说明"打分方式"是关键设计。
- **EFT 种子数据的作用**（附录 A.3）：没有 EFT 时模型常常打不出格式化分数，有效偏好对很少，增益更小。
- **正样本 vs 偏好对**（附录 A.4）：只用自评高分样本做 SFT 不涨。
- **为什么奖励建模会自己变好**：作者给的是**假设**而非实验——因为一般指令遵循能力变强，LLM-as-a-Judge 这个任务也跟着变强（p.11）。这里的因果并未单独验证。
- **模型自己出题**（附录 A.5）：只做了人工检查，未用于训练，用来回应"prompt 来自外部模型"的质疑。
- 总体而言，分析偏少，主要放附录；正文靠"两条轴同时上升"这一结果本身承担说服力。

## 10. 局限与未来工作
- 局限一节（p.12–13）语气是"初步结果，还有很多值得探索"，列出：只跑了 3 轮、单一设置；需要研究该效应在更多轮次、不同能力模型上的 "scaling laws"；长度增长；reward hacking 是否发生；训练奖励与评测都是 LLM；缺安全评估。
- **顺势铺垫**：结论中主动承认"现实中很可能会饱和"，但随即说仍可能超越人类偏好。这种"先承认天花板、再保留希望"的写法既显得诚实，也给后续工作（更多轮、meta-rewarding、推理任务）留了明确入口。事实上该组后续确实发表了多篇延伸工作。

## 11. 标题和摘要的写法特点
- **标题**：三个词，方法名即标题，不加副标题、不写数字。概念足够新时，这种写法最有记忆点。
- **摘要结构**（五步）：
  1. 愿景（超人智能体需要超人反馈）；
  2. 现状的两个缺陷（受限于人类水平；奖励模型分离且冻结）；
  3. 本文做了什么（用 LLM-as-a-Judge 给自己打分）；
  4. 两个发现（指令遵循提升 + 自我奖励能力提升）+ 招牌数字（超过 Claude 2 等）；
  5. 克制的展望（还有很多待探索，但打开了"两条轴持续提升"的可能）。
- 摘要里没有任何方法细节（没有 DPO 超参、没有数据量），只有机制和结论。

## 12. 对我们的启发

### 对 Paper A（模型自己量化自己、压缩后的模型做下一轮压缩者，RSI）
- **可借鉴**：
  - "两条轴同时提升"的叙事几乎可以直接迁移：Paper A 的两条轴是"被压缩后的任务能力"和"作为压缩者的能力"。若能展示第 t 轮压缩出的模型在下一轮做出了更好的量化决策，就是本文表 4 的翻版。实验章节可以同样分成"任务性能"与"压缩者能力"两个小节。
  - Gap 可仿照"冻结的奖励模型"写成"外部固定的压缩策略 / 人工设计的量化配方不会随模型改进"，再在相关工作中逐一把 GPTQ/AWQ 等归结为"压缩者是固定的"。
  - 粗体小标题即结论的写法，对迭代结果（第 1 轮→第 2 轮→第 3 轮）特别适用。
- **要避免**：
  - 本文"为什么评判能力会变好"只给假设。Paper A 若声称"压缩者能力提升"，审稿人一定会追问：是压缩决策本身变好了，还是只是模型更会遵循格式？需要一个控制实验（例如把第 t 轮的压缩决策交给固定模型执行，隔离"决策质量"）。
  - 压缩场景下"能力下降"是默认预期，不能像本文对 NLP benchmark 那样用乐观小标题带过；应正面报告精度—压缩率曲线。
  - 外部参与要在正文说清：本文把"prompt 来自外部模型""Claude 2 选 checkpoint"放在脚注和训练细节里，后来被广泛批评"不够自"。Paper A 若有外部校准集或外部评测模型，应在方法部分明确列出闭环边界。

### 对 Paper B（模型写代码编辑自己训出的 LoRA、编辑后的模型做下一轮编辑者，RSI）
- **可借鉴**：
  - "把奖励建模当成一种指令遵循任务"的包装可迁移为"把权重编辑当成一种代码生成任务"：既然模型会写代码，编辑 LoRA 就是它已有能力的一个特例，于是"编辑能力"和"任务能力"可以互相迁移。这是一个简单、可记的核心洞见。
  - Figure 1 用两段式闭环 + "下一轮模型"回边，非常适合 Paper B：左段"写编辑代码 → 执行得到新 LoRA"，右段"评估 → 选择/训练"，回边标注"编辑后的模型成为新的编辑者"。
  - 用 IFT/EFT/AIFT 这类短名来标记"哪一轮数据/适配器训出哪一轮模型"，能显著降低迭代实验的阅读负担。
- **要避免**：
  - 只有 3 轮且增益已在变小，本文靠"初步结果"的措辞消化。Paper B 若主打 RSI，需要更多轮或明确报告饱和点，否则"递归"只是"迭代两次"。
  - 本文只有一个内部基线（SFT）。Paper B 至少要有"固定编辑者（第 0 轮模型一直当编辑者）"这一基线，才能证明"编辑后的模型当编辑者"本身有贡献，这是本文缺失、但最能支撑 RSI 主张的对照。
  - 长度膨胀之于本文，相当于"LoRA 范数膨胀 / 过拟合评测集"之于 Paper B；应提前设计检测 reward hacking 的分析，而不是只放进局限。
