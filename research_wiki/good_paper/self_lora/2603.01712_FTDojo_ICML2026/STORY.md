# FT-Dojo：叙事拆解（STORY）

> 本文件不重复 notes.md 里的数字，只分析作者"怎么讲故事"，供模仿叙事结构用。页码指 paper.pages.md 中的 Page 编号。

## 1. 元信息
- 标题：FT-Dojo: Towards Autonomous LLM Fine-Tuning with Language Agents
- Venue：ICML 2026（PMLR 306；arXiv 2603.01712 v2，cs.AI）
- 作者与机构：Qizheng Li、Yifei Zhang、Xiao Yang、Xu Yang（四人共同一作）、Zhuo Wang、Weiqing Liu（通讯）、Jiang Bian；Microsoft Research Asia，以及北大、南大、芝加哥大学。
- 论文类型：**"Benchmark + 配套方法"**的复合型论文。前半是环境/基准（FT-Dojo），后半是为该基准设计的 agent（FT-Agent），实验同时服务两者。
- 篇幅特点：正文约 9 页，结构为"引言 → FT-Dojo（任务定义、架构、环境形式化、任务集与评测）→ FT-Agent（挑战 → 框架）→ 实验（主结果、前沿 agent 与骨干、消融、案例）→ 相关工作 → 结论"，附录 A–G 很长（人工基线协议、全量结果、完整决策轨迹、prompt）。

## 2. 一句话卖点
**端到端 LLM 微调（从原始数据挑数据、合成数据、配训练、看反馈再迭代）应该被当成一个交互式 agent 任务来定义和评测；我们给出第一个这样的环境，并给出一个"强的初始基线" agent。**

作者希望读者记住两件事：FT-Dojo 是"第一个"微调 agent 交互环境；以及案例研究里的"二元性"——agent 能从失败中累积学习，但缺乏因果诊断能力。

## 3. 开场钩子
- **第一段是"具体痛点 + 自然的下一步"**（p.1）：LLM 通用能力很强，但化学、法律、金融等垂直领域常需要领域适配；提示工程不够用，生产级应用通常要微调；而微调是劳动密集的、每个新领域都要重新做一遍（领域专家和 ML 工程师协作理解需求、整理数据、配训练、评估 checkpoint）。段末用一个问句收尾：agent 能否自动化端到端 LLM 微调？
- **第二段把问题放进 AI-for-AI 的趋势**：MLE-Bench、DSBench 等基准已经在评测 agent 做传统机器学习工程，然后立刻**划清界限**：LLM 微调比传统 MLE 更开放、更复杂，给出两条具体差异——(i) 数据需要"构造"而不只是"处理"；(ii) 分析信号不止总分，还包括训练动态、验证曲线、采样输出。
- 写法特点：不讲"超级智能"愿景，而是从一个从业者都认同的工作负担出发，用一个问句定义研究问题，再用"与最近邻基准的两点差异"建立新颖性。这是 benchmark 论文非常标准且有效的开场。

## 4. Gap 怎么陈述
- **双层 gap，对应论文的两半**：
  1. **基准层 gap**（p.1）：数据构造与微调配置在多种分析信号下的迭代联合优化，"既没有被正式定义为 agent 任务，也没有被系统评测过"。这是"空白型 gap"：不是前人做得不好，而是没人做。
  2. **方法层 gap**（p.2、p.4）：在 FT-Dojo 中观察到，即使有最强 LLM 后端和同样的微调工具，通用 agent（OpenHands）也表现很差，有时甚至不如不微调的原始模型。作者进一步把原因归结为通用 agent 会忽略噪声反馈中的关键信号，导致低价值改动和资源浪费。
- **证据方式**：方法层 gap 来自**自己基准上的观察**——先建基准、再在基准上发现现有 agent 不行、再据此设计新 agent。这让基准和方法互相"背书"：基准证明了问题存在，方法证明了基准有区分度。
- **三挑战 → 三机制一一对应**（§3.1–3.2）：
  - 挑战 1：上下文越来越长，淹没 agent → 机制：结构化迭代规划（只保留高层假设）。
  - 挑战 2：探索低效，配置坏了也跑满训练 → 机制：fail-fast 逐级校验。
  - 挑战 3：读不懂多层反馈 → 机制：多层反馈分析（指标、错误样例、loss 曲线）。
  每个挑战都用粗体一句话命名，并在方法中由一个阶段专门解决。这种"挑战与模块严格配对"的写法让方法看起来是"被问题逼出来的"，而不是拼凑的。
- **相关工作的落点**：MLE-bench/MLE-Dojo 等假设数据固定、只做特征工程或模型搜索；数据选择方法（DoReMi 等）是开环的静态指标；LaMDAgent 等依赖预定义模板或盲目搜索。每类都归结为"不闭环、不处理原始数据构造"。

## 5. 核心洞见 / 关键想法的包装
- **基准的关键想法**：评测对象不是一组静态数据集，而是"在统一交互协议下的自主微调过程"。作者专门写了一个 **"Benchmark Framing"** 段落（p.3），预先回应"这些数据集都不是新的"这一可预见的审稿质疑：基准化的对象是过程（任务接口、共享原始数据仓库、沙盒、验证/测试协议、结构化反馈），已有 benchmark 只是被用作留出评测器。这是非常值得学习的"先发制人"写法。
- **方法的关键想法**：让 LLM 在"算法层面"被评测，而不是卡在工程问题上（p.5）。FT-Agent 被包装为"借鉴专家实践"的三阶段循环，其价值被定位为"揭示底层 LLM 的算法能力"。
- **命名**：
  - "Dojo"（道场）暗示一个供 agent 反复练习、对抗的场地，延续 MLE-Dojo 等命名谱系，读者一看就知道是交互环境。
  - "FT-Agent" 直白说明用途。
  - 案例里的失败模式被命名为 "shotgun debugging"（散弹式调试），成功模式被称为"累积学习"。给现象起名字，能让分析结论被记住和引用。
- **克制的定位**：作者反复把 FT-Agent 称为"强的初始基线"（strong initial baseline），并在对比前沿 agent 时明确写"支持其适用于该基准，而非证明它是普遍更优的 agent 框架"。这种降调既降低审稿风险，也与"benchmark 为主"的定位一致。

## 6. Figure 1 讲了什么，为什么有效
- 内容（p.3）：FT-Dojo 架构与 agent 交互流程。agent 在隔离沙盒中，与三个接口交互：Meta API（任务与系统信息）、数据仓库（训练数据）、评测器（返回结构化反馈）；agent 反复查询信息、提交代码与配置、执行训练、根据反馈修正。
- 为什么有效：
  - **把"环境"画成一个 agent 可交互的系统**，而非一张数据集表。这直接服务于"我们基准化的是过程"这一论点。
  - **三个接口用三个符号（I、D、F）标注**，和 Eq.1 的形式化定义一一对应，读者在图和公式之间可以无缝切换。
- Figure 2（p.5）补充 FT-Agent 的三阶段循环，并用红/绿表示失败与成功的尝试，视觉上传达"从失败中学习"。Figure 4 的成功/失败两条轨迹则是全文的"情感高潮"。

## 7. 贡献列表
原文有显式的 3 条贡献（p.2）：
1. 提出 FT-Dojo，第一个端到端 LLM 微调的交互式基准环境，13 个任务、5 个领域，数据策略与训练配置都是优化目标。（**基准**）
2. 提出 FT-Agent，面向微调的 agent 框架，三个针对性机制，帮助避开基础工程陷阱、聚焦高层决策、更好地揭示底层 LLM 的算法能力，作为该基准的强初始基线。（**方法**）
3. 实验：13 个任务中 10 个最好；前沿 agent、开源骨干、3 次运行统计支持主要结论；案例分析揭示涌现能力（基于历史记忆的失败恢复、迭代自改进）和根本局限（因果推理）。（**实证 + 分析发现**）
- 第 3 条把"实验结果"和"案例发现"打包在一起，并主动写入"局限"。贡献列表里就预告负面发现，与 R-Zero 引言中预告"指出优势与局限"是同一种策略。

## 8. 实验如何支撑每个 claim
| 主张 | 对应实验 / 表 |
|---|---|
| 基准具有多样性与难度 | 表 1：13 个任务的数据质量特征（缺 CoT、仅 QA 对、高复杂度等） |
| 通用 agent 在该任务上表现差，FT-Agent 更好 | 表 2 主结果：base 模型、人工 SFT、OpenHands、FT-Agent（3 次运行均值±标准差） |
| FT-Agent 探索更深、更高效 | 表 3：有效迭代轮数、改进率、成本；附录表 8 有效迭代次数 |
| 增益来自面向微调的设计，而不只是更强骨干 | 表 4：五任务受控对比，含 Codex、Claude Code、不同规划骨干、LLM 辅助的人工 SFT |
| 不是因为 12 小时预算偏袒 fail-fast | 预算敏感性：OpenHands 在 AIME 上给 24 小时也无提升 |
| 数据量、骨干、目标模型规模的影响 | 图 3 消融：2k vs 5k 样本、骨干替换、3B vs 7B |
| agent 能做什么、不能做什么 | 图 4 与附录 D：Mol Edit 成功轨迹 vs PI4PC 失败轨迹；完整决策表（表 9） |

- **基线选择**：base 模型（下限）、资深从业者的人工 SFT（人类参照，限两轮、不用 LLM 辅助）、配备同样工具的 OpenHands（通用 agent 参照），补充 Codex、Claude Code（前沿商用 agent）。人类基线的约束在附录被明确称为"比较的重要局限"，并补了一个 LLM 辅助人工 SFT 的变体来"界定比较范围"。
- **"受控协议"段落**：明确列出所有 agent 系统固定的外部条件（同一目标模型、数据仓库、沙盒、训练/评测包装、API、时钟预算），只变化 agent 框架。这是 agent 论文回应"不公平对比"质疑的标准写法。
- **直接回应审稿意见**：正文中出现"审稿人提出 FT-Agent 的增益是来自微调导向的设计，还是来自更强的框架/骨干"这样的句子（p.7），随后给出受控对比。把 rebuttal 实验写进正文，并明确说出是在回答哪个质疑，读起来透明可信。
- **诚实的负面结果**：
  - 13 个任务中有 3 个不是最好；人工 SFT 在标准化格式任务（金融 QA）上仍有竞争力，作者顺势总结"自主微调在需要迭代数据诊断、动态工具使用或约束感知优化时最有用"。
  - 2k→5k 数据量增加结果好坏参半，可视化任务反而下降。
  - LLM 辅助的人工 SFT 在 AIME 上比 FT-Agent 更好。
  - PI4PC 的散弹式调试导致零净提升。
  - 3 次运行只对 FT-Agent 做了，基线是单次运行（作者给出 GPU 时间理由）。

## 9. 分析与消融：回答"为什么有效"
- **探索动态**（表 3）：用"轮数更多、改进率更高"来说明 fail-fast 与结构化规划的作用，直接对应挑战 1 和 2。
- **骨干替换**：GPT-5.2 最好，开源骨干仍有竞争力，说明"框架可迁移，但高层编排质量仍关键"。这同时回答了"是不是只是 GPT-5.2 强"的质疑。
- **数据量消融**：得到"质量优于数量"的小结论，并用固定时间预算解释（数据越多，可迭代的轮数越少）。
- **案例研究的"二元性"叙事**（§4.5）：作者把分析写成"能力 vs 缺陷"的对照——Mol Edit 从 2% 的灾难性失败一路修正到 56%，展示累积学习；PI4PC 中 agent 不做因果诊断就乱用通用技巧，导致剧烈波动和零收益，被总结为"当前 agent 是高效的工具优化者，但难以成为严谨的科学家"。这个对照让分析既有亮点又有反思，是全文最有记忆点的部分。
- 附录 D 给出逐轮决策轨迹（策略→反馈），让"为什么有效"可以被读者逐步检查，而不只是看最终数字。

## 10. 局限与未来工作
- 没有独立的 Limitations 章节；局限分散在三处：
  1. 正文案例研究（因果诊断与长程规划不足）；
  2. 附录 B（人工基线的两轮约束是比较的重要局限）；
  3. 结论最后一句（开放世界数据获取与更强推理机制是重要未来方向）。
- 另有显式的**利益冲突声明**（p.2）：FT-Agent 和 R&D-Agent 代码库由作者所在机构开发。这在 agent 系统论文中少见但很加分。
- 铺垫下一篇：结论把"因果诊断"和"开放世界数据获取"定义为未来方向，正好对应案例研究暴露的失败模式，下一篇（更强推理的微调 agent）的问题已被这篇的案例"预注册"。

## 11. 标题和摘要的写法特点
- **标题**：基准名 + 冒号 + "Towards ..."。"Towards" 是一个降调词，承认目标尚未完全实现，与"强的初始基线"定位一致；"with Language Agents" 明确技术路线。
- **摘要结构**：
  1. 痛点（垂直领域微调劳动密集：整理数据、配训练、迭代诊断）；
  2. 空白（端到端 LLM 微调尚未被系统地当作交互式 agent 任务研究）；
  3. 基准（FT-Dojo，13 任务 5 领域）+ 一句"不是新的静态数据集集合，而是标准化接口、数据仓库、沙盒、反馈协议与留出评测"（摘要里就做了 benchmark framing）；
  4. 方法（FT-Agent 三机制）；
  5. 结果（10/13 最好，补充对比与多次运行支持主要结论）；
  6. 案例发现（能从失败中累积学习，但暴露因果诊断与长程规划的局限）；
  7. 代码链接。
- 摘要同时包含正面结果和负面发现，读者对论文的预期被准确设定。

## 12. 对我们的启发

### 对 Paper A（模型自己量化自己、压缩后的模型做下一轮压缩者，RSI）
- **可借鉴**：
  - **"与最近邻工作的两点差异"开场**：Paper A 可以写"LLM 辅助量化/AutoML 压缩已经存在，但自我压缩更难：(i) 压缩者本身在每一轮都被改变；(ii) 压缩质量的信号不止困惑度，还包括逐层误差、激活异常值等"。
  - **挑战→机制一一配对**：例如"压缩后能力下降导致下一轮决策变差"对应"保留校准记忆/回退机制"；"量化配置空间组合爆炸"对应"结构化提案"；"评估信号嘈杂"对应"多层诊断"。
  - **成功/失败二元案例**：Paper A 可以展示一条"压缩者在第 t 轮仍做出合理位宽分配"的轨迹和一条"压缩后的模型开始做出退化决策"的轨迹，并给失败模式起名字。
  - **fail-fast 校验思想**：在 Paper A 的每轮压缩前做小规模校验（如少量层/少量样本的误差检查），既是工程上必要的，也能作为一个可消融的模块。
- **要避免**：
  - FT-Dojo 中决策者是 GPT-5.2、数据生成者是 GPT-5，被训练的模型从不当决策者。Paper A 的卖点是"无外部更强模型、压缩后的模型自己当压缩者"，叙事中必须明确与"外部前沿 LLM 当 ML 工程师"这类工作划清界限，并把 FT-Agent 类系统作为"外部编辑者"上界或对照。
  - 本文的验证/测试集很小（AIME 各 15 题），统计意义弱。Paper A 的评估集要足够大，并报告多次运行。

### 对 Paper B（模型写代码编辑自己训出的 LoRA、编辑后的模型做下一轮编辑者，RSI）
- **可借鉴**：
  - **"Benchmark Framing"式的先发制人段落**：Paper B 可以预先说明"我们的贡献不是新的 LoRA 编辑算子，而是让模型自己选择和组合这些算子、并递归地由编辑后的模型继续编辑的过程"，提前化解"这些操作都是已有的（TIES、DARE、SVD 截断）"这一质疑。
  - **受控协议段落**：明确固定哪些条件（同一基座、同一 LoRA 训练配置、同一评估预算、同一代码执行沙盒），只改变"谁当编辑者"。这对 Paper B 的核心对照（固定编辑者 vs 递归编辑者 vs 外部大模型编辑者）非常关键。
  - **把 rebuttal 实验写进正文并点明质疑**：例如"有人会问增益是否只来自多跑几轮 LoRA 训练"，然后给等计算量对照。
  - **把 FT-Agent 当作"外部编辑者"基线**：FT-Dojo 的设定（外部 GPT 写数据处理代码与训练配置）正是 Paper B 的"非自我"对照，可以直接引用其框架做上界或参照，说明"即使不用更强外部模型，自编辑也能达到可比效果"。
  - **在贡献列表和摘要里预告局限**：Paper B 若发现编辑后的模型在某些轮次写出更差的编辑代码，可以像本文一样把它作为"发现"写入贡献，而不是藏起来。
- **要避免**：
  - 本文的 agent 提升有相当部分可能来自外部强模型合成的 CoT（蒸馏），作者没有充分拆分。Paper B 若使用任何外部数据或模型，必须把"自编辑的贡献"和"外部知识注入"分开报告。
  - 本文没有测量"编辑者能力随轮次是否提升"，因为编辑者是固定的外部模型。Paper B 的 RSI 主张恰恰需要这一测量（例如固定任务上比较第 t 代编辑者写出的编辑代码质量），这是 Paper B 相对本文最重要的新增实验。
  - 基线单次运行、FT-Agent 三次运行的不对称做法容易被质疑；Paper B 应对核心对照组统一做多次运行。
