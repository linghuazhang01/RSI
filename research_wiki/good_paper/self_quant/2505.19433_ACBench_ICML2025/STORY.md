# STORY：ACBench 的叙事拆解（Can Compressed LLMs Truly Act?）

> 本文件只分析作者怎么讲故事，方便模仿叙事结构。具体数字、配置和数据可信度问题见同目录 `notes.md`。

## 1. 元信息
- 标题：Can Compressed LLMs Truly Act? An Empirical Evaluation of Agentic Capabilities in LLM Compression
- Venue：ICML 2025（PMLR 267；arXiv 2505.19433 v2）
- 作者与机构：Peijie Dong*、Zhenheng Tang*（共同一作），Xiang Liu、Lujun Li、Xiaowen Chu、Bo Li（香港科技大学（广州）、香港科技大学）
- 论文类型：基准 + 实证分析论文，不提新压缩方法；附带三个“分析工具”（ERank、Top-k 排序相关性、Energy）。

## 2. 一句话卖点
**压缩评测不能只看 PPL 和 GLUE，必须看 agent 能力。** 4-bit 量化基本保住了工作流生成和工具调用（掉 1–3%），但真实场景应用掉 10–15%；量化总体比剪枝稳；R1 蒸馏的小模型在 agent 任务上反而更差。

## 3. 开场钩子
引言是标准的“能力 → 代价 → 现有方案 → 评测太窄”四步：
1. **宏大背景**：LLM 在代码生成、科研、多智能体协作上表现出变革性能力（用三类应用 + 引用堆出“重要性”）。
2. **代价**：部署成本高；训练后压缩（剪枝、量化）能把模型缩小到约 1/4，同时在 PPL、算术等标准基准上保持性能。
3. **转折**：现有压缩评测只看单轮语言建模（WikiText-2 PPL）和 NLU（GLUE）。而真实 agent 应用（机器人控制、金融分析）需要超越静态基准的能力。
4. **用四个带具体例子的需求把 gap 写实**：多步规划（WebShop 中的 API 调用序列）、长上下文一致性（40k token 的大海捞针）、跨轮自适应推理、工具集成。最后点名一篇只评测量化模型 NLU 的前作，称其忽略了 agent 能力是“关键疏漏”。

钩子类型：**应用驱动的痛点**。标题用问句（“真的能行动吗？”），“Truly”一词呼应 LLM-KICK 的 “true merits”，是同一谱系的“戳破表象”叙事，只是把评测维度从“知识”换成了“agent 能力”。

## 4. Gap 怎么陈述
- **被指为不足的点**：评测范围。现有压缩基准（如 llmc 等）停留在单轮、静态任务，没有覆盖多轮、需要工具和规划的 agent 场景。
- **证据形式**：主要是**列举式论证**，不是实验证据。引言里没有像 LLM-KICK 图 1 那样的“指标正常但行为崩坏”的具体失败例子；需求是靠“agent 需要 X、Y、Z”加引用推出来的。
- 引言还另外提出两个子 gap：(1) 压缩如何改变模型内部表示缺少系统工具；(2) 在 agent 任务上量化与剪枝谁更好、是否互补，还没有人比较过。
- **评价**：这种写法省事、覆盖面大，但说服力弱于“先给一个反例”。好处是把 benchmark 的四个维度和 gap 一一对应，读者一读完引言就知道后面四个评测章节是什么。

## 5. 核心洞见 / 关键想法
- **洞见**：压缩的影响要按 agent 能力分解来看，不同能力对压缩的敏感度不同（工作流、工具调用比较耐压；真实环境任务、结构化输出、长上下文检索比较脆弱）。
- **包装方式**：
  - **一个 taxonomy**：把 agent 能力分成四类（动作执行、工作流生成、长上下文理解、真实场景应用），每类对应 1–3 个现成基准（T-Eval、WorfBench、LongBench / LongGenBench / 大海捞针、AgentBoard）。四类名称简短，便于记忆和组织章节。
  - **一个名字**：ACBench（Agent Compression Benchmark）。
  - **三个“新”分析指标**：ERank（有效秩）、Top-k 排序一致性、Energy（借自 OOD 检测）。作者把它们称为“novel analytical tools”，用来增加方法感，让论文不只是“跑分合集”。
  - **三个维度的研究问题**：压缩对 agent 能力的影响；压缩对模型本身（内部表示）的影响；不同压缩方法的比较。
- 和 LLM-KICK 一样，强调“用现成数据集，但它们之前没被用来评测压缩模型”。

## 6. Figure 1（以及 Table 1）讲了什么，为什么有效
- **Figure 1** 三个子图：
  - (a) 从“单轮的量化 LLM”到“多轮 agent 场景下的压缩 LLM”的转变，直接可视化 gap。
  - (b) 压缩方法一览（GPTQ、AWQ、SmoothQuant；SparseGPT、Wanda）。
  - (c) 基准总览：四类能力及其组成。
- **Table 1**（第 2 页）起到第二张 teaser 的作用：一行一个“章节 → 能力 → 基准 → 测试规模 → 模型族”，同时是全文的**路线图**。
- 为什么有效：(a) 把“评测范式转变”画成一张图，比文字更直观；Table 1 让审稿人在第 2 页就看到覆盖面（12 个任务、15 个模型），先在“工作量”上建立信任。
- 弱点：Figure 1 是概念总览，没有任何结果。和 LLM-KICK 的“反差图”相比，第一眼的冲击力弱很多。

## 8. 实验如何组织去支撑每个 claim
**结构**：先放第 3 节“压缩效应的统计分析”（三个指标），再按能力分成第 4–7 节，每节固定两小节：**实验设置 → 压缩效应**。“压缩效应”里每段用一个**加粗的结论式小标题**开头，例如“量化比稀疏化更能保住工具调用能力”“压缩显著影响结构化输出生成”“蒸馏推理模型表现不如未蒸馏版本”。读者只看粗体就能得到全部结论。第 4 节结尾还有一段“压缩策略建议”，把发现转成可操作的建议。

**主张 → 实验映射**：
| 主张 | 对应实验 |
|---|---|
| 压缩改变内部表示（有效秩下降、top-k 排序不稳、早期解码置信度两极化） | 第 3 节：图 2（ERank）、图 4–5（Top-k 相关性、与 PPL 的 Spearman 相关）、表 2（OPT 125M–6.7B）、附录 C.7（Energy） |
| 量化优于剪枝（工具调用） | 第 4 节：T-Eval，图 6，附录表 8 |
| 结构化输出更脆弱 | 图 3 + 表 8：JSON vs 字符串格式 |
| 同等比特预算下，大模型量化更划算 | 图 7：7B FP16 vs 14B INT8 等，1.5B–14B |
| 工作流生成基本不受影响（掉点 ≤5%） | 第 5 节：WorfBench，附录表 10 |
| 模型越小越怕压缩 | 第 5 节：Qwen2.5-3B vs 32B（Alfworld、Lumos） |
| 长上下文：>7B 模型基本不受影响，小模型和蒸馏模型脆弱；32K 是共同边界 | 第 6 节：LongBench（表 3–5）、LongGenBench（表 6–7）、大海捞针（附录 C.5） |
| 真实场景应用明显退化，只有 AWQ 和 Wanda 可接受 | 第 7 节：AgentBoard，表 9 |
| 蒸馏推理模型 agent 能力下降 | 表 8（T-Eval 70%→43.6%）、WorfBench、表 9（PDDL 33%→1%）、图 8 四个基准汇总 |

**基线选择**：只选能在 vLLM 上部署的训练后方法（GPTQ、AWQ、SmoothQuant；Magnitude、SparseGPT、Wanda），理由是“实际可部署”。这个选择被写成优点，而不是限制。

**诚实的负面 / 反直觉结果**：
- 蒸馏推理模型在 agent 任务上更差，作者明确写成“与常规预期相反”，并给出两点解释（教师模型本身 agent 能力弱；小模型容量有限，优先保推理就牺牲工具能力）。这是全文最有记忆点的发现之一。
- 小模型（<3B）在压缩前就做不了很多任务，作者如实说明。
- 不过，按 notes 中的核查，部分表格存在基线异常和疑似重复填表，正文没有讨论；只有单一稀疏率、没有方差。

## 9. 分析与消融
- **三个内部指标**（第 3 节）回答“压缩对模型做了什么”：
  - ERank：比特越低有效秩越低，大模型压缩后保持更高的有效秩，作者据此推测大模型更耐压缩。
  - Top-k 排序一致性：k 从 10 降到 3 时一致性变差，而 top-3 恰恰决定生成，作者用来解释下游退化；并且与 PPL 有强 Spearman 相关，用来证明指标有意义。
  - Energy：压缩模型在解码早期置信度两极化，后期与原模型趋同。
- **同比特预算比较**（图 7）：把问题从“压缩掉多少”换成“同样显存下，小模型全精度和大模型量化哪个好”，这是一个对部署者更有用的视角。
- **输出格式消融**（JSON vs 字符串）：把“掉点”归因到格式遵循。
- **规模分析**：3B vs 32B 的压缩敏感度对比。
- 弱点：内部指标和 agent 得分之间没有建立定量联系，分析部分更像“附加的工具展示”，没有真正回答“为什么某个 agent 能力更脆弱”。

## 10. 局限与未来工作
- 局限单列一节，很短，三条全是**范围限定**：只做了训练后量化和剪枝，没做 QAT；只选 vLLM 兼容的方法（排除了 QuaRot 等）；全部用默认配置，没扫 group size 等。最后一句提醒结论只在这些条件下成立。
- 未来工作没有单独写，只在结论里说希望未来的压缩研究更关注真实的 agent 应用；在蒸馏部分顺带提出“需要能同时保住推理和 agent 能力的蒸馏方法”。
- 没有明显为下一篇铺垫具体方法；Impact Statement 写得较长，重复了基准价值。

## 11. 标题和摘要的写法特点
- **标题**：问句主标题 + 说明性副标题。问句制造悬念，副标题交代论文类型（empirical evaluation）和对象（agentic capabilities × LLM compression）。这是评测论文常用且安全的格式。
- **摘要结构**：
  1. 一句背景（训练后压缩降低成本）。
  2. 转折：现有压缩基准只关注语言建模和 NLU，忽略 agent 能力（用括号列出四类能力）。
  3. 提出 ACBench，并用 (1)(2)(3) 列出覆盖面：12 任务 / 4 能力、量化 + 剪枝方法、15 个模型（小模型、标准模型、蒸馏推理模型）。
  4. 一条带数字的核心发现（工作流和工具 1–3% vs 真实应用 10–15%）。
  5. 一句介绍三个分析指标。
  6. 一句“提供可操作的见解” + 代码。
- 特点：摘要里**覆盖面信息远多于发现**，只给了一条定量发现。这样写突出“工作量大”，但读者记住的结论不多。

## 12. 对我们的启发

### Paper A（模型自己量化自己；压缩后的模型当下一轮压缩者，RSI）
**可借鉴**
- **直接作为动机证据**：ACBench 说明压缩后的模型在工具调用、工作流上相对稳，但在真实环境任务和**结构化输出（JSON）**上明显变差。而 Paper A 中下一轮压缩者恰恰需要写配置、调工具、生成代码。可以在引言里引用这一点，说明“压缩后的模型还能当压缩者吗”不是显然成立的，是值得研究的问题。
- **把“压缩者角色”拆成能力 taxonomy**：仿照四类 agent 能力，把压缩者需要的能力拆成：规划压缩方案、调用量化工具、写 / 改代码、读长日志、判断结果好坏。每一轮都分别追踪，比只报一个总分更有解释力。
- **结论式加粗小标题 + 策略建议段**：每个实验小节用一句结论做小标题，最后加一段“对自我压缩系统的建议”，便于审稿人快速抓重点。
- **同预算比较**：仿照图 7，把“第 k 轮自我压缩得到的模型”与“同显存的更小全精度模型”或“人工一次性压到同样大小的模型”比较，回答“自我压缩到底值不值”。
- **Table 1 式路线图**：一张表列出“章节 → 研究问题 → 评测任务 → 模型 → 轮数”，在第 2 页建立覆盖面和工作量的印象。

**要避免**
- 不要只用列举式论证陈述 gap；引言里要给一个具体反例（例如第 2 轮压缩者生成的量化配置把关键层压坏）。
- 不要堆砌和主线没有定量联系的“新指标”；如果引入内部指标（如有效秩），必须证明它能预测下一轮压缩者的表现。
- 不要只做一个压缩强度、不报方差；RSI 的多轮误差累积对噪声更敏感，必须多 seed、给置信区间。
- 要有显式的贡献列表，并检查基线行是否异常（ACBench 的表格问题是反面教材）。

### Paper B（模型写代码编辑自己训出的 LoRA；编辑后的模型当下一轮编辑者，RSI）
**可借鉴**
- **“提升某项能力会牺牲 agent 能力”**：ACBench 里蒸馏提升了推理却损害了工具调用。Paper B 的自我编辑也可能出现同样情况：编辑 LoRA 提升了目标任务，却削弱了“写代码编辑自己”的能力。可以借用这个反直觉发现作为风险动机，并在实验中专门追踪“编辑者能力”。
- **结构化输出脆弱**：编辑者需要生成能运行的代码，格式和语法遵循很关键。可以仿照 JSON vs 字符串的对比，单独统计“代码能否执行”和“逻辑是否正确”。
- **用标题问句制造悬念**：例如“编辑过自己的模型还能继续编辑自己吗？”。

**要避免**
- Paper B 是方法论文，不能像 ACBench 那样只给覆盖面、少给机制。需要明确的方法图和闭环说明。
- 不要让“分析工具”和主实验脱节；任何权重层面的分析都要和编辑效果挂钩。
