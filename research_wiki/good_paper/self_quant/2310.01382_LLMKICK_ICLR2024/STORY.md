# STORY：LLM-KICK 的叙事拆解（Compressing LLMs: The Truth is Rarely Pure and Never Simple）

> 本文件只分析作者怎么讲故事，方便模仿叙事结构。具体数字和方法细节见同目录 `notes.md`。

## 1. 元信息
- 标题：Compressing LLMs: The Truth is Rarely Pure and Never Simple
- Venue：ICLR 2024（arXiv 2310.01382 v2）
- 作者与机构：Ajay Jaiswal、Zhangyang Wang（UT Austin），Zhe Gan、Xianzhi Du、Bowen Zhang、Yinfei Yang（Apple）。一作是在 Apple 实习期间完成的。
- 论文类型：评测 / 反思型论文（re-evaluation + benchmark），不提新压缩方法。

## 2. 一句话卖点
**PPL 几乎不变，并不代表压缩模型的能力没变。** 用知识密集型任务重新评测，SoTA 剪枝在 25–30% 稀疏时就开始失效，量化比剪枝稳；但压缩模型把知识放进上下文后，仍然是不错的检索器和摘要器。

## 3. 开场钩子
引言前三段是一个“先肯定、再收窄、最后发问”的漏斗：
1. **宏大背景 + 一个具体代价数字**：LLM 已经渗透到 NLP、视觉、图学习；但参数量太大，作者给了一个很直观的数字：GPT-175B 光加载权重就要 325GB 显存、至少 5 张 A100。用“民主化”作为价值锚点。
2. **领域进展 + 话锋一转**：剪枝和量化两条路线都很成功，声称 50–60% 稀疏或 2–3 bit 下性能不掉。转折点是：这些结论几乎都只靠 PPL。作者没有说“这些方法不好”，而是说“评估太窄”，会限制新方法的发展，也看不到压缩模型新的能力和缺陷。
3. **把问题变成一个可检验的问句**：PPL 对稠密模型本来就被质疑过；而压缩模型都来自同一个母模型、结构完全相同，彼此差异更细微，评估更难。于是提出全文的研究问题（斜体）：对与稠密模型高度相似的压缩模型，PPL 能多好地反映能力变化？

钩子类型：**具体痛点（指标失灵）**，不是宏大愿景。标题本身也是钩子：借用王尔德的名句，暗示“真相没那么简单”，一眼就能看出这是一篇“戳破神话”的论文。

## 4. Gap 怎么陈述
- **被指为不足的点**：不是某个压缩算法，而是整个领域的**评估协议**（只看 PPL）。这是一个“元层面”的 gap，攻击面大，但不会直接得罪某个方法。
- **论证分两层**：
  - 文献层：PPL 在稠密模型比较中就被质疑（引用 Muhlgay et al.）；稠密模型已经有很多超越 PPL 的评测，但压缩模型还没有人做（“unlike dense LLMs, no such effort”）。
  - 证据层（第 2 节 + 图 1）：图 1 上排显示 Vicuna-7B/13B/33B 的 PPL 在 45–60% 稀疏前基本不动；而且 30% 稀疏前，SoTA 剪枝和最简单的 magnitude 剪枝几乎一样，暗示“SoTA 的优势可能是假的”。图 1 下排给出两道事实问答，未压缩模型答对，所有压缩版本都答错或胡编。
- **技巧**：gap 用“一条看起来平坦的曲线 + 两个具体的失败例子”同时支撑。曲线说明指标不敏感，例子说明真实能力确实丢了。

## 5. 核心洞见 / 关键想法
- **洞见**：压缩模型之间的差别很细微，必须用**知识密集型**任务才能看出来；而且要把“知识丢失”和“使用上下文的能力”分开测。
- **包装方式**：
  - 起一个好记的缩写 **LLM-KICK**（Knowledge-Intensive Compressed LLM BenchmarK），名字本身就点明“知识密集”这个卖点。
  - 定义了一个可判定的概念 **Matching Compressed LLM**：相对稠密模型掉点不超过 ε0（取 5%）就算 matching。这个定义借自彩票假设 / 稀疏子网络文献（作者自己的研究背景）。它把一堆曲线变成一个二元结论：每个方法在每个任务上“最多能压到多少还算 matching”。作者还解释了为什么把常用的 1% 放宽到 5%，提前堵住“标准太严”的质疑。
  - 强调“没有新建数据集”，全部来自已被广泛接受、但压缩领域还没用过的现有数据集。这既是诚实的说明，也是一种防御：降低“数据集质量”方面的攻击面。
- **自我定位**：明确说自己和“开发新压缩方法”的潮流是正交的，是“退一步重新评估”。另外特意说明目的不只是找失败案例，也会报告对压缩有利的发现，避免被看成单纯的“唱衰文”。

## 6. Figure 1 讲了什么，为什么有效
- 内容：上排是 PPL 随稀疏率变化的曲线（几乎平坦）；下排是两道 FreebaseQA 风格的事实问题（希区柯克电影、伍迪·艾伦的本名），给出未压缩 Vicuna-7B 和四种压缩版本（Magnitude/SparseGPT/Wanda 50%、GPTQ 4-bit）的实际回答。
- 为什么有效：
  1. **反差感强**：“指标说没事”和“模型实际答错”放在同一张图，读者几秒内就能理解论点。
  2. **例子可读、可验证**：琐事问答不需要专业背景，错误答案（例如答成演员名、答“100% correct”）本身就很有冲击力。
  3. **覆盖所有被评方法**：每个 SoTA 方法都出现一次失败，避免被说成挑选个别方法。
- 图题直接叫 “True Merits of SoTA Compression”，与全文“真相”主题呼应。

## 8. 实验如何组织去支撑每个 claim
**结构**：三个 Setting，每个 Setting 的标题都是一个问句：
- Setting 1：压缩模型还能多好地调用剩下的知识？
- Setting 2：压缩模型能多好地综合放进上下文的知识？
- Setting 3：压缩模型能多好地遵循指令？

每个任务都用同一个三段式模板：**任务定义与动机 → 数据集细节 → 结果与分析（带圆圈编号的观察 1、2、3…）**。读者很容易对齐各个任务的结论。

**主张 → 实验映射**：
| 主张 | 对应实验 |
|---|---|
| PPL 无法反映能力变化 | 图 1（PPL 曲线 + 失败例子） |
| 剪枝在低稀疏率就失效 | 图 2 FreebaseQA（Factoid-QA）；图 3 MMLU；图 6 MT-Bench（matching 只到约 25%） |
| N:M 结构化稀疏全部失败 | 图 2–6 每张图的 N:M 子图 |
| 量化优于剪枝 | 图 2–5 中 GPTQ 8/4-bit 曲线；附录 A.6 补 AWQ、LLM.int8() |
| 不同学科受影响不同 | 图 3 按 STEM/人文/社科/其他拆分 |
| 丢的是知识，不是使用上下文的能力 | 图 4 TriviaQA 闭卷 vs 开卷正面对比 |
| 能摘要，但长上下文更吃力 | 图 5 CNN/DailyMail 按长短三档 + GPT-4 打分 |
| 输出变得重复 | 图 6(c) 平均 unique token 数 |
| 大而稀疏不如小而稠密 | 第 4 节：13B 剪到约 7B 参数 vs 稠密 7B（MMLU） |
| 校准数据很重要 | 图 7：校准样本数 1→128 |

**基线选择**：只选“训练无关、数据无关”的前两名剪枝方法（SparseGPT、Wanda）+ 最朴素的 magnitude 剪枝 + 一种主流量化（GPTQ）。作者明确解释是为了“减少冗余实验和结果杂乱”。magnitude 剪枝作为“最笨的基线”，是故意放进去的：它用来证明 SoTA 在低稀疏区间并没有优势。

**诚实的负面 / 意外结果**：
- 对压缩有利的发现被放在显眼位置（开卷检索、摘要），并且作者主动说“to our surprise”。
- 量化在摘要上甚至略好于稠密模型，作者如实报告。
- 最简单的 magnitude 剪枝在 matching 区间与 SoTA 持平甚至略好，这对 SoTA 方法是负面结果，对读者是有用的结论。

## 9. 分析与消融
作者主要靠**对照设计**回答“为什么”，而不是靠机理分析：
- **闭卷 vs 开卷**（最核心的分析）：同一批问题，唯一区别是是否把证据文档放进上下文。开卷能恢复大部分性能，说明压缩主要伤的是参数里存的知识，而不是阅读和抽取能力。这是一个非常干净的“消融式对照”。
- **精确生成 vs 选择题**：FreebaseQA 要求生成精确答案，MMLU 只需选字母；后者掉点更温和，作者用“任务从生成放松到选择”来解释。
- **上下文长度分档**：把摘要文章分成短、中、长三档，长文掉得更多。
- **unique token 统计**：用一个简单的统计量说明压缩模型生成更重复。
- **小而稠密 vs 大而稀疏**、**校准样本数**、**k-shot（附录 A.7）**、**LLaMA-2（附录 A.9）**、**AWQ / LLM.int8()（附录 A.6）**：这些附录内容看起来是为回应审稿意见补的，覆盖了“只测了 GPTQ”“只测了 Vicuna”“只测 zero-shot”等常见质疑。

## 10. 局限与未来工作
- 写法极短，合并在“结论与局限”一节里：只评测了 Vicuna（decoder-only），理由是开源许可、性能好、能遵循指令。
- 未来工作只有一句：研究能否用 LoRA / QLoRA 等参数高效微调**恢复**压缩丢失的知识。这为后续“压缩 + 恢复”类工作做了铺垫。
- 没有正面讨论的弱点：没有测速度和显存；没有 20B+ 模型的下游测试（33B 只在 PPL 图里出现）；主结果都是折线图，正文没有数值表。

## 11. 标题和摘要的写法特点
- **标题**：前半句点明对象（Compressing LLMs），后半句借用文学名句表态。不说方法、不说数据，只表达立场。好记，但信息量低，需要摘要补足。
- **摘要结构**：
  1. 一句背景（LLM 代价高）。
  2. 一句领域现状（训练无关压缩已达到 50–60% 稀疏、3–4 bit，PPL 几乎不掉）。
  3. 转折 + 定位：大家都在开发更复杂的方法，本文退一步，质疑这些方法依赖的指标（PPL）。
  4. 提出 LLM-KICK。
  5. 用“优点和困境”并列的方式列出 4 条发现，有负面也有正面，每条带具体阈值。
  6. 一句愿景 + 代码链接。
- 关键词设计：“re-evaluate”“redefine the evaluation protocol”“true capabilities”反复出现，强化“揭示真相”的主题。

## 12. 对我们的启发

### Paper A（模型自己量化自己；压缩后的模型当下一轮压缩者，RSI）
**可借鉴**
- **“指标说没事，实际已经坏了”的开场**：RSI 自我量化最大的风险是：每一轮的代理指标（PPL、校准 loss、模型自评）看起来都正常，但多轮累积后能力已经漂移。可以仿照图 1，用一张图并列“逐轮 PPL 曲线（平坦）”和“第 k 轮模型作为压缩者写出的量化配置 / 代码出错的具体例子”。
- **可判定的概念定义**：仿照 “Matching Compressed LLM” 定义一个可判定的量，例如“第 k 轮仍然 matching（相对初始模型掉点 ≤ε）”，再定义“自我压缩深度 = 连续保持 matching 的最大轮数”。这样能把多轮曲线压缩成一个可比较的数字，并提前说明 ε 怎么选、为什么。
- **闭卷 vs 开卷式的对照**：区分“压缩伤了模型存的知识”和“压缩伤了模型执行压缩任务的程序性能力”。例如同一个压缩任务，给模型完整工具文档 / 示例（开卷）和不给（闭卷），看下一轮压缩者能力下降来自哪里。
- **问句式的 Setting 标题**：例如“压缩后的模型还能做好压缩吗？”“多轮之后误差会累积还是自我纠正？”，每节固定用“动机 → 设置 → 编号观察”模板。
- **最笨基线**：放一个“人类固定配方的逐轮量化”（例如每轮都用同一个 GPTQ 配置）作为基线，看自主压缩在早期轮次是否真的比它好。这和 LLM-KICK 用 magnitude 剪枝检验 SoTA 是同一个逻辑。

**要避免**
- LLM-KICK 是纯评测，没有方法；Paper A 必须有一个方法 / 系统贡献，不能只停留在“发现自我压缩会退化”。
- 不要只用 7B 模型和折线图；主要结论要有数值表，且要覆盖我们关心的规模（约 27B）。
- 不要只用 GPT-4 打分来衡量“作为压缩者的能力”，最好用可执行、可验证的结果（压缩后的模型实际大小、真实下游得分）。

### Paper B（模型写代码编辑自己训出的 LoRA；编辑后的模型当下一轮编辑者，RSI）
**可借鉴**
- LLM-KICK 的未来工作正好是“用 LoRA 恢复压缩丢失的知识”。Paper B 可以在相关工作里把它当作一个起点：从“人来做 LoRA 恢复”走向“模型自己写代码编辑 LoRA”。
- **“训练 loss 正常 ≠ 能力正常”**：编辑 LoRA 后，训练 / 验证 loss 可能看起来没问题，但编辑者能力（写代码、理解权重结构）可能悄悄下降。可以仿照图 1 的“指标 vs 具体失败例子”。
- **流畅但事实错误**这个发现对 Paper B 有直接意义：编辑后的模型生成的代码可能看起来像样，但逻辑错。要准备“表面流畅 vs 实际可执行”的对照统计（类似 unique token 分析，可以统计代码执行通过率、重复代码比例）。
- **正负结果平衡**：主动报告编辑在哪些能力上反而提升，增加可信度。

**要避免**
- 不要把核心贡献写成“又一个评测”；Paper B 的卖点是闭环的自我编辑机制。
- 标题借用名句很巧，但对方法论文来说信息量太低；Paper B 的标题应该直接点出“自我编辑 + 递归”。
