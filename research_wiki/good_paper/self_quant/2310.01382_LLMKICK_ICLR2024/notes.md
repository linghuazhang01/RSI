## 研究问题
SparseGPT、Wanda、GPTQ 等方法声称在 50–60% 稀疏或 3–4bit 量化下 PPL 几乎不变。本文的问题是：对于和原始稠密模型高度相似的压缩模型，PPL 能否反映真实能力的变化？作者构建了 LLM-KICK，从三个场景检验：(1) 压缩后还能调用多少预训练知识；(2) 知识放进上下文时能否利用；(3) 指令遵循和多轮对话。

## 方法细节
### 被压缩的模型
- Vicuna-7B、Vicuna-13B（主实验），LLaMA-1-7B（图 2），LLaMA-2-7B（附录 A.9，图 15–17）。
- **Vicuna-33B 只出现在图 1 的 PPL 曲线里**（p3），下游任务都没有测 33B。所以 20B–35B 区间只有 PPL 证据。

### 压缩方法与配置
- 剪枝：一次性 Magnitude（基线）、SparseGPT、Wanda。
  - 非结构化稀疏率从 0% 扫到 75%，步长 5%。
  - N:M 结构化：1:2、2:4、4:8。
- 量化：GPTQ 16/8/4bit（GPTQ-for-LLaMa 实现）。附录 A.6 补充了 AWQ（8bit）和 LLM.int8()。
- 校准：WikiText。图 7 扫了 1–128 条校准样本；主实验用默认设置，具体条数没写。group size 没写。
- 结果是 3 次独立运行的平均。
- **不做任何微调或恢复**。结论里把用 LoRA/QLoRA 恢复丢失的知识列为未来工作（p9）。

### “匹配压缩模型”的定义（p4）
- 相对稠密模型掉点不超过 5%，就算“matching”，即可接受。

## 关键实验与数字
### (a) 量化 vs 剪枝（相近压缩率）
- 正文的总体结论是量化好于剪枝（p3 第 3 点、p6）。MMLU 上，Vicuna-7B 的 8bit 和 Vicuna-13B 的 4bit GPTQ 属于 matching；剪枝的 matching 区间只有大约 20–40%（图 3，p6）。
- **8bit 量化也不是无损的**：FreebaseQA 上 8bit GPTQ 掉约 8–10%（图 2，p5）。附录表 2（p20）的 Vicuna-7B 8bit 结果：Factoid-QA GPTQ 60.14%、AWQ 60.31%、LLM.int8() 61.02%（稠密 65.44，见表 3），MMLU 47.10/47.18/47.82。LLM.int8() 在所有任务上都略好于 GPTQ 和 AWQ 的 8bit。
- **大而稀疏 vs 小而稠密**（p9）：Vicuna-13B 剪掉 46.16%，参数量约等于 7B，MMLU 分别为 Magnitude 31.7%、Wanda 45.3%、SparseGPT 46.3%，都低于稠密 Vicuna-7B 的 46.7%。作者认为当前的稀疏算法还不值得付出剪枝的代价。

### (b) 哪些能力最容易被压缩伤到
- **参数化知识（闭卷事实问答）最脆弱。** FreebaseQA 上剪枝在 30–35% 就失去 matching，之后急剧下降（图 2，p5）。图 1 展示了 50% 剪枝和 4bit GPTQ 的 Vicuna-7B 在事实问题上输出错误或无关回答。
- **MMLU 下降相对平缓**，因为从生成答案变成了选择答案。人文和社科比 STEM 掉得多（图 3，p6）。
- **上下文检索（开卷）非常稳**：Vicuna-7B 在约 40% 稀疏和 8bit 下仍是 matching，Vicuna-13B 在约 50% 稀疏和 4bit 下仍是 matching（图 4，p7）。也就是说，知识可以通过上下文补回来。
- **上下文摘要稳**，但文章越长掉得越多；量化甚至略好于稠密模型（图 5，p8）。
- **指令遵循和多轮对话**：剪枝只在约 25% 以内是 matching。压缩模型生成的 unique token 变少，重复变多（图 6c，p9）。
- 结论（p9）：压缩显著损害了预训练时编码的知识，但在知识放进上下文的场景下表现不错。

## 作者自己声明的局限（p9）
- 只评测了 Vicuna（decoder-only），理由是许可证、性能和指令遵循能力。
- 没有研究如何用 LoRA/QLoRA 恢复丢失的知识，留作未来工作。
- 全部用各方法的默认设置。

## 方法问题与替代解释
- 【推断】主要结果都只以折线图呈现，没有数值表（附录表 3 只覆盖到 50%，量化没有完整表），复核困难。“16-bit GPTQ”实际上近似未压缩，图例的含义不清楚。
- 【推断】附录表 2 里指令遵循的 GPT-4 分数（GPTQ 8bit 9.74）高于表 3 的稠密基线（7.763），两张表的打分口径似乎不一致，也可能是相对分数，正文没有说明。
- 【推断】8bit GPTQ 在 FreebaseQA 上掉 8–10%，这和后续很多工作“INT8 近乎无损”的结论不一致。可能是早期 GPTQ-for-LLaMa 实现的问题，也可能是 exact match 对措辞变化很敏感（压缩模型的答案表述可能变了，但内容是对的）。
- 【推断】GPT-4 作为裁判、GPT-3.5 作为参照，绝对分数受裁判偏好影响。摘要每档只有 100 篇，MT-Bench 只有 80 题，统计功效有限，图中“量化优于稠密”可能只是噪声。
- 【推断】模型都是 2023 年的 Vicuna 和 LLaMA，现代模型（Qwen2.5/3，训练 token 更多、知识密度更高）对压缩可能更敏感，也可能更鲁棒。后续 UniComp（2602.09130）和 ACBench（2505.19433）在 Qwen 上测到的 50% 非结构化剪枝损伤，看起来比 LLM-KICK 在 Vicuna 上测到的小（例如 Qwen2.5-7B Wanda 50% 的 SK=90.36）。所以 LLM-KICK 的断崖位置不能直接套用到新模型上。
- 【猜测】闭卷 QA 的大幅下降里，有一部分可能是“知道但说不出来”（生成格式退化），不一定是知识被抹掉了。开卷检索仍然很稳，这和“阅读/抽取电路保留、长尾事实记忆受损”的解释相符，但本文没有直接区分这两种情况。

## 对“约 27B 模型自我压缩（压缩后还要继续当 agent）”研究设计的启示
1. **不能用 PPL 做每轮的接受准则。** 本文最核心的证据是：PPL 在 45–60% 稀疏之前基本不变（图 1），但闭卷知识在 30–35% 稀疏就已经掉出 5% 的容忍区间（图 2）。自我压缩循环中，如果让 agent 用 PPL 作为自我评估信号，【推断】很可能会持续接受实际上已经退化的模型。
2. **方法上优先量化（8bit 最稳，4bit 在更大的模型上可以 matching）**；剪枝如果要用，只用低稀疏率（不超过 20–25%）的非结构化剪枝，完全避免 N:M（图 2–4、表 3）。证据来自 7B/13B；Vicuna-13B 能在 4bit 下 matching 而 7B 不行，提示规模越大越耐量化【推断：27B 应当更耐 4bit，但本文没有直接测】。
3. **大而稀疏不如小而稠密**（p9）：对“27B 自我剪枝到约 14B 参数”这类设计来说，这是负面证据。剪完的效果可能还不如直接换一个原生的 14B 模型，除非有恢复训练。
4. **LoRA**：本文没有实验，只把它列为未来工作。没有证据说明 LoRA 能恢复压缩丢失的参数化知识。
5. **agent 任务和知识任务要分开评测。** 压缩模型在知识放进上下文时（检索、摘要）很稳，而闭卷知识和开放式指令遵循很脆弱（图 4–6）。【推断】如果“执行下一轮压缩”这个 agent 任务主要依赖上下文里的文档和工具输出，它可能比闭卷知识更耐压缩；但多轮指令遵循在约 25% 稀疏就开始退化，而这正是 agent 的核心能力。评测建议包括：闭卷事实 QA（FreebaseQA 或 TriviaQA 闭卷）、MMLU（按学科拆分）、TriviaQA 开卷（上下文利用）、长文档摘要（按长度分档）、MT-Bench 多轮对话，以及生成多样性（unique token 或重复率）。
6. **校准和 few-shot 是低成本的缓解手段**：SparseGPT 增加校准样本、推理时加 2–3 个 shot，都能在高稀疏下挽回性能（图 7、图 14）。【推断】自我压缩的 agent 可以把这两个当作可以调的旋钮。
7. 【推断】本文发现压缩模型生成的内容更重复、多样性下降（图 6c）。在多轮自我改进循环里，这可能让 agent 的探索能力逐轮萎缩，可以把生成多样性作为一个监控指标。
